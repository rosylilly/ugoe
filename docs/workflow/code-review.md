# コードレビューの手順 (M9)

M9 では、クレート・パッケージ・アプリごとに、いまあるコードを読み直します。機能の追加の途中では見落としやすい誤り・規約の違反・
テストの穴・重複を見つけ、小さいものはその場で直し、大きいものは後続のタスクにします。マイルストーンは [roadmap.md](../roadmap.md#m9-コードレビュー-)。

## 進め方

1. 対象の `README.md`、関係する仕様書 (`docs/spec/`)・ADR・設計書を読む。
2. 対象のコードを **テストを含めてすべて** 読む。生成したコード (`apps/editor/src/lib/generated/` など) は、生成元だけを読む。
3. 下の「観点」に沿って所見を集める。参考に `cargo clippy -p <crate> -- -W clippy::pedantic` を流してもよい (設定は変えない。出た警告を全部直す必要はない)。
4. 所見を「所見の扱い」に沿って、直すか起票するかに分ける。
5. 直したものはテストで確かめ、`just ci` を通す。
6. タスクファイルの「メモ」に、所見の表 (下の「記録の形」) を書く。

## 観点

### すべてに共通

- **正しさ:** 境界の値 (空・0・1 個・最大)、NaN と無限大、整数のあふれと `as` の切り捨て、添字の範囲外、順序に依存する処理、決定性 (ランタイム層)。
- **パニック:** ライブラリでの `unwrap()`・`expect()`・添字・`unreachable!()`。外から来たデータ (ファイル・IPC・ネットワーク・FFI) で止まらないか。
- **エラー処理:** 握りつぶし (`let _ =`・`.ok()`・空の `catch`)、意味の分からないエラー、利用者に見せる文言のコード化 (ADR 0029)。
- **規約 (AGENTS.md):** 依存方向、`ugoe-model` はデータだけ、ランタイム層の I/O・スレッド・時刻、編集は `Command` を通す、AI は提案だけ、`unsafe`、`TODO(T####)` の書き方。
- **仕様との一致:** 仕様書と実装の食い違い。どちらが正しいかを判断して直す。判断できなければ仕様書に `> 未決:` と書く。
- **テスト:** 振る舞いに対してテストが無いところ、許容誤差の無い浮動小数点の比較、時刻や順序に依存して不安定なテスト、何も確かめていないテスト。
- **API:** 公開の範囲が広すぎないか、doc コメントの有無と正しさ、名前の一貫性、引数の型 (bool の並び・単位の取り違え)。
- **重複と不要なコード:** ほかのクレートやファイルとの重複、使われていない関数・型・依存、古くなった TODO とコメント。
- **性能:** 毎フレームの処理での確保・複製・線形探索 (ランタイムの目標は 1 体 1ms。roadmap.md の M7)、不要な再計算。

### M9 で繰り返し見つかった誤り

M9 の 32 のレビューで、複数の場所に同じ形で見つかったもの (詳しくは下の「M9 の結果」)。上の観点のうち、特にこれらを確かめる。

- **NaN と無限大の通り道:** `if x <= 0.0 { return }` は NaN を通す。弾くなら `!(x > 0.0 && x.is_finite())` か `is_nan() || x <= 0.0` と書く。
  `f32::max`・`min` は NaN を捨て、`clamp` は残す。重みや強さは NaN だけでなく無限大も拒む (`0 × ∞` と `∞ − ∞` が NaN になる)。
  ホストから来る数の前提は下の層 (`Puppet`・`ugoe-runtime`) で決め、上の層 (C ABI・wasm・バインディング) は表し方だけを持つ (T0010)。
- **時間を消費するループと時間の累積:** `while t > len { t -= len }` 型のループは、巨大な `dt` や極端に短い長さで f32 の桁落ちにより止まらない。回数に上限を持たせる。
  何日も動く処理の `elapsed += dt` は `f64` か周期での折り返しにする。
- **外から来た数での確保と積:** 見出し・宣言・モデルの番号の大きさで確保する前に上限を確かめる。格子の大きさや画素の数の積は `checked_mul`・`saturating_mul`
  か `usize` で求める (wasm32 の `usize` は 32 ビット)。`f32` から整数への `as` は飽和するので、その後の `+ 1`・`* 2` があふれる。
- **外から来た文字列をバイトの位置で切る:** 文字の境界を確かめる (`trim` は全角の空白も除く)。外部のエラーの本文を文言に入れるときは長さを制限する。
- **同じ処理の写し:** 検証・デコード・寿命の管理を 2 か所に写すと、片方だけが直る。写す前に共有の置き場所を探し、無ければ起票する。
- **大文字小文字を区別しないファイルシステム:** 「書いた後に、今回書かなかったファイルを消す」処理は、大文字小文字だけが違う名前を同じファイルとして消しうる (CI は Linux だけ)。
- **テストの時間と資源:** 固定のポート・プロセス ID だけの一時ディレクトリ・重い動的 import の `beforeAll` は、並行の `just ci` で不安定になる。

| 対象 | 特に見ること |
| --- | --- |

| ネットワーク (`ugoe-ai`・`ugoe-mcp`・スタジオの API) | 認証とトークン、ループバック限定、タイムアウトと再試行、秘密がログに出ないか、転送 (3xx) で独自のヘッダの秘密が別のホストへ行かないか、応答の本文の上限、接続の数え方が panic で戻らない形でないか |
| Svelte のフロントエンド | Svelte 5 の runes の使い方 (`$effect` の後片付け・無限の更新・`$derived` で足りる `$effect`・作り直すオブジェクトや `$state.snapshot` が思わぬ依存になる `$effect`)、イベントの解除、`await` をまたぐ開始と停止・読み直しの後勝ち (世代の番号で確かめる)、`pointercancel`、`svelte:window` のショートカットがダイアログの中で効かないか、`Math.min(...配列)` などの引数の数の上限、IPC の型と `ipc.ts` の同期、直書きの文言 (i18n。例外の文も)、`@ugoe/ui` で置き換えられる自前の部品 |

| Tauri のバックエンド | コマンドに編集のロジックが無いか (`Command` を通す)、ファイルの許可の範囲 (CSP・ウィンドウごとのコマンドの許可)、ファイルを読み書きするコマンドが `async` か (同期のコマンドはメインのスレッドで動く)、保存が一時ファイルを経るか、エラーをコードで返しているか |

## 所見の扱い

| 重大度 | 例 |
| --- | --- |
| 高 | 誤った結果・クラッシュ・データの損失・セキュリティの穴・規約の違反 (依存方向・`unsafe`・`Command` を通さない編集) |
| 中 | 珍しい入力での誤り、テストの穴、仕様との食い違い、性能の問題、分かりにくいエラー |
| 低 | 読みにくさ、重複、doc コメントの不足、名前 |

- **このタスクで直す:** タスクの `crates:` の中で完結し、公開 API と設計を変えないもの。バグを直すときは、先に失敗するテストを書く。
- **起票する:** 公開 API の変更、設計の判断、範囲の外の変更、半日を超える修正。分野の番号帯で新しいタスクを起票し (milestone は M9)、メモから ID で参照する。
  `ugoe-core`・`ugoe-model` の公開 API の変更は、インターフェースを先に入れる小さなタスクにする ([multi-agent.md](multi-agent.md))。
- **やらないこと:** 好みだけの書き換え、整形だけの変更、大きな作り直し (必要なら起票して利用者に相談する)。UI の見た目と配置は M10 で扱う。

## 記録の形

タスクファイルの「メモ」に次の表を書きます。直したものも、起票したものも、見送ったもの (理由つき) もすべて書きます。

```markdown
| 重大度 | 場所 | 内容 | 対応 |
| --- | --- | --- | --- |
| 高 | `src/bundle.rs:120` | 展開後の大きさを確かめずに確保する | 直した (上限を足し、テストを追加) |
| 中 | `src/lib.rs` | 公開の `foo` が仕様の名前と違う | T0140 を起票 |
| 低 | `src/util.rs` | `bar` と `ugoe-runtime` の `baz` が重複 | 見送り (ランタイム層からツール層へは寄せられない) |
```

最後に、横断の所見 (ほかのクレートにもありそうなこと) を「横断」として書きます。T0008 がまとめて扱います。

## M9 の結果

32 のレビュー (T0136〜T0914) で、所見は高 36・中 176・低 284 (各タスクの所見の表の行の数)。高はすべてそのタスクで直したか、後続のタスクで直した
(目パチの無限ループは T0317、`follow` の無限大は T0139・T0424)。読み込み・入口・時間のループで、細工した入力や極端な値でパニック・無限ループ・巨大な確保に
なるものが多かった。後続のタスクの一覧と M9 の完了の判断は [roadmap.md](../roadmap.md#m9-コードレビュー-)。まとめは T0008 が行った。
