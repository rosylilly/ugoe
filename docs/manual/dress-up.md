# 着せ替え

着せ替えは、衣装・髪型・アクセサリーを **モジュール** として本体のモデルとは別に作り、アプリの中で付け外しする仕組みです。
1 つのモデルに衣装を全部入れる代わりに、衣装ごとに別のファイル (`.ugoemod`) にして、あとから増やしたり配ったりできます。
仕組みの詳しい約束は [着せ替えモジュール仕様](../spec/modules.md)、設計の判断は [ADR 0024](../adr/0024-module-authoring.md) にあります。

## 全体の流れ

| 段階 | どこで | 内容 | 状態 |
| --- | --- | --- | --- |
| 1. 本体にスロットを作る | 本体のプロジェクトの「Slots」タブ | 衣装を付ける場所 (取り付け先・描画順の範囲・隠す部分・使ってよいパラメータ) を決める | [使える](#スロットを作る) |
| 2. 衣装を作る | モジュールのプロジェクト | 本体を下敷きにして、衣装の PSD を取り込み、メッシュとリギングを作り、`.ugoemod` に書き出す | [使える](#衣装を作る) |
| 3. 試す | 本体のプロジェクトのプレビュー | `.ugoemod` を読み込んで付け外しし、動きと前後関係を確かめる | [使える](#プレビューで試す) |
| 4. 使う | ビューア | `.ugoe` に `.ugoemod` を付け外しする | [使える](#ビューアで付け外しする) |

すぐに試すには、ビューアの「サンプル」→「着せ替え」で見本の本体と衣装を開きます ([見本で試す](#見本で試す))。
エディタでは、同じ見本をプロジェクトとして開けます ([見本のプロジェクトを開く](#見本のプロジェクトを開く))。

モジュールはスロットの **名前** だけで取り付け先を指定します。本体のスロットの名前を後から変えると、その名前を指していた
モジュールは付けられなくなるので、配った後は名前を変えないでください。

## スロットを作る

スロットは、モジュールを取り付ける場所です。髪なら `Hair`、衣装なら `Outfit`、帽子なら `HeadAccessory` のように、
取り付けるものの種類ごとに 1 つ作ります。1 つのスロットには、同時に 1 つのモジュールが付きます。

1. 右の列の上の「Slots」タブを押す。
2. 「+ Slot」を押す。空いている描画順の範囲 (手前の方) に、`Slot` という名前のスロットができて選ばれる。
3. 「Name」をスロットの名前 (例: `Hair`) に変えて、Tab キーで離れる。使える文字は英数字と `_` だけ。
4. 下の表のとおりに各項目を決める。欄を離れるか、チェックを変えるたびに反映される。1 回の変更が、1 回の Ctrl+Z で戻る。

![スロットの編集](images/slots.png)

| 項目 | 内容 |
| --- | --- |
| 「Attach to」 | モジュールが一緒に動くデフォーマ (髪なら頭の回転、衣装なら体のワープ)。モジュールの最上位のメッシュとデフォーマは、このデフォーマの中に置かれる。「Canvas」ならどれにも付かない |
| 「Parent part」 | モジュールのパーツの親にする本体のパーツ。このパーツをポーズやモーションで隠すと、モジュールも一緒に隠れる。「None」なら親なし |
| 「Draw order」 | モジュールのメッシュを描く描画順の範囲 (下の [描画順の範囲を決める](#描画順の範囲を決める))。ほかのスロットの範囲と重ねられない |
| 「Replaces」 | モジュールを付けている間、隠す本体のパーツ (例: 最初から描いてある髪) |
| 「Parameters」 | モジュールが動きに使ってよい、本体の独自のパラメータ。`AngleX` や `EyeLOpen` などの標準パラメータは、選ばなくても使える |
| 「Mask sources」 | モジュールがマスク (クリッピング) に使ってよい本体のメッシュ (例: 前髪を顔の中に収めるための顔) |
| 「Colliders」 | モジュールの物理が当たってよい本体の衝突体 (例: 長い髪が首に掛かるように首の衝突体)。衝突体は「Physics」タブで作る ([物理](physics.md)) |
| 「Pose parts」 | モジュールのパーツが追従してよい、本体のポーズのパーツ (例: 腕の差分 A / B に合わせて袖の差分 A / B を切り替える) |
| 「Show to apps」 | アバタープロファイルの「アプリに見せるスロット」に入れる。入れていないスロットは作者用で、アプリは利用者に見せない。アバタープロファイルがないと選べない ([アバタープロファイル](avatar.md)) |

各項目の下に、何のための設定かの短い説明が出ます。「Replaces」などの一覧の項目は、見出しを押すと開きます。
見出しの右に、選んでいるものが出ます (何もなければ `none`)。

一覧の行の右に `app` と出ているスロットはアプリに見せるもの、`overlap` と出ているスロットはほかのスロットと
描画順の範囲が重なっているもの (古いファイルなど) です。重なりは範囲を狭めて直してください。

「Remove slot」でスロットを消します。アプリに見せるスロットからも外れます (Ctrl+Z で戻せます)。

### 描画順の範囲を決める

モジュールのメッシュの描画順 (0〜1000) は、スロットの「Draw order」の範囲に縮めて写されます。
そのため、モジュールは **範囲より上 (手前) の本体のメッシュより奥、範囲より下 (奥) の本体のメッシュより手前** に描かれます。
範囲の中に描画順がある本体のメッシュとは、モジュールのメッシュと前後が入り組みます。

パネルの下の「Draw order」に、本体のメッシュが手前から奥の順 (パラメータが既定値のとき) に並び、スロットの範囲の手前の端
(`front end ▼`) と奥の端 (`back end ▲`) の行が差し込まれます。選んでいるスロットの範囲の中のメッシュは色が付きます。
行を押すと、そのメッシュが選ばれてビューポートで枠が出ます。

![描画順と範囲](images/slots-draw-order.png)

範囲の決め方の例:

- 前髪のモジュールを顔より手前・横の髪より奥に描くなら、範囲を顔の描画順と横の髪の描画順の間に取る。
- 本体の既定の髪と入れ替えるなら、既定の髪のパーツを「Replaces」に入れ、範囲を既定の髪のメッシュの前後に取る。
- 範囲の端が接するだけ (`300〜400` と `400〜500`) は重なりとみなしません。

「Select meshes in range」を押すと、選んでいるスロットの範囲に入る本体のメッシュがまとめて選ばれ、ビューポートで確かめられます。

### うまくいかないとき

| 出るメッセージ | 理由と対処 |
| --- | --- |
| `` slot `Outfit`: draw order 140..950 overlaps slot `Hair` (940..980) `` | 範囲がほかのスロットと重なる。重ならない範囲にする |
| `Slot names may use only letters, digits and _` | 名前に英数字と `_` 以外の文字がある |
| `` slot `Hair` already exists `` | 同じ名前のスロットがある |
| `` deformer `HeadRotation` still has children: …, slot `Hair` `` | スロットの取り付け先のデフォーマは消せない。先にスロットの「Attach to」を変える (「Parent part」のパーツも同じ) |

パラメータ・メッシュ・パーツ・衝突体を消すと、スロットの一覧の項目 (「Parameters」「Mask sources」「Replaces」など) からも外れます。

## 衣装を作る

衣装は、本体を参照する **モジュールのプロジェクト** で作ります。本体は下敷きとして表示され、衣装と重ねた姿を見ながら作れます。
本体はこのプロジェクトの中では変えられません (本体を直すときは本体のプロジェクトを開きます)。

### 新しいモジュールを作る

1. 本体のプロジェクトにスロットを作って保存しておく ([スロットを作る](#スロットを作る))。`.ugoe` に書き出したものも本体に使えます。
2. ファイルメニューの「New Module…」を押す。
3. 「Project folder…」で本体の `.ugoeproj` フォルダーを、または「.ugoe file…」で本体の `.ugoe` を選ぶ。本体のスロットが一覧に出る。
4. 衣装を付けるスロットを選び、「Module name」を決めて (最初はスロットの名前)「Create」を押す。

![新しいモジュール](images/module-new.png)

「What you can do in a module project」を開くと、モジュールのプロジェクトでできること (衣装の要素・PSD の取り込み・メッシュ・
キーフォーム・衣装の物理・AI のリギングの提案) と、本体のプロジェクトで直すこと (本体の要素・パラメータ・アバタープロファイル・スロット・エフェクト・
ライティングと物理の全体の設定、パラメータを足すこと、モーションと表情) が出ます。

モジュールの名前は、本体に付けたときの要素の名前の頭に付きます (`CatEars/band` のように)。`/` を含む名前と `#` で始まる名前は使えません。
同じ本体に同時に付けるモジュールどうしは、名前を変えておきます。

### 見本のプロジェクトを開く

着せ替えの見本 (ビューアの「サンプル」→「着せ替え」と同じもの) を、本体とモジュールのプロジェクトとして開けます。
スロットの作り方とモジュールのプロジェクトの組み方の例として、エディタで開いて中を見られます。

ファイルメニューの「Open Sample…」を押し、見本を置く場所のフォルダーを選びます。その中に新しいフォルダー
`ugoe-dress-up-sample` (もうあれば `ugoe-dress-up-sample-2` など。前に書き出して編集した見本は上書きしません) を作って次のプロジェクトを書き、
本体を開きます。モジュールのプロジェクトは、隣の本体 `../dress-up.ugoeproj` を参照します。

| プロジェクト | 開くと |
| --- | --- |
| `dress-up.ugoeproj` | 本体。「Slots」タブにスロット `Hair`・`Headwear`・`Outfit` があり、3 つとも「Show to apps」が入っている (本体はアバタープロファイルのレベル 2 を名乗る)。物理のタブには既定の後ろ髪を揺らすリグ `HairSway` がある。モーション (`idle`・`nod`・`shake`・`tilt`) と表情 (`smile`・`surprised`・`sad`) も入っている |
| `long-hair.ugoeproj` | スロット `Hair` のモジュール `LongHair`。後ろ髪は回転デフォーマ `Sway` と物理で揺れ、本体の肌を反転マスクに使う |
| `twin-tails.ugoeproj` | スロット `Hair` のモジュール `TwinTails`。房が結び目を軸に揺れ、内側へ振れると本体の肩の衝突体 `Shoulders` に当たる |
| `cat-ears.ugoeproj` | スロット `Headwear` のモジュール `CatEars` |
| `sailor.ugoeproj` | スロット `Outfit` のモジュール `Sailor`。体のワープに付き、本体のシャツを置き換える |

モジュールのプロジェクトは、続けて「Open…」で開きます (ダイアログは見本のフォルダーから始まります)。モジュールのプロジェクトを開くと本体が下敷きに出て、
本体のパラメータで一緒に動きます。物理のタブには本体のリグ `HairSway` も並びます (モジュールでは動かせない行。
下の「[衣装を組む](#衣装を組む)」の、リグの順番の ▲▼ やテンプレートの制限を試せます)。「Export Module…」で書き出すと、ビューアの見本と同じ `.ugoemod` になります。
中身の詳しい説明は [assets/samples/README.md](../../assets/samples/README.md#dress-up) にあります。

コマンドラインで書き出すこともできます (リポジトリのルートで):

```sh
just cli sample dress-up -o /tmp/dress-up --project /tmp/dress-up/projects
```

### 衣装を組む

作ったモジュールのプロジェクトでは、ファイルメニューの名前の横に `Module: <スロット>` と出ます。印に指を置くと本体の場所と、
できること・できないことが出ます。印を押すと [モジュールの設定](#モジュールの設定を変える) が開きます。

1. 「Import PSD…」で衣装の PSD を取り込む。本体と同じ大きさのキャンバスで描いた PSD なら、描いた位置に重なります。
   取り込んだメッシュは、見た目を保ったままスロットの取り付け先 (「Attach to」のデフォーマ) の中に入り、描画順はスロットの範囲に収まります。
2. 本体のパラメータのスライダーを動かして、衣装が一緒に動くか確かめる。取り付け先のデフォーマの動きには自動で付いてきます。
3. 衣装だけの動き (揺れ・変形) は、本体のプロジェクトと同じ方法で作る: 自動メッシュとメッシュの編集、デフォーマ、キーフォーム、推定とミラー、物理。
   AI タブの「Propose rig」で、下の「AI に衣装のリグを提案させる」の提案を作ることもできます。

![本体を下敷きにした衣装](images/module-workspace.png)

左のツリーでは、本体の要素に `base` の印が付いて薄く表示されます。本体の要素は選んで確かめられますが、編集はできません。

- 本体の要素を選ぶと、インスペクタの欄が薄くなって押せなくなり、「This belongs to the base model and can't be edited here. Edit it in the
  base project.」と出ます。ビューポートでは選択の枠が灰色の破線になり、形を変えるツール (フォームの編集・ギズモ・「Edit mesh」) は出ません。
- ビューポートの上の「Module outline」を入れておくと (最初から入っています)、衣装のメッシュすべての輪郭が点線で重なり、本体と見分けられます。
- 本体のものは、ほかの画面でも変えられません: パラメータの「+」と定義の編集、アバタープロファイル、「Slots」タブ、「Physics」の World と
  本体のリグ・衝突体、「Lighting」のモデル全体の設定と本体のテクスチャの法線マップ。パラメータのスライダーは動かせます。
- 「Lighting」の「Lit meshes」では、本体のメッシュに `base` の印が付いて押せません。「All on」「All off」は衣装のメッシュだけを変えます。
- 「Physics」のリグの一覧では、衣装のリグは本体のリグの後に動くので、▲▼ は衣装のリグどうしでだけ使えます。「Templates」では、
  「Create missing parameters」が押せず (モジュールはパラメータを足せません)、「Neck」には衣装の回転デフォーマだけが出ます。
  本体にない中継パラメータ `BodyBounce` を作る「+ Bounce」は、本体にそのパラメータがなければ使えません。
- 要素の名前やテクスチャの名前には、本体に付けたときに付く `<モジュールの名前>/` を出しません。

### AI に衣装のリグを提案させる

モジュールのプロジェクトでも、右の列の「AI」タブで提案を作れます ([AI でリギングを提案する](ai.md) と同じ操作)。見出しが
「Auto rig the costume from PSD」になり、提案の中身が衣装向けになります。**パラメータは足さず、本体も変えません。**

1. 「Import PSD…」で衣装の PSD を取り込んでおく (取り込んだ PSD が分類の元になります)。
2. 「AI」タブで「Propose rig」を押す。レイヤーを分類し (`headwear`・`earwear`・`bottomwear` など)、次の提案を作ります。
   - **追従:** 取り付け先の下にある本体のワープ (顔の向きのワープなど) のうち、衣装を覆うものの動きを写したワープ (`Follow…`) で衣装を包みます。
     たとえば取り付け先が頭の回転のデフォーマなら、帽子は頭の傾きに加えて、顔の振り向き (`AngleX`・`AngleY`) にも付いていきます。
   - **本体の絵の形の変化への追従:** 目の開閉のように、本体のメッシュそのものが形を変える部分に重なる衣装 (アイシャドウ・化粧など) は、
     その形の変化に付いていきます (目を閉じると一緒に潰れる)。顔の振り向きと目の開閉のように両方が動くときも、合わせて付いていきます。
     帽子・眼鏡・耳飾り・髪・服は付いていきません。
   - **揺れ:** 髪・尻尾 (`tail`)・耳飾り (`earwear`)・首の飾り (`neckwear`)・スカート (`bottomwear`) のラベルの衣装は、振り子の物理で揺れます
     (頭か体を振ると遅れて揺れる)。帽子や上の服は揺らしません。本体がスロットで衝突体を公開していれば、揺れる衣装はそれに当たって
     体にめり込みません (最初から当たっている衝突体は使いません。提案の理由に出ます)。
   - **差分のポーズ:** 名前の末尾の A / B だけが違う衣装 (`Sleeve A` と `Sleeve B`、`ribbon_a` と `ribbon_b` など) は、1 つだけを表示する
     ポーズになります。本体に同じ文字の差分 (腕の A / B など) があり、スロットがそれを公開していて絵が重なれば、本体の差分と一緒に切り替わります。
     名前がばらばらでも、同じ種類 (レイヤーの分類が同じ) で同じ所に重なり、PSD で 1 つだけを見せて残りを隠してある衣装 (見せている「帽子」と
     隠してある「キャップ」など) も差分とみなし、見せていたものを最初に表示するポーズにします。すべて見せている重なった絵 (影など) はポーズにしません。
     AI でレイヤーを分類すると、AI が同じ部品の別の絵とみなしたもの (形や位置が違う帽子とベレー帽など) もポーズにします。分類の結果の
     「Labels」を開くと、「Alternative drawings of the same part」に組が並びます。
     名前以外で見つけた差分も、本体の差分をスロットが公開していれば、見せている衣装は本体で最初に表示される差分に、隠してある衣装は
     重なる本体の差分に付いて一緒に切り替わります。名前で見つけた差分の文字が本体の差分の名前と合わないとき (本体は「Arm Up」と
     「Arm Down」など) も、PSD で 1 つだけを見せていれば同じように付きます。
3. 「Preview」で本体のパラメータを動かして確かめ、「Adopt」で採用する (1 回の Undo で戻ります)。プレビュー中に「Run physics」を押すと
   物理が動き、スライダーを動かして揺れ方を確かめられます。

「How to rig」の欄で組み方を選べます (AI には送りません)。

| 欄 | 内容 |
| --- | --- |
| 「Follow the base warps exactly」 | 切ると (最初)、衣装を追従のワープで包みます。衣装を描き足しても組み直さずに済みますが、振り向きで少しずれます。入れると、本体のワープの動きを衣装のメッシュに直接書き込み、ずれません。メッシュの頂点を編集したら提案し直してください (下の知らせが出ます) |
| 「Keep swaying parts out of the base's colliders」 | 揺れる衣装を本体の衝突体に当てます (最初から入) |
| 「Turn A / B variants into poses」 | 衣装の差分をポーズにします (最初から入) |

- AI を使うと、揺れの大きさと振り子の長さを衣装の絵から決めます。注文 (「耳飾りをもっと揺らして」など) も添えられます。
  パラメータを足すような注文は「Not applied」として示されます。
- 取り付け先の下に衣装を覆う本体のワープも形の変わる本体の絵もなく、揺れるラベルの衣装も差分もなければ、「nothing to rig」と出ます。
  衣装は取り付け先の動きだけに従います。
- スロットが公開していない本体のパラメータ (標準パラメータ以外) には従いません。提案の理由に出ます。
- 採用した提案が本体の動きを書き込んだ衣装のメッシュの頂点・三角形を後から編集すると、「AI」タブの上に「Propose the rig again」と
  そのメッシュの名前が出て、タブに印が付きます。そのメッシュを選ぶと、インスペクタの上にも同じ知らせと「Open AI tab」が出ます。
  もう一度「Propose rig」して採用し直してください。今の形のままでよければ「Dismiss」で消せます。知らせはプロジェクトに保存され、
  開き直しても出ます。

### ポーズを手で編集する

右の列の「Poses」タブで、ポーズ (1 つだけを表示する差分の組) を手で作り、直せます。

- 「+ Group」で新しいグループを作り、「+ Entry」で差分を足します。ツリーで 2 つ以上のパーツを選んで「+ Group from selection」でも作れます。
  先頭の差分 (「first」) が最初に表示されます。差分をドラッグするか ▲▼ で並べ替え、✕ で外します。
- 「Show the pose in the viewport」を入れると、ビューポートでグループごとに 1 つの差分だけが見えます (アプリでの見え方)。差分の「Show」で
  見せる差分を切り替えて確かめられます。モデルは変わりません。タブを離れると元の (すべて見える) 表示に戻ります。
  プレビューの右の列の「Pose」の節でも、グループごとに見せる差分を選べます ([プレビュー](preview.md#ランタイム-runtime)。
  モジュールのプロジェクトでは、いまの編集を付けて比べている間も選べます)。
- 「Links」で、差分と一緒に切り替わるパーツ (袖など) を選びます。
- モジュールのプロジェクトでは、本体のグループ (「base」の印) は変えられません。スロットの「Pose parts」で本体が公開した差分にだけ、
  衣装のパーツを「Links」で追従させられます (腕の A / B に袖の A / B を付けるなど)。衣装だけのグループは自由に作れます。

### グルーで継ぎ目をつなぐ

右の列の「Glue」タブで、2 つのメッシュの頂点を引き寄せるグルーを作り、直せます。袖と腕の境目のように、動くと隙間が開く継ぎ目に使います。

- 「New glue」で Mesh A と Mesh B を選び、「Distance (px)」(基準の姿で、この距離より近い頂点どうしをつなぐ) を決めて「+ Glue」を押します。
  ツリーで 2 つのメッシュを選んでおくと、それが最初から入っています。近い頂点が 1 つも無いと、パネルの上に理由が出ます。
- 一覧のグルーを押すと、下に編集の欄が出ます。「Weight」は寄せる先 (0 で A に、1 で B に、0.5 で真ん中)、「Intensity」は引き寄せる強さ
  (1 で完全に重なる)。「Swap」で A と B を入れ替え (見た目は同じ)、「Pair again within … px」で頂点の組を作り直し、「Remove glue」で消します。
  「Select meshes」で両端のメッシュをツリーで選べます。
- 強さをパラメータで変えるには、編集の欄のパラメータとキーを選んで「+ Axis」を押します (例: 腕を下ろした角度で 0)。軸ごとに「+ Key」で
  キーを足し、「×」で外します。キーごとに「AngleX = 30」のような強さの欄が並ぶので、それぞれの強さを入れます。
- 選んだグルーの頂点の組は、ビューポートに線で重なります (A のメッシュは緑、B のメッシュは紫の破線)。ビューポートの下の「Add pairs」を
  押して A と B の頂点を 1 つずつ押すと組が増え、「Remove pairs」を押して組の線の中の四角を押すとその組が外れます (Esc で終わる)。
  B の頂点は 1 つの A の頂点とだけ組むので、同じ B の頂点を組み直すと前の組が置き換わります。組んだ頂点はグルーで引き寄せられて
  重なって見えるので、新しく組むのはまだ組んでいない頂点 (中が白い丸) です。どれも Undo で戻せます。
- モジュールのプロジェクトでは、本体のグルー (「base」の印) は変えられず、つなげるのは衣装のメッシュどうしだけです。描画用の複製のグルー
  (「clone」の印) は、インスペクタの「Sync」で作り直してください。

![Glue タブ。衣装の Back と Front をつなぐグルーを作り、重みを 0.25 にした](images/module-glue.png)

![ビューポートに重なったグルーの組。「Add pairs」で A の頂点を押し、B の頂点を待っている](images/module-glue-pairs.png)

![本体の要素を選んだところ。インスペクタが無効になり、ビューポートに「Base model」と出る](images/module-base-readonly.png)

それでも本体を変える操作をすると、`… belongs to the base model and can't be edited here. Edit it in the base project` と出て、何も変わりません。

キーフォームに使えるパラメータは、`AngleX` などの標準パラメータと、スロットの「Parameters」で本体が公開したものだけです。
それ以外の本体のパラメータもスライダーで動かせますが、キーフォームに使うと書き出しのときにエラーになります。

### モジュールの設定を変える

ファイルメニューの `Module: <スロット>` の印を押すと「Module settings」が開きます。「Apply」で反映し、Ctrl+Z で戻せます。

![モジュールの設定](images/module-settings.png)

| 欄 | 内容 |
| --- | --- |
| 「Module name」 | モジュールの名前。本体に付けたときの要素の ID の頭 (`<名前>/…`) になる。同じ本体に同時に付けるモジュールどうしは違う名前にする |
| 「Slot」 | 付けるスロット。描画順はそのスロットの範囲に写し直される。取り付け先 (「on …」) の違うスロットに移すときは「Keep where it appears」(最初から入) で、衣装がいま見えている場所のまま新しい取り付け先に移る。外すと、衣装の位置は取り付け先からの位置のままなので、見た目の場所が変わる |
| 「Requires」 | アプリがモジュールを付けるときに本体に求める条件: アバタープロファイルのレベル、ほかのスロット、パラメータ。本体が持つものから選ぶ |

本体がそのスロットや条件を満たさないとき (移したスロットがマスクや使っているパラメータを公開していないなど) は、理由が出て何も変わりません。

![取り付け先の違うスロットへ移す。「Keep where it appears」で見た目の場所を保つ](images/module-keep-look.png)

- 「Keep where it appears」は、衣装の一番外側のメッシュとデフォーマを、新しい取り付け先から見た位置に置き直します。パラメータが
  既定の値のときの見た目が同じになります。たとえば頭 (HeadWarp) に付けた猫耳を服 (BodyWarp) のスロットに移しても、耳は頭の上に残ります
  (その後は体と一緒に動きます)。
- 衣装の物理の衝突体のうち、取り付け先に付けたもの (「Physics」で取り付け先を選んで作ったもの) も、いまの位置のまま新しい取り付け先に
  置き直します。揺れもの (リグ) の根元は衣装のデフォーマに付いているので、デフォーマと一緒にそのまま残ります。
  パラメータを動かしたときの揺れ方は新しい取り付け先に合わせて変わるので、移した後に「Preview」で確かめます。

### 本体を変えたとき

モジュールのプロジェクトを開いている間に本体のファイルが変わると (本体のプロジェクトを別のウィンドウで保存したなど)、
「The base model changed」と出ます。

- 「Reload the base」で新しい本体を下敷きにします。衣装の編集は、保存していないものも残ります (Undo の履歴は消えます)。
- 「Later」でそのまま続けます (同じ変更についてはもう尋ねません)。
- 「Reload automatically」を入れると、次からは尋ねずに読み直し、ファイルメニューの横に「Reloaded the base model: it was changed outside
  the editor」と出ます。プロジェクトの外での書き換え ([外でプロジェクトが書き換えられたとき](screen.md#外でプロジェクトが書き換えられたとき)) の「Reload automatically」と同じ設定です
  (プロジェクト自体は、保存していない変更がないときだけ自動で読み直します)。
- 新しい本体に衣装が合わなくなったとき (スロットを消した・名前を変えたなど) は、何も変わらず、下の「本体の問題」の枠が出ます。
- 本体のファイルを動かした・消したときは「The base model is gone」と出ます。「Locate base project…」か「Locate base .ugoe…」で
  新しい場所の本体を選ぶと、開き直さずに下敷きが替わります (保存していない編集は残ります。保存すると新しい場所を覚えます)。

### 保存と書き出し

- 「Save」「Save As…」で `.ugoeproj` に保存します。保存するのは衣装の部分 (`module.json` と衣装の画像) だけで、本体は保存しません。
  本体の場所は、プロジェクトからの相対パスで覚えます。本体とモジュールのプロジェクトは、同じ親のフォルダーの中に置いておくと動かしやすくなります。
- 「Export Module…」で書き出しの欄を開き、「Export .ugoemod…」で `.ugoemod` に書き出します。書き出す前に、モジュールだけでの検査と、
  本体に付けたときの検査を行います。描画順がスロットの範囲からはみ出したメッシュがあれば、書き出した後に警告が出ます。
- 欄の「Pack textures into atlases」を入れると、衣装のテクスチャを 1 枚 (大きければ数枚) のアトラスにまとめて書き出します。本体に付けたときの
  描画の回数が減ります。設定はプロジェクトに残ります。書き出した後、欄の下にファイルの大きさとまとめた枚数が出ます。

  ![Export Module… の欄でアトラス化を選んで書き出す](images/module-export-atlas.png)

### うまくいかないとき

本体の問題で開けないとき (または本体を読み直せないとき) は、画面の上に何が起きたかと直し方の枠が出ます。

![本体の問題と直し方](images/module-problem.png)

| 枠の説明 | 理由と直し方 |
| --- | --- |
| `The base model "…" is not where this module expects it` | 本体が見つからない (動かした・名前を変えた)。「Locate base project…」か「Locate base .ugoe…」で本体を選び直し、保存する |
| `The base model "…" can't be read` | 本体が壊れている、またはモジュールのプロジェクトを選んだ。本体を選び直す |
| `The base model "…" no longer has slot "…"` | 本体からスロットがなくなった (名前を変えた)。一覧からスロットを選んで「Use this slot」で開き (保存すると覚える)、または「Open base project」で本体を開いてスロットを戻す |
| `This module no longer fits the base model "…"` | 本体はあるが衣装が合わない (公開していたパラメータ・マスクを外したなど)。「Open base project」で本体を直すか、本体を選び直す。「Details」に元のメッセージが出る |
| `A physics rig of this module collides with a collider that slot "…" exposes, but the base model "…" has no physics` | 衣装の揺れものが、スロットの「Colliders」で公開した本体の衝突体に当たるが、本体に物理が無い (物理を消した本体・物理を含まない `.ugoe` など)。物理 (その衝突体を含むもの) のある本体を選び直すか、「Open base project」で本体の物理を戻して保存し、衣装を開き直す。「Details」に衝突体とリグの名前が出る。衣装に当たる衝突体が無いときは、「Physics」タブの「Colliders」にも同じ案内が出る。本体を直さずに開くなら「Open without these colliders…」: 外す当たり (リグ → 衝突体) が並ぶので、「Remove and open」で揺れものからその当たりを外して開く (保存するまでファイルは変わらない) |

![揺れものの当たりを外して開く前に、外すものを確かめる](images/module-problem-drop.png)

説明の中の本体のファイル名は `"…"` で囲んで出ます。本体を選び直してもスロットがないときは、その本体についての説明に替わり、続けてスロットを選べます。
開いているモジュールの本体を読み直せなかったとき (本体を外で変えた・動かした) の選び直しと「Use this slot」は、開き直さずに下敷きを替えるので、
保存していない編集も残ります (保存すると新しい本体とスロットを覚えます)。

| 出るメッセージ | 理由と対処 |
| --- | --- |
| `… belongs to the base model and can't be edited here. Edit it in the base project` | 本体の要素を変えようとした。本体のプロジェクトを開いて直す |
| `` mesh `…` refers to the base part `…` `` など | 衣装の要素を本体のパーツ・デフォーマ・テクスチャにつなごうとした。衣装の要素は衣装のパーツに入れ、スロットの取り付け先の中に置く |
| `` parts `Hat/Brim` and `Brim` would both be `Brim` in the module; rename one `` | 読み込んだ要素と新しい要素の名前が、頭の `<モジュールの名前>/` を除くと同じになる。新しい要素の名前を変える |
| `` module `…`: parameter `…` is not exposed by slot `…` `` (書き出し) | 本体が公開していないパラメータをキーフォームに使った。本体のスロットの「Parameters」に入れるか、キーフォームから外す |
| `` module `…`: mesh `…` masks with `…`, which is not available `` (書き出し) | 本体がスロットの「Mask sources」で公開していないメッシュでマスクした |

本体を変えたときは、[本体を変えたとき](#本体を変えたとき) のとおり、読み直すと新しい本体が下敷きになります。

## プレビューで試す

本体のプロジェクトのプレビューで `.ugoemod` を読み込み、付けたり外したりして、動き・前後関係・隠れる部分を確かめます。
**モデルは変わりません** (Undo の履歴にも残りません)。

![プレビューの着せ替え。髪の LongHair と服の Dress を付けている](images/dress-up-preview.png)

1. ヘッダーの「Preview」を押してプレビューに入る ([プレビュー](preview.md))。右のパネルに「Dress-up」の節が出ます。
2. 「Load .ugoemod…」を押してモジュールのファイルを選ぶ。または、`.ugoemod` のファイルをエディタのウィンドウにドロップする
   (いくつでもまとめて入れられます)。
   読み込むとすぐに付きます。同じスロットにほかのモジュールが付いていれば、差し替わります。
3. 付け替えるときは、「Slots」のスロットの欄でモジュールを選ぶ。「(none)」で外します。
   「Modules」の行のチェックボックスでも付け外しできます。
4. スライダー・フェイストラッキング・モーション・表情で動かして確かめる。付け外ししても、スライダーの値やトラッキングは
   そのまま続きます (物理の揺れだけ止まり、今の姿から始まり直します)。

| 欄 | 内容 |
| --- | --- |
| 「Slots」 | 本体のスロットと、いま付いているモジュール。欄には、そのスロットに付けるモジュールのうち読み込んだものが出る。読み込んだものが無ければ「(no module)」。アバタープロファイルの「Show to apps」に入れていないスロットには `authors only` と出る (ビューアなどのアプリでは利用者に見えない。ここでは試せる) |
| 「Modules」 | 読み込んだモジュール。右にそのモジュールの付くスロット (`→ Hair`) が出る |
| 「↻」 | ファイルから読み直す。モジュールを書き出し直したら押す (付いていれば新しい版に付け替わる) |
| 「✕」 | 外して一覧から除く |

- 読み込んだモジュールの一覧 (と、付けていたか) はプロジェクトに残り、次に開いたときも同じものを読み込みます
  (ヘッダーの保存の印が付くので、残すなら保存します)。プレビューに入るたびにファイルから読み直すので、書き出し直した
  モジュールはそのまま新しい版で試せます。本体の `.ugoeproj` と同じフォルダに置いたモジュールは、フォルダごと移しても読めます。
- プレビューを出ると、編集の画面は本体だけに戻ります。次に入るとまた付きます。
- スロットの設定 (範囲・Replaces など) を変えたいときは、プレビューを出て「Slots」タブで直し、また入って確かめます。
- モジュールのプロジェクトのプレビューでは、本体だけを描き、**いまの編集を書き出したもの** を `editing` の印の付いた行として付けます
  (ファイルには書きません)。同じスロットのほかの `.ugoemod` を読み込むと差し替わるので、「Slots」の欄で選び直して見比べられます。
  ほかのスロットの `.ugoemod` を付けて、ほかの衣装と重ねた見た目も確かめられます。`editing` の行は一覧から除けず、プロジェクトの一覧にも残りません。
- 前に書き出した同じ名前の `.ugoemod` も読み込めます。いまの編集は「Slots」の欄で「CatEars (editing)」のように ` (editing)` を付けた名前で出るので、
  同じスロットで書き出したファイル (「CatEars」) と選び直して、どこを変えたかを見比べられます。一覧では、いまの編集は `editing` の印の付いた行です。
  ファイルの行には、いまの編集との違いが「3 differences from your current edits」のように出て、開くと「Meshes: 5 → 4 (removed: EarL)」
  「Textures: …」「Required slots: …」のような行 (ファイル → いまの編集の向き) が並びます。同じなら「Same as your current edits.」と出ます。
  足したり変えたり除いたりしたメッシュ・デフォーマ・パーツ・グルー・物理のリグ・衝突体・ポーズのグループと追従は、行の下に
  「Band: vertices 4 → 6; draw order 500 → 520」「Sway: settings of 1 particle」「Collar: radius 8 → 12」
  「HairB / HairA: entries HairA / HairB → HairB / HairA」「ArmA: links (added: Sleeve)」のように何が違うかが出ます
  (ポーズのグループは差分のパーツを ` / ` でつないだ名前、追従は本体の差分のパーツの名前で出ます)。
  名前を押すと、プレビューのままビューポートでその要素が強調されます (メッシュは輪郭、物理のリグは粒子の鎖、衝突体は円やカプセル)。
  強調されるのは、いまスロットに付いている方 (いまの編集かファイル) の要素です。除いた要素は、ファイルの方を付けると見えます。
  いまの編集で除いた要素 (ポーズのグループなど) のメッシュがいまの編集に残っていれば、その輪郭を破線で描き、下の知らせに
  「Removed: … is not in your current edits」と出ます (ファイルに無い足した要素をファイルで見たときは「Added: …」)。
  もう一度押すか「Clear」でやめます。強調しているときに「Fit」を押すと、ビューポートがその要素に寄ります (全体に戻すのはビューポートの右上の「Fit」)。
  「Select」を押すと、プレビューを出て左のツリー (物理のリグと衝突体は「Physics」タブ、グルーは「Glue」タブ、ポーズは「Poses」タブとツリーの
  パーツ) でその要素が選ばれます (もう一度「Preview」を押すと、付けていたモジュールは付き直ります)。書き出すときに「Pack textures into atlases」を選んだファイルとも、アトラスの前の
  テクスチャと UV に戻して比べるので、変えていなければ「Same as your current edits.」と出ます。

  ![違いの行の下に、変えたメッシュの頂点と描画順が出る。「Select」でプレビューを出てツリーで選ばれる](images/module-compare-details.png)

  ![違いの名前を押すと、プレビューのままビューポートでその要素が強調される](images/module-compare-highlight.png)

  ![ポーズのグループの違いを強調して「Fit」でビューポートを寄せた](images/module-compare-pose.png)

  ![書き出した cat-ears.ugoemod の行に、耳を消したいまの編集との違いが出る](images/module-compare-differences.png)

  ![前に書き出した同じ名前の cat-ears.ugoemod を読み込み、いまの編集 (editing) と差し替えて比べる](images/module-compare-exported.png)
- いまの編集が書き出しの検査に通らないとき (公開していないパラメータを使っているなど) は、「Your edits can't be put on the base …」と理由が出て、
  編集中の姿のままプレビューします。このときは、そのモジュールのスロットは「Slots」に出ず、そのスロットのモジュールを読み込むと
  「This project is the module for slot …」と出て付きません。

![モジュールのプロジェクトのプレビュー。いまの編集 (CatEars) と同じスロットの BunnyEars を差し替えて比べる](images/module-compare-preview.png)

### プレビューで付けられないとき

付けられないモジュールは、その行の下に理由が赤い字で出ます。「Details」を開くと元のメッセージが出ます。

![付けられないモジュールの理由](images/dress-up-errors.png)

| 出るメッセージ | 理由と対処 |
| --- | --- |
| `Hat goes in slot "Hat", but this model has no such slot.` | モジュールが付くスロットが本体に無い。「Slots」タブで同じ名前のスロットを作る (大文字小文字も同じに) |
| `Dress needs this model to have slot "Hair".` | モジュールが、ほかのスロット (`Hair`) があることを条件にしている。そのスロットを作る |
| `Cape uses parameter "TailSwing", which this model does not have.` | モジュールが使うパラメータが本体に無い |
| `… uses parameter "Secret", but slot "Outfit" does not allow it.` | 本体にはあるパラメータだが、スロットの「Parameters」で選んでいない。選ぶ |
| `… masks mesh … with a mesh this model does not offer.` | マスクに使う本体のメッシュを、スロットの「Mask sources」で選んでいない |
| `…'s physics collides with a collider this model does not offer.` | 物理が当たる本体の衝突体を、スロットの「Colliders」で選んでいない |
| `… follows a pose part that slot … does not offer.` | 追従するポーズのパーツを、スロットの「Pose parts」で選んでいない |
| `… needs a higher avatar profile level than this model declares.` | モジュールが求めるアバタープロファイルのレベルを、本体が名乗っていない ([アバタープロファイル](avatar.md)) |
| `This is not a .ugoemod file, or it is damaged or from a newer version of ugoe.` | ファイルが `.ugoemod` でない・壊れている・新しい版の ugoe で書き出された |
| `Only .ugoemod files can be loaded here.` | `.ugoemod` 以外のファイルをドロップした |

- 「… was taken off: 理由」という枠が出たら、付けていたモジュールが自動で外れています。プレビューの外でスロットを消したり
  名前を変えたりした後などです。理由を読んでスロットを直し、もう一度付けてください。枠は「✕」で閉じます。
- ファイルが見つからない (移した・消した) ときは、その行にファイルの場所のエラーが出ます。「✕」で除いて読み込み直してください。

## ビューアで付け外しする

ビューア (`ugoe-viewer`) で、スロットのある `.ugoe` を開いてから `.ugoemod` を読み込むと、右のパネルの「着せ替え」で付け外しできます。
細かい振る舞いは [ビューアの README](../../apps/viewer/README.md#着せ替え-t0706) にあります。

1. 本体の `.ugoe` を開く (「開く」・ウィンドウへのドロップ・ファイルのダブルクリックか OS の「このアプリで開く」)。スロットがあれば「着せ替え」のパネルが出る。
2. `.ugoemod` を読み込む。パネルの「モジュールを開く…」(いくつでも選べる)、ツールバーの「開く」、ウィンドウへのドロップ、
   ファイルのダブルクリック (OS の「このアプリで開く」) のどれでもよい。ダブルクリックは、ビューアを開いていれば
   そのウィンドウに読み込む (どの OS でも)。
   読み込んだモジュールはそのまま付き、同じスロットに付いていたモジュールとは入れ替わる。
   本体とモジュールをまとめてドロップしてもよい。フォルダや開けないファイルが混ざっていても、開けるものだけを開き、飛ばしたものの
   名前がステータスバーに出る。アプリでは、ドラッグしている間の枠の色で分かる (青 = すべて開ける、黄 = 一部を飛ばす、赤 = 開けるものが無い)。
   ブラウザでは、ドラッグしている間はファイルの名前が分からないので、種類で分かるもの (画像などの開けないもの、JSON) だけを色で示し、
   `.ugoe`・`.ugoemod` とフォルダは落としたときに確かめる (枠は青)。
3. パネルはスロットごとに、いま付いているモジュールと、読み込んだモジュールを並べる。

| ボタン | すること |
| --- | --- |
| 付ける | 空いているスロットに付ける |
| 差し替える | そのスロットに付いている別のモジュールと入れ替える |
| 外す | 外して本体の姿に戻す (スロットが置き換えていた本体の髪なども、また見える) |
| × | 読み込んだモジュールを一覧から除く (付いていれば外す) |

- 付け外ししても、パラメータ・フェイストラッキング・ライティングはそのまま続く。物理の揺れだけは止まって、静かな姿から揺れ直す。
- モデルに無いスロットのモジュールには「モデルに無い」と出て、付けられない。
- 同じモデルを開き直す (エディタで書き出し直したファイルなど) と、付けていたものを付け直し、合わなくなったものは外して
  ステータスバーに「このモデルに合わないため、着せ替えの「Dress」を外しました」のように知らせる。
- 別のモデルを開くと、読み込んでいたモジュールは一覧から消える。付けていた組はモデルごとに覚えている (次の節)。

### モデルごとに組を覚える

ビューアは、モデルごとに読み込んだモジュールと付けていた組を覚えています (最近開いた 20 体まで。古いものから忘れる)。
前に着せ替えをしたモデルを開くと、パネルに「前にこのモデルに付けていた組があります」と出るので、「戻す」を押すと
その組に戻ります。「今回は戻さない」を押すか、そのまま付け外しすると、いまの組で覚え直します。
パネルの「前の組を自動で戻す」に印を付けると、尋ねずに戻します。

- 同じモデルかどうかは、ファイルの場所 (「開く」で選んだか、ウィンドウにドロップしたパス) か、ファイルの中身で見分けます。名前が同じでも中身も場所も違えば
  別のモデルです。「開く」で選んだファイルを書き出し直しても、同じ場所なら同じモデルとして扱います。
- モジュールは、覚えていたファイルの場所から読み直します。ファイルを動かしたり消したりしていると
  「前に付けていた「Sailor」(sailor.ugoemod) のファイルを読めないため、戻せません」と出ます。もう一度開けば付けられます。
- アプリのビューアでは、「開く」「モジュールを開く…」で選んだファイルも、ウィンドウにドロップしたファイルも、ダブルクリックで開いたファイルも場所を覚えるので、
  起動し直した後も戻せます。
- ブラウザで開いたビューアでは、選んだファイルとドロップしたファイルの場所が分からないので、ページを閉じると読み直せません。
  開いている間は中身を覚えているので戻せますが、開き直した後は「ファイルの場所が分からないため戻せません。もう一度開いてください」
  と出ます。
- 覚えた組があるモデルでは、パネルに「このモデル用に覚えた組があります」と出ます。「覚えた組を忘れる」を押すと、そのモデルの組を忘れ、
  次に開いたときに尋ねなくなります。付けているモジュールはそのままです。その後で付け外しすると、そのときの組をまた覚えます。
- ツールバーの「覚えたもの」で、組 (と光源の設定) を覚えているモデルの一覧を出せます。開いていないモデルの組も「忘れる」で忘れられ、
  「すべて忘れる…」でまとめて忘れられます ([ライティング](lighting.md#覚えたものの一覧))。

### 見本で試す

ビューアのツールバーの「サンプル」を押し、「着せ替え」を選ぶと、見本の本体 (スロット `Hair`・`Headwear`・`Outfit` を持つ)
と 4 つのモジュールを読み込みます。長い髪 (`LongHair`)・猫耳 (`CatEars`)・セーラー服 (`Sailor`) が付いた姿で開き、
パネルの `Hair` の「差し替える」でツインテール (`TwinTails`) に替えられます。「外す」で本体の既定の髪やシャツに戻ります。
髪の房は物理で揺れるので、`AngleX` のスライダーやフェイストラッキングで頭を振ってみてください。

![ビューアの着せ替えの見本。TwinTails・CatEars・Sailor を付けている](images/dress-up-viewer-sample.png)

見本のファイルはリポジトリの [assets/samples/dress-up/](../../assets/samples/README.md#dress-up) にあり、
ほかのファイルと同じように「開く」やドロップでも開けます。スロットの範囲や置き換えの設定の例としても使えます。
エディタで開くプロジェクトは [見本のプロジェクトを開く](#見本のプロジェクトを開く) で作れます。

### 付けられないとき

付けられないときは何も変わらず、パネルに理由が出ます。

| 出るメッセージ | 理由と対処 |
| --- | --- |
| 「Hat」を付けるスロット「Hat」が、このモデルにありません | モジュールが指すスロットが本体に無い。本体にその名前のスロットを作るか、モジュールの取り付け先を直す |
| 「Cape」に必要なパラメータ「Tail」が、このモデルにありません | モジュールの `requires` のパラメータが本体に無い |
| 「X」が使うパラメータ「P」を、スロット「S」が公開していません | 本体のスロットの「Parameters」に、そのパラメータを足す |
| 「X」が求めるアバタープロファイルのレベルを、このモデルが満たしていません | 本体のアバタープロファイルのレベルを上げるか、モジュールの要件を下げる |
| 着せ替えのモジュール (.ugoemod) として読めません (…) | ファイルが壊れているか、`.ugoemod` ではない |
| 先にモデル (.ugoe か .json) を開いてください | モデルを開く前に付けようとした |
