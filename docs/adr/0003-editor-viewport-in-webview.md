# 0003: エディタのビューポートは WebView 内の wasm で描画する

- 状態: Accepted
- 日付: 2026-09-28

## 背景

Tauri のエディタで、モデルを描画するビューポートをどう実現するか。

## 決定

ランタイムとレンダラを wasm (`ugoe-wasm`) にビルドし、WebView の `<canvas>` に描画する。WebGPU が使えればそれを使い、使えなければ WebGL2 にフォールバックする (wgpu の `webgl` feature)。

## 理由

- 配布するランタイムとまったく同じコードでプレビューできる (Web 版のランタイムの検証にもなる)。
- UI (ギズモ、選択枠、オーバーレイ) を DOM やキャンバスで重ねやすい。
- パラメータスライダーの操作が IPC を往復しないので、遅延が小さい。

## 検討した代替案

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| ネイティブの wgpu サーフェスを WebView の下や子ウィンドウとして重ねる | ネイティブの性能が出る | OS ごとにウィンドウの合成の扱いが異なり、実装も保守も難しい。UI を重ねにくい |
| バックエンドでオフスクリーン描画し、画像を WebView に転送する | 実装が単純 | 転送の遅延と帯域が大きく、60fps を保てない |

## 結果

- Linux の WebKitGTK は WebGPU に未対応のため、WebGL2 で動かす必要がある。レンダラは WebGL2 で動く機能だけを使う ([spec/rendering.md](../spec/rendering.md))。
- WebView 内の wasm の性能で足りなくなった場合は、ネイティブのサーフェスを重ねる方式を再検討する。
