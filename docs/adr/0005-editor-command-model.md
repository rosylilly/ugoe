# 0005: 編集操作はすべてシリアライズ可能な Command を通す

- 状態: Accepted
- 日付: 2026-09-28

## 背景

エディタは、GUI・CLI・AI エージェント (内部の自動リギングと、外部の MCP クライアント) から操作される。操作ごとに別々の経路で編集ロジックを書くと、Undo・検証・ログがばらばらになる。

## 決定

- すべての編集操作を `ugoe_editor_core::Command` (serde でシリアライズできる enum) として表現し、`Document::apply` だけがモデルを変更する。
- 1 コマンドを Undo の 1 単位とする。`Batch` で複数のコマンドをまとめられる。
- Undo は最初はスナップショット方式 (モデル全体の clone) で実装する。

## 理由

- GUI・CLI・AI・MCP が同じ経路を通るので、検証と Undo が 1 か所で済む。
- コマンドの JSON Schema を、そのまま AI のツール定義にできる。
- 操作を記録・再生できるので、バグの再現やテストが容易になる。

## 検討した代替案

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| 逆操作方式の Undo を最初から作る | メモリ効率が良い | コマンドごとに逆操作を正しく実装する手間とバグの危険が大きい。モデルが小さいうちは不要 |
| CRDT などによる共同編集を前提にする | 将来の同時編集に強い | 現時点では過剰 |

## 結果

- 大きなモデルでは、スナップショット方式の Undo がメモリを多く使う。モデルの clone が 10ms を超える、または履歴が 500MB を超える場合に、逆操作方式への移行を検討する。
