# 0007: ファイルベースのタスクボードと worktree による並行開発

- 状態: Accepted
- 日付: 2026-09-28

## 背景

複数のコーディングエージェントが、このリポジトリで同時に作業する。作業の重複、マージの衝突、設計の食い違いを防ぐ仕組みが必要である。

## 決定

- タスクは `docs/tasks/T####-slug.md` に 1 ファイル 1 タスクで書く (フロントマターに状態・依存関係・触ってよいクレートを書く)。
- エージェントは git worktree と、タスクごとのブランチで作業する。
- クレートの境界を作業の単位とし、タスクが触ってよいクレートを明示する。
- コミットは英語の Conventional Commits 形式とし、lefthook の Git フック (commitlint、整形、検査) と CI で強制する。
- 手順の詳細は [workflow/multi-agent.md](../workflow/multi-agent.md)。

## 理由

- GitHub Issues などの外部サービスがなくても、リポジトリだけで状況が分かる。エージェントはファイルを読むだけで次の作業を選べる。
- 1 タスク 1 ファイルにすると、状態の更新同士でマージが衝突しにくい。
- 触ってよい範囲を明示すると、並行する作業同士が衝突しにくくなる。

## 結果

- タスクの状態がリポジトリの履歴に残る。
- GitHub のリモートを使うようになったら、Issues と同期するかどうかを再検討する。
