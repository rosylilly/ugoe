# 0014: 着せ替え (実行時のモジュール合成)

- 状態: Accepted
- 日付: 2026-09-28
- 関連: [spec/modules.md](../spec/modules.md)、ADR 0012、ADR 0013

## 背景

ゲーム (特にガチャ系) やアバターアプリでは、衣装・髪型・アクセサリーを別々に作り、実行時に組み合わせたい。
1 つのモデルにすべての差分を入れて表示を切り替える方法では、ファイルが肥大化し、追加の配信もできない。

## 決定

1. **本体モデルは「スロット」を公開する。** スロットは名前の付いた取り付け位置で、取り付け先のデフォーマ (またはキャンバス)、描画順の範囲、既定で表示する本体のパーツ (差し替えられる側) を持つ。
2. **モジュールは、別ファイルの部分モデルである。** パーツ・メッシュ・デフォーマ・テクスチャ・物理を持ち、取り付けるスロットの名前と、使うパラメータ (標準パラメータ ID または本体が公開するパラメータ) だけに依存する。本体の内部の ID には依存しない。
3. **ランタイムは、本体とモジュールの組を合成して 1 つのコンパイル済みモデルを作る。** 組み替えは再合成 (コンパイルのやり直し) で行う。毎フレームのコストは通常のモデルと同じになる。
4. モジュールを取り付けると、スロットが指定する本体のパーツ (例: 既定の髪) を非表示にできる。
5. モジュールには、対応する本体のプロファイル (ADR 0012 のアバタープロファイルや、ゲーム固有のスロット定義) を宣言させ、合成時に検査する。

## 検討した代替案

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| 1 つのモデルにすべての差分を入れ、パーツの表示を切り替える | 仕組みが不要 | ファイルが肥大化する。後から衣装を追加配信できない |
| モジュールが本体の内部 ID を直接参照する | 実装が単純 | 本体を修正するとモジュールが壊れる。スロットという契約を挟むことで独立して作れる |
| 描画時に複数のモデルを重ねて描く | 合成が不要 | 描画順が本体とモジュールの間で入り組む表現 (髪の前後) ができない。変形も共有できない |

## 結果

- 衣装や髪型を別のチームや後から作り、追加配信できる。
- スロットの定義が本体とモジュールの間の互換性の契約になり、壊すと互換性が失われる。
- 組み替えのたびにコンパイルが走る。性能の目標 (中規模のモデルで数 ms 以内) を T0111 で計測する。
