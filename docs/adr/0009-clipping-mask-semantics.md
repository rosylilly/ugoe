# 0009: クリッピングマスクの意味論

- 状態: Accepted
- 日付: 2026-09-28
- 関連: T0202、T0107、T0205、[spec/rendering.md#マスク](../spec/rendering.md#マスク)、[spec/model.md](../spec/model.md#メッシュ)

## 背景

マスクの効き方は T0202 で「テクスチャのアルファだけで決め、マスク用メッシュの不透明度は掛けない」と暫定で決め、Cubism と一致するかを未確認として残していた。

判断の基準は **Cubism と一致するかではなく、リガーにとって便利かどうか** とする ([vision.md](../vision.md) の「機能的な互換」)。そのため、Web 上のマニュアル・ノウハウ記事・フォーラムの要望を調べ、マスクが実際にどう使われているか、何が不満とされているかを確認した。

### 調査で分かったこと

| 論点 | 分かったこと | 出典 |
| --- | --- | --- |
| 主な用途 | 目 (白目で黒目・瞳孔・ハイライト・影を切り抜く、まばたき) が最も多い。次いで口の中 (歯・舌を口内メッシュで切り抜く)、影や柄の二重塗り、反転マスクによる髪越しの眉・目の透かし | [公式マニュアル: クリッピング](https://docs.live2d.com/cubism-editor-manual/clipping-mask/)、[CGbox](https://cgbox.jp/2021/01/20/howto-clip/) |
| マスク専用メッシュ | 「マスク用のアートメッシュを複製して不透明度 0% にする」のが公式に推奨された定番の手法。「非表示」や「下絵」にすると書き出されず、警告や不具合の原因になる。キーフォームの範囲外で全マスクが非表示になると、クリッピング自体が解除される (切り抜かれていたものが全部見える) | 公式マニュアル、[旧フォーラム #2458](https://forum.live2d.com/discussion/2458)、[Steam の議論](https://steamcommunity.com/app/616720/discussions/0/3187989767048759627) |
| マスクの不透明度 | Cubism のマスク描画はテクスチャのアルファだけを使い、不透明度は無視する (SDK のシェーダ `fragshadersrcsetupmask.frag` で確認)。上の「不透明度 0% のマスク専用メッシュ」はこの挙動が前提になっている | [CubismWebFramework](https://github.com/Live2D/CubismWebFramework) |
| 透け量の調整 | 反転マスクで部分的に透かした箇所の透け具合を調整したい、という要望がある。現状はマスクのテクスチャを描き直すしかない | [Creators Forum #3483](https://creatorsforum.live2d.com/t/topic/3483) |
| 通常と反転の併用 | 1 つのメッシュに通常マスクと反転マスクを同時に使えない。公式も「多数のご要望をお寄せいただいている」と回答 | [旧フォーラム #2614](https://forum.live2d.com/discussion/2614) |
| 複数マスク | 和集合 (Cubism の実装は 1 − Π(1 − α))。「舌を口内と輪郭の両方に収めたい」という共通部分の要望があるが、仕様として未対応 | [旧フォーラム #1783](https://forum.live2d.com/discussion/1783) |
| 入れ子 | 白目 → 黒目 → 瞳孔のように連鎖させると、マスクとして使われるのは黒目の切り抜き後ではなく元の形なので、瞳孔が白目からはみ出す。定石は「全部を白目に直接クリップする」ことだが、表現が制限される | [Creators Forum #731](https://creatorsforum.live2d.com/t/topic/731) |
| 精度と上限 | マスク数の上限 (1 モデル 36 など) と、共有アトラスの解像度不足による縁のぼやけ・ディザへの不満がある | [Creators Forum #2405](https://creatorsforum.live2d.com/t/topic/2405)、[#2262](https://creatorsforum.live2d.com/t/topic/2262) |

「目を閉じると黒目が残る」のような、マスクの不透明度を反映してほしいことを示す具体的な報告は見つからなかった。

## 決定

1. **マスク用メッシュの不透明度・表示状態・色・合成モード・裏面カリングは、マスクの効き具合に影響しない。** 効き具合はテクスチャのアルファ (と、後述の入れ子の継承) だけで決まる。
2. **マスク専用メッシュ (`mask_only`) を持つ。** 色としては描画されず、常にマスクとして働く。「不透明度 0% にする」という回避策を不要にする。
3. **マスクの参照ごとに通常と反転を指定する。** 見える量 = (通常マスクの結合) × (1 − 反転マスクの和集合)。メッシュ単位の `invert_mask` は廃止する (全参照を反転にすれば同じことができる)。
4. **通常マスクの結合は、既定が和集合 `1 − Π(1 − c)`、選べば共通部分 `Π c`。** 和集合の式を、飽和加算 `min(1, Σ c)` から Cubism と同じ式に変える。半透明のマスクが重なる部分が自然になる。
5. **マスクは入れ子を継承する。** マスクとして使われるメッシュ自身がマスクを持つ場合、その切り抜き後の形がマスクになる。循環 (自分自身を含む) は検証エラーにする。
6. **切り抜かれる側のキーフォームに `mask_strength` (0〜1、既定 1) を持つ。** 最終的な係数 = `1 − mask_strength × (1 − m)`。マスクの効き具合 (透け量) を調整でき、パラメータで動かせる。
7. **マスクの数に上限を設けない。既定の精度は、マスクの画面上の大きさ以上の解像度とする。** 精度を下げる設定はレンダラのオプションで持つ。
8. **「全マスクが非表示ならクリッピングを解除する」挙動は持たない。** マスクは常に形どおりに効く。

## 検討した代替案

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| マスクの効き具合にマスク用メッシュの不透明度を掛ける | マスクをフェードさせると切り抜きも一緒に薄くなる | 定番の「不透明度 0% のマスク専用メッシュ」が使えない。ポーズ切り替えなどでマスクと切り抜かれる側が一緒にフェードすると、不透明度が二重に掛かり (opacity²) 急に消える。フェードは `mask_strength` で表現できる |
| 不透明度を掛けるかどうかをメッシュごとに選べるようにする | どちらの用途にも対応できる | 設定の組み合わせが増えて分かりにくい。求められていた「透け量の調整」は `mask_strength` の方が直接的に満たす |
| 入れ子を継承するかをマスク参照ごとに選べるようにする | Cubism と同じ「元の形」も表現できる | 元の形を使いたい具体的な用途が見つからなかった。必要になったら後から追加できる |
| 和集合を飽和加算 `min(1, Σ c)` のままにする | 実装が単純 | 半透明のマスクが重なると不自然に濃くなる。Cubism から移ってきたリガーの直感とも合わない |

## 結果

- データ定義 (`ugoe-model` の `Mesh` と `MeshKeyform`) が変わる。1.0 より前なので `SCHEMA_VERSION` は 0 のままとする ([spec/file-formats.md](../spec/file-formats.md#バージョニング))。実装は T0107 (データとランタイム) と T0205 (レンダラ) で行う。
- レンダラは、入れ子の継承・共通部分・通常と反転の併用を、WebGL2 で動く方法で実現する必要がある。マスク集合をまとめて描く今の方式 (T0202) を拡張する。
- エディタは、マスク専用メッシュを色ではなく輪郭などで表示する必要がある。
