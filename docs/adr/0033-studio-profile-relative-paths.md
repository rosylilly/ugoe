# 0033: スタジオのプロファイルは、プロファイルのフォルダの下のファイルを相対パスで持つ

- 状態: Accepted
- 日付: 2026-10-08
- 関連: T0852 (この ADR)、ADR 0028 の 4. (このうち「モデルのパスは絶対パスで持つ」を置き換える)、T0838 (読めるパスの許可)、
  [studio.md](../studio.md#プロファイルのパス)

## 背景

ADR 0028 の 4. は、プロファイルがモデルのパスを絶対パスで持ち、見つからなければ選び直させると決めた。シーンのモジュール・背景の画像・
ホットキーの着せ替えのモジュールも同じく絶対パスで持っていた。そのため、プロファイルとモデルを 1 つのフォルダにまとめて人に渡しても
(配信の見本・別の計算機への引っ越し)、受け取った側ではすべてのシーンで選び直しになる。

案は 3 つあった (T0852)。

- A. 読むときは相対パスも受け付け、書くときはプロファイルのフォルダの下のファイルだけを相対パスにする。
- B. 読むときだけ相対パスを受け付ける (スタジオは絶対パスで書く。保存し直すと絶対パスに戻る)。
- C. 「フォルダに書き出す」操作を足し、使うファイルを 1 つのフォルダに写して相対パスで書く (写す操作・名前のぶつかり・大きさの上限・
  許可の扱いが増える)。

利用者の決定 (2026-10-08): 案 A。`..` を含む相対パスは読まない。

## 決定

1. **読む:** プロファイルの中のパス (シーンの `model`・`modules`・`background.path`、ホットキーの着せ替えの `module`) は、絶対パスか、
   プロファイルのファイルのあるフォルダを基準にした相対パス。相対パスは読むときに絶対パスに解き、スタジオの中 (画面・読めるパスの許可・
   外部 API の `dressup.*`) では解いた絶対パスで扱う。
2. **相対パスの字面:** 区切りは `/` と `\` のどちらも区切りとして読む (どの OS でも同じに読む)。`.` と空の名前は飛ばす。
   次のものはプロファイルのフォルダの外に出られるので **読めないパス** とする: `..` (と、Windows が末尾の点と空白を落として `..` に
   読むかもしれない点と空白だけの名前)・区切りから始まるもの (ルート・UNC)・`:` を含むもの (ドライブ名・代替データストリーム)・空のもの。
   読めないパスは解かずに字面のまま残し、読むところは相対パスを読まずに「見つからない」とする (画面は選び直させる)。
   保存し直しても字面のまま書く (黙って消さない)。
3. **書く:** 保存先のフォルダ (とその下) にあるファイルは、そのフォルダからの相対パス (区切りは `/`) で書く。外にあるもの、相対パスで
   書くと同じファイルに解けないもの (名前に `\` や `:` を含む) は絶対パスで書く。別の場所へ「名前を付けて保存」したら、新しい場所を
   基準に書き直す。
4. **比べるのは字面:** 解くときも書くときも記号のリンクはたどらない。リンクしたフォルダから開いたプロファイルは、そのリンクのパスを
   基準にする。フォルダの下にある記号のリンクは、ほかのファイルと同じく OS がたどって読む。
5. **プロファイルの版は上げない** (`version: 1` のまま。リリース前のため、古い形の読み替えは書かない)。

## 理由

- 利用者は何もしなくても、プロファイルの隣か下にファイルを置けば、フォルダごと渡せる形になる。C は要望が出たら A の上に足せる。
- `..` を拒むのは、受け取ったプロファイルが、相対パスで受け取った側のフォルダの外のファイル (たとえば同じ親の下のほかのファイル) を
  指さないようにするため。絶対パスは今までどおり受け付けるので、これは閉じ込めではない。記号のリンクをたどっても、絶対パスで指せる
  ファイルより読めるものは増えない。そのため字面で比べ、正規化 (リンクを解くこと) はしない。
- 区切りを OS で変えないのは、Windows で書いたプロファイルを手で直したもの (`models\avatar.ugoe`) を、ほかの OS でも同じに読むため。
  字面の規則を OS に依らずに決めると、パスの組み立てを手元の OS の単体テストで確かめられる。

## 影響

- `apps/studio/src-tauri/src/profile.rs` の `Profile::read`・`Profile::write` が解く・戻す。メモリの上は絶対パスなので、読めるパスの許可
  (`access.rs`) と `dressup.list`・`dressup.set` は変えずに解いた絶対パスで比べる。`stage::read_asset` は相対パスを読まない。
- 外部 API のトークンと鍵はプロファイルに入っていないので、相対パスにしても渡したプロファイルから漏れるものは増えない。
- Windows の区切りとドライブ名の扱いは、単体テスト (`#[cfg(windows)]`) を書いたが、実機では確かめていない (T0852 のメモ)。
