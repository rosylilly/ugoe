# 0017: 単一ランタイムと 1 行導入

- 状態: Accepted
- 日付: 2026-09-28
- 関連: [portability.md](../portability.md#配布)、ADR 0001、ADR 0002

## 背景

Live2D はプラットフォームごとに SDK が分かれており、導入の手順や挙動がそれぞれ異なる。
ugoe はすでに 1 つの Rust のコアをすべての環境で使う設計である (ADR 0001、ADR 0002)。これを配布の形でも徹底し、主要な環境に 1 行で導入できるようにする。

## 決定

1. **すべての配布物を 1 つのコア (`ugoe` クレート) から作る。** 環境ごとの差は薄いバインディング層だけにする。
2. **次の配布物を用意する。**

   | 環境 | 配布物 | 導入 |
   | --- | --- | --- |
   | Rust | crates.io の `ugoe` | `cargo add ugoe` |
   | Web | npm の `@ugoe/runtime` (wasm + TypeScript の型) と、Web Components の `<ugoe-avatar>` | `npm i @ugoe/runtime` / `<script type="module">` |
   | Unity | UPM パッケージ (ネイティブライブラリ同梱) | パッケージマネージャに URL を追加 |
   | Godot | GDExtension (godot-rust) | アセットライブラリ |
   | Unreal | プラグイン (ネイティブライブラリ同梱) | プラグインの追加 |
   | C / その他 | `ugoe-ffi` の共有ライブラリとヘッダ | 各 OS 向けのビルド済みバイナリ |

3. **すべての配布物で同じ適合テスト (同じモデル・同じパラメータで同じ頂点と画像) を通す。** 参照となる出力を `ugoe render` と `ModelInstance` の出力から作り、各バインディングの CI で比較する。
4. **リリースを自動化する。** タグを打つと、すべての配布物のビルドと公開が CI で行われる。バージョン番号はすべての配布物で揃える。
5. 公開には、プロジェクトのライセンスの決定が前提になる (未決)。

## 結果

- 利用者は環境を問わず同じ挙動のランタイムを 1 行で導入できる。
- 各エンジン向けのバインディングと CI の保守が必要になる。適合テストを共通化することで負担を抑える。
