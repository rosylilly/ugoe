# 0023: 実行中のエディタと MCP をつなぐ (エディタの中の MCP サーバと、stdio の中継)

- 状態: Accepted (2026-09-30、利用者の要望)
- 日付: 2026-09-30
- 関連: ADR 0006 (AI は提案するだけ)、ADR 0022 (エージェントに判断を任せる経路)。ADR 0005 (エディタの編集は Command を通す)

## 背景

`ugoe-mcp` (T0508・T0513〜T0515) は `.ugoeproj` を自分で開いて編集し、実行中のエディタとは通信しない。
エージェントの編集をエディタで見るには保存 → 開き直すしかなく、同じプロジェクトを同時に開くと後から保存したほうが勝つ。
利用者は、エディタで作業しながら、エージェント (Claude Code・OpenCode・ChatGPT) に編集を頼み、その提案をエディタの画面で確かめて採用したい。
また、Windows で動くエディタと、WSL の中で動くエージェントを組み合わせて使いたい。

## 決定

1. **エディタの中に MCP サーバを置く (ブリッジ)。** エディタは、開いている `Document` を対象にした `ugoe-mcp` のツール (同じ `Tools`) を、ループバックの HTTP (T0514 の Streamable HTTP) で出す。
   - `ugoe-mcp` のツールは、文書の持ち主を抽象化する (ファイルを自分で開く持ち主と、エディタの文書を借りる持ち主)。ツールの形・名前・結果は両方で同じにする。
   - 待ち受けはループバックだけ・トークン必須。エディタの設定で有効にする (既定は無効)。
   - 起動中は、ポートとトークンを書いた発見用のファイルを、利用者だけが読める場所 (OS のアプリのデータのディレクトリ) に置き、終了時に消す。
2. **採用はエディタの画面で利用者が行う (ADR 0006)。** ブリッジ経由の提案は、エディタの AI タブの提案の一覧に出る (エージェントの名前付き)。
   エージェントが `apply_proposal` を呼ぶと、エディタが確認のダイアログを出し、利用者が承認したときだけ適用する (拒否・時間切れはツールのエラー)。
   プロジェクトを開く・閉じる・別名で保存するなど、利用者の作業を奪う操作はブリッジからはできない (または確認を求める)。
3. **`ugoe-mcp --editor` は stdio とエディタの中継になる。** stdio しか話せないクライアント (Claude Code・OpenCode) は、`ugoe-mcp --editor` を登録すれば実行中のエディタにつながる。
   発見用のファイルからポートとトークンを読む。エディタが起動していなければ、分かりやすいエラーを返す。
4. **Windows のエディタと WSL のエージェント:**
   - 推奨: WSL から Windows 版の `ugoe-mcp.exe --editor` を stdio で登録する (WSL の相互運用で .exe を起動できる。通信は Windows の中のループバックで完結し、ネットワークの設定が要らない)。エディタに `ugoe-mcp.exe` を同梱する。
   - 代わり: WSL の Linux 版 `ugoe-mcp --editor` が、Windows 側の発見用のファイルを `/mnt/c/...` から読み、Windows のループバックへつなぐ (WSL の「ミラー」のネットワークのときだけ。NAT のときはつながらない旨を示す)。
   - パスの変換: エージェントが WSL のパス (`/mnt/c/...`・`/home/...`) を渡したら、中継が Windows のパス (`C:\...`・`\\wsl.localhost\...`) に変換し、結果のパスは逆に戻す。
5. **ファイルを直接扱う形 (いまの `ugoe-mcp`) も残す。** エディタが外でプロジェクトが書き換えられたことに気づき、開き直すかを利用者に尋ねる (同時の編集で黙って上書きしない)。
6. **つなぎ方をエディタから示す。** エディタの設定に「エージェントをつなぐ」の画面を置き、ブリッジの有効化と、Claude Code・OpenCode・ChatGPT (トンネル)・WSL ごとの登録のコマンドを示してコピーできるようにする。操作マニュアルに章を足す。

## 検討した代替案

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| ファイルを介すだけ (いまの形) | 実装が要らない | 開き直しが要り、同時の編集で変更が消える。提案を画面で見られない |
| エディタが独自の IPC (名前付きパイプなど) を開き、`ugoe-mcp` がそれを使う | MCP に依存しない | ツールの形を二重に持つ。WSL とのあいだで名前付きパイプは扱いにくい |
| エディタの中の MCP サーバだけ (中継なし) | 部品が少ない | stdio しか話せないクライアントからつなげない |
| WSL から Windows のループバックへ直接つなぐのを推奨 | 追加のバイナリが要らない | WSL のネットワークの設定 (NAT とミラー) で結果が変わる |

## 結果

- エージェントの提案が、エディタの画面にそのまま出て、プレビュー・一部の採用・Undo ができる。
- `ugoe-mcp` のツールは 1 つの実装のまま、ファイルとエディタの両方で使える。
- エディタは MIT の `ugoe-mcp` をライブラリとして組み込み (エディタは GPL-3.0-only で、組み込みは可)、`ugoe-mcp.exe` をサイドカーとして同梱する。
