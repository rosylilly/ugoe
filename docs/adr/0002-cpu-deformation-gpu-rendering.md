# 0002: 変形は CPU、描画は GPU

- 状態: Accepted
- 日付: 2026-09-28

## 背景

パラメータから頂点を計算する処理 (キーフォームの補間とデフォーマの変形) を、CPU と GPU (コンピュートシェーダ) のどちらで行うか。

## 決定

変形は **CPU で決定的に** 評価し (`ugoe-runtime`)、GPU は描画にだけ使う (`ugoe-render`)。

## 理由

- ゲームエンジンに組み込むとき、エンジンの描画パイプラインに頂点を渡すだけで済む ([portability.md](../portability.md) の段階 B)。
- WebGL2 にはコンピュートシェーダがない。
- 当たり判定・物理・エディタでの頂点選択など、CPU 側で変形結果が必要な処理が多い。
- 1 体あたりの頂点数は数千〜数万で、CPU でも十分に速い。
- 決定的なので、スナップショットテストがしやすい。

## 検討した代替案

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| GPU のコンピュートシェーダで変形する | 大量のモデルを表示するときに速い | WebGL2 で動かない。CPU 側で結果を使うには読み戻しが必要。エンジン統合が難しくなる |

## 結果

- 多数のモデルを同時に表示するときは、CPU がボトルネックになりうる。そのときはまず SIMD と並列化 (インスタンス単位) で対処し、それでも足りなければ GPU 評価を「追加の」バックエンドとして検討する。
