# 0024: 着せ替えのモジュールは、本体を参照する別のプロジェクトとして作る

- 状態: Accepted (2026-09-30、利用者の判断)
- 日付: 2026-09-30
- 関連: ADR 0014 (合成できるモジュール)、ADR 0005 (エディタの編集は Command を通す)

## 背景

M4 で、スロットとモジュールのデータ (T0111・T0121)、合成、`.ugoemod` の読み書き (T0113)、`Puppet` の付け外しの API ができた。
ところがエディタにもビューアにも、スロットを定義する・モジュールを作る・付け外しを試す操作がなく、利用者は着せ替えを使えない。

## 決定

- **モジュールは、本体を参照する「モジュールのプロジェクト」(`.ugoeproj`) として作る。** プロジェクトの種類 (本体 / モジュール) を `project.json` に持ち、モジュールのプロジェクトは本体 (`.ugoeproj` か `.ugoe`) とスロットの ID を参照する。
  - 編集の対象は `Module` (パーツ・デフォーマ・メッシュ・グルー・テクスチャ・物理・ポーズ)。`Command` はモジュールにも使えるようにする (モデルと同じ規則で、`Document` がモジュールを持てる形)。
  - 本体は下敷きとして読み取り専用で表示し、合成した姿 (`compose`) をビューポートとプレビューで見せる。本体のパラメータで動かして確かめられる。
  - 衣装の PSD を取り込み、自動メッシュ・リギング (推定・AI の提案を含む) はモデルと同じに使える。
  - 書き出しは `.ugoemod`。書き出しの前に `validate_module` と、本体との合成の検証を行う。
- **スロットは本体のプロジェクトで定義する。** スロットを足す・変える・消す `Command` と、スロットの画面 (描画順の範囲・取り付け先・置き換える要素・公開するパラメータ・衝突体・ポーズ) を置く。
- **試す:** 本体のプロジェクトのプレビューで、`.ugoemod` を読み込んで付け外しできる。ビューアも `.ugoe` に `.ugoemod` を付け外しできる (wasm に付け外しの口を足す)。
- 本体の中からモジュールを切り出す操作は、今は作らない (後続の候補)。

## 検討した代替案

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| 本体の中で印を付けて切り出す | 1 つのファイルで済む | 衣装が増えると本体が重くなる。別の人が衣装だけ作れない |
| モジュールの専用のエディタ | 画面を最適化できる | 同じ編集の仕組みを二重に持つ |

## 結果

- 衣装ごとに別のプロジェクトとして作り、配布できる。
- `Document` と `Command` はモデルとモジュールの両方を扱う必要があり、editor-core の変更が大きい。段階に分けて入れる。
