# 0020: マイルストーンの順序と、AI 支援を 1.0 に含めること

- 状態: Accepted (2026-09-29、利用者の判断)
- 日付: 2026-09-29
- 関連: ADR 0018 (1.0 の範囲の部分をこの ADR で置き換える)、ADR 0006 (AI は提案だけ)、ADR 0017 (単一ランタイム)、ADR 0021 (公開仕様)

## 背景

ADR 0018 で、1.0 を「AI 連携を除く、現在定義しているすべての機能」とし、ロードマップを M4 (配布と統合) → M5 (AI 連携、1.0 以降) の順にしていた。
M3・M3.5 を終えた時点で、利用者から次の方針が示された。

- Unity などのエンジンへの移植は大きく先送りし、1.0 の直前に外部から使えるようになればよい。
- 先に AI 支援と、公開のモデル仕様を詰めたい。
- AI 支援も 1.0 の範囲に入れる。

## 決定

- **1.0 は、現在定義しているすべての機能を含む (AI 支援を含む)。** ADR 0018 の「1.0 の範囲」の決定をこの ADR で置き換える。ライセンスの決定 (MIT と GPL-3.0-only) は ADR 0018 のまま。
- **マイルストーンの順序を次のようにする。**
  1. M4 AI 支援 (旧 M5)
  2. M5 公開のモデル仕様 (新設。ADR 0021)
  3. M6 表現の拡充 (旧 M4 のうち、着せ替え・ライティング・描画の最適化など、ランタイムとエディタの機能)
  4. M7 配布と移植 (旧 M4 のうち、C ABI・crates.io・npm・Unity・Godot・Unreal・適合テスト。1.0 の直前)
- 1.0 = M1〜M7 の完了。
- AI 支援はツール層 (`ugoe-ai`・エディタ・`ugoe-mcp`) にだけ置き、ランタイムとファイル形式は AI に依存しない (ADR 0006 のとおり、AI は `Command` の列を提案するだけ)。したがって AI を 1.0 に含めても、ファイル形式の互換性の約束は増えない。
- 1.0 で約束する AI 支援は「提案の形式と、提案を確認して採用する流れ」。どのモデル (プロバイダ) でどれだけの品質が出るかは約束しない。

## 検討した代替案

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| AI 支援は先に作るが 1.0 の範囲外 (実験的) のまま | 1.0 の範囲が小さい | 利用者の方針と合わない。AI 支援を差別化の中心に置けない |
| 移植 (M7) を先に行う | 早くから外部で使える | 仕様とランタイムが固まる前に移植すると、移植先を何度も直すことになる |

## 結果

- 公開仕様 (M5) を固めてから移植 (M7) するので、移植先の手戻りが減る。
- 1.0 までの範囲はさらに大きくなる。1.0 より前はファイル形式の互換性を保証しない (ADR 0004) ことは変わらない。
- 外部のエンジンから使えるのは M7 の後になる。それより前に外部から使いたい要望が出たら、C ABI (T0401) や npm (T0404) だけを前に出すことを検討する。
