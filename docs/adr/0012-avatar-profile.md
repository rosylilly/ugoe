# 0012: 2D アバターの標準プロファイル

- 状態: Accepted
- 日付: 2026-09-28
- 関連: [spec/avatar-profile.md](../spec/avatar-profile.md)、[spec/model.md](../spec/model.md#標準パラメータ)

## 背景

3D の VRM が普及したのは、どのアプリでも同じモデルが同じように動くからである。
2D アバターにはそうした共通の仕様がなく、配信アプリごとにパラメータ名やトラッキングの対応付けを設定し直す必要がある。
ugoe は、2D アバターの共通仕様を作ることで、VTuber や配信アプリが「どのアプリでも使える」という理由で選べるようにする。

## 決定

1. **「ugoe アバタープロファイル」を仕様として定める** ([spec/avatar-profile.md](../spec/avatar-profile.md))。内容は次のとおり。
   - 標準パラメータ (ID・値域・向きの約束)。既存の `ugoe_model::standard` を土台に拡張する。
   - フェイストラッキングとの対応。ARKit の 52 ブレンドシェイプと頭の向きから、標準パラメータへの対応表を定める。
   - メタデータ。作者・連絡先・利用許諾 (アバターとしての利用者の範囲、商用利用、暴力的・性的表現、政治・宗教、再配布、改変、クレジット表記) を持たせる。
   - 当たり判定や視線・口などのアプリが必要とする情報 (スロット名・標準の当たり判定名)。
   - 準拠レベル。最低限 (頭の向き・目・口) から完全 (ARKit 相当の表情) まで段階を設ける。
2. **プロファイルはモデルのデータの一部として持つ** (`Model.avatar`)。バンドルに入り、アプリはそれを読むだけで対応付けができる。
3. **仕様を公開する。** 仕様書は実装から独立して読めるように書き、自由なライセンスで公開する。ライセンスの種類は、プロジェクト全体のライセンスと合わせて決める (未決)。
4. **検証ツールを用意する。** `ugoe validate --profile avatar` で準拠レベルとメタデータの不足を検査する。

## 検討した代替案

| 案 | 利点 | 欠点 |
| --- | --- | --- |
| VRM を 2D に拡張して使う | 既存のエコシステムがある | VRM は glTF (3D) を前提としており、2D のメッシュ変形を表現できない。メタデータの考え方は参考にする |
| Live2D の標準パラメータ名をそのまま使う | 既存のモデラーが慣れている | ファイル形式と機構は互換にしない方針 (vision.md)。名前の対応表はインポートの補助として持つ |
| パラメータ名だけを決め、メタデータは持たない | 軽い | 利用許諾がないと、配信アプリやサービスが安心して扱えない。VRM の成功要因の 1 つがメタデータである |

## 結果

- アプリ側は、プロファイルに準拠したモデルなら追加の設定なしでトラッキングを接続できる。
- 標準パラメータの ID は変更できなくなる (互換性の約束)。追加はできる。
- プロファイルの仕様にはバージョンを付け、ADR 0013 の機能宣言と組み合わせて互換性を管理する。
