# T0635: エディタ: プレビューモード (パラメータのスライダーで仕上がりを確かめる)

## 目的

今のエディタでは、パラメータのスライダーは編集のためのパネル (キーの追加・値の入力) の一部で、インスペクタや物理のタブと画面を分け合っている。
物理・目パチ・呼吸は物理のプレビューなど個別の場所でしか動かず、組み上げたモデルが実際にどう動くか (すべてのパラメータを動かしたときの仕上がり) を確かめにくい (利用者の要望、2026-09-29)。
編集の道具を隠し、パラメータのスライダーを並べて、ランタイムと同じ `Puppet::update` で動かすプレビューモードを作る。

## 受け入れ条件

- [x] ヘッダー (かツールバー) の切り替えでプレビューモードに入る・出る。プレビュー中は編集の道具・ギズモ・選択を隠し、ビューポートを広く使う。編集のコマンドは送らない
- [x] すべてのパラメータのスライダーを、パラメータグループごとに並べる (絞り込み、1 つずつ・すべて既定値に戻す)。値を数値でも入れられる
- [x] 物理・目パチ・呼吸・リップシンク・ポーズを `update(dt)` で動かし、それぞれを有効・無効にできる (T0309 の `set_enabled`)。物理のリセット
- [x] モーション・表情を選んで再生・停止できる (プロジェクトのもの。T0630)
- [x] プレビューのスライダーの値は編集の姿 (編集用のスライダーの値) と別に持ち、プレビューを出ると編集していた姿に戻る
- [ ] 可能ならビューアのフェイストラッキング (T0703) をプレビューで使えるようにする (どちらも GPL なので写してよい。共有の部品に切り出すかは決めて書く)。難しければ後続のタスクにする (→ T0636 に移した。満たしていない。メモ)
- [x] ヘッドレスのブラウザで見本 (`assets/samples/avatar.ugoe` のプロジェクト) を使って確かめ、操作マニュアルにプレビューの章を足す
- [x] `just ci`・エディタのビルドが通る

## メモ

- **やったこと (`apps/editor/src/lib/preview/`):** ヘッダーの「Preview」/「Exit preview」で出入りする。プレビュー中は
  左の列・タイムライン・右の列を CSS で隠し (中身は壊さない)、ビューポートの編集のツール (`ToolOverlay`) を外し、
  Undo / Redo のボタンとショートカットを止め、右に `PreviewPanel` を出す。コマンドは送らない。ファイルメニューで
  モデルが変わったらプレビューを出る。
- **動かし方:** `ViewportController` に汎用の `FrameDriver` (`setDriver`・`applyStages`・`driven`) を足した。driver が
  あると毎フレーム `update(dt)` を回し、段は driver の `stages`、読み込みのたびに `loaded`、`setParameter` は編集用の値
  だけを書く。`setDriver(null)` はモデルを読み直して編集用の値を書き戻す (物理・モーション・表情・目パチの状態も
  初めからになる)。物理のプレビュー (T0629) は止め、タイムラインの再生と表情のプレビュー (T0630) は `driven` を見て
  止まる (`TimelinePanel.svelte` に effect を 1 つ)。**プレビューモードが優先。**
- **パネル:** 段 (物理・目パチ・呼吸・リップシンク・ポーズ) の切り替え (最初はリップシンクだけ止める。設定の無い段は
  「(not set up)」)、物理の「Reset」、リップシンクの音量、ドキュメントのモーションの再生・停止 (`start_motion_json`
  の `force`。イベントを最近 5 つ表示)、表情の選択、パラメータのスライダー (グループごと・絞り込み・値の入力・1 つずつ
  と全部の既定値)。バンドルが作れず JSON で表示しているときは `set_physics_json` でドキュメントの物理を渡す。
  純粋な関数は `preview.ts` (Vitest 10 件)。
- **フェイストラッキング:** MediaPipe の同梱 (ビルドでのモデルの取得・約 9 MiB)・カメラの許可 (エディタの Tauri 側)・
  ビューアのコード約 1300 行の移植・共有の部品にするかの判断が要るので、team-lead と相談して T0636 に分けた。
  `FrameDriver.beforeUpdate` がトラッキングの入力を渡す場所になる想定。
- **確かめたこと:** `ugoe sample avatar --project` のプロジェクトの `model.json` に標準の effects (目パチの間隔は 2 秒)
  とパラメータグループを手で足したもの (リポジトリ外) を、ビルドした画面 (`just wasm`・`vite build`) と本物の
  `Document` への HTTP ブリッジ (リポジトリ外) でヘッドレス Chrome で開き、モーション `Shake` (AngleX 0 → 30 → -30 → 0、
  1 秒にイベント) と表情 `Smile` をコマンドで足して確かめた。左・タイムラインが隠れ、Undo が消える。グループ
  「Face 3 / Eyes 8 / Brows 5 / Mouth 7 / Body 4」。5 秒で EyeLOpen が 0〜1 (目パチ)、Breath が 0〜1 (呼吸)。
  物理あり: AngleX を 30 にした後の 0.1〜1.5 秒のビューポートの画像が毎回変わる (揺れ)、物理なし: 変わらない。
  モーションの再生で AngleX が 30 → -30 と動き「Events: peak」、■ で止まる。Smile で MouthForm・EyeLSmile が 1。
  リップシンク 0.8 で MouthOpenY 0.8 (入力しても 0.8)、切ると入力の 0.3 が効く。値域の外は拒否。絞り込み「eye」で
  Eyes だけ。Reset all・↺。プレビュー中の Ctrl + Z は効かない。**出ると、入る前と出た後のビューポートの画像が
  バイト単位で一致** し、編集のスライダー (AngleZ 10) もそのまま。再び入ると編集中の姿から始まる。タイムラインを
  再生中に入ると再生が止まる (時刻が止まり、出た後は「▶ Play」)。マニュアルの画像 (`preview.png`) はこの画面。
- **確かめていないこと:** 実際の Tauri のウィンドウでの操作 (`cargo check -p ugoe-editor` と `vite build` まで)。
  ポーズの段 (見本にポーズのグループが無い)。
- **後続の候補:** 目パチ・呼吸・リップシンクの設定 (`Model.effects`) とポーズを編集するコマンドと画面 (今は読み込んだ
  モデルの設定でしか動かない)。`ugoe sample avatar` の見本に `Effects::standard()` と呼吸、パラメータグループを
  入れる (今の見本は目パチも呼吸も動かない)。プレビューで気に入った姿を表情やキーとして取り込む操作。
  リップシンクの音量を音声やマイクから与える。
