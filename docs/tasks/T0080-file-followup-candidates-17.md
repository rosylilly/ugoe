### ADR 0031 の平方根の例外 (T0193) に新しい ADR が要るか

- **要らないと判断した。** 起票していない。理由:
  - ADR 0031 の「数学関数は `libm` に寄せる」の目的は「`std` の有無でも OS でも、同じ入力から同じビット列」。平方根は IEEE 754 で正しく丸めると
    決まった演算で、`std` の `f32::sqrt` (命令) と `libm::sqrtf` は同じビット列を返す (T0193 が wasm で 2^32 通りすべてを比べて不一致 0、
    単体テスト `sqrt_matches_libm_bit_for_bit` が固定する)。決定の目的と結果を変えないので「覆す」には当たらない。
  - 「検討した代替案」で退けた「`std` があれば `std`」は、OS の数学ライブラリで結果が変わるのが理由で、正しく丸めると決まった平方根には当たらない。
    追記にその理由が書いてある。
  - ADR 0031 は既に、決定を具体にする追記 (T0182・T0491・T0494) を重ねる形で運用している。
- 見直すきっかけ (メモだけ): 平方根以外の関数 (`sin`・`powf` など) を `std` や近似に替えたくなったときは、結果のビット列が変わるので新しい ADR が要る。
