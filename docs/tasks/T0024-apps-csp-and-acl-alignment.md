# T0024: 3 つのアプリの CSP と許可の細部を揃え、ビューアのコマンドの一覧を acl.rs にする

## 目的

エディタ (T0686)・ビューア (T0727)・スタジオ (T0820) が CSP とコマンドの許可を別々に入れたので、細部が揃っていない。

- スタジオは `src-tauri/src/acl.rs` にコマンドの一覧を置き、`build.rs` が `include!` して、`generate_handler!` と capabilities と CSP の要点の
  一致をテストする。ビューアはこの形になっていない (T0727 の候補)。
- スタジオに `frame-ancestors 'none'` が無い。`worker-src`・`font-src`・`mediastream:` は、使っていないアプリでは外すか、3 つで揃える (T0820 の候補)。
- ビルドが作る `src-tauri/permissions/autogenerated/` の gitignore の置き場所がアプリごとに違う。

## 受け入れ条件

- [x] 3 つのアプリの CSP と capabilities を表にして違いを洗い出し、揃えた (違いを残すものは理由を docs に書いた)
- [x] ビューアのコマンドの一覧を `src-tauri/src/acl.rs` に置き、`generate_handler!`・`COMMANDS`・capabilities・CSP の一致をテストする (スタジオと同じ形)
- [x] `autogenerated/` の gitignore を同じ置き場所にした
- [x] e2e (T0022 の CSP の違反の検査があればそれも) で 3 つのアプリが動く
- [x] `just ci` が通る

## メモ

- T0019 で起票した (元の候補: T0727 のビューアの acl.rs、T0820 の CSP と許可の細部)。
- T0024 (やったこと):
  - 3 つの `app.security` を表にした (docs/architecture.md#webview-の-csp-とコマンドの許可)。違いは、エディタ・スタジオだけの
    `worker-src 'self' blob:`・`font-src 'self' data:`・`media-src` の `mediastream:`、ビューアとエディタだけの `frame-ancestors 'none'`、
    値の並びの違い (`data: blob:` と `blob: data:`、`'self'` の位置) だった。
  - CSP は 3 つで同じ値にした。`worker-src`・`font-src`・`mediastream:` はどのアプリも使っていないので外した (Worker を作るコードは
    アプリにも packages/ にも MediaPipe の vision_bundle にも無い。`@font-face` も無い。カメラは `srcObject` の MediaStream で CSP の対象外)。
    スタジオに `frame-ancestors 'none'` を足した。各アプリの `acl.rs` のテスト `content_security_policy_is_the_same_in_every_app` が
    自分と他の 2 つの `app.security` が同じことを確かめる (エディタの `worker-src` の検査は外し、`frame-ancestors` の検査を 3 つに足した)。
  - ビューアのコマンドの一覧を `src-tauri/src/acl.rs` に移し (`build.rs` が `include!`)、エディタと同じテスト (`generate_handler!` と
    `COMMANDS`・capability が全部を許す・`main` だけ・CSP の要) と、webview に `dialog:*` を渡していないことのテストを足した。
  - 生成物の gitignore はルートの `.gitignore` に揃えた (スタジオの `gen/schemas/`・`permissions/autogenerated/`・`src/lib/wasm/generated/` を
    移し、`apps/studio/.gitignore` を消した)。エディタの `src-tauri/.gitignore` (`/binaries/`、sidecar) はビルドの生成物ではないので残した。
  - 文書: docs/architecture.md (CSP の表・capabilities の表・違いを残す理由)、docs/editor.md、apps/viewer/README.md、apps/studio/README.md。
- 違いを残したもの (理由は docs/architecture.md): ビューアだけ webview に dialog の権限が無い (バックエンドがダイアログを開いてパスを覚える)、
  エディタだけ opener (ヘルプと規約の URL)、スタジオの出力ウィンドウは受け手のコマンドだけ。
- 確かめたこと: `just e2e` (Linux・WebKitGTK、同梱したページのデバッグビルド) で 3 つとも通った (エディタ 10・ビューア 6・スタジオ 12。
  画像からの MediaPipe のトラッキングと「has no CSP violations」を含む)。
- 確かめていないこと: Windows (WebView2) と macOS (WKWebView) で、`worker-src`・`mediastream:` を外しても実物のカメラでトラッキングが動くこと
  (Linux の e2e にカメラは無い)。
- 起票の候補: エディタ・スタジオもファイルのダイアログをバックエンドで開き、コマンドが読み書きできるパスを利用者が選んだものに絞る
  (ビューアの `FileAccess` の形。今はエディタの `write_json_file`・`write_png_file` などは webview から渡されたパスに、拡張子だけを確かめて書く)。
