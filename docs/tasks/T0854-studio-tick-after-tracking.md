# T0854: スタジオ: トラッキングが届いたら次の刻みを早める

## 目的

スタジオでは、操作ウィンドウがカメラのトラッキングの値を IPC で指揮役に送り、指揮役は決まった間隔の刻み (30・60・120 回/秒) で
`Puppet::update` を回して受け手に配る。値が刻みの直後に届くと、次の刻みまで (60 刻みで最大約 17 ms) 待つので、カメラからの遅れは
ビューアより「IPC の 1 往復 + 最大 1 刻み」多い (ADR 0028 の 3. の「遅れ」、docs/studio.md#入力 の「次の刻みを早める調整はしていない」)。
値が届いたら次の刻みを前に寄せて、この「最大 1 刻み」を縮める。

刻みの時刻がずれても、指揮役は実測の `dt` を配り受け手はその `dt` で物理を回すので、受け手どうしの形は揃う
(docs/studio.md#刻みの速さと正確さ)。崩れうるのは動きの滑らかさ (`dt` の揺れ) と負荷なので、そこを測って決める。

### やり方の候補 (作業者が測って選ぶ。公開の形は変わらないので利用者の判断は要らない)

- **a. 位相を合わせる:** 値が届いたら、次の刻みの予定をその時刻 (+ 小さな余裕) へ寄せる。刻みの速さは変えず、カメラ (30 / 60 fps) の
  フレームの直後に刻みが来るように少しずつ揃える。`dt` の揺れが小さい。
- **b. すぐに刻む:** 値が届いたら、前の刻みから一定の間隔 (例: 刻みの間隔の半分) 以上経っていればすぐ刻み、次の予定をそこから数え直す。
  遅れは最も小さいが、カメラと刻みの速さが違うと `dt` が揺れ、刻みの速さが設定を超えうる。

推奨は a (滑らかさを崩さずに、遅れの平均を下げる)。

## 受け入れ条件

- [ ] 変える前に、値が届いてから刻みで使われるまでの待ち (平均と最大) を測る仕組みを入れ、偽のトラッキング (一定の間隔で値を送る
      テストか、操作ウィンドウの記録の再生) で、30・60・120 刻みとカメラの 30・60 fps の組で測ってメモに書いた
- [ ] 刻みのスレッド (`lib.rs` の `run_ticks`) と刻みの時刻の決め方 (`pacing.rs`) に、値が届いたら次の刻みを前に寄せる調整を入れた。
      時刻は引数で受け取る形を保ち (`pacing.rs` は時計とスレッドを持たない)、単体テストで、届いた時刻に対して次の刻みがどこへ動くか・
      刻みの速さが設定を超えないこと・届かなくなったら元の間隔に戻ることを確かめた
- [ ] 変えた後に同じ組で測り直し、待ちが縮んだことと、`dt` の揺れ・負荷の表示 (実際の刻みの速さと最も長い間隔) が注意を出さないことを
      メモに書いた。外部 API のパラメータの上書きや、トラッキングを使わないとき (待機モーションだけ) の刻みが変わらないことも確かめた
- [ ] docs/studio.md#入力 の「次の刻みを早める調整はしていない」の行と、#刻みの速さと正確さ を直した
- [ ] `just ci` が通る
