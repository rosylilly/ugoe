# T0612: ミラーと深度からの回転のアルゴリズム

## 目的

`docs/spec/keyform-inference.md` のミラー (頂点の対応付け・反転) と深度からの回転を実装する。

## 受け入れ条件

- [x] 頂点の対応付けが許容距離を超えたらエラーと対応しない頂点の一覧を返す
- [x] ワープの制御点の列の反転、回転デフォーマの角度の符号反転のテストがある
- [x] 深度からの回転で、中間・斜めのセルが式どおりになるテストがある
- [x] `ugoe render` で振り向きを目視確認した結果をメモに書く
- [x] `just ci` が通る

## 参考

- `docs/spec/keyform-inference.md#ミラー`
- `docs/spec/keyform-inference.md#深度からの回転`

## メモ

- API: `mirror_keyforms(model, source, target, &MirrorOptions)` と `infer_depth_rotation(model, target)`。どちらも `InferReport` (書いたセル) を返し、エラーのときはモデルを変えない。
  格子の軸の扱いは `grid.rs` (`Layout`) に切り出し、加算合成の本体 (`combine`) を値の列の上で動くようにして深度からの回転と共有した。
- ミラーの決めたこと (仕様に追記済み):
  - 先は元の `mirror` の相手 (省略・自分自身なら元自身) でなければエラー。格子の軸は 1 対 1 に対応しなければエラー。
  - メッシュは先の頂点ごとに、反転した元の最も近い頂点を対応させる。ワープは位置を見ず列の反転で対応させる。
  - 許容距離の既定 1px は親の座標系に換算する (ワープの親は基準の制御点の外接矩形の長辺、回転の親は拡大率)。
  - 自己対称 (元 = 先) では、自分自身に写るセルと、元が `derived` のセルは書かない (何度実行しても同じ)。
    `overwrite_authored` を付けると左右とも `authored` のセルは入れ替わる (仕様に明記)。
- 深度からの回転の決めたこと (仕様に追記済み):
  - 角度は `(値 − default) × angle_scale`。正の yaw で手前が右、正の pitch で手前が上へ動く向きに回転行列を定めた。
  - `Rot(c)` (基準のセルを回した形) に、`authored` のセルと `Rot` の差を加算合成で広げたものを足す。
    手直しがなければ全セルが式どおり、`yaw` / `pitch` 以外の軸は加算合成で足し合わさり、`AngleX=30` の手直しは斜めにも入る。
  - 親がワープのメッシュ・ワープはエラー (`NonAffineParent`)。親が回転デフォーマなら深度を拡大率で割って局所座標の単位に直す。
- 目視確認: `cargo run -p ugoe-rigging --example depth_face -- <json>` で、4×4 の顔のワープ (中央が 48px 手前の楕円体に近い深度) と
  子のメッシュ (輪郭・目・鼻・口) を作り、右目の `AngleX` の格子を左目からミラーで作った。`ugoe render` で AngleX = ±30, ±15、
  AngleY = ±30、(30, 30)、(30, −30)、(−15, −30) を描いて見た。
  - 良かった点: AngleX 正で目鼻口が右へ寄り、顔の右側が縮んで振り向いて見える。負は左右対称に逆。AngleY 正で上、負で下を向く。
    中間 (±15) は端の約半分。ミラーした右目は左目の手付けの動き (奥へ回る側の目が細くなる) を正しく左右反転していた。
  - 気になった点 1: 当初の順 `R_x(pitch)·R_y(yaw)` では、斜め (30, 30) などで目の線が約 16° 傾き、首をかしげたように見えた。
    レビューで `R_y(yaw)·R_x(pitch)` (pitch を頭自身の軸で先に回す) に決め、仕様と実装を変えた。描き直すと、斜めでも
    目の線と口は水平のままで、顔全体が上下・左右に向きを変えるだけになった (縦の線は少し傾く)。
  - 気になった点 2: 輪郭が矩形のまま深度を与えたので、辺の中点 (深度 34px) が角 (0) より大きく動き、振り向いた側と逆の辺がへこむ。
    深度の作り方 (輪郭の深度を 0 に近づける) の問題で、アルゴリズムの誤りではない。深度の塗り方の指針をエディタ・T0505 で扱うとよい。
- 後続の候補: 親がワープの要素の深度からの回転 (親の基準の格子で局所的にアフィン近似する)、ミラーでの `depth` の写し、
  エディタのコマンド (`MirrorKeyforms` / `InferKeyforms { method: depth_rotation }`、T0611)。
