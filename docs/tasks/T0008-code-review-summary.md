# T0008: コードレビュー: 横断の所見のまとめと後続の整理

## 目的

M9 の各レビューのタスクがメモに残した「横断」の所見 (複数のクレートやアプリにまたがるもの) と、起票された後続のタスクを整理する。
同じ種類の問題が複数の場所にあれば 1 つのタスクにまとめ、規約や手順に足すべきことを文書に反映する。

## 受け入れ条件

- [x] 各レビューのタスクのメモの「横断」を読み、種類ごとにまとめた表を docs/workflow/code-review.md の末尾 (「M9 の結果」) に書いた
- [x] 重複した後続のタスクを 1 つにまとめた (まとめた側を残し、もう一方は理由を書いて閉じる)
- [x] 繰り返し見つかった種類の誤りを、AGENTS.md・docs/workflow/code-review.md の観点・lint や検査のスクリプトで防げるかを検討し、防げるものはそうするか起票した
- [x] docs/roadmap.md の M9 に、後続のタスクの一覧と M9 の完了の判断を書いた
- [x] `just ci` が通る

## メモ

### やったこと

- **横断の表:** 32 のレビューのメモの「横断」を読み、docs/workflow/code-review.md の末尾「M9 の結果」に種類ごとの表 (25 の種類) を書いた。
  所見の数は各タスクの表の行を数えた (高 36・中 176・低 284)。「直した」と書いたものは、各レビューの所見の表で直したことを確かめた。
- **確かめて閉じた横断の所見** (コードは変えていない): C ABI と headless の `texture_count` はモデルの検証の後で確保する (問題なし)。
  MCP の中継 (`ugoe-mcp/src/relay.rs`) は秘密を `Authorization` だけで送りループバックへつなぐ (ureq の転送で漏れない)。`physics_to_json` は未知の値を調べている。
  スタジオの API のテストは空きのポートを使うよう直っている。エディタとスタジオの Tauri のコマンドはエラーをコードで返している (英語の文はビューアだけ。T0729)。
  `Math.min(...配列)` はエディタからは消えた (face-tracking の短い配列だけ)。
- **重複のまとめ:** T0145・T0318 → T0141、T0694 → T0698、T0697 → T0932 (閉じた側は status: done とメモ、残した側は受け入れ条件・crates:・depends_on を広げた)。
  T0323 はデータと呼び出す場所が違うのでまとめず、depends_on に T0141 を足して方針に揃えるようにした。3 つのアプリの同じ所見
  (T0685〜T0687・T0726〜T0728・T0819・T0820) は、アプリごとに範囲が違うのでまとめず、各タスクのメモに「先に終えたものの形に揃える」と書いた。
- **起票 (横断の所見で既存のタスクに無いもの):** T0009 (PNG のデコードを 1 か所に)、T0010 (ホストから来る数の扱いの表)、T0011 (アプリのファイルの扱いの残り)、
  T0012 (格子と画素の積のあふれ)、T0013 (CI の feature と Windows・macOS)、T0014 (editor-core の削除の後始末)、T0015 (検証エラーの列)、
  T0016 (テストの一時ディレクトリ)、T0017 (`missing_docs`)。T0018・T0019 は使っていない。

  - AGENTS.md の「コード」に「繰り返し見つかった誤り (M9 のコードレビュー)」(NaN・時間のループ・確保と積・Tauri のコマンド・非同期の開始と停止) を足した。
