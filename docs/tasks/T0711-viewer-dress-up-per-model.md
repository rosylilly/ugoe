# T0711: ビューア: 付けているモジュールの組をモデルごとに覚える

## 目的

利用者の要望 (T0706 の後続の候補)。モデルを開き直したときに、前に付けていた衣装の組を戻せるようにする。

## 受け入れ条件

- [x] モデルごとに、読み込んだモジュール (ファイルの場所) と付けていた組を覚え、開いたときに戻すか尋ねる (または自動で戻す設定)。モデルを見分ける鍵は T0709 と揃える
- [x] 見本 (T0710) を切り替えたときや別のモデルを開いたとき、前のモデルのモジュールが一覧に残ったまま外れる (T0706 からの振る舞い) のを、モデルごとの組の覚え方に合わせて整理する (T0710 の後続の候補)
- [x] モジュールのファイルが見つからないときの扱い。覚える数の上限と古いものの削除。壊れた値でも落ちない
- [x] Vitest とヘッドレスのブラウザで確かめる。README を更新する
- [x] `just ci`・ビューアのビルドが通る

## 参考

- `docs/tasks/T0706-viewer-dress-up.md`・`docs/tasks/T0709-viewer-light-per-model.md`

## メモ

### やったこと

- **モデルの鍵 (T0709 と共有):** `apps/viewer/src/lib/modelMemory.ts`。`ModelIdentity = {name, fingerprint, location?}`。
  `location` は読み直せる場所 (`path:<絶対パス>` = Tauri のダイアログ・起動時の引数、`sample:<パス>` = 同梱の見本、`url:<URL>` =
  ブラウザの `?model=`)。`host.ts` が読むときに `ModelFile.location` に入れ、`readFileAt` で読み直す (`path:` は
  `ViewerHost.readPath`。ブラウザには無い)。`fingerprint` は長さと 2 つの 32 ビットのハッシュ (同期・暗号ではない)。
  **場所が同じか指紋が同じなら同じモデル** (`sameModel`)。名前は比べない。`ModelMemory<T>` は localStorage の 1 キーに最近使った順で
  上限付きに覚え、`get` (場所を優先、次に指紋)・`set`・`delete`・`models`。壊れた JSON・違う版・形の違う項目・例外を出す `parse`・
  使えない localStorage でも落ちない。README の「モデルごとに覚える (T0711)」に書き、T0709 のタスクファイルの参考にも足した。
- **組を覚える:** `dressUpMemory.ts` (`ugoe-viewer.dress-up`。20 体まで、1 体 64 モジュールまで)。モジュールの名前とファイルの鍵、
  付けていたもの (合成の順)。着せ替えを操作するたびに覚え直し、何も読み込んでいなければ忘れる。中身は覚えない。
- **戻す:** モデルを開いたとき (別のモデル、または同じモデルを見本のようにモジュールと一緒に開き直したとき)、覚えている組と違えば
  パネルで「前にこのモデルに付けていた組があります: … [戻す] [今回は戻さない]」。「前の組を自動で戻す」(`ugoe-viewer.dress-up.auto-restore`)
  なら尋ねずに戻す。モジュールは読み込み中 (名前) → このセッションで読んだ中身 (指紋、32 個まで) → 覚えた場所の順に探す。
- **ファイルが見つからないとき:** 場所から読めない・場所が無い (ドロップとブラウザで選んだファイル) ものは戻さず、パネルに
  「前に付けていた「X」(x.ugoemod) は、ファイルの場所が分からないため戻せません。もう一度開いてください」などと出す。このとき
  覚えている組は変えない (開き直してから戻せる)。
- **見本の切り替え・別のモデル (追記の項目):** 別のモデルを開くと、読み込んでいたモジュールを一覧から除く (`unload_module`)。
  T0706 の「一覧に残ったまま外れる」はやめた。前のモデルの組は覚えてあるので、戻るときに尋ねる。同じモデルを開き直すときは
  残して wasm が付け直す (T0706・T0124 の警告の経路は変えていない)。開けなかったときは除いたモジュールを戻す。
  モデルを開く前に読み込んだモジュールは残す。モデルとモジュールを一緒に開く経路は `Player.load(model, modules)` にまとめた
  (`samples.ts` の `openSample` は `target.load(model, modules)` を呼ぶだけに変えた。`SAMPLES` の定義は変えていない。
  App のドロップも同じ)。
- GPU の作り直しでは組を覚え直さない (`#quiet`)。`dressUp.ts` (T0124 の構造化された警告) は触っていない。
- Vitest: `modelMemory.test.ts` (8 件)・`dressUpMemory.test.ts` (7 件)、`samples.test.ts` を新しい `load` の形に。
- 文書: `apps/viewer/README.md` (構成・「着せ替え」の開き直しの節・「付けていた組を覚える」・「モデルごとに覚える」)、
  `docs/manual/dress-up.md` (「モデルごとに組を覚える」)。

### 確かめたこと

- `just ci`・`vite build`。
- ヘッドレスの Chrome (SwiftShader の WebGL2、ビルドした `dist/` を `vite preview`) で、見本の「着せ替え」→ TwinTails に差し替え →
  「アバター」(モジュールが一覧から消え、パネルが隠れる) → 「着せ替え」(尋ねる → 戻すで TwinTails)、同じ見本の開き直し、ページの
  読み直し後、「今回は戻さない」(覚えた組は残る)、自動で戻す、見本のモデルをドロップ (指紋で同じモデル。見本の場所からモジュールを読む)、
  モデルとモジュールのドロップ → 別のモデル → 戻す (このセッションの中身から)、ページを読み直した後の「場所が分からない」の知らせと、
  開き直して付けられること、壊れた localStorage の値 2 通り。スクリプトとスクリーンショットは scratchpad の `T0711/`
  (`check.mjs`、`shots/01-avatar-cleared.png`・`02-offer.png`・`03-restored.png`・`04-unavailable.png`)。

### 確かめていないこと・後続の候補

- Tauri (WebKitGTK) のウィンドウ、`path:` から読み直す経路 (`read_model_file`) は動かしていない。`.deb` のビルドもしていない
  (バックエンドは変えていない)。
- GPU を失ったときの付け直し: `WEBGL_lose_context` では WebPuppet が失ったと判断せず作り直しが起きなかったので、コードを読んだだけ。
- Tauri でもドロップしたファイルは場所が分からない (`dragDropEnabled: false` で File API を使うため)。Tauri のドロップのイベントで
  パスを受け取れば、ドロップしたモジュールも起動し直した後に戻せる。
- 覚えた組を一覧で見る・消す操作 (「このモデルの組を忘れる」) は無い。T0709 の「既定に戻す」と一緒に考えるとよい。
