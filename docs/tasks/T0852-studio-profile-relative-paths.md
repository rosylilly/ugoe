# T0852: スタジオ: プロファイルの相対パス (判断が要る)

## 目的

スタジオのプロファイルは、シーンのモデル・着せ替えのモジュール・背景の画像・ホットキーの着せ替えのモジュールを **絶対パス** で持つ
(ADR 0028 の 4.「モデルのパスは絶対パスで持ち、見つからなければ選び直させる」、docs/studio.md#プロファイルの形式)。
そのため、プロファイルとモデルを 1 つのフォルダにまとめて人に渡しても (配信の見本・別の計算機への引っ越し)、受け取った側では
すべてのシーンで選び直しになる。相対パスでも持てるようにして、フォルダごと渡せば開けるようにする。

**判断が要る** (ADR 0028 の決定を覆す。プロファイルの形式の意味が変わる)。作業者は下の案から勝手に選ばず、利用者に確かめてから進める。
リリース前なので、プロファイルの版 (`version: 1`) は上げず、古い形の読み替えも書かない (利用者の方針)。

### 案

- **A. 読むときは相対パスも受け付け、書くときはプロファイルのフォルダの中のファイルだけ相対にする:** 相対パスはプロファイルの
  ファイルのあるフォルダを基準に解く。保存のときは、ファイルがプロファイルのフォルダ (とその下) にあれば相対パス (区切りは `/`)、
  外にあれば絶対パスで書く。別の場所へ「名前を付けて保存」したら、新しい場所を基準に書き直す (外に出たものは絶対パス)。
- **B. 読むときだけ相対パスを受け付ける:** スタジオは今までどおり絶対パスで書く。人に渡す見本は手で書き換える。実装は小さいが、
  スタジオで保存し直すと絶対パスに戻る。
- **C. 書き出しの操作を足す:** 「フォルダに書き出す」で、プロファイルと使うファイル (モデル・モジュール・画像) を 1 つのフォルダに
  写し、相対パスで書く。渡しやすいが、ファイルを写す操作と、名前のぶつかり・大きさの上限・許可 (`access.rs`) の扱いが増える。

### 推奨

A。利用者は何もしなくても、プロファイルの隣か下にファイルを置けば渡せる形になる。C は要望が出たら A の上に足せる。
相対パスは `..` を含まないもの (プロファイルのフォルダの下だけ) に限り、`..` を含むもの・ドライブやルートから始まるものは
読めないパスとして扱う (受け取ったプロファイルが、プロファイルのフォルダの外のファイルを相対パスで指せないように。
絶対パスは今までどおり受け付ける)。
