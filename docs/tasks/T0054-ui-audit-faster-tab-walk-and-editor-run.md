# T0054: ui-audit: Tab のたどりを速くし (PNG を Node の側で読む)、エディタの 13 組を前面の 600 秒に収める

## 目的

`just ui-audit --only editor` は 13 の組で 10 分ほどかかり、エージェントが前面で流す Bash の上限 (600 秒) に収まらない。
T0048・T0049・T1651・T1657 などのワーカーは毎回 `--variants` で分けて流している。T0045 で足した画像によるフォーカスの印の判定は、
止まりごとに 2 回撮り、ページの中で PNG を読むので 1 回のたどりを 4〜6 秒から 18〜42 秒に延ばした。

## 受け入れ条件

- [x] Tab のたどりで撮った PNG を Node の側で読む (zlib で展開する小さな読み手か、既にある依存。新しい依存を入れるなら理由をメモに書く)。
      判定 (`focusChange`・`imageRing`) の結果が前と同じことを、単体テストと `--compare` で確かめた
- [x] エディタの全部の組を 1 回の `just ui-audit --only editor` で、ほかの作業の無い機械で 600 秒より十分短く (目安 8 分以内) 流せる。
      組を並行に流す (ブラウザのページを組ごとに分ける) か、組ごとの場面を減らすかを決め、理由をメモに書いた
      (場面を減らすなら、どの組でどの場面を見なくなるかを README に書く)
- [x] 前と後の所要時間 (たどり 1 回と、エディタの全体) をメモに書いた
- [x] `--compare` で前と後の指摘が同じ (増減があれば理由を書く)。`just ui-audit-check` が通る
- [x] tests/ui-audit/README.md (実行の時間・並行の数の指定があればその口) と docs/testing.md を直した
- [x] `just ci` が通る

### やったこと (T0054)

- `lib/png.mjs`: Chrome の撮る PNG (8 ビット・インターレースなし・グレー・RGB・それぞれのアルファ付き) を読む小さな読み手
  (`node:zlib` の `inflateSync` で展開し、5 つのフィルタを戻す)。新しい依存は入れていない。`lib/walk.mjs` の `focusDiff` が
  Tab の止まりの前と後の PNG を Node の側で読み、`page-checks.js` の `focusChange` (変えていない) で数える。ページの中の
  `focusDiff` は消した (`decodePng` は `pixelAudit` が使うので残した)。
- 単体テスト (`test/png.test.mjs`): 5 つのフィルタ・IDAT の分割・色の型ごとの広げ方・読めない PNG の例外と、Node の側で読んだ差が
  画素を直に比べた `focusChange` と同じこと (devicePixelRatio 2 の換算も)。
- 確かめ (コミットしていない一度きりの比べ): Chrome の撮った PNG 31 枚 (エディタの場面 27 枚と、dpr 1・2 で撮った全体と切り抜き) を、
  ページの中の `createImageBitmap` と Node の読み手で読み、画素がすべて同じだった (撮った PNG はすべて色の型 2 (RGB))。
- **組を並行に流す方を選んだ** (`run.mjs` の `--jobs N`。既定 3)。組ごとに別のブラウザのコンテキスト・ページ・偽のホストを使っていて、
  組どうしで共有する状態が無い (静的サーバは読むだけ) ので、並行にしても場面は変わらない。場面を減らすと見なくなる所が出るので選ばなかった。
  結果は組の順に並べ直すので、報告・`summary.json`・`tab.txt` は並行の数によらない。アプリごとの所要時間をログに出す。
  既定の 3 は、ほかのワーカーが同じ機械でビルドや ui-audit を流していても場面の待ち (`waitForTimeout`) が足りるように控えめにした。
- README (実行の `--jobs`・「時間と並行の数」・流れ・たどりの時間と PNG の読み方) と docs/testing.md (時間) を直した。
