# T0045: ui-audit: Tab の止まりのフォーカスの印を、フォーカスの前と後の画像の差で判定する

## 目的

`just ui-audit` の `focus` の検査は、自分と 2 つ上の祖先の `outline`・`box-shadow` を見てフォーカスの印の有無を決めている (`lib/walk.mjs`)。
地の色や枠の色だけを変える印や、3 つ以上上の祖先に付く印は見逃したり誤って数えたりする。フォーカスの前と後の画像の差で、印が見えるかを判定する
(T0915 の任意の候補。T0918 の候補)。

- [x] 今の CSS の判定と画像の判定が食い違う止まりを 3 つのアプリで洗い、メモに書いた (どちらが正しいかも)

- [x] `just ci` が通る

### やったこと (T0045)

- `lib/walk.mjs`: Tab の止まりごとに、止まりの矩形を 6px 広げた範囲を、フォーカスのある今 (後) と `blur()` した後 (前) に撮り、
  フォーカスを戻す。差は `page-checks.js` の `focusChange` (RGB の差 16 以上を「変わった」、前と後の比 3:1 以上を「はっきり変わった」)
  で数え、`imageRing` で決める (はっきり変わった画素が幅と高さの和の面積に届けば印あり、変わった画素だけが届けば `faint focus ring`、
  どちらも届かなければ `no focus ring`)。画面の外の止まりは CSS の判定のまま。たどる間は欄のカーソル・選択の地・ツールチップを隠す。
  閾値と理由は tests/ui-audit/README.md の「フォーカスの印の判定」。
- `tab.txt` に CSS の判定と食い違う止まりの印 (`(css: ring)`・`(css: none)`)、フォーカスを戻せなかった止まり (`FOCUS-LOST`) を出し、
  印ありでない止まり・食い違う止まりの前と後の画像を `<組>-focus-<番号>-before.png`・`-after.png` に書く。run.mjs はたどりの時間をログに出す。
- テスト (`just ui-audit-check`): 画素の数え方・印の決め方・範囲の切り方・報告の文。

### CSS の判定と画像の判定の食い違い (3 つのアプリ、`en-light-wide` と `en-dark-forced-wide` の 120 の止まりずつ)

- 食い違いは 1 つだけ: エディタの `en-dark-forced-wide` の止まり 10、パーツの木 (`div[tree] "Parts"`)。CSS は輪あり
  (`.tree:focus-visible` の `outline`)、画像は `faint` (変わった画素は要る量の 4 倍あるが、3:1 以上の画素は 0.54 倍。比の最大 8.73 は角の丸みの所)。
  強制色では `.tree` の透明な 1px の枠が文字の色 (白) で描かれ、`outline-offset: -2px` の輪がその枠の上に重なって、白が強調の色
  (水色。白との比 1.2) に変わるだけになる。印は見えるが「前と後の比 3:1」には届かないので、**画像の判定が正しい** (WCAG 2.4.13 の考え方。
  2.4.7 の「見える」だけなら満たす)。ライトの組では輪がはっきり出る (食い違いなし)。
- ほかの止まり (6 組 × 120) は両方とも印あり。印ありの止まりの、はっきり変わった画素は要る量の 1.5 倍以上 (少ないのはビューアの光の向きの
  つまみ 1.5 倍・スタジオの Sensitivity の欄 1.7 倍・エディタのライセンスの textarea 2.0 倍。前と後の画像で輪が出ていることを目で確かめた)。
  今のアプリには、CSS の判定が見逃す形の印 (地の色だけ・3 つ以上上の祖先) で問題になる止まりは無かった。

### `focus` の数と実行の時間

- `focus` の数 (別のもの): 前 editor 0・viewer 0・studio 0 → 後 editor 1 (上の `faint focus ring`)・viewer 0・studio 0。
  `--variants en-light-wide,en-dark-forced-wide` (Tab をたどる 2 つの組だけ。`focus` はこの 2 つの組からだけ出る) を `--compare` で比べた。
- 時間: 1 回のたどり (120 の止まり) が 4.4〜5.9 秒 → 18〜42 秒 (ほかのワーカーと並べて流した機械の負荷 15〜22 で、揺れが大きい)。
  止まりごとに撮るのが 2 回 (それぞれ 40〜70ms) と、ページの中で PNG を読むのに 40ms ほど。3 つのアプリで 6 回たどるので、`just ui-audit` は
  2〜3 分ほど延びる (上の絞った実行で 3 分 39 秒 → 6 分 40 秒)。CDP の `Page.captureScreenshot` を直に呼ぶ・rAF を待たないも試したが、
  速くならなかった (rAF の待ちは外した)。

### やらなかったこと

- 範囲 (止まりから 6px) の外に出る印 (大きな祖先の遠い辺)。範囲の中の辺で足りることが多いので見ていない。
- 全部の組 (`just ui-audit` の 3 つのアプリのすべての場面) は流していない (Tab をたどるのは 2 つの組だけで、ほかの場面は変えていない)。

### 起票の候補

- エディタのパーツの木 (`.tree:focus-visible`) の強制色の印: `outline-offset: -2px` の輪が強制色で描かれる枠に重なり、色が変わるだけになる。
  強制色で `outline-offset` を外に出す (または枠を `transparent` のまま描かない) と 3:1 の変化になる。`apps/editor/src/lib/panels/TreePanel.svelte`。
- たどりの速さ: PNG を Node の側で読む (zlib で展開する小さな読み手) と止まりあたり 40ms ほど減らせる見込み。
