# T0876: スタジオの e2e: 重い検出のトラッキングを長く流せるようにする

## 目的

T0871・T0873 で、スタジオの e2e (tests/e2e/specs/studio.test.mjs の T0812 の手順) は「トラッキングの待ち」の値の数と遅れた値の数を集め、
`tracking.json` の `trackingWaitSummary` に値の数で重みを付けた割合を残すようになった。ところが流す長さ (`TRACKING_MS` = 13 秒) のうち集めるのは
約 7 秒で、値が 17〜18 個しか集まらず、割合が回ごとに 0〜28% と揺れる (T0873 のメモ)。これでは pacing.rs を変えた前後を e2e で比べられない。
普段の `just e2e` の時間は延ばさずに、比べたいときだけ長く流せるようにする。

## 受け入れ条件

- [ ] 環境変数 (例: `UGOE_E2E_TRACKING_MS`) で、重い検出のトラッキングを流す長さを変えられる。既定は今の 13 秒のまま。範囲の外や数でない値は分かるエラーで止める (上限は 120 秒ほど。決めた値と理由をメモに書く)
- [ ] 長く流したときも、判定 (表示が出る・届いた回数・応答の中央値・AngleX が動く) が今と同じ意味になる (届いた回数の下限は流す長さに比例させるか、今の値のままにするかを決めて理由を書く)
- [ ] 長く (例: 60 秒) 2〜3 回流して、値の数と重み付きの割合をメモに書いた。13 秒のときの揺れ (T0873 のメモ: 0〜28%) と比べて、回ごとの揺れが小さくなるか確かめた
- [ ] tests/e2e/README.md と docs/testing.md (e2e の節) に、長く流す方法と、前後を比べるときの手順を書いた
- [ ] `just e2e --only studio` (既定の長さ) が通る
- [ ] `just ci` が通る
