### 実際の AI での 1 回 (MCP で Claude Code が判断する経路。2026-09-30)

利用者の判断で、ADR 0022 の「外部のエージェントに判断を任せる経路」で、このタスクのワーカー (Claude Code、Claude Opus 5.5) 自身が判断した。
外部の API キーは使っていない。利用者の Claude Code の設定 (MCP の登録) は変えず、`ugoe-mcp` (debug ビルド) を stdio で起動して JSON-RPC を
流す使い捨てのドライバ (scratchpad の `T0510/mcp.py`) で呼んだ。画像はドライバが PNG に保存し、Read で自分で見た。

- **流れ:** `import_psd` → `get_psd_layers` ×3 (24 レイヤー、8 枚ずつ) → 画像を見て分類を決める → `set_layer_labels` → `get_rig_guide` →
  値を決める → `propose_rig` → `apply_proposal` → `save_project` (`.ugoe` も) → `propose_edit` (`update_avatar_profile`、レベル 1・名前・作者)
  → `apply_proposal` → `save_project`。`ugoe validate --profile avatar` は「claims level 1, satisfies level 1 / ok」。
  ドライバは呼び出しごとにサーバを起動し直すので、判断を渡す段で `import_psd` と `set_layer_labels` を呼び直している (取り込みは決定的)。
- **分類 (名前の規則の既定との比較):** 24 レイヤーすべてで、画像を見た判断は名前の規則のラベル・左右と同じだった (See-Through の英語の名前は正確)。
  変えたのは確からしさだけ: `handwear-l` / `handwear-r` は 0.6 (実際は二の腕の肌・網の袖・上着の袖がまとまった腕全体で、`handwear` と `arm` の
  間。語彙の説明「gloves, sleeves or cuffs」に近いので `handwear` のまま)、`topwear` は 0.8 (肩と胴の肌を含む)。リグには影響しない
  (どちらも頭に入らない)。ほかに気づいたこと: `earwear-r` の外接矩形 (幅 311 px) は耳から離れた数画素のごみを含む (見本のメモと同じ)。
  合成画像は開いた目と閉じた目、開いた口と閉じた口が重なって見える (README のとおり)。
- **値 (既定との比較):** `turn_angle_scale` 0.6 (既定 0.7。目の大きい平らなアニメ調の顔なので小さく)、`eye_close_bend` −0.06 (既定 +0.04。
  閉じた目の絵が上に凸の笑った閉じ目なので、つぶれる途中の弧も上に曲げる)、`eye_close_line` 0.7・`mouth_open_height` 0.35 は既定のまま
  (閉じた目の絵・開いた口の絵があるので使われない)。1 回目で検証を通った (問い直しなし)。
- **結果の絵** (scratchpad の `T0510/render/`、`ugoe render`・llvmpipe で 512×512): 中立・`AngleX` ±30 (顔が向いた側へ寄り、後ろ髪が反対に
  見える)・`AngleY` 30・`AngleZ` 30 (頭だけ傾く)・ウインクと開いた口・半目・`Breath` 1・組み合わせ (両目を閉じて口を開け、斜め上を向く。
  笑った閉じ目の絵に入れ替わる)。髪揺れは頭を 0.1 秒で 30 まで向けるモーション (`turn.json`) の 0.15 秒後を物理あり・なしで描いて見比べ
  (`sway-compare-0.75.png`)、後ろ髪の毛先が遅れていることを確かめた (前髪の揺れは 512 px では目で分かりにくい)。どれも自然に見える。
- **量と時間:** ツールの呼び出し 16 回 (最終のコードでの流れ。途中の係数を直す前にもう 1 回、5 回呼んだ)、エラー 0 回。サーバが返した画像は
  26 枚・約 1.97 MB (レイヤー一覧 25 枚 約 1.17 MB、リグのガイドの原画 1 枚 約 0.80 MB)。そのうち自分で見た (Read) のは合成画像と
  サムネイル 10 枚の計 11 枚 (名前と外接矩形で判断できるものは見ていない)。描いた絵は 7 枚見た。サーバの処理は合計約 7 秒 (取り込み 1.5〜3 秒)、
  ugoe-mcp のビルドを含めた実行と判断は約 10 分 (11:05〜11:15)。
- **費用:** この経路は ugoe が API を呼ばないので API の請求はない。エージェント (Claude Code) の利用量として数えられるのは、見た画像 11 枚
  (Claude の画像のトークンは概ね幅×高さ÷750 なので、1024 px の合成画像 1 枚で約 1,400、256 px 以下のサムネイル 10 枚で計 1,000 未満。
  描いた絵 7 枚 (512 px) で計約 2,500) と、ツールの結果のテキスト 約 50 KB。1 回の自動リギングの判断に要るのは数千〜1 万トークン程度と見積もる。
  エディタの中で API を呼ぶ経路なら、同じ判断は分類 1 回 (画像 25 枚) + リグ 1 回 (画像 1 枚) の 2 リクエスト。
- **気づいたこと:**
  - 名前の付いた See-Through の PSD では、分類は名前の規則でほぼ足りる。エージェントの判断が効くのは値 (特に閉じた目の弧の向き) だった。
  - `get_psd_layers` の 8 枚ずつの既定だと、全部を見るのに 3 回呼ぶ。サムネイルを 1 枚の一覧画像にまとめる案 (T0513 の後続の候補) が効く。
  - `ugoe render --param AngleX=30 --time 0.2` では、物理が最初のフレームでその姿に落ち着くので髪は揺れない (`docs/testing.md` の例の
    「頭を 30 にした直後から揺らす」は動的物理では当てはまらない)。揺れを見るにはモーションで頭を動かす。
