# T0617: 推定の使い勝手 (深度の編集と、組み合わせのセルの自動推定)

## 目的

M2 の受け入れテスト (T0616) で見つかった、キーフォームの推定 (ADR 0010) を使ううえでの 2 つの穴を埋める。

1. 既存のメッシュ・ワープに頂点ごとの深度 (`depth`) を設定するコマンドも UI もなく、エディタから深度からの回転を使えない。
2. 新しい格子にキーを足すと、組み合わせのセルも `authored` になるため、推定の前に手で `derived` にする手間がある。ADR 0010 の「端の形だけ作れば、組み合わせは推定される」を満たすには、この手間をなくす必要がある。

## 受け入れ条件

- [ ] 深度を設定するコマンド (例: `SetDepth { target: mesh | warp, depth: Option<Vec<f32>> }`) があり、長さを検査し、深度からの回転のセルを作り直す (`touched`)
- [ ] 深度の簡単な作り方をコマンドまたはエディタの機能として用意する: 一様な値、要素の外形から作るふくらみ (ドーム状) のプリセット、選択した点の値の設定
- [ ] インスペクタに深度の編集 UI がある (プリセット・選択点の値)。ビューポートで深度を色などで確かめられると望ましい
- [ ] `AddKeyformKey` で新しくできたセルのうち、中立でない軸が 2 本以上あるセル (組み合わせのセル) は `derived` (加算合成) とし、その場で推定する。1 軸のセル (端のセル) は従来どおり補間した値の `authored` とする。全軸に中立のキーがない格子では従来どおり。キーを足しても見た目が変わらないこと (T0608 の条件) は保つ
- [ ] `docs/spec/keyform-inference.md` と `docs/editor.md` を更新し、T0616 の受け入れテストから「手で derived にする」手順を取り除く (テストが新しい挙動を確かめる)
- [ ] `just ci`・`just gen` (差分なし)・エディタのビルドが通る
