# T1637: エディタ: 空のプロジェクトと 200% の拡大で、タイムラインと左右の列の大きさを決める (判断が要る)

## 目的

低い・狭い画面で、エディタの中央 (ビューポートとタイムライン) が狭くなる:

- 空のプロジェクトでは、ビューポートの空の状態のボタン (3 つ目) が低い画面で送らないと見えない。タイムラインは使わないのに高さを取る (T0673 の候補)。
- 200% の拡大 (CSS の幅 720px) では中央の列が 260px ほどになり、タイムラインの表のキーの列が 100px ほどしかない (T0675 の候補)。

**判断が要る:** 案:

- A. 空のプロジェクトではタイムラインを自動で畳む (利用者が開いたら覚えた開閉に従う)。狭い窓では左右の列を既定より狭める (列の幅の範囲の下限まで。覚えた幅は変えない)。
- B. 空のプロジェクトではタイムラインを畳む。狭い窓ではタイムラインを畳み、左右の列はそのまま。
- C. 自動では何もしない (区切りで利用者が変える)。マニュアルに狭い画面での勧めを書く。

推奨は、1024×720・200% の拡大 (720×450) の画像で A と B を比べてから書く。

    B にするなら、監査と e2e の手順で先にタイムラインを開く変更が要る。閾値を 900px 未満にすれば 1024px では今のまま開く。
  - **案 C** (自動では何もしない): 画面は前のまま。200% の拡大の空のプロジェクトでは 3 つ目のボタン「Open Sample…」が
    タイムラインに隠れる (送る必要がある)。マニュアルに「狭い画面ではタイムラインを畳む・区切りで列を狭める」を書くだけ。
  - **推奨: B (閾値は 900px 未満。200% の拡大などの本当に狭い窓だけ)。** 理由: A の列を狭める効果は 720px ではほぼ無く
    (`36vw` の上限が先に効く)、1024px ではツリーを削る。200% の拡大の中央の列では、タイムラインを開いても表は窮屈なので、
    畳んでビューポートを確保し、要るときに 1 回押して開く方が損が少ない。空のプロジェクトを畳むのは A・B 共通で、どちらでも入れたい。
