# T0709: ビューア: 光源の設定をモデルごとに覚える

## 目的

利用者の要望 (T0705 の後続の候補)。今は光源の設定がビューア全体で 1 つなので、モデルごとに覚えて、開いたときに戻す。

## 受け入れ条件

- [x] モデルを見分ける鍵 (ファイルのパス・名前・中身の指紋など) を決めて書く。モデルごとの設定がなければ、最後に使った設定 (または既定) から始める
- [x] 覚える数の上限と古いものの削除。壊れた値でも落ちない
- [x] 「このモデルの設定を既定に戻す」操作
- [x] 着せ替えの組の記憶 (T0711) にも「忘れる」操作が無い。光源の「既定に戻す」と揃えて、モデルごとに覚えたもの (光源・着せ替えの組) を忘れる操作を置く (T0711 の後続の候補)
- [x] Vitest とヘッドレスのブラウザで確かめる。README を更新する
- [x] `just ci`・ビューアのビルドが通る

## メモ

### やったこと

- **鍵:** T0711 の `modelMemory.ts` の `ModelIdentity` (場所か中身の指紋が同じなら同じモデル) をそのまま使う。新しい鍵は作っていない。
- **入れ物:** `lighting.ts` の `lightingMemory()` = `ModelMemory<LightingSettings>` (`ugoe-viewer.lighting.models`、50 体まで。1 体 1 KB 足らず)。
  `parseModelLighting` はオブジェクトでない値を読み飛ばし、中の壊れた値は `sanitizeLighting` で直す。壊れた JSON・違う版・例外を出す
  localStorage は `ModelMemory` が覚えていないものとして扱う。
- **覚える・戻す (`player.svelte.ts`):** 光源を変えると (`setLighting`)、開いているモデルの設定として覚える。モデルを開くと (`#recallLighting`)
  覚えた設定があればそれにし (最近使ったものにし、鍵も新しくする)、無ければ **最後に使った設定** のまま (T0705 の `ugoe-viewer.lighting`
  を「最後に使った設定」として残した)。開くだけでは覚えない。既定を「最後に使った設定」にしたのは、T0705 までの使い方 (好みの光源で
  見本を次々に見る) を保つため。
- **既定に戻す:** ライティングのパネルに「このモデル用に覚えた設定」/「このモデル用の設定はまだありません」と「既定に戻す」(`resetLighting`)。
  そのモデルの設定を忘れて「標準」にする (最後に使った設定も「標準」)。覚えておらず既定のままなら押せない。
- **着せ替えの組を忘れる (追記の項目):** 着せ替えのパネルに「このモデル用に覚えた組があります」と「覚えた組を忘れる」(`forgetDressUp`)。
  付けているモジュールはそのまま、尋ねている組は取り消す。次に着せ替えを操作するとまた覚える (組は操作のたびに自動で覚えるため)。
  覚えた組だけがあってスロットもモジュールも無いモデル (尋ねて「今回は戻さない」を押した後など) でも忘れられるよう、
  `dressUpRemembered` のときもパネルを出す (`App.svelte`)。
- Vitest: `lighting.test.ts` に 4 件 (モデルごとに覚える・忘れる・場所と指紋、上限、壊れた値、最後に使った設定に触らない)。
- 文書: `apps/viewer/README.md` (構成・「付けていた組を覚える」・「モデルごとに覚える」の表・「ライティング」)、
  `docs/manual/lighting.md` (「ビューアの光源はモデルごとに覚える」)、`docs/manual/dress-up.md` (「覚えた組を忘れる」)。

### 確かめたこと

- `just ci` (main (T0517) に rebase し、`just wasm` をやり直した後)・`vite build`。
- ヘッドレスの Chrome (SwiftShader の WebGL2、ビルドした `dist/` を `vite preview`) で、A = 「サンプル」→「アバター (ライティング)」、
  B = 別の法線マップ付きのモデル (T0707 の途中の版 `scratchpad/T0707/t.ugoe` をドロップ。場所なし):
  A を開く (標準・覚えていない) → 夕日 (覚えた) → 「アバター」(パネルなし) → B (最後に使った夕日・覚えていない) → 夜のランプ →
  A (夕日) → B (夜のランプ) → ページを読み直して A (夕日) → 「既定に戻す」(標準・A の項目が消える) → B (夜のランプのまま)。
  壊れた値 (壊れた JSON、形の違う項目と、色が `nope`・方位が 1e99 の項目) でもエラーは出ず、前者は最後に使った設定、後者は直した値 (方位 180°)。
  着せ替え: TwinTails に差し替え → 別のモデル → 戻ると尋ねる → 「覚えた組を忘れる」(localStorage の項目が消える、モジュールはそのまま) →
  別のモデル → 戻っても尋ねない。
  スクリプトとスクリーンショットは scratchpad の `T0709/` (`check.mjs`、`shots/01-a-first.png`・`02-a-sunset.png`・`03-b-lamp.png`・
  `04-a-reset.png`・`05-dress-up-remembered.png`・`06-dress-up-forgot.png`)。
  - 見本の `avatar-lit.ugoe` と中身が同じファイルをドロップすると、指紋で同じモデルとみなされ、鍵が場所なしのものに置き換わる
    (T0711 の `ModelMemory.set` の決め方どおり。その後に見本から開いても指紋で見つかる)。

### 確かめていないこと・後続の候補

- Tauri (WebKitGTK) のウィンドウ、`.deb` のビルドはしていない (バックエンドは変えていない)。
- 「既定に戻す」の後、別のモデルを見てから戻ると、そのモデルは最後に使った光源で始まる (覚えていないモデルの規則どおり)。
  「このモデルは常に標準」と覚えたいなら、戻した後で「標準」を押せば覚える。紛らわしければ、戻したときに既定を覚える案もある。
- 覚えたモデルの一覧を見る・すべて忘れる操作は無い (上限で古いものから消えるだけ)。設定の画面を作るときに考える。
- ライティングを受けるのがモジュールだけのモデルで、モジュールを外すとパネルが消え、覚えた光源を「既定に戻す」で忘れられない
  (項目は上限で古いものから消える)。
