- **初めての配信までの手順 (偽のホストの `-first-run` の場面と、見本の場面でたどった):**
  1. 起動 (新しいプロファイル: 名前の無いモデルの無いシーンが 1 つ、どれも配信していない) → 中央の空の状態の「モデルを選ぶ…」、ツールバーの同じボタン。
     迷う所: ツールバーに「保存済み」と出ていた (一度も保存していないのに) → 「未保存」にした。右の「シーンの編集」の頭に
     「このシーンは配信していません [このシーンに切り替える]」が出ていた (モデルの無いシーンで切り替えても何も出ない) → モデルの無いシーンでは出さない。
     名前の欄が空 (一覧は「シーン 1」) → placeholder に表示名。「表情とモーション」に無効の「トラッキング中もモーションを優先する」が出ていた → 設定を右の列へ分けた。
  2. モデルを選ぶ。**行き止まり:** 右の「シーンの編集」の「モデルを選ぶ…」で選ぶと、シーンを更新するだけで配信しない (出力ウィンドウに何も出ず、
     知らせの「このシーンに切り替える」を押す必要があった) → どのシーンも配信していないときは、そのシーンに切り替えて出すようにした
     (ツールバーの「モデルを選ぶ…」は前から切り替え、出力ウィンドウが隠れていれば表示する)。
  3. 出力ウィンドウ: 出力ウィンドウには何も重ねないので、枠・背景・大きさが操作ウィンドウから分からなかった (「枠がありません。ドラッグで動かせます」の文だけ)
     → 「いまの状態」に出力の印、「出力ウィンドウ」のパネルに「いまの大きさ」「枠」「背景」と取り込み方の案内。
  4. 大きさ: 「出力ウィンドウ」のパネルが右の列の「ホットキー」(長い) の下にあり、送らないと届かなかった → 右の列を準備の順に並べ替えた
     (シーンの編集・入力・出力ウィンドウ・ブラウザソース・仮想カメラ、その後にホットキー・モーションの設定・操作 API・負荷・パラメータ)。
  5. 保存: 上の帯の「名前を付けて保存…」(前から。変えた後に出る)。
  6. 入力 (カメラ・マイク): 右の列の 2 つ目 (変えていない)。
  7. 取り込み: 出力ウィンドウのパネルの案内から、すぐ下の「ブラウザソース (OBS)」「仮想カメラ」へ (前は仮想カメラが間に挟まり、取り込みの方法が 3 か所に散っていた)。
- **ダイアログと知らせ (エディタとそろえた):** T0673 はまだ todo なので、エディタの今のダイアログ (`NewModuleDialog`・`ModuleSettingsDialog`・
  `BaseChangeDialog`・`ExternalChangeDialog`・AI の設定) の形にそろえた: 取り消し・保留が先で決定 (`primary`) が並びの最後、設定は下に「閉じる」。
  - 操作 API の承認の知らせ: 「承認」「拒否」「後で」→「後で」「拒否」「承認」(テストを足した)。
  - 設定のダイアログ: 下に「閉じる」(エディタの設定と同じ。言語とテーマはすぐ効くので決定のボタンは無い)。
  - シーンの削除・プロファイルを捨てる・トークンと URL の作り直し・許可の取り消しは、前から `AlertDialog` (取り消しが先・既定のフォーカスも取り消し・Esc で取り消し)
    で、エディタの確かめと同じ。入力とホットキーにダイアログは無い (ホットキーの削除は行の「削除」ですぐ。元に戻すには足し直す。下の候補)。
- **ホットキーの衝突・登録できないとき:** パネルの頭に「n 個のホットキーを登録できません」の `Notice` (warning)、その行に左の線と三角の印と理由
  (前は危険の色の文だけ)。ぶつかりの理由は「ホットキー n と同じキー」(行に番号が無いので分からない) から、相手の操作の名前 (「シーンの切り替え: 雑談」) に。
  キーのボタンから理由を `aria-describedby` で読む (前から)。「いまの状態」のホットキーの印は前から三角になる。部品テストを足した。
- **出力ウィンドウの様子:** `OutputPanel.svelte` (Control.svelte から分けた)・`lib/status.ts` の `outputBadge`・`lib/labels.ts` の `backgroundLabel`。
  OS が大きさを小さくしたときの注意は、補足の文から `Notice` (warning) と印の三角に。単体テストを足した。
  透過は「背景」の欄に、配信しているシーンの背景 (透過・単色・クロマキー・画像) として出す (出力ウィンドウ自体は常に透過で、背景はシーンが決めるため)。

  登録できないホットキーの場面と 960px の組を足した。
