# T1668: エディタ: モーションのグラフで、近いキーの押せる範囲が重なる (200% の拡大で 0 秒と 1 秒のキーが約 2px 重なる)

## 目的

T1662 でエディタの送る枠の行末を `--ugoe-scrollbar-gap` で空けた結果、`en-light-zoom200` でモーションの編集の時刻の軸が 16px 狭くなり、
グラフのキー「Key at 0」と「Key at 1」の押せる範囲 (24px) が約 2px 重なる (ui-audit の `target-size` / 重なりの指摘が 1 件増えた)。
キーの間が 1 秒より近ければ、T1662 の前から重なる種類の問題 (T1662 の候補)。

## 受け入れ条件

- [x] 近いキーの押せる範囲の扱いを決め、理由をメモと docs/ui.md (押せる大きさ) に書いた。案: 行の名前の列の最小 (150px) を縮める・重なるときは押せる範囲を中点で分ける (WCAG 2.5.8 の「間隔」の例外の考え方)・キーを選ぶ代わりの手段 (キーボード) があることを根拠に例外にする
- [x] 決めた形で直し、部品のテストか ui-audit で確かめた
- [x] `just ui-audit --only editor --variants <zoom200 を含む組>` で指摘が増えない (T1662 で増えた 1 件が消える)。`just e2e --only editor` と `just ci` が通る

## 参考

- T1662 のメモ、apps/editor のモーションの編集 (MotionEditor・CurveGraph)

## メモ

- T1662 のワーカーの報告から起票した (2026-10-07)。
- 決めたこと: 押せる範囲が重なる所では、上に描かれた印ではなく **押した所に中心が近い印** をつかむ (押せる範囲を中点で分ける案)。
  押せる範囲そのものは 24×24 のまま。理由 (docs/ui.md#そのほか の「近い印の重なり」に書いた):
  - WCAG 2.5.8 の「間隔」の例外は、押した所がどの部品に当たるかが近さで決まり、狙った部品の周りに余裕があることを求める考え方。
    中点で分けると、印から隣の印までの半分はどこを押してもその印に当たり、上に描かれた印が隣の範囲を奪うことが無い。
  - 押せる範囲を縮めて重ならないようにすると 24px 未満になる (ui-audit の `target-size` も増える)。行の名前の列 (150px) を縮める案は、
    キーの間隔がもっと短いと同じことが起きるので根本の解決にならない。キーボードを根拠に例外にする案は、グラフの印に
    フォーカスが止まらない (`tabindex="-1"`) ので採らなかった。
  - パラメータのスライダーの下のキーの印 (T1634 の `nearestMarkerKey`) と同じ形にそろう。
- やったこと:
  - `timeline.ts` に `nearestMark` (押せる範囲の正方形に合わせ、距離は縦横の大きい方で測る。等しければ先の印) を足し、
    `CurveGraph.svelte` の `onDown` で、押した所に近い印 (キーと取っ手。等しければキー) をつかむようにした。
    重なりは意図したものなので、押せる範囲の `rect` に `data-ui-audit-overlay` を付けた。
  - テスト: `timeline.test.ts` (`nearestMark`) と `CurveGraph.test.ts` (幅 44px で 0 秒と 1 秒のキーが 2px 重なり、上の 1 秒のキーの
    範囲の中の 0 秒に近い所を押すと 0 秒のキーが動く)。後者は直す前に流して、1 秒のキーが動いて落ちることを確かめた。
  - `just ui-audit --only editor --variants zoom200` (92 場面) を、直す前の CurveGraph.svelte を作業ツリーに一時的に戻して撮った基準と
    `--compare` で比べた: +0 -1 ~0 (T1662 で増えた `rect@.graph "Key at 0: 0" is covered by rect@.graph "Key at 1: 8"` が消え、すべて 0 件)。
  - `just e2e --only editor` (筋書き 16) と `just ci` が通った。
- やらなかったこと: ドープシート (MotionEditor の `.diamond`) のキーも近いと押せる範囲が重なり、上に描かれた (後の) キーが取る。
  `position: absolute` なので ui-audit の重なりの検査には出ない。T1666 が MotionEditor を並行して触っているので、今回は触らなかった。
- 起票の候補:
  - ドープシートのキーの印 (`MotionEditor.svelte` の `.diamond`) も、押せる範囲が重なる所では押した所に近いキーをつかむ (`nearestMark` を使う)。
  - ドープシートのキーの印はボタンだがキーボードで押しても選ばれない (`onpointerdown` だけ)。Enter・Space でキーを選ぶ。
