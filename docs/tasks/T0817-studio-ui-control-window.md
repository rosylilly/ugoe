# T0817: スタジオ UI: 操作ウィンドウの配置とレイアウト

## 目的

配信中に素早く操作する画面として、スタジオの操作ウィンドウの配置とレイアウトを見直す。
基準は docs/ui.md (T0915 で足す「UI の品質の基準」を含む)。直せないもの・大きいものは後続のタスクにする (milestone は M10)。

- [x] 状態の印 (負荷・API・ソース・トラッキング・マイク) を、色だけでなく形と文で示し、意味が Tooltip で分かる

## メモ

- **やったこと:**
  - 並び: 表情とモーション・ポーズを右の列から中央の列へ移し、中央の頭に状態の印、その下に配信しているシーン (大きな文字)・モデル・
    モーション・表情を置いた。右の列は設定だけ (シーンの編集・入力・ホットキー・出力・仮想カメラ・ブラウザソース・操作 API・負荷・パラメータ)。
    中央の「フレーム」「1 刻みの時間」「受け手」の行は消した (1 刻みの時間は負荷の印と「フレームレートと負荷」、受け手の数は負荷の印の Tooltip)。
    空の状態 (モデルなし) に「モデルを選ぶ…」のボタンを置いた。
  - 状態の印 (`StatusBadge.svelte`・`lib/status.ts`): トラッキング・口パク (入のときは音量のメーター)・ホットキー・負荷・API・ソース。
    形 (丸にチェック・中の空いた丸・三角・八角) と文と Tooltip (印はフォーカスできる)。ツールバーの「API」「ソース」の札と負荷の文は除いた。
  - 幅: 13〜17rem / 20rem〜 / 20〜28rem。960px 以下は「シーン | 中央」の 2 列の下に設定、640px 以下は 1 列。ツールバーはプロファイルの名前を
    省略して (全体は `title`) 狭い幅でも 2 行 (前は 360px で 4 行)。
  - シーンの一覧: 各シーンに切り替えのホットキー (`Kbd`)、操作は「追加」+ `IconButton` 4 つ (複製・上へ・下へ・削除) で 1 行 (前は 2 行)。
    hover と押下を T0916 の重ね (`overlay-hover`・`-active`) にそろえた。
  - 誤操作: シーンの削除は前から AlertDialog (テストを足した)。操作 API の承認の後に「承認しました (権限)」の知らせと「取り消す」
    (承認の取り消し = `revokeApiClient`)。上の帯のエラー (T0815 の低の所見) を閉じられる `Notice` (danger) にした。
  - 文書: docs/studio.md (操作ウィンドウの図・表・状態の印の表・幅、API・ソース・負荷の印の場所)、docs/ui.md (「スタジオの操作ウィンドウ (T0817)」)、
    docs/manual/studio.md の文 (「画面」・シーンの操作・印・承認・ポーズの位置)、apps/studio/README.md。T0919 のメモに撮り直す画像を書いた。
  - テスト: `lib/status.test.ts` (印の形と順)、`ScenesPanel.svelte.test.ts` (ホットキーの表示・削除の確かめ)。
- **監査 (`just ui-audit --only studio`):** 前 (`target/ui-audit-before`、main b71a74ee) も後 (`target/ui-audit-after`) も 38 場面ですべての検査が 0 件。
  `--compare` は `+0 -0 ~0`。
- **前と後の画像の比べ (ライト・ダーク × 日英 × 広い幅・狭い幅、と 200%・DPR 2):**
  - 広い幅 (1280): 前は中央の列が 9 行の事実だけで右半分が空き、表情とモーションは右の列を送らないと見えなかった。後は送らずに状態の印・
    配信中のシーン・表情・モーションの一覧が見える。右の列の頭は前と同じくシーンの編集。
  - 狭い幅 (360): 前はツールバーが 4 行で、シーンの操作のボタンが 2 行。後はツールバー 2 行・シーンの操作 1 行で、
    最初の画面にシーンの一覧と状態の印まで入る (日本語・英語とも)。
  - 200% (640px 相当): 1 列。ツールバーは 1 行 (名前を省略)。ダーク: 印の地と枠はトークンの色で、コントラストは監査で 0 件。
  - 960 と 1100 は監査の組に無いので別に撮って見た (2 列 + 下に設定・3 列)。
- **`just ci`:** main (e9ef06f9) に rebase した上で通った。
- **やらなかったこと:**
  - 承認の確かめのダイアログ (承認を 2 段にする) はやめ、取り消しの知らせにした (承認の知らせ自体が確かめの役で、ダイアログを重ねると配信中に手間が増える)。
  - 取り消しの知らせを Control.svelte の部品テストでは確かめていない (Control はホストを丸ごと要るので、部品テストの下地が無い)。
    偽のホストでは承認を待つクライアントを作らないので、監査の画像にも出ない。
  - 状態の印の「注意」「動かせない」の見た目は、偽のホストが出さない (トラッキング・口パクは動かせず、API は入のまま) ので画像では見ていない
    (形は単体テストで確かめた)。
  - 実物の WebView (WebKitGTK・WebView2・WKWebView) での表示は確かめていない (T0919)。
- **起票の候補:**
  - `just ui-audit` の偽のホストに、承認を待つクライアント・負荷の注意・ホットキーの登録できないもの (`problems`) の場面を足し、印の注意の形と
    承認・取り消しの知らせを撮れるようにする。960px の組 (画面の半分) も足すとよい。
  - 「表情とモーション」の中の設定 (待機モーション・トラッキング中のモーションの優先・優先するパラメータ) は配信中に触らないので、
    折りたたんだ `Section` か右の列へ分ける (今は中央の列で表情とモーションの一覧の下にある)。
