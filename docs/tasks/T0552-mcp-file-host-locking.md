# T0552: MCP: FileHost の読み書きを表全体の錠の外で行い、保存と書き出しを半端にしない

## 目的

`host::FileHost` は開いているプロジェクトの表を 1 つの `Mutex` で守り、プロジェクトの読み込み (`load`)・保存
(`Project::save`)・`.ugoe` の書き出しをその錠を握ったまま行う。`--http` では要求を接続ごとのスレッドで同時に処理するが、
大きなプロジェクトや PSD 由来のテクスチャの多いプロジェクトを読む・保存する間は、ほかのプロジェクトへの要求も含めて
すべて待たされる (T0529 のレビューで見つけた)。

また `save` はプロジェクトを保存して「保存済み」にしてから `.ugoe` を書き出すので、書き出しに失敗するとツールは
エラーを返すがプロジェクトは保存済みになる (半端)。書き出しは一時ファイルを経ずに `fs::write` で直接上書きするので、
途中で失敗すると既存の `.ugoe` も壊れる (T0669 のレビューでも指摘)。

プロジェクトごとの錠にする (表の錠は探す・入れる間だけ) か、読み込みを錠の外で行って入れるときに競合を解くかを決めて直し、
保存と書き出しの順と失敗の扱い (書き出しのバイト列を先に作る・失敗をどう伝えるか) を決める。

## 受け入れ条件

- [x] 1 つのプロジェクトを読み込み・保存している間も、ほかのプロジェクトへの要求が待たされない (テスト)
- [x] 同じプロジェクトを同時に開いても、文書が 2 つにならない (テスト)
- [x] `save_project` の `bundle` の書き出しに失敗したときの状態と文言を決め、テストと README に書いた
- [x] `.ugoe` の書き出しは一時ファイルに書いてから名前を変える (途中で失敗しても既存のファイルを壊さない)
- [x] `just ci` が通る

## メモ

- T0529 のレビューで起票した。

### やったこと

- **錠をプロジェクトごとにした (`src/host.rs`):** `FileHost` の表は `パス → Arc<Mutex<SlotState>>` (枠) にし、表の錠は枠を探す・
  入れる・除く間だけ握る。読み込み・保存・書き出しは、そのプロジェクトの枠の錠だけを握って行う。同じプロジェクトへの要求は
  枠の錠で 1 つずつ進むので、同時に開いても文書は 1 つ。閉じた・読み込みに失敗した枠は表から除き、`Removed` の印を付ける
  (除いた枠の錠を待っていた要求は表から枠を取り直す)。錠の順は「枠 → 表」だけ (表の錠を握ったまま枠の錠を待たない)。
  「読み込みを錠の外で行い、入れるときに競合を解く」案は、同じプロジェクトを 2 回読むうえ、どちらを採るかの規則が要るので取らなかった。
- **保存と書き出しの順:** `.ugoe` のバイト列を保存の前に作り、同じディレクトリの一時ファイル (`.<名前>.<pid>.<番号>.tmp`) に
  書いて `sync_all` してから、プロジェクトを保存し、名前を変えて置き換える (`StagedFile`。捨てると一時ファイルを消す)。
  - 保存の前に失敗 (バイト列が作れない・一時ファイルが書けない): 何も変えない。文は `` failed to write `…`: …; nothing was saved ``。
  - プロジェクトの保存に失敗: 一時ファイルを消し、`.ugoe` は前のまま。文は `Project::save` のエラー。
  - 保存の後の名前の変更に失敗: プロジェクトは保存済み (`modified: false`)、`.ugoe` は前のまま。文は
    `` saved the project, but failed to write `…`: …; the previous file is left as it was ``。
  - パスを `` `…` `` で囲んだので、`--editor` の中継の WSL のパスの変換も効く。
- テスト: `host::tests` に、a の錠を握っている間に b を読み込み・編集・保存と書き出し・閉じられること
  (`a_busy_project_does_not_block_other_projects`)、8 スレッドが同時に開いて提案の番号が重ならず表の枠が 1 つで、開き直す・
  閉じると同時でも枠が残らないこと (`opening_the_same_project_at_once_makes_one_document`)、書き出し先のディレクトリが無いと
  何も保存しないこと、置き換えが行き先 (空でないディレクトリ) を壊さず保存済みになり一時ファイルが残らないこと。
  `tests/stdio.rs` の `propose_apply_undo_and_save` に、ツールとしての `nothing was saved` の文と `modified: true` のまま。
- README の「ツール」に書き出しの失敗の表、「依存」の段落にプロジェクトごとの錠を書いた。`DocumentHost::save` の doc にも書いた。
- `just ci` は通った (main に rebase した後)。

### やらなかったこと

- 「読み込み・保存している間」のテストは、同じ枠の錠を握る `with_project` の `f` で止めて作った (実際に遅い読み込みを
  作る手段 (FIFO など) は使っていない)。
- `Approvals` の待ちや `Tools` 側の `extras` の錠は触っていない (どちらも短い)。

### 起票の候補

- **エディタの持ち主の書き出し (`apps/editor/src-tauri/src/mcp.rs` の `EditorHost::save`):** 同じく保存の後に
  `std::fs::write` で `.ugoe` を直接上書きする (途中で失敗すると既存の `.ugoe` を壊し、書き出しの失敗で半端になる)。
  `crates:` の外なので触っていない。`StagedFile` 相当を `ugoe-editor-core` (`write_if_changed` と同じ形) に置いて共有するとよい。
