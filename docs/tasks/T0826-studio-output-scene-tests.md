# T0826: スタジオ: 出力の受け手のシーンの適用をテストする

## 目的

`Output.svelte` の `onScene` / `applyScene` / `showLook` (シーンの通知を 1 つずつ順に処理する・読んでいる間に次のシーンが来たら古い方を捨てる・
モデルの読み直しとモジュールの付け直しと見せ方だけの変更・背景の画像の blob URL の作り直しと解放) にはテストが無い。
判断 (`planScene`) と配置の計算 (`stageLayout`) だけが lib/outputLayout.ts でテストされている (T0815 のレビューで見つけた)。

`Player` と配信の口 (`OutputFeed`) を差し替えられる形に処理を lib へ分け、順序と取り消しの振る舞いをテストする。

## 受け入れ条件

- [x] 続けて届いたシーンのうち、最後のものだけが当たる (途中のモデルを読まない・古いシーンの見せ方を当てない)
- [x] 同じモデルのシーンでは読み直さず、モジュールの組が変われば付け直す
- [x] 背景の画像を替えたら前の blob URL を解放する
- [x] `just ci` が通る

## 参考

- docs/studio.md#シーンの切り替えと受け手
- apps/studio/src/lib/outputLayout.ts

## メモ

- やったこと: T0825 で入った `apps/studio/src/Output.svelte.test.ts` (happy-dom と偽の Player・偽の `OutputFeed`) に「Output scene changes」の
  4 つのテストを足した。続けて届いたシーンは最後のものだけが当たる (途中のモデルを取らない・古い見せ方を当てない)、背景の画像を取っている間に
  次のシーンが来たら古い見せ方を捨てる、同じモデルなら読み直さずモジュールの組が変われば付け直す、背景の画像を替えたら・閉じたら blob URL を解放する。
- 直したバグ: 見せ方だけ・モジュールだけのシーンで、背景の画像を取っている間に次のシーンが来ても、古いシーンで `continueScene` を呼んでいた。
  `showLook` の後に版を確かめてから呼ぶようにした (先に失敗するテストを書いた)。同じモデルなので実害は小さい (フレームの下限は変わらない) が、
  「古いシーンに移らない」に揃えた。
- docs/studio.md#シーンの切り替えと受け手 に「順序」の項 (1 つずつ順に処理・古い方の続きを捨てる・blob URL の解放) を足した。
- やらなかったこと: 目的にある「処理を lib へ分ける」はしなかった。T0825 の偽の Player で部品のまま差し替えてテストできるため、分けると
  `$state` (`shown`・`image`) の受け渡しが増えるだけになる。
- 起票の候補: なし。
