# T0573: MCP: エージェントの差分の組 (variant_sets) も承認を経て残す (判断が要る)

## 目的

T0570 で、エージェントが答えた分類 (ラベルと左右) は、リグの提案に添えた `set_layer_correction` を利用者が承認すると `project.json` の直しとして残るようになった
(利用者の判断: 案 A)。差分の組 (`variant_sets`) と確からしさは直しに含まれないので残らない (T0570 のやらなかったこと・候補)。
差分の組も承認を経て残す形を決めて入れる。

**判断が要る:** 案:

- A. 直し (`editor.classification` の `corrections`) に組の欄を持たせ、`set_layer_correction` で一緒に提案する (提案の数は増えない。直しの形が変わる)。
- B. 組の直しを別の項目とコマンド (`set_variant_set_correction` など) にし、リグの提案に添える (直しの形はそのまま。コマンドが増える)。
- C. 今のまま (組は残さない。エディタで開き直した後は、自動の分類か利用者の分類の組を使う)。

推奨は判断の前に、組を使う処理 (自動リギングの差分の扱い・エディタの提案の一覧) を調べて書く。

## メモ

- T0040 で起票した (元の候補: T0570 (`variant_sets`))。
- **blocked (案の判断が要る。実装はしていない):**
  - **組を使う処理 (調べたこと):**
    - 組 (`LayerLabel::variant`) を読むのは **モジュールの自動リギングのポーズ** (`ugoe_ai::module_rig::pose::hinted_variants`) だけ。
      ふつうのプロジェクトのリグ (`propose_rig`・`ugoe_ai::rig`) は `MeshPart::variant` に写すが使わない。
      モジュールでも組は手がかりの 1 つで、名前の末尾の A / B (`named_variants`) と PSD で片方を隠した重なり (`drawn_variants`) でも見つける。
    - リグを承認するとポーズのグループがモデルに入り (`Model::pose`)、以後の提案はポーズに入ったパーツを組にしない (`posed_parts`)。
      つまり **承認したリグでは組はポーズとして既にモデルに残る**。組が開き直した後に効くのは、ポーズのコマンドを外して承認した・
      Undo した後などに、開き直してから **新しく** モジュールのリグを提案するときと、表示 (エディタの AI タブの
      「Alternative drawings of the same part」・MCP の `get_psd_layers` の `variant`・結果の `variant_sets`) だけ。
    - エディタの AI 自身の組は分類のキャッシュ (`.ugoe-cache/classification.json`、T0567) に残る。MCP はキャッシュを読むだけ。
      エディタには組を直す画面はない (見るだけ)。直し (`corrected_labels`) は組を保ち、ラベルと左右だけを重ねる。
    - MCP の `set_layer_labels` の `variant_sets` は **PSD 全体の組を置き換える** (一部の組だけを足す形ではない)。組の番号は
      組の中で最も小さいレイヤーの番号で、PSD のレイヤーの並びに依るので、そのままでは保存の鍵にならない。
  - **案 A (直しに組の欄):** `corrections` の 1 件に `variant` (組の名前か、組の代表のレイヤーのパス) を足す。
    - 形: `{"path", "label", "side", "variant"?}`。直しは 1 レイヤーの全体を置き換えるので、「欄なし = 下の組のまま」「`null` = 組から外す」
      「値 = その組」の 3 つを分ける必要がある。組だけ決めたレイヤー (ラベルは名前の規則のまま) も、ラベルと左右ごと利用者の答え (`set_by=user`) になる。
    - 提案: コマンドは増えないが、組のレイヤーのうちエージェントがラベルを決めていないものの分だけ `set_layer_correction` が増える。
      組は N 行に分かれるので、一覧で 1 行だけ外すと組が欠ける (1 枚になった組は捨てる)。Undo は今と同じ (リグと 1 つの `Batch`)。
    - エディタの直しの画面 (T1615。範囲外の apps/editor) は直しを丸ごと送るので、組の欄を保つよう直さないと、ラベルを直すたびに組が消える。
  - **案 B (組を別の項目とコマンドに):** `editor.classification.variant_sets: [[<パス>, ...], ...]` と、PSD 全体の組を置き換える
    コマンド (`set_variant_sets { sets }`、`null` で消す) を足す。リグの提案の先頭に 1 つだけ添える (`keep_labels` と同じく外せる)。
    - 形: 直しの形は変わらない。残した組があれば自動の分類 (キャッシュの組か、ない) の組を **丸ごと置き換える** (`set_layer_labels` と同じ意味)。
      重ねるのは `corrected_labels` (エディタと MCP で共有) で、直しと同じ `LayerCorrections` に持たせればエディタの表示は apps/editor を触らずに戻る。
    - 提案: +1 行 (一覧では「差分の組 N 組」の 1 行。組が欠けない)。Undo はリグと同じ 1 つの `Batch`。
    - 費用: コマンド 1 つ (codegen・スキーマ・エラーのコード・Batch の中での扱い)・`file-formats.md` に 1 行・テスト。
  - **案 C (今のまま。文書だけ):** 開き直した後の組はキャッシュ (エディタの AI) の組か、なし。承認したリグの組はポーズとしてモデルに残るので、
    失うのは「開き直してから新しく出すモジュールのリグの手がかり」と表示だけ (名前の A / B と隠した重なりの手がかりは残る)。
    ファイル形式・コマンド・提案の数は変わらない。README・ai-integration.md・editor.md に「組はポーズとして残る。手がかりは残らない」と書く。
  - **推奨: C** (残すなら B)。理由: 組の唯一の使い手はモジュールのポーズの手がかりで、承認すればポーズとしてモデルに残るので、
    別に組を残しても効く場面は狭い (開き直してから新しいモジュールのリグを出すときだけ)。残すと決めるなら、組は PSD 全体の関係で
    `set_layer_labels` も全体を置き換えるので、それに合わせた B が素直 (1 行・欠けない・直しの形とエディタの直しの画面に触れない)。
    A は 1 レイヤーの直しに組という複数レイヤーの関係を割り振るので、3 つの状態・組の欠け・エディタの画面の修正が要り、勧めない。

  グループとしてモデルに残り、組そのものは `project.json` に残さず、開き直した後のモジュールのリグは名前と重なりの手がかりで組を見つけると書く。
