# T0562: ugoe-mcp: 接続の数の上限を超えたときの 503 も、読み残しで RST になって失われないようにする

## 目的

T0556 で、要求を読み終える前の誤りの答え (408・413・431 など) の後は、書く側を閉じてから上限付きで読み捨てて閉じる (lingering close) ようにした。
接続の数の上限を超えたときの `503` (`crates/ugoe-mcp/src/http.rs` の受け付けのスレッド) は、要求を読まずに答えて閉じるので、
相手が送り終えていなければ RST になり、Windows のクライアントは答えを失いうる。受け付けのスレッドで読み捨てると、ほかの接続の受け付けが止まる (T0556 の候補)。

## 受け入れ条件

- [x] `503` の答えの後も、受け付けを止めずに上限付きで読み捨ててから閉じる (枠の外の短い読み捨て用のスレッドなど。そのスレッドの数にも上限がある)
- [x] 要求を送り終える前に `503` を読むクライアントが答えを受け取れるテストがある
- [x] crates/ugoe-mcp/README.md と http.rs の冒頭の doc の上限の説明を更新した
- [x] `just ci` が通る

## メモ

- T0032 で起票した (元の候補: T0556)。
- やったこと (claude-worker-T0562):
  - `crates/ugoe-mcp/src/http.rs`: 接続の数の上限を超えた接続は、受け付けのスレッドで `503` を書いたあと (小さな答え。
    書き込みの時間の上限を `linger_timeout` にした)、読み捨ての枠が空いていれば `ugoe-mcp-reject` という短いスレッドに
    `linger` (書く側を閉じて 2 秒・1 MiB まで読み捨てる。T0556 と同じ関数) を任せる。枠は `Limits::max_rejections`
    (既定 8。接続の枠 `max_connections` の外) で、`ConnectionSlot` で数を戻す。枠が無いかスレッドを立てられなければ、
    従来どおり書いてすぐ閉じる。コマンド行のオプションは足していない。README の「上限」と http.rs の冒頭の doc に書いた。
  - テスト: `rejections_reach_clients_that_are_still_sending` (本文を送る前に 503 を読み、その後も残りを送れる。読み捨てを
    無効にすると Linux でも `(503, false)` で失敗することを確かめた)、`rejections_do_not_block_accepting` (読み捨ての枠 1 つで
    断った接続を 3 つ開いたままにしても、すぐに 503 が返る)。
  - 受け付けの順はつないだ順とは限らない (Linux のループバックでも入れ替わるのを観測した) ので、枠を握る接続は keep-alive の
    `ping` に答えてもらってから使う (`hold_a_connection`)。http のテストを 100 回流して失敗なし。
- やらなかったこと: Windows (Wine を含む) では確かめていない。`503` の答えは受け付けのスレッドで書く (送信のバッファに収まる
  大きさなので止まらない想定。止まっても `linger_timeout` で切れる)。
