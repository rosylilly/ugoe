# T0562: ugoe-mcp: 接続の数の上限を超えたときの 503 も、読み残しで RST になって失われないようにする

## 目的

T0556 で、要求を読み終える前の誤りの答え (408・413・431 など) の後は、書く側を閉じてから上限付きで読み捨てて閉じる (lingering close) ようにした。
接続の数の上限を超えたときの `503` (`crates/ugoe-mcp/src/http.rs` の受け付けのスレッド) は、要求を読まずに答えて閉じるので、
相手が送り終えていなければ RST になり、Windows のクライアントは答えを失いうる。受け付けのスレッドで読み捨てると、ほかの接続の受け付けが止まる (T0556 の候補)。

## 受け入れ条件

- [ ] `503` の答えの後も、受け付けを止めずに上限付きで読み捨ててから閉じる (枠の外の短い読み捨て用のスレッドなど。そのスレッドの数にも上限がある)
- [ ] 要求を送り終える前に `503` を読むクライアントが答えを受け取れるテストがある
- [ ] crates/ugoe-mcp/README.md と http.rs の冒頭の doc の上限の説明を更新した
- [ ] `just ci` が通る
