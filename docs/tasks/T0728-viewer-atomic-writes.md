# T0728: ビューアの保存を、一時ファイルに書いてから置き換える形にする

## 目的

ビューアの `write_json_file` (トラッキングの記録) と `write_png_file` (スクリーンショット) は、選んだパスに `std::fs::write` で
直接書く (`apps/viewer/src-tauri/src/lib.rs`)。保存のダイアログで既存のファイルを選んで上書きするとき、書く途中で失敗する
(ディスクがいっぱい・ネットワークのドライブが切れる・アプリが落ちる) と、元のファイルが途中までの中身で壊れる。
コードレビュー (T0724) で見つけた。エディタ (T0685・T0686) とスタジオ (T0819・T0820) の同じ形の所見と揃えて直す。

## 受け入れ条件

- [x] 同じディレクトリの一時ファイルに書き、`sync` してから選んだパスに置き換える (rename)。失敗したら一時ファイルを消し、元のファイルは残る
- [x] エディタ・スタジオと同じ関数の形に揃える (共有できる場所があれば使う。アプリ同士で import はしない)
- [x] 失敗したときに元のファイルが残ることのテストがある
- [x] `just ci` が通る

## メモ

- T0008: 3 つのアプリに同じ所見がある (同期のコマンド: T0685・T0726・T0819、CSP とコマンドの許可: T0686・T0727・T0820、一時ファイル経由の保存: T0687・T0728)。
  先に終えたタスクの形 (非同期にする関数・CSP の中身・一時ファイルの書き方) に後のタスクが揃える (docs/workflow/code-review.md#m9-の結果)。
- T0728 (やったこと): `apps/viewer/src-tauri/src/atomic_write.rs` に `write_atomic(path, bytes) -> io::Result<()>` を置き、
  `write_json_file`・`write_png_file` と、覚えた読めるパスの `readable-files.json` (`save_paths`) をこれで書く。README の
  「ファイルの読み書きの範囲」に書いた。選んだ形 (エディタの T0687 はこれに揃える):
  - **一時ファイルの名前:** 行き先と同じディレクトリの `.<ファイル名>.<プロセス ID>.<連番>.tmp` (連番はプロセスの中の
    `AtomicU64`)。MCP の `StagedFile` (`crates/ugoe-mcp/src/host.rs`、T0552) と同じ名前。同じディレクトリなのは rename が
    同じファイルシステムの中で済むため。先頭の `.` で Unix では隠れる。
  - **手順:** `File::create` → 書く → `sync_all` → 閉じる → `std::fs::rename` で置き換える。
  - **失敗の扱い:** 作る・書く・sync・rename のどこで失敗しても一時ファイルを消し (消せなくても無視)、エラーをそのまま返す
    (コマンドはこれまでどおり `"<path>: <error>"` の文字列)。行き先の前のファイルには触れないので残る。アプリが落ちたときは
    一時ファイルが残りうる (前のファイルは壊れない。掃除はしない)。
  - **Windows:** `std::fs::rename` が `MoveFileExW(MOVEFILE_REPLACE_EXISTING)` なので既存のファイルを置き換える。行き先を
    ほかのアプリが削除の共有なしで開いている・読み取り専用などで置き換えられなければエラーで、前のファイルが残る。rename の前に
    一時ファイルを閉じる。**Windows・macOS の実機では確かめていない** (Linux (WSL2) でテストした)。
  - **共有:** アプリ同士で import しない規則なので、ビューアの中に置いた (スタジオの `api/store.rs`・editor-core の
    `write_if_changed` も同じ考えの別の実装)。
  - テスト: `atomic_write` のテストで、置き換え・途中まで書いて失敗したときに前のファイルが残り一時ファイルが無いこと・
    rename が失敗したとき (行き先が中身のあるディレクトリ) と一時ファイルを作れないときに一時ファイルが残らないこと。
- T0728 (やらなかったこと): 親のディレクトリの `sync` (rename の永続化) はしない (MCP と同じ)。置き換えると、前のファイルの
  権限・シンボリックリンクは引き継がない (新しいファイルになる。リンクを選んだならリンクが通常のファイルに置き換わる)。
- 起票の候補: 3 つのアプリと MCP・editor-core で同じ「一時ファイルを経た置き換え」が別々にあるので、ツール層の小さなクレート
  (またはアプリが共有できる場所) に 1 つにまとめる。
