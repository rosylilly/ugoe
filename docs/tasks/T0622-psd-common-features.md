# T0622: PSD のよく使われる未対応機能

## 目的

T0620 の調査 (`docs/tasks/T0620-psd-real-world.md` のメモ) で、実際のペイントツールがよく使うのに未対応の機能が分かった。優先度の高いものから対応する。

## 受け入れ条件

- [x] レイヤーマスク (チャンネル -2 / -3) をアルファに適用する (優先度: 高)
- [x] `luni` を持たない PSD のレイヤー名を Shift-JIS として読む (SAI などを想定。判定方法を決める) (優先度: 高)
- [x] ZIP 圧縮・予測付き ZIP のチャンネルを展開する (寛容なライセンスの展開ライブラリ、例: `miniz_oxide`) (優先度: 中)
- [x] 16 ビットの PSD (`Lr16` を含む) を 8 ビットに変換して取り込む (優先度: 中)
- [ ] 実物の PSD (`assets/fixtures/psd-real/`) が手に入ったものから、テストに加える
- [x] `just ci` が通る

## メモ

### やったこと

- **レイヤーマスク:** チャンネル -2 をアルファに掛ける (矩形はキャンバス座標、外は既定の色、濃度も掛ける)。
  ベクトルマスクと併用したレイヤーでは、両方を合成した最終的なマスク -3 だけを掛ける。マスク情報の並び
  (-3 のフラグ・既定の色・矩形が、濃度などの値より先) は仕様書と違い、psd-tools の読み方 (issue #693) に従った。
  -3 の見出しは、-3 のチャンネルがあるときだけ読む。無効・矩形が空のマスクは掛けない。マスクのチャンネルが
  読めないときは `LayerMaskIgnored` を警告して掛けずに取り込む。
- **Shift-JIS の名前:** `luni` がなければ、パスカル文字列を UTF-8 → Shift-JIS (CP932) → Windows-1252 の順に、
  最初に正しく読めたもので読む (`encoding_rs`)。判定の理由は `crates/ugoe-psd/README.md`。
- **ZIP:** 無圧縮・PackBits に加えて ZIP・予測付き ZIP (8/16 ビット) を `miniz_oxide` で展開する。
  展開した大きさが合わない・壊れたストリームは `Invalid`。
- **16 ビット:** ヘッダの後のレイヤー情報が空なら、末尾の追加情報 `Lr16` (8 ビットなら `Layr`) を探して読む。
  標本は `round(v * 255 / 65535)` で 8 ビットにする。合成画像 (レイヤーのない PSD) も 16 ビットを読む。32 ビットは
  引き続き `Unsupported`。
- 仕様にない圧縮方式の色・アルファのチャンネルを持つレイヤーは、取り込まずに `UnsupportedCompression` を警告する
  (以前はアルファだけが読めないと不透明として取り込んでいた)。
- テスト用ライター: マスク (矩形・画素・既定の色・無効・濃度)・-3・`luni` を書かない名前・16 ビット (`write_psd16`)。
  ZIP は `miniz_oxide` で本当に圧縮する (以前は圧縮しないブロックだけ)。
- `WarningKind` は変えていない (`LayerMaskIgnored` の意味が「掛けられなかったマスク」に変わっただけ)。公開 API の変更はない。

### 依存の追加

- `miniz_oxide` 0.9 (MIT OR Zlib OR Apache-2.0): ZIP の展開。`png` 経由で既に `Cargo.lock` にあった版で、新しい取得はない。
- `encoding_rs` 0.8 ((Apache-2.0 OR MIT) AND BSD-3-Clause): Shift-JIS の表を自前で持たないため。これも既に `Cargo.lock` にあった
  (Tauri 側の依存)。どちらも寛容なライセンスで、`just licenses` が通る。ツール層 (`ugoe-psd`) だけの依存。

### 検証

- ImageMagick 6.9 (`tests/fixtures.rs` の `imagemagick_agrees_on_masks_zip_and_16_bit`): マスク (-2) を持つレイヤーを無圧縮・
  PackBits・ZIP・予測付き ZIP で書いた 8 ビットと 16 ビット (`Lr16`) の PSD を ImageMagick でも読み、マスクを掛けた
  各レイヤーの RGBA が取り込みと ±1 で一致する (独立した実装で、ライターの ZIP・16 ビット・マスクの形も確かめた)。
- ImageMagick 6.9 について分かったこと: 16 ビットでは、グローバルなレイヤーマスク情報が空で、その直後に `Lr16` がある
  ときだけレイヤーを読む (ライターは 16 ビットではグローバルな情報を空にした。取り込みはどちらも読む)。既定の色 255 の
  マスクの外を約 55 として扱う (赤だけの色の輝度を使う不具合)。-3 と濃度は読まない (-3・濃度を持つファイルも開けることは
  確かめた)。これらは `tests/import.rs` で値を確かめる。
- 壊れた入力: ランダムに壊す・途中で切るテストに、マスク・-3・濃度・ZIP・16 ビットを含む PSD を足した。

### やらなかったこと・後続タスクの候補

- **実物の PSD の追加:** `psd-real/` に新しいファイルは無く (既存の ComfyUI のもの 1 つは引き続き通る)、マスク・Shift-JIS・
  16 ビットの実ファイルでは確かめていない。受け入れ条件の「実物の PSD をテストに加える」は満たしていない。
  特に、-3 の並びと「-3 は合成済み」という扱い、SAI の名前の文字コードは実ファイルで確かめたい
  (Photoshop のベクトルマスク + 画素マスク、SAI の日本語のレイヤー名、Photoshop の 16 ビットの PSD)。
- **グループのマスク:** 合成したグループに掛かるので、子のアルファに掛けると重なりで結果が変わる。警告だけにした。
  エディタでマスク専用のメッシュにする (T0605 のクリッピングと同じ仕組み) のが候補。`LayerNode::Group` にマスクを足す
  公開 API の変更になる。
- **ベクトルマスクだけのレイヤー** (`vmsk` / `vsms`、画素のマスクなし): パスを塗る処理が要るので読まない。警告も出していない
  (検出して `LayerMaskIgnored` を出すのが小さな後続)。
- **マスクのぼかし (feather):** 値は読み飛ばし、掛けない。
- **32 ビット (`Lr32`)・PSB:** 対応していない。
