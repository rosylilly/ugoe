# T1612: エディタ: スロットの欄・カーブのキーの時刻・グルーの組を doc.send で送り、パネルのドラッグの送り直しを点検する

## 目的

T0693 でパネルの編集を `doc.send` (送る直前に今のモデルからコマンドを組み立てる) の列にしたが、残りがある。

- `SlotsPanel.svelte` の範囲の欄は自前の `busy` で、適用中の確定を捨てる。ID の変更も送る直前に今の ID を引く形にする (T0695・T0693 の候補)。
- `CurveGraph.svelte` のキーの時刻の欄は、適用中に次の確定をすると古い時刻のキーを動かそうとして `NotFound` になる (T0695 の候補)。
- `GlueOverlay` の組の追加・削除は、ドラッグの開始時のグルーから `set_glue` を組み立てる (T0693 の候補)。
- タイムラインなどパネルのドラッグでも、送っている間の `pointermove`・`pointerup` で送り直していないか点検する (T0699 の候補)。

## 受け入れ条件

- [x] 上の 3 つが `doc.send` で送る直前に組み立て、適用中の確定を捨てない・古い値で失敗しない。それぞれに先に失敗するテストを書いてから直した
- [x] パネルのドラッグを点検し、送り直しがあれば直した (点検した部品の一覧をメモに書いた)
- [x] `just ci` が通る

## メモ

- T0026 で起票した (元の候補: T0695 の `SlotsPanel` と `CurveGraph`、T0693 のスロットと `GlueOverlay`、T0699 のパネルのドラッグ)。
- やったこと:
  - `SlotsPanel`: 自前の `busy` (欄・ボタンの無効と `if (busy) return`) をやめ、すべて `doc.send` で送る直前のスロットから
    組み立てるようにした (範囲・取り付け先・パーツ・各リスト・アプリに見せる・追加・削除・名前の変更)。名前の変更は、送った
    変更 (前の ID → 新しい ID) をパネルが覚え、後に並べた編集は送る直前にたどって今の ID を引く (`slots.ts` の `resolveSlot`)。
    選んでいるスロットも同じくたどるので、名前の変更を読み直した直後に最初のスロットへ選び直さない。
  - `CurveGraph` のキーの時刻と値の欄: `doc.send` で送る直前のカーブ (`doc.motions`) から組み立てる。時刻を変えた確定の後の
    確定は、送った変更 (前の時刻 → 新しい時刻) をたどって今の時刻のキーを動かす (`timeline.ts` の `followKey`)。
  - `GlueOverlay`: 組の追加・削除を `doc.send` で送る直前のグルーから組み立てる。`busy` (送っている間の押下を捨てる) をやめた。
    削除は番号でなく組の頂点で指す (`glues.ts` の `withoutPair(glue, a, b)`。前の削除の後に押した印が別の組を指さない)。
  - テスト (先に失敗することを確かめてから直した): `SlotsPanel.test.ts` (送っている間の範囲の確定・名前の変更の後の編集・欄を
    無効にしない)、`CurveGraph.test.ts` (時刻の続けての確定・時刻の後の値)、`GlueOverlay.test.ts` (送っている間の追加・削除)。
    純粋な関数のテスト (`resolveSlot`・`followKey`・`withoutPair`) も足した。テストの道具の `FakeDocument` に `send`
    (本物と同じく前の送信の後で組み立てる)・`motions`・`onApply` (読み直しの代わりに写しを書き換える) を足した。
  - docs/editor.md#パネルからの編集 に「目印が変わる編集の後」を足した (crates の範囲外だが小さな文書の追記)。
- パネルのドラッグの点検 (送っている間の `pointermove`・`pointerup` で送り直すか): 送り直すものは無かった。
  - `TreePanel` (行のドラッグ): 離したときに `press`・`drag` を消してから送る。後の移動・離す操作は `press` が無いので受けない。
  - `PosesPanel` (要素のドラッグ): 離したときに `cancelDrag` してから `doc.send`。同上。
  - `MotionEditor` のドープシートのキーのドラッグ: 離したときに `drag` を消してから送る。ルーラーのシークはコマンドを送らない。
  - `CurveGraph` のキー・取っ手のドラッグ: 離したときに `drag` を消してから送る。
  - `App` の区切りのドラッグ: コマンドを送らない。`@ugoe/ui` の `Slider` (`GluesPanel` の重みなど): `oncommit` は
    離したときに 1 回だけで、`GluesPanel` は `doc.send` (`updateGlue`)。
- やらなかったこと・確かめていないこと:
  - ドープシート・カーブのグラフのキーのドラッグは、離したときの (読み直す前の) 時刻からコマンドを組み立てる。前の移動を
    送っている間に同じキーをもう一度ドラッグすると、古い時刻のキーを動かそうとして失敗しうる (今回の対象の欄ではないので直していない)。
  - 実機 (`just editor`) では確かめていない (この環境では画面を操作できない)。happy-dom の部品のテストと Vitest で確かめた。

    (送った時刻の変更をたどる `followKey` を使える)。
