# T0085: 1.0 の範囲を改め、M7・M11 を完了にする

## 目的

docs/roadmap.md の「1.0 の範囲」と ADR 0020 は「1.0 = M1〜M7 の完了」のままで、M8 の節の「M8 は 1.0 に含める」(利用者の決定) や、その後の M9〜M11 と食い違っている。
M7 と M11 には完了の判断の節が無い (M9 の T0008・M10 の T0919 のような節)。利用者の決定に合わせて文書を揃える。

## 決まっていること (利用者、2026-10-11)

- **1.0 の範囲:** 今進めている開発はすべて 1.0 に入れる (M1〜M11)。
- **M7・M11:** 完了にしてよい。M7 に残る T0407 (Unreal のプラグイン) と T0443 (Unity の実機での確認) は、M7 の完了の条件から外す (T0407 は 1.0 の後の候補、T0443 は人の手の確認として残す。扱いを節に書く)。

## 受け入れ条件

- [ ] 新しい ADR (docs/adr/0035-…) を書き、1.0 の範囲を「M1〜M11 の完了」(と、Release の作業) にする。ADR 0020 の 1.0 の範囲の部分を置き換える (0020 の状態に「1.0 の範囲は ADR 0035 で置き換え」と書く。順序の決定などは 0020 のまま)。docs/adr/README.md の一覧も
- [ ] docs/roadmap.md の「1.0 の範囲」の節を直し、M8 の節の「1.0 に含める」と矛盾しないようにした。M9〜M11 の節の 1.0 との関係の書き方も揃えた
- [ ] M7 と M11 に、M9 (T0008)・M10 (T0919) と同じ形の完了の判断の節を書き、見出しに ✅ を付けた。M7 は T0407・T0443 の扱い、M11 はタスクがすべて done であることと残る手作業 (fuzz・nostd-build-std・perf のワークフローの初回の結果) を書いた
- [ ] docs/vision.md・docs/release.md・README.md・英語の公開仕様 (spec/) など、「1.0 = M1〜M7」と書いた所をすべて直した (`rg 'M1〜M7|M1-M7|M1–M7'` などで探した)
- [ ] `just ci` が通る
