## メモ

- **作ったもの:** `just ui-audit` (`tests/ui-audit/`。README に流れ・場面・検査・確かめないこと)。T0907 の shots.mjs・audit.mjs (スクラッチ領域に残っていた) を元に作り直した。
  - ビルド (`just wasm` と `vite build`、エディタの見本は `ugoe sample dress-up --project`) → 静的サーバ (空いているポート。並行に流せる) →
    playwright-core で入っている Chrome を開く。偽のホスト: エディタは読むだけの IPC の偽物 (T0665 の Rust のブリッジは持ち込まず JS にした。
    Tauri のコマンドが `AppHandle` (Wry) に固定されていて、Tauri の mock runtime で本物のコマンドを動かすのは大きな書き換えになるため。
    知らないコマンドは null を返して報告に名前を出す)、スタジオは `StudioHost` のメソッドを host.ts から読んですべて置く (足りないと画面がエラーを出した)。
  - 組: ライト・ダーク × 日英 × 広い幅・狭い幅、`ja-light-wide-dpr2`、`en-light-zoom200` (CSS の幅を半分・DPR 2)。すべて reduced motion。
    場面はアプリごとに空の状態・見本・下まで送った画面・設定・メニュー・エディタの右の列の 7 つのタブなど。3 つで 216 場面、ビルド込みで 6 分ほど。
  - 検査: コントラスト (自前)・横のはみ出し・文字の重なりと切れ (新しく足した。T0907 には無かった)・24px 未満・名前と ARIA (axe-core)・
    reduced motion の下の動き・画面のエラー・Tab の止まり。同じ部品の行を「種類」にまとめて数え、`--compare` で前の結果と比べる。
    `.aria.yml` (アクセシビリティの木) を残す。単体テスト `just ui-audit-check` (`just ci` と CI の ci.yml に入れた)。
  - `just ui-shots` は部品の見本、`just ui-audit` はアプリの画面、と役割を分けて justfile・docs/testing.md・packages/ui/README.md に書いた。
- **依存の判断:** axe-core を入れた (MPL-2.0。読み上げの名前の計算と WCAG の規則を自前で正しく書くのは難しいため。手を加えずに道具の中だけで使い、
  アプリには入らない)。playwright-core (Apache-2.0。ブラウザをダウンロードしない) も入れた。どちらもルートの devDependencies。
  `just licenses` は通る (ルートの devDependencies は検査の対象の外。アプリと packages の依存は増えていない)。コントラストと押せる大きさは
  axe でなく自前 (祖先の重ねた地・部品の押せる範囲を扱うため)。
- **文書:** docs/ui.md に「UI の品質の基準」(配置・レイアウト・デザイン (状態の表・空・読み込み中・エラー)・アクセシビリティ)、「確かめ方」の表
  (スクリーンリーダー・200% の拡大・reduced motion の手順)、「3 つのアプリの基準線 (T0915)」。docs/testing.md に「UI の監査」。
