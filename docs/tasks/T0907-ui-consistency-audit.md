# T0907: UI: 3 つのアプリの見直し (キーボード操作・フォーカス・コントラスト・ライトとダーク・小さい画面)

## 目的

移行の後に、3 つのアプリで見た目と操作が揃っているかを見直す。

## 受け入れ条件

- [x] キーボードだけで主な操作ができる、フォーカスが見える、文字のコントラストが基準を満たす (docs/ui.md)
- [x] ライトとダーク、高 DPI、狭い幅で崩れない (ヘッドレスの Chrome のスクリーンショット)
- [x] 見つかった崩れを直す。直せないものは後続のタスクにする
- [x] スタジオの操作ウィンドウのヘッダーを組み直す (言語・テーマ・ライセンスをビューアとエディタと同じく「設定」のダイアログにまとめるなど。T0811 でボタンが 2 行に折り返すようになった)
- [x] これまでのタスクで残った見た目の課題: エディタのビューポートの左上の説明と右上の webgl2 の重なり (T0664)、「書き出し…」の枠が Esc や外のクリックで閉じない (T0665)
- [x] `just ci` が通る

## 参考

- docs/ui.md

## メモ

- **確かめ方:** ビルドした 3 つのアプリをヘッドレスの Chrome で開き (エディタは T0665 の使い捨てのブリッジ = 本物の ugoe_editor_core、ビューアは vite preview、
  スタジオは偽の StudioHost)、ライト・ダーク × 英語・日本語 × 広い幅 (エディタ 1440・ほか 1280) と狭い幅 (エディタ 1024・ほか 360)、と devicePixelRatio 2 で撮った。
  各場面で、文字のコントラスト (WCAG 2.x の式。祖先の地を重ねて計算。自前のスクリプト `audit.mjs`、新しい依存なし)・横のはみ出し・24px 未満の押せるもの、
  Tab でたどったフォーカスの印と名前を記録した。スクリプトと画像はスクラッチ領域の `scratchpad/T0907/` (`shots.mjs`・`audit.mjs`・`run.sh`・`build.sh`、
  画像は `shots/before/` と `shots/after/<アプリ>/`、記録は `log-after-<アプリ>.txt` と各フォルダの `report.txt`)。
- **見直しの結果 (直した後):**

  | 観点 | エディタ | ビューア | スタジオ |
  | --- | --- | --- | --- |
  | 文字のコントラスト (無効を除く) | 0 件 (前: 非表示のパーツ名 3.4・由来の凡例の記号 3.2〜4.0) | 0 件 | 0 件 |
  | 横のはみ出し (狭い幅) | なし | なし | なし |
  | 狭い幅の崩れ | なし (ヘッダーは 2 行に折り返す。前から) | 直した (パネルが潰れていた) | 直した (列が重なっていた) |
  | キーボード | 直した (ツリーの印が薄い) | 問題なし | 直した (ツールバーに Tab で届かない) |
  | 24px 未満 | 0 件 (前: タイムラインの行とキー・ツリーの開閉・パラメータの値の欄) | 0 件 (前: トラッキングのパネル) | 0 件 (同) |
  | ライト・ダーク・高 DPI | 崩れなし | 崩れなし | 崩れなし |

- **直したもの:**
  - スタジオ: ヘッダーの言語・テーマ・ライセンスを、ビューアと同じ歯車の「設定」のダイアログ (`SettingsDialog.svelte`) にまとめた。ライセンスは設定の
    「ライセンスを表示…」から重ねて開く。1280 幅で負荷・API・ソースの印が出ても 1 行。印の説明は `title` から Tooltip に (フォーカスできる)。
    960px 以下で 3 つの列が重なっていたのを、列ごと送るようにした。
  - `@ugoe/ui`: `Toolbar` が、描いた時点で中がすべて無効だと Tab で届かない (Bits UI の roving の初期値) のを、押せる項目の 1 つだけを tabindex 0 に保って直した
    (Vitest あり)。`Toggle` に `tooltip`。`mergeAttributes` を公開し、エディタの `TipButton` を Popover・Menu のトリガーにできるようにした。
  - エディタ: 「書き出し…」を Popover に (Esc・外のクリックで閉じ、開いたボタンへ戻る。中の Select で選んでも閉じない)。ビューポートの左上の道具の並びと
    提案のプレビューの帯が、右上の HUD (webgl2・スクリーンショット・全体を表示) の幅を空けて折り返す (`--viewport-hud-width`)。メッシュ編集の説明に地を敷いた。
    非表示・本体のパーツ名を opacity から控えめな文字の色に、ツリーのフォーカスの印を focus ring に、由来の凡例の記号とパラメータの ◆ のコントラストを上げた。
    古い変数 (`--accent` など) を 20 ファイルでトークンに置き換え、`app.css` の別名を消した。
  - `@ugoe/face-tracking`: パネルを @ugoe/ui に移した (Section・Select・Toggle・Slider・Button・Tooltip。`@ugoe/ui` に依存を足した)。
    すぐ効く選択はチェックボックスから Toggle に、説明は Tooltip に、平滑化の説明は見える補足に、体の値の説明は一覧の中の文にした。
    ビューアの `app.css` の別名と標準の部品の装いを消した。
  - ビューア: 360px でパネルが潰れて中身がほぼ見えなかったのを、パネルの列ごと送るようにした。
  - 文書: docs/ui.md (色・`title` の扱い・Toggle の tooltip・Toolbar の補い・「3 つのアプリの見直し」)、docs/studio.md、apps/studio/README.md、packages/face-tracking/README.md。
- **押せる大きさ (2026-10-02、利用者の判断 B):** エディタの密な行を 24px にした。タイムラインの行 20 → 25px (24 と区切りの線)・行の◆のボタン 24 幅・
  ドープシートのキー (見た目の◆ 10px は ::before、押せる範囲 24×24)・グラフの点と取っ手 (透明な 24×24 の枠)・ツリーの行 22 → 24px と開閉 (押せる範囲 24×24、並びの幅は 14px のまま)・
  パラメータの名前と値の欄・標準の文字と数値の欄と select (app.css で 24px 以上)。`@ugoe/ui` の NumberField は枠のどこを押しても欄にフォーカスする。
  行が減っても回るように: ドープシートは選んだ行 (グラフでキーを選び直したときも) を見える所まで送り、表は 3 行を残してエディタの全体を送る
  (1024×720 ではグラフを出すと表が 0 行になっていた。前から)。ヘッドレスの Chrome で、表を下まで送ってからグラフの点を押すと選んだ行が見えること、
  ドープシートのキーとグラフの点の横の位置が 1px 以内で一致することを、全場面 (1440 と 1024・日英・ライトとダーク) で確かめた (`log-after-editor.txt`)。
- **マニュアル (T0806) 向けに画面が変わったところ:** エディタのタイムライン (行が高くなり見える行数が減る。低い画面ではタイムラインの全体を送る) とツリー (行が高い)、スタジオのヘッダー (言語・テーマ・ライセンス → 右端の歯車の「設定」)、スタジオの狭い幅の並び、
  トラッキングのパネル (3 つのアプリ。チェックボックス → スイッチ、平滑化に数値の欄と説明)、エディタの「書き出し…」の枠 (Popover。見た目はほぼ同じ)。
- **確かめていないこと:** 実物の Tauri の WebView (WebView2・WKWebView・WebKitGTK) での表示。スクリーンリーダーでの読み上げ。WebView の 200% の拡大
  (devicePixelRatio 2 で代えた)。エディタの Tab の記録は最初の 70 個 (右の列の奥までは届いていない)。本物のカメラでのトラッキングのパネル (動いている間の表示)。
- **範囲外の変更:** `pnpm-lock.yaml` (`@ugoe/face-tracking` → `@ugoe/ui` の依存)。
- **team-lead に相談したこと:** エディタの密な行の押せる大きさ → 利用者の判断で B (24px にする)。上のとおり実装した。
- **後続の候補:**
  - エディタにアプリのライセンス (third-party-notices) を出す口が無い (ビューア・スタジオにはある)。
  - 残した `title` (フォーカスを受けない要素の補い) のうち、行の中の説明 (物理のリグの欄・カーブのフェードの欄) を見える補足か Tooltip に。
  - `Slider`・`Select`・`NumberField` に tooltip の口 (トラッキングの平滑化の説明を見える補足にした理由)。
  - ビューアの広い幅で、トラッキングのパネルを開いたままだとライティング・モーションのパネルが低くなる (各パネルが中で送る作り。前から)。
