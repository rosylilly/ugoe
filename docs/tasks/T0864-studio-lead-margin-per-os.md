# T0864: スタジオ: 促しの余裕を OS に合わせる

## 目的

T0854 は、トラッキングの値が刻みの `LEAD_MARGIN` (1 ms) 前に届くように促しを寄せた。測ったのは WSL2 (Linux) だけで、
Windows・macOS ではスリープの粒度が粗く、1 ms の余裕では刻みに遅れて 1 刻み待つ値が増えうる (T0854 の「確かめていないこと」)。
余裕を OS (と実際の遅れ) に合わせる。

### やり方の候補 (作業者が選ぶ。公開の形は変わらないので利用者の判断は要らない)

- **A. 自分で合わせる (推奨):** 刻みに遅れた値の割合 (T0863 で集める) を見て、余裕を下限と上限 (例: 1〜4 ms) の間で増減する。
  実機の値を待たずに `pacing.rs` の単体テスト (仮の時刻で、スリープが 2・15 ms 遅れる機械を模す) で確かめられ、機械ごとの違い (電源の設定・
  負荷) にも追いつく。余裕を増やすほど値は古くなる (最大で余裕の分) ので、遅れが無くなったら少しずつ戻す。
- **B. OS ごとの定数:** Windows・macOS の実機で T0863 の表示を見て、遅れた値の割合が小さくなる値を `#[cfg]` で決める。実機での測定が要る
  (作業者の環境では Windows・macOS を動かせない)。

A を推奨する (実機が無くても確かめられ、B の実機の測定は A の確かめとして docs/manual-check.md に残せる)。

## 受け入れ条件

- [ ] 選んだ形と理由を docs/studio.md#刻みの速さと正確さ に書いた
- [ ] A なら: 余裕の増減を `pacing.rs` に入れ (時計とスレッドを持たない形を保つ)、仮の時刻のテストで、スリープが遅れる機械では余裕が増えて遅れた値の
      割合が下がること・遅れが無くなると戻ること・余裕が上限を超えないこと・刻みの間隔が設定のままであることを確かめた。
      B なら: 実機で測った値 (OS・機械・カメラと刻みの組・遅れた値の割合) をメモに書き、その値を OS ごとに決めた
- [ ] `ticker.rs` の `measure_tracking_wait` で、変更の前と後の待ち (平均・p95・最大) をメモに書いた
- [ ] docs/manual-check.md の待ちを見る手順 (T0863 で足したもの) に、Windows・macOS で遅れた値の割合を見ることを足した
- [ ] `just ci` が通る (Windows・macOS 向けの `#[cfg]` を足したら `just cross-check` も)
