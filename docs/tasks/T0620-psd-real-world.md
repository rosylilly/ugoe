# T0620: 実用の PSD への対応 (仕様どおりのテスト用 PSD と実ファイルの検証)

## 目的

T0619 の実機確認で、テスト用の `assets/fixtures/layers.psd` が Photoshop で開けないこと、表示が虹色の模様で確認用に適さないことが分かった。
ugoe の PSD の読み込みは、自作の書き出し処理と ImageMagick の出力でしか検証されておらず、実際のペイントツールが書き出した PSD で動くかが分かっていない。

## 受け入れ条件

- [x] 今の `layers.psd` が Photoshop で開けない原因を、PSD の公開仕様 (Adobe の File Formats Specification) と照らして特定し、メモに書く
- [x] テスト用 PSD の書き出し処理が、仕様どおりの (Photoshop などで開ける) PSD を書く。偽の中身は書かない
- [x] 取り込みのエラー処理を試すための壊れた入力・未対応の中身は、ファイルにせずテストの中で作る (仕様どおりの PSD と分ける)
- [x] 確認用の PSD を用意する: 意味の分かる簡単なキャラクターの絵 (単色の図形でよい: 顔・両目・口・髪・体など) を、グループ・クリッピング・非表示のレイヤー・不透明度を含めて描いたもの。`just editor` で取り込んで見た目で確かめられること。合成画像も正しく作る
- [x] ImageMagick で読み、合成画像とレイヤーが期待どおりであることを確かめる
- [x] 実際のペイントツールの PSD を置けば自動でテストされる場所 (例: `assets/fixtures/psd-real/`) と、その追加手順・ライセンスの記録方法を用意する (ファイルが無ければテストは何もしない)
- [x] PSD の仕様のうち、実際のツールがよく使うのに未対応のもの (16 ビット、ZIP 圧縮、レイヤーマスク、グレースケールなど) を洗い出し、優先度を付けて後続タスクの候補にする
- [x] `just ci` が通る

## メモ

### Photoshop で開けなかった原因 (診断)

Photoshop が手元に無いため、Photoshop が実際にどこで拒んだかは確かめられていない。旧 `layers.psd` を書いた
ライター (`crates/ugoe-psd/tests/common/mod.rs`) の出力を、Adobe の "Adobe Photoshop File Formats Specification"
(<https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/>) と 1 項目ずつ照らした結果は次のとおり。

**仕様に反していたもの (旧 `layers.psd` に入っていた)**

1. **`levl` (レベル補正の調整レイヤー) の中身が 2 バイト** (`00 02` + 詰め物 2 バイト)。仕様の "Levels file format" では
   版 (2 バイト、= 2) と 29 組のレベルレコード (1 組 10 バイト: 入力の下限・上限、出力の下限・上限、ガンマ × 100) の
   計 292 バイトが必要。調整レイヤーの設定は開くときに読まれるので、**最も疑わしい原因**。
2. **`lrFX` (レイヤー効果) の中身が 4 バイト** (版 0・効果の数 0)。仕様の "Effects Layer info" では効果の数は
   6 (Photoshop 5/6) か 7 (Photoshop 7) で、続けて `8BIM` + `cmnS`・`dsdw` などの各効果の中身が要る。これも疑わしい。
3. **レイヤーのブレンド範囲が空 (長さ 0)**。仕様の "Layer blending ranges data" では合成のグレーの範囲 (元・先) と
   チャンネルごとの範囲が並ぶ。Photoshop 自身は常に書く。長さ 0 を拒むかは分からない (不確か)。
4. **Unicode のレイヤー名 (`luni`) に終端の 0 がない**。仕様の "Unicode string" は UTF-16 の単位数・文字列・2 バイトの 0。
   旧ライターは 4 バイトへの詰め物で偶然 0 が入る名前 (文字数が奇数) 以外では 0 を書いていなかった。影響は小さいと思われる。

**仕様違反ではないが、実際のファイルと違ったもの**

5. 画像リソースが空 (長さ 0)。仕様は必須のリソースを定めていないが、Photoshop の出力には必ずある。拒まれるかは不確か。
6. グローバルなレイヤーマスク情報が空 (長さ 0)。長さで読み飛ばせるので問題ないと思われる。
7. 合成画像 (画像データのセクション) が背景レイヤーのコピーで、レイヤーを重ねた結果ではなかった。形式としては正しいが、
   合成画像だけを表示するビューア (プレビュー・サムネイル) では違う絵になる。

**テストの中だけで作っていた偽の中身** (ファイルではないが「偽の中身を書く」ライターだった)

8. ZIP のチャンネル (圧縮方式 2) の中身が zlib のヘッダ 2 バイトと 0 が 2 バイトだけ (deflate のブロックも Adler-32 もない)。
9. ユーザーマスクの矩形 (4x4) を書くのに、マスクのチャンネル (-2) を書いていなかった (チャンネル数・長さと矛盾)。
10. スマートオブジェクトの `SoLd` / `PlLd` の中身が 0 が 4 バイト (実際はディスクリプタの構造)。

ヘッダ・カラーモードデータ・レイヤーレコードの固定部・チャンネルの長さ・PackBits の行・セクション区切り (`lsct`)・
`lyid`・`iOpa`・各セクションの長さと詰め物は仕様どおりだった (ImageMagick でも読めていた)。
なお `iOpa` (塗りの不透明度) は公開仕様に項目がないが、Photoshop が書くキーとして広く知られている。

### 直したこと

- ライター: 解像度の画像リソース (1005、72 dpi)、ブレンド範囲 (グレー + 4 チャンネル、すべて 0..255)、
  `luni` の終端の 0、グローバルなレイヤーマスク情報 (不透明度 100・種類 128)、グループの印に「画素が見た目に関係しない」
  フラグ (bit 4)、マスクのチャンネル (-2) を書く。ZIP (2) と予測付き ZIP (3) は、圧縮しないブロックだけの
  正しい zlib ストリームで書く。仕様にない圧縮方式は panic する。合成画像はレイヤーから計算し (`tests/common/compose.rs`、
  通常・乗算・不透明度・塗り・クリッピング・通過/通常のグループ・非表示・マスクに対応)、白に重ねて PackBits で書く。
  何も変えないレベル補正の中身 `levels_identity()` を用意した。
- `layers.psd`: レイヤーの並び・位置・画素は同じ。`levl` を仕様どおりの 292 バイトにし、`メモ` の偽の `lrFX` を外した。
  - テストの変更: `layers.psd` の警告は `レベル補正` の 1 件だけになった (`ugoe-psd` の `imports_fixture_tree`、
    `ugoe-editor-core` の `reports_warnings`)。レイヤー効果の警告は、`tests/import.rs` の
    `layer_effects_are_ignored_with_a_warning` (`lrFX` / `lfx2` のキーだけを持つ、中身を省いた入力をテストの中で作る) で試す。
  - `truncated_input_is_an_error` などの「レイヤー情報の終わり」の位置は、画像リソースが空でなくなったので長さを読んで求める。
- 新しい `character.psd` (320x400、85KB): 単色の図形 (4x4 の標本化で縁を滑らかにした楕円・角丸矩形・多角形) で描いた
  キャラクター。グループ `体` (通常) / `頭` (通過) / `目` (入れ子)、`顔の影` (顔でクリッピング・乗算)、`頬` (不透明度 50%)、
  非表示の `口 (開き)` を含む。構成は `assets/fixtures/README.md`。
- 壊れた入力・未対応の中身は `tests/import.rs` の中で作る (途中で切れた入力・ランダムに壊した入力・対応の取れないグループ
  (`write_psd_unchecked`)・ZIP・調整レイヤー (仕様どおりのものと中身を省いたもの)・レイヤー効果・画素のないスマートオブジェクト)。
  中身を省いた追加情報を使うテストには、その旨をコメントに書いた。

### 検証

- ImageMagick 6.9 (`crates/ugoe-psd/tests/fixtures.rs`、ImageMagick が無い環境では飛ばす):
  - `identify` が見る画素を持つレイヤーの (幅, 高さ, 位置) が、書いたレイヤーの列と一致する
    (ImageMagick はグループの印と画素のない調整レイヤーを数えず、非表示のレイヤーは数える)。
  - `convert file.psd[0]` の合成画像が、`compose::flatten` の計算結果とバイト単位で一致する。
  - `character.psd` の合成画像の意味のある点 (背景・髪・服・首・顔・影の掛かった額・顔の外の髪 (クリッピング)・
    頬 (50%)・両目の瞳・白目・口・非表示の開いた口) の色を確かめる。
- CLI: `ugoe import-psd assets/fixtures/character.psd -o <tmp>/character.ugoeproj --bundle <tmp>/character.ugoe`
  → `4 parts, 12 meshes, 320x400 canvas`、警告なし。`ugoe render <tmp>/character.ugoe -o render.png` (llvmpipe) の PNG を
  目で見て、茶色の髪 (後ろ髪と、ぎざぎざの前髪)、肌色の顔、前髪の下の影、青い瞳に白い光の両目、半透明の桃色の頬、
  赤い笑った口、首、白い襟の付いた青い服が、薄い青灰色の背景の上に描かれていた。ImageMagick で読んだ合成画像との差は
  730 画素で最大 2/255 (縁の滑らかさの丸めの違い)。
- `ugoe-editor-core` に `character.psd` を取り込むテスト (`imports_character_fixture`) を足した。
- **Photoshop で開けるかは確かめられていない** (Photoshop・Krita・GIMP が無い)。T0619 の確認項目に、両方の PSD を
  Photoshop で開く項目を足した。開けなかった場合は、上の診断の 3・5 (ブレンド範囲・画像リソース) の形を実ファイルに合わせる。
  ほかにも、グループの本体のレコードのブレンドモード (今は `norm`、本当の値は `lsct` の `pass`)、ブレンド範囲の組の数
  (グレー + 4 組にした) は、Photoshop の実ファイルと同じかを確かめていない。

### 実ファイルのテストの置き場所

`assets/fixtures/psd-real/` (今は `README.md` だけ)。置いた `*.psd` は `crates/ugoe-psd/tests/real_world.rs` が取り込み、
8 ビット RGB なら成功すること (警告は可)、それ以外 (PSB・16/32 ビット・RGB 以外) は `Unsupported` になることを確かめる。
ImageMagick があれば、画素を持つレイヤーの数 (取り込まずに飛ばした画素のあるレイヤーを含む) が ImageMagick の数と一致すること
も確かめる。再配布できるファイルだけを置き、ツール・機能・作者・ライセンス・出所を `psd-real/README.md` の表に書く。
仕組みは、ImageMagick で書いた PSD (8 ビット RGB のレイヤー付き・レイヤーなし、16 ビットのグレースケール) と `character.psd` の写しを一時的に置いて動くことを確かめた (コミットしていない)。

### 実際のツールがよく使うのに未対応のもの (後続タスクの候補)

優先度は、Live2D 向けのイラスト (CLIP STUDIO PAINT・Photoshop・SAI・Krita・Procreate で描いたもの) を取り込む頻度で付けた。
実ファイルで確かめたものではなく、形式の仕様とツールの一般的な出力からの見立て。`psd-real/` に実ファイルが入ったら見直す。

| 優先度 | 機能 | 今の扱い | 後続タスクの案 |
| --- | --- | --- | --- |
| 高 | レイヤーマスク (-2、ベクトルマスクと併用時の -3)。Photoshop・CLIP STUDIO の書き出しでよく使われる | 警告して無視 (マスクの外も見える) | マスクをアルファに掛けて取り込む (矩形・既定の色・無効/相対位置のフラグ、-3 の優先)。グループのマスクも |
| 高 | Shift-JIS などのパスカル文字列だけのレイヤー名 (`luni` を書かない古いツール、SAI など。未確認) | UTF-8 として読むので文字化け | `luni` が無いときの名前の文字コードの推定 (依存を足すなら MIT/Apache の `encoding_rs`) |
| 中 | 16 ビット (Photoshop で 16 ビットで描く人がいる)。レイヤー情報は `Lr16` の追加情報に入り、チャンネルは多くが ZIP (予測付き) | `Unsupported` | 16 ビットを 8 ビットに落として取り込む。ZIP と `Lr16` を含む |
| 中 | ZIP / 予測付き ZIP のチャンネル (16/32 ビットと PSB でよく使われる。8 ビットでも書くツールがありうる) | 警告して飛ばす | `miniz_oxide` (MIT/Apache) などで展開する |
| 中 | Photoshop のブレンドモードのうち ugoe に無いもの (オーバーレイ・ソフトライト・覆い焼きなど) | エディタ側で通常に落とす | 取り込み時の警告を揃え、近いモードへの写し方を決める |
| 中 | クリッピングの土台がグループ・非表示の土台・`clbl` (クリッピングしたレイヤーをまとめて合成) | エディタ側 (T0605) で扱える範囲だけ | 実ファイルで見た目を比べる |
| 低 | レイヤー効果 (`lfx2` など。境界線・影) | 警告して効果を除いた画素を取り込む | 効果を別のレイヤーに焼き込む選択肢 (Photoshop の「レイヤーを作成」相当) |
| 低 | PSB (大きな PSD。30000px を超えるキャンバス) | `Unsupported` | 長さの 8 バイト化だけで読める。必要になったら |
| 低 | グレースケール・CMYK・Lab・インデックス | `Unsupported` | グレースケールだけ RGB に広げて取り込む (線画だけのファイル) |
| 低 | 32 ビット (`Lr32`、HDR) | `Unsupported` | 必要が出るまで扱わない |
| 低 | スマートオブジェクト (`SoLd` / `PlLd` / `SoLE`)・テキストレイヤー (`TySh`) | 通常はレイヤーのチャンネルに描画済みの画素があるので取り込める。無いときだけ警告 | 実ファイルで確認するだけ |
| 低 | セクション区切りの変種 (`lsdk`、終わりの印の名前の違い、種類 0 の `lsct`、アートボード `artb`) | `lsdk` と種類 1〜3 は対応、他は通常のレイヤー | 実ファイルで確認するだけ |
| 低 | 合成画像にアルファがある (レイヤー数が負、4 チャンネル目が透明度) | レイヤーがあれば合成画像を読まないので影響なし。レイヤーの無い PSD では 4 チャンネル目をアルファにする | なし |
