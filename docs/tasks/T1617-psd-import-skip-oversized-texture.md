# T1617: PSD の取り込みで、上限を超える画像のレイヤーを飛ばして警告し、取り込み全体を失敗させない

## 目的

T0560 で、テクスチャの追加・差し替えのコマンドが、一辺が上限 (既定 16384) を超える PNG を `edit.texture_too_large` で拒むようになった。
その結果、PSD の取り込みで上限を超えるレイヤーが 1 枚でもあると、取り込み全体が失敗するようになった (以前は取り込めて、ビューポートで表示できないだけだった)。

T0554 では、メッシュが大きすぎるレイヤー (`TooLarge`) は警告 `psd.layer_too_large` を出してそのレイヤーだけを飛ばす、と決めている。
画像が大きすぎるレイヤーも同じ扱いにして、1 枚のために取り込み全体を失わないようにする (利用者の方針: 上限で使える範囲を狭めず、可用性を下げない)。

## 受け入れ条件

- [x] PSD の取り込み (新規と既存のプロジェクトへの取り込み、AI の提案で PSD を読む経路) で、上限を超える画像のレイヤーは取り込まず、警告 (`psd.layer_too_large` を使うか新しいコードか決める) を出して、ほかのレイヤーは取り込む
- [x] 飛ばしたレイヤーの名前と大きさと上限が警告の引数で分かり、エディタの画面に日英で出る
- [x] 飛ばす代わりに縮小して取り込む案も検討し、選んだ理由を docs/editor.md の取り込みの規則の表に書いた
- [x] 上限を超えるレイヤーを含む PSD で、取り込み全体が失敗せず、警告が出て、ほかのレイヤーが取り込まれるテストがある (大きな画素を確保しない形で)
- [x] `just ci` が通る

## メモ

### やったこと (T1617)

- **警告のコード: 新しい `psd.layer_texture_too_large` にした。** `psd.layer_too_large` の引数は自動メッシュの格子のセル数で、
  画像の画素数と上限 (一辺) とは意味が違うため。引数は `layer` (名前)・`width`・`height` (余白を含むテクスチャの画素数)・`max` (`DEFAULT_MAX_IMAGE_SIDE`)。
  エディタの画面では、ほかの `psd.*` の警告と同じく名前を警告の `path` で前に出すので、日英の文には `{{layer}}` を入れていない (名前が 2 度出ないように)。
- `Builder::add_layer` が、余白を足した寸法 (`layer.width + 2 * pad`) を、画素を広げる (`pad_image`)・自動メッシュより前に見て、
  上限を超えたらそのレイヤーだけ飛ばす。上限ちょうどは取り込む。取り込みはすべて `layer_tree_command_with` を通るので、
  エディタの新規・既存への取り込み、CLI、MCP の `import_psd` が同じ扱いになる。エディタの AI の提案 (`classify_psd_layers`) は
  `LayerTree` を読むだけでテクスチャを追加しないので、もともと失敗しない (変えていない)。
- **縮小しない理由** を docs/editor.md の取り込みの規則の表に書いた (解像度が黙って変わり差分の絵とずれる、テクスチャ上の 1 px = キャンバスの 1 px の写像が崩れる、まれでペイントソフトで直せる)。
  コードの表・docs/ai-integration.md (PSD 取り込みと MCP の節) にも足した。
- テスト `import_tests::layer_with_texture_larger_than_the_limit_is_skipped_with_a_warning`: 高さ 1 px で幅が上限 + 1 / ちょうどのレイヤーを前後のレイヤーと並べ、
  警告 1 件 (引数)・上限ちょうどのテクスチャの追加が通ること・ほかのレイヤーが取り込まれることを確かめる (先に失敗するのを確かめた)。
- カタログの見本 (`message_catalog.rs`)・日英の訳・`messageCodes.ts` (`just gen`)。
- `just ci` が通った (main に rebase した後)。

- 実機のエディタの画面での表示は確かめていない (翻訳のカタログの検査と Vitest まで)。
