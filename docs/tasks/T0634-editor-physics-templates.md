# T0634: エディタ: 物理のテンプレート (体の追従・弾み)

## 目的

フェイストラッキングのアプリの多くは体の向きを出さないので、顔の角度から物理で体を遅れて追従させ、弾ませる設定が定番になっている (参考の記事 4・2)。
順序付きの連鎖 (T0312) と加算の出力 (T0313) を使い、定番の設定をテンプレートとして 1 回の操作で作れるようにする。

## 受け入れ条件

- [x] テンプレート: 「体の追従」(AngleX/Y/Z → BodyAngleX/Y/Z、遅れと戻り)、「弾み」(中継用パラメータを挟んで角度に弾みを足す)、「首の追従」。標準パラメータの ID で作り、ないパラメータは作るか飛ばすかを選べる
- [x] コマンドの列として適用し、1 回の Undo で戻る。テストで、顔を振ったときに体が遅れて付いてくること
- [x] 操作マニュアルの物理の章に、テンプレートの使い方と中身の説明を書く
- [x] `just ci`・`just gen`・エディタのビルドが通る

## メモ

- **コマンド:** `Command::ApplyPhysicsTemplate { template, options }` を末尾に追加 (`OP_COUNT` 90)。
  `physics_template::commands(model, physics, template, options)` がコマンドの列 (`add_parameter`・`add_physics_rig`・
  `reorder_physics_rig`・同じ ID のリグは `set_physics_*` で置き換え) を作り、`apply_to` が `batch` と同じく 1 つの Undo 単位で適用する。
  列だけを作れるので、AI や CLI は確かめてから `batch` で適用できる。規則は `docs/editor.md#物理のテンプレート`。
- **テンプレートの中身:** 体の追従 = `AngleX/Y/Z` → 角度 (正規化 = 入力の値域) → 粒子 1 の角度 × 0.3 を `BodyAngleX/Y/Z` に `add`。
  静止時の角度 = 頭の回転なので、トラッキングの体 = 頭 × 0.3 の下では結果が「振り子の角度 × 0.3」になり `overwrite` と同じ (テストで確認)。
  弾み = `AngleX` → x → 中継 `BodyBounce` (内部用、上書き) → x (反転) → `BodyAngleX` に × 0.4 で `add`。
  首の追従 = `AngleZ` (角度)・`AngleX` (x、50%) → 首の回転デフォーマの角度 × 0.3 (動的物理)。首は `options.neck` か、名前に neck/首 を含む回転デフォーマ。
  参考の記事 (乾物ひも) の Cubism の設定 (パラメータの複製・位置 X の入力で弾みを作り角度に戻す) を、加算の出力と中継で表した。
- **係数の決め方:** `Puppet` にトラッキング (頭 20°) を与え、係数を掃いて決めた。体: `mobility` 0.65・`delay` 0.5・`acceleration` 1.5
  (90% に 7 フレーム、行き過ぎ約 12%、1 秒で収まる)。0.8 以上では値域 (±10) まで行き過ぎた。
- **テスト (`physics_template_tests.rs`):** JSON の形、軸ごとの省略と 1 回の Undo、パラメータの作成、拒否、中継 (`has_relay`)、置き換え、
  既存のリグが読むパラメータを書くリグをその前に置くこと、`Puppet` + トラッキングで体が遅れて付いてきて行き過ぎて落ち着くこと
  (加算と上書きの一致)、弾みの行き過ぎと往復 (3 回以上) と収まり、首 (自動選択・種類の拒否・遅れて傾いて落ち着く・Undo)。Vitest 3 件 (`templates.test.ts`)。
- **画面:** 物理のパネルに「Templates」(`TemplateSection.svelte`)。「Create missing parameters」「Body blend」「Neck」と 3 つのボタン。
  ついでに、パラメータにだけ出力するリグの粒子をビューポートに描かないようにした (動的物理の設定と混ざると、キャンバスの原点に点が出ていた)。
- **確かめたこと:** 見本のアバター (`ugoe sample avatar --project`) を T0635 と同じ使い捨ての HTTP ブリッジ + vite build + ヘッドレス Chrome
  (スクラッチ領域) で開き、「+ Body follow」「+ Bounce」でリグ 5 つと内部用の `BodyBounce` ができ、「relay」の印が付くこと、Undo 1 回で弾みが
  パラメータごと消え Redo で戻ること、首のデフォーマがない見本では「+ Neck follow」が押せないこと、物理のプレビューと T0635 のプレビューモードで
  `BodyAngleX` 9・`AngleX` 30 にして動くこと (エラーなし)。画面の動きの量はソフトウェア描画のフレームが遅く測れなかったので、同じプロジェクトを
  `Puppet` で動かして確かめた (体の追従: 0.1 秒ごとに 6.00 4.91 6.40 6.70 6.64 … 6.00、弾みを足すと 4.12 7.49 8.57 … と往復)。マニュアルの画像 1 枚。
- **分かったこと:** `add` では、頭が急に動いた最初のフレームは物理の出力が 1 ステップ遅れる (`physics.md#時間の進め方`) ので、足す量が 0 で
  基準値 (トラッキングの値) がそのまま出て、次のフレームから遅れが入る。連続したトラッキングでは目立たない。
- **後続の候補:** 見本のアバターに首の回転デフォーマとテンプレートを入れる。プレビューにトラッキング (T0636) が入ったら、`BodyAngle*` を
  手で頭 × 0.3 にしなくても確かめられる。係数の強さ (倍率) をテンプレートの選択にする。粒子の欄が f32 を切り捨てて出す (0.95 が 0.949)。
