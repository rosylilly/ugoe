### 確かめたこと

- **外部 API (T0805):** `127.0.0.1` と `::1` にだけ束ね、接続元もループバックかを確かめる。`Host`・転送ヘッダ・`Origin` の検査は経路に依らず先に通す。
  トークンと鍵は OS の乱数の 256 ビットで、定数時間で比べる。初めてのクライアントは利用者の承認まで何もできず、権限は利用者が選ぶ。
  既定は切。入力 (JSON-RPC・引数・名前の長さ・メッセージとフレームの大きさ・値と期限) の検証はある。穴は見つからなかった。
- **ブラウザソース (T0808):** スイッチとトークンは別。違うトークンと切っているときは同じ `404`。ファイルは今のシーンの分だけで、
  `assets/` のパスは `..` などを断る。応答に `no-referrer`・`nosniff`・CSP。溢れたページは閉じる。
- **ホットキー:** 割り当てが変わったときだけ登録し直し (`unregister_all` → 登録)、割り当ての画面では外す。押されたら `spawn_blocking` で行う。
- **保存:** プロファイルと `studio-api.json` は一時ファイルに書いて置き換える。未来の版のプロファイルは開かない。`studio-api.json` は
  読めなかったときに起動しただけで書き換えていた (下の表、直した)。
- **指揮役と受け手の通知:** シーンの通知はフレームより先に (指揮役を握ったまま) 配る。外部 API の舞台の通知は舞台のロックの中で送るので順は保つ。
  演技の通知は刻みの差分なので、同じモーションの始め直しを取りこぼし、終わりで発火したイベントの名前と順が違っていた (下の表、直した)。

### 横断

- **Tauri の同期のコマンドはメインのスレッドで動く。** ファイルを読む・大きなバイト列を返すコマンドが `async` でないと、イベントループを塞ぐ。
  エディタ・ビューアのバックエンドにもありそう (T0819 はスタジオだけ)。
- **CSP が `null` で、アプリのコマンドをウィンドウで絞っていない。** エディタ・ビューアも同じ形のはず (T0820 で確かめる)。
- **起動時に読めなかった設定のファイルを既定で上書きする** 形は、ほかのアプリの設定 (覚える設定・最近の一覧) にもないか確かめたい。
- **差分で作る通知は、同じ値への遷移 (始め直し) を取りこぼす。** 状態の比較だけで通知を作るところでは、世代の番号を持たせる。
- **keepalive は「届いたもの」で数える。** 送ったもので数えると、聞くだけの相手が切れる (ugoe-mcp の `--http` などのネットワークの口)。
