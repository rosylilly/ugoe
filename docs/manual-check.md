# 実機の確認表

エディタ・ビューア・スタジオを、実際の OS・WebView・機器 (カメラ・マイク・OBS・会議アプリ) で手で確かめるための一覧です (T0007)。
各タスクは自動テスト・ヘッドレスの Chrome・使い捨てのブリッジで確かめましたが、作業の環境 (WSL2) では動かせないものがあり、
タスクのメモ・[studio.md の「実機で確かめていないこと」](studio.md#実機で確かめていないこと)・T0619 などに散らばっていました。それをここにまとめます。

- まず [用意する](#用意する) で一式を作り、[最初の一巡 (Windows、30 分)](#最初の一巡-windows30-分) を回してください。
- 残りは [確認の項目](#確認の項目) を優先度の順に。結果は [結果を書き戻す](#結果を書き戻す) の流れで返してください。
- 画面の操作の詳しい手順は利用者向けのマニュアル ([manual/](manual/README.md)。スタジオは [manual/studio.md](manual/studio.md)) にあります。
  確かめてマニュアルと食い違えば、それも NG として書いてください。

## 優先度と印

| 優先度 | 意味 |
| --- | --- |
| **A** | 配信で使う流れ、または壊れると困るもの (データを失う・入れられない・配信が止まる)。最初に確かめる |
| **B** | OS ごとにしか分からないもの (WebView の違い・OS のダイアログ・権限・パス・機器)、主な機能の画面での操作 |
| **C** | 細部・外部のサービスや道具が要るもの・開発者向け |

- **OS:** W = Windows (WebView2)、M = macOS (WKWebView)、L = Linux (WebKitGTK)。項目の見出しの [ ] に、確かめる OS を書いています。
- **自動 (T0006):** Linux (WebKitGTK) の本物の Tauri のアプリを動かす自動テスト (T0006) が受け持つ予定のもの。その OS の欄は手で確かめなくてよい
  (T0006 が入るまでは手で確かめる)。Windows と macOS は自動テストの外なので、手の確認に残ります。
- **元のタスク:** 項目の末尾の (T0xxx) は、その「確かめていないこと」を書いたタスクです。詳しい背景はそのタスクのメモにあります。

## 用意する

### Windows (WSL2 で作って Windows で入れる)

WSL2 のリポジトリで、インストーラを作り、Windows のフォルダーに一式をまとめます。

```sh
just app::build PLATFORM=windows   # 3 つのアプリの NSIS のインストーラ (署名なし)。target/dist/<アプリ>/windows/ にできる
just check-pack                    # Windows の %USERPROFILE%\ugoe-check に一式をまとめる (出力先は引数で変えられる)
```

`just check-pack` (`scripts/check-pack.mjs`) が作るもの:

| パス (`ugoe-check\` の下) | 中身 |
| --- | --- |
| `installers\` | 3 つのアプリのインストーラ (`ugoe_<版>_x64-setup.exe` = エディタ、`ugoe-viewer_…`、`ugoe-studio_…`) |
| `samples\` | 見本のモデル (`avatar.ugoe`・`avatar-lit.ugoe`・`dress-up\` の本体とモジュール) |
| `fixtures\` | エディタの取り込みに使う PSD (`character.psd`・`layers.psd`) |
| `ugoe-sample-profile.json` | スタジオの見本のプロファイル ([manual/studio.md の見本のプロファイル](manual/studio.md#見本のプロファイル) と同じ中身)。モデルを `samples\` の Windows のパスで指す |
| `manual-check.md` | この確認表の写し。結果を書き込む |

- プロファイルはモデルを絶対パスで持つので、`ugoe-check` フォルダーを動かしたら `just check-pack --force` で作り直します
  (`--force` が無ければ、結果を書き込んだ `manual-check.md` とプロファイルは上書きしません)。
- リポジトリの `pnpm --filter @ugoe/studio sample-profile` は、WSL の中で実行すると `/home/...` のパスになり、Windows のスタジオからは読めません。
  Windows で使うプロファイルは `just check-pack` で作ります。
- インストーラは署名していません。初回は SmartScreen の「Windows によって PC が保護されました」が出るので、「詳細情報」→「実行」で進めます
  ([apps/editor/README.md の配布物の署名](../apps/editor/README.md#配布物の署名))。
- スタジオのインストーラは管理者の権限を求めます (仮想カメラの登録のため。UAC の「はい」を押す)。エディタとビューアは求めません。
- WebView2 Runtime は Windows 10 (1803 以降)・11 には入っています。無ければインストーラが取りに行きます。

### Linux

```sh
just app::build PLATFORM=linux     # target/dist/<アプリ>/linux/ に .deb・.rpm・.AppImage
sudo apt install ./target/dist/studio/linux/*.deb   # 例: スタジオ。エディタとビューアも同じ
pnpm --filter @ugoe/studio sample-profile ~/ugoe-sample-profile.json   # 見本のプロファイル (リポジトリの assets/samples を指す)
```

### macOS

macOS の上で `just app::build PLATFORM=macos` で作ります (署名なし。Gatekeeper の警告は「システム設定」→「プライバシーとセキュリティ」の
「このまま開く」で越える)。仮想カメラは Apple Developer Program のアカウントが要ります ([release.md の macOS の仮想カメラ](release.md#macos-の仮想カメラ))。
見本のプロファイルは Linux と同じ `pnpm --filter @ugoe/studio sample-profile` で作ります。

## 確認の項目

結果の欄は `未` を `OK`・`NG`・`-` (確かめない・対象外) に書き換え、NG なら何が起きたか (画面の文・スクリーンショットのファイル名) を続けて書きます。
例: `- 結果: W OK (10/04) ・ M 未 ・ L 自動 (T0006)`

### I. インストールと起動

#### I01 インストーラで入れて起動できる [A: W]

- 手順: `installers\` の 3 つのインストーラを順に実行する (SmartScreen は「詳細情報」→「実行」、スタジオの UAC は「はい」)。スタートメニューから 3 つを起動する。
- 期待: どれもエラー無く入り、ウィンドウが開く (スタジオは操作ウィンドウ)。描画のところが真っ黒・真っ白のままにならない。
- 元: T0004・T0625・T0701・T0807
- 結果: W 未

#### I02 上書きで入れ直しても失敗せず、設定が残る [A: W]

- 手順: スタジオで設定 (言語やテーマ) を変え、プロファイルを保存して閉じる。同じスタジオのインストーラをもう一度実行する (仮想カメラを使った後なら、なお良い)。起動する。
- 期待: インストーラが失敗しない (DLL が使用中でも退けて続く)。起動すると、前の設定と最後のプロファイルのまま。
- 元: T0807 ([studio.md の Windows の未確認 7.](studio.md#windows-media-foundation))
- 結果: W 未

#### I03 アンインストールで消える [B: W]

- 手順: 「設定」→「アプリ」から 3 つをアンインストールする。再起動する。管理者の PowerShell で
  `reg query "HKLM\SOFTWARE\Classes\CLSID\{128A1A50-B227-494B-952E-0C011BB01869}"` を実行する。
- 期待: スタートメニューから消える。`reg query` が「見つかりません」になり、スタジオのインストール先のフォルダーに `ugoe_studio_vcam.dll` が残らない。
- 元: T0807 ([studio.md の Windows の未確認 7.](studio.md#windows-media-foundation))
- 結果: W 未

#### I04 Linux のパッケージで入れて起動できる [B: L]

- 手順: 3 つの `.deb` を `apt install` で入れ、アプリのメニューから起動する。余裕があれば `.AppImage` と `.rpm` も。
- 期待: 起動する。エディタの「Connect agents」が同梱の `ugoe-mcp` を見つける (登録のコマンドにパスが出る)。
- 元: T0004・T0715・T0722・T0642
- 結果: L 未

#### I05 ライセンスの表示に同梱物が出る [B: WML]

- 手順: 3 つのアプリで、設定 (歯車) またはステータスバーの「ライセンス」を開く。
- 期待: アプリのライセンス (GPL-3.0-only) と、同梱のもの (MediaPipe など) の表記が出る。インストールしたアプリでも空にならない。
- 元: T0811
- 結果: W 未 ・ M 未 ・ L 未

### S. スタジオ

#### S01 見本のプロファイルを開くと、出力ウィンドウにモデルが透過で出る [A: WML]

- 手順: ツールバーの「プロファイル」→「プロファイルを開く…」で `ugoe-sample-profile.json` を選ぶ。出力ウィンドウが隠れていれば、ツールバーの「出力ウィンドウ」を押す。
- 期待: 「雑談」が配信中になり、枠の無い出力ウィンドウにモデルが出る。モデルの外側は透けて後ろのウィンドウが見える (黒や白で塗られない)。目パチと呼吸で動いている。
- 元: T0801・T0802
- 結果: W 未 ・ M 未 ・ L 自動 (T0006)

#### S02 出力ウィンドウを左ドラッグで動かせる [A: WML]

- 手順: 出力ウィンドウのモデルの上と、透けているところの上で、左ボタンを押したまま動かす。
- 期待: どちらでもウィンドウが付いてくる。離すとその場所に留まる。修飾キーは要らない。
- 元: T0813・T0801
- 結果: W 未 ・ M 未 ・ L 未

#### S03 大きさのプリセットが物理ピクセルになる [A: WM]

- 手順: 画面の拡大率を 150% (Windows の「ディスプレイ」) にして、「出力ウィンドウ」のパネルの「大きさ」を 1920 × 1080 と 1280 × 720 にする。
- 期待: 画面の上では 1280 × 720 (150% のとき) に見え、OBS の取り込みの大きさ (ソースのプロパティ) は 1920 × 1080 になる。
  画面に収まらない大きさでは、パネルに今の大きさと注意が出る。
- 元: T0801
- 結果: W 未 ・ M 未

#### S04 出力ウィンドウを閉じても隠れるだけ、操作ウィンドウを閉じるとアプリが終わる [B: WML]

- 手順: 出力ウィンドウを選んで Alt + F4 (macOS は ⌘W)。ツールバーの「出力ウィンドウ」を押す。「最前面に置く」を入れて、ほかのウィンドウを前に出す。最後に操作ウィンドウを閉じる。
- 期待: 出力ウィンドウは隠れ、「出力ウィンドウ」で同じ状態のまま戻る。「最前面に置く」の間はほかのウィンドウより前にある。操作ウィンドウを閉じるとプロセスが残らず終わる (タスクマネージャーに残らない)。
- 元: T0801
- 結果: W 未 ・ M 未 ・ L 未

#### S05 シーンを切り替えると見せ方が替わる [A: WML]

- 手順: 左の「シーン」で「夕方 (ライティング)」→「着せ替え」→「ゲーム (右下)」→「雑談」の順に押す。「雑談」と「ゲーム (右下)」を何度か行き来する。
- 期待: 夕方は夕日の色の光が当たる。着せ替えは緑の背景にロングヘアとセーラー服。ゲームは右下に小さく出る。
  雑談とゲームの行き来では揺れものが跳ねず、トラッキングとモーションが続く (同じモデル)。
- 元: T0802
- 結果: W 未 ・ M 未 ・ L 自動 (T0006)

#### S06 プロファイルが保存され、起動し直すと戻る [A: WM]

- 手順: シーンの名前を 1 つ変える (「シーンの編集」)。ツールバーに「保存済み」が出るのを待つ。スタジオを閉じて起動し直す。
  「プロファイル」→「名前を付けて保存…」で別の名前に保存し、「プロファイル」の最近の一覧から元のものを開く。
- 期待: 起動し直すと、同じプロファイルと最後のシーンに戻り、名前の変更が残っている。OS の保存と開くのダイアログが出て、Windows のパス (`C:\Users\...`) で保存できる。最近の一覧に両方が出る。
- 元: T0802
- 結果: W 未 ・ M 未 ・ L 自動 (T0006)

#### S07 カメラで顔がモデルに付く [A: WML]

- 手順: 「入力」の「カメラ (フェイストラッキング)」でカメラを選び、「開始」を押す (許可を求められたら許す)。正面を向いて「キャリブレーション」。首を振る・傾ける・目を閉じる・口を開ける。
- 期待: カメラの一覧に名前が出る。映像とランドマークが出る。「いまの状態」のトラッキングが「顔あり (n fps)」になり、出力ウィンドウのモデルが同じ向きに動く。
  macOS は初回に OS の許可を求められる。
- 元: T0803・T0812・T0703
- 結果: W 未 ・ M 未 ・ L 未

#### S08 トラッキングが固まらない (T0812 の回帰) [A: WML]

- 手順: トラッキングをしたまま 2 分、「表情とモーション」の表情とモーションを 10 回ほど押し、シーンを 2 回切り替える。
- 期待: モデルが顔に付いてくる遅れが 1 秒より短いまま。「顔あり (n fps)」の n が 0 に落ちたままにならない。ボタンを押してから効くまでに数秒かからない。
- 元: T0812
- 結果: W 未 ・ M 未 ・ L 自動 (T0006。偽のカメラ)

#### S09 操作ウィンドウを最小化してもトラッキングと口パクが続く [A: WML]

- 手順: カメラとマイクを始めた状態で操作ウィンドウを最小化し、30 秒、顔を動かして話す。戻す。
- 期待: 最小化している間も出力ウィンドウのモデルが顔と声に付いてくる。戻したときに「顔あり」のまま。
- 元: T0803・T0804
- 結果: W 未 ・ M 未 ・ L 未

#### S10 マイクで口が動く [A: WML]

- 手順: 「マイク (口パク)」でマイクを選び「開始」。黙ってから話す。「ノイズの閾値」と「感度」を動かす。
- 期待: 「音量」のメーターが声で動き、モデルの口が開く。黙ると閉じる。閾値を上げると小さな音で口が開かなくなる。
- 元: T0803
- 結果: W 未 ・ M 未 ・ L 未

#### S11 スタジオが前面に無くてもホットキーが効く [A: WML]

- 手順: メモ帳など別のアプリを前面にして、Ctrl + Shift + 2 (夕方)・Ctrl + Shift + 1 (雑談)・Ctrl + Alt + N (うなずく)・Ctrl + Alt + 1 (笑顔を重ねる・外す)・Ctrl + Alt + P (トラッキングの一時停止) を押す。
- 期待: どれも出力ウィンドウに効く。前面のアプリには文字が入らない。Linux は X11 のセッションで (Wayland は S13)。
- 元: T0803
- 結果: W 未 ・ M 未 ・ L 未

#### S12 ホットキーの割り当てと、登録できないときの理由 [B: WML]

- 手順: 「ホットキー」で「ホットキーを足す」→「キーを決める」→ キーを押す → 操作を選ぶ。既にあるキー (Ctrl + Shift + 1) を別の行にも割り当てる。
  ほかのアプリがグローバルに登録しているキー (OBS のホットキーなど) を割り当てる。修飾キーの無い F9 を割り当てる。
- 期待: キーを決めている間はほかのホットキーが効かない。同じキーは「ホットキー n と同じキーです」。ほかのアプリが使うキーは登録できない理由が出る。F9 は注意が出る。
- 元: T0803
- 結果: W 未 ・ M 未 ・ L 未

#### S13 Wayland ではホットキーの知らせが出る [B: L]

- 手順: Wayland のセッションでスタジオを起動し、「ホットキー」を開く。スタジオを前面にしてホットキーを押す。別のアプリを前面にして押す。
- 期待: 前面のときだけ効く、操作 API を使うように、という知らせが出る。前面では効き、ほかのアプリが前面のときは効かない。
- 元: T0803
- 結果: L 未

#### S14 OBS のウィンドウキャプチャで透過が届き、裏に隠れても止まらない [A: W]

- 手順: [studio.md の OBS でのウィンドウの取り込み](studio.md#obs-でのウィンドウの取り込み) の Windows の手順で、「ウィンドウキャプチャ」(「Windows 10 (1903 以降)」) に
  `[ugoe-studio.exe]: ugoe studio output` を選ぶ。OBS のプレビューで背景を見る。出力ウィンドウをほかのウィンドウの裏に置く。
  背景が黒いときは、「ゲームキャプチャ」(「特定のウィンドウをキャプチャ」・「透過を許可」) も試す。
- 期待: モデルの外側が透けて OBS の下のソースが見える。裏に置いても OBS の画が動き続ける。どちらのキャプチャで透過が届いたかを書く。
- 元: T0804

## 結果を書き戻す

1. 利用者は、`check-pack` の写し (`ugoe-check\manual-check.md`) の結果の欄を書き換える。スクリーンショットは同じフォルダーに置き、ファイル名を NG の欄に書く。
2. 一巡したら、書き換えた写し (または NG の項目だけ) を team-lead に渡す。
3. team-lead (またはエージェント) は、結果をこのファイルの結果の欄に写し、コミットする (`docs(tasks): record manual check results`)。
   OK が揃った項目は、元のタスクのメモの「確かめていないこと」を消さずに「確認済み (日付)」と足す。
4. NG はタスクにする (1 つの不具合 = 1 タスク。似たものはまとめる)。タスクのメモにこの表の ID (例: S14) を書き、直したら同じ項目を確かめ直してもらう。
5. マニュアルとの食い違いは、マニュアルを直すタスクにする (画面の名前・OS の画面の名前など)。
6. 新しいタスクで「確かめていないこと」が出たら、タスクのメモに加えてこの表にも項目を足す (優先度と OS を付ける)。
