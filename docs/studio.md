# スタジオの設計 (apps/studio)

配信者が配信中に使うデスクトップアプリ「スタジオ」の画面と操作の設計。範囲・構成・描画の場所・外部 API の安全性を決めた理由は
[ADR 0028](adr/0028-studio.md)。画面の部品と翻訳は ADR 0029 と docs/ui.md (T0900 で書く) に従う。

> この文書は T0800 で骨子を書いた。プロファイルの形式 (T0802)・入力とホットキー (T0803)・API のメッセージ (T0805。英語のリファレンスは
> [studio-api.md](studio-api.md)) などは、各タスクで詳しくする。

配信者向けの使い方 (マニュアル) は [manual/studio.md](manual/studio.md) (T0806)。実機でまだ確かめていないことは [実機で確かめていないこと](#実機で確かめていないこと) にまとめた。

## 全体の構成

```
 操作ウィンドウ (WebView)                      バックエンド (Rust)                         受け手
 ┌──────────────────────┐   IPC     ┌──────────────────────────────┐  Channel   ┌────────────────────────┐
 │ シーン・入力・出力の設定 │ ───────► │ 指揮役 (conductor)             │ ─────────► │ 出力ウィンドウ (WebView)  │
 │ カメラ → トラッキング    │ トラッキング│  ugoe::Puppet (物理は切る)     │            │  wasm で物理を回して描く   │
 │ マイク → 音量          │ 音量      │  モーション・表情・トラッキング・ │  WebSocket ├────────────────────────┤
 │ (モデルは描かない)      │ 操作      │  目パチ・呼吸・リップシンク      │ ─────────► │ ブラウザソース (OBS)      │
 └──────────────────────┘           │  刻みごとに {seq, dt, values}   │            │  @ugoe/runtime (wasm)   │
          ▲                          │                              │  チャネル   ├────────────────────────┤
          │ 状態・負荷の通知           │ ホットキー (グローバル)          │ ─────────► │ 仮想カメラ               │
          └───────────────────────── │ 外部 API (WebSocket)           │            │  ugoe-render (常駐) →    │
                                     │ プロファイルの読み書き          │            │  NV12 などに変換して OS へ │
                                     └──────────────────────────────┘            └────────────────────────┘
```

- **指揮役** だけがパラメータの値を決める。受け手は届いたフレームを順に適用して物理を回し、描く ([ADR 0028 の 3.](adr/0028-studio.md#3-描画の場所と物理と時間の扱い))。
- 出力ウィンドウ・ブラウザソース・仮想カメラは独立で、どれを閉じても他は続く。

### フレームの配信 (内部の形)

外部 API とは別の、スタジオの中の形。版を上げて変えてよい (ブラウザソースのページもスタジオが配るので、いつも同じ版で揃う)。

| メッセージ | 中身 | いつ |
| --- | --- | --- |
| `scene` | `revision`・モデルとモジュールの版・モデルの表示名・パラメータの ID の並び・付けるモジュールの名前 (合成の順)・ライティング・位置と大きさと回転・背景 (T0802) | 接続したとき、シーンが変わったとき |
| `frame` | `seq`・`revision`・`dt`・リセットの印・`values` (指揮役の物理の段に入る直前の値。`scene` の ID の並びの順の `f32`)・`lip_sync` (リップシンクの音量と強さ。当てなければ無し)・`part_opacities` (モーションのパーツの不透明度のカーブ。カーブのあるパーツだけの番号・値・重み) | 刻みごと (30 / 60 / 120 回/秒。[刻みの速さ](#刻みの速さと正確さ)) |

- 指揮役は `update` の後の `Puppet::values_before_physics()`・`Puppet::lip_sync_applied()`・`Puppet::part_opacities_applied()` を
  `values`・`lip_sync`・`part_opacities` にする (T0134・T0135)。パーツの番号はモデル (モジュールを付けたら合成したモデル) の `parts` の順。
  着せ替えの直後に前のシーンのフレームを付け直したモデルに当てると、モジュールのパーツの番号はずれうる (本体のパーツは合成でも番号が変わらない。
  モデルに無い番号は受け手が無視する)。モーションが本体のパーツを切り替える限り影響は無い。
- `scene` は JSON (`apps/studio/src-tauri/src/stream.rs` の `Scene`)。受け手はモデル・モジュール・背景の画像のバイト列を `scene_model(revision)`・
  `scene_module(revision, index)`・`scene_background(revision)` のコマンドで取る (今のシーンのファイルだけを出す。任意のパスは読ませない)。

  ```json
  {
    "kind": "scene",
    "revision": 7,
    "modelRevision": 5,
    "modulesRevision": 6,
    "modelName": "avatar.ugoe",
    "parameterIds": ["AngleX", "AngleY"],
    "modules": ["CatEars"],
    "lighting": null,
    "transform": { "x": 0.1, "y": 0, "scale": 1.2, "rotation": 0 },
    "background": { "kind": "chroma", "color": "#00ff00" }
  }
  ```

  | 項目 | 中身 |
  | --- | --- |
  | `revision` | シーンの版。シーンの状態 (モデル・着せ替え・見せ方) が変わるたびに上がる。フレームの `revision` と同じ数 |
  | `modelRevision` | モデルを読んだときの `revision`。モデルの無いシーンは 0 |
  | `modulesRevision` | 付けるモジュールの組を変えたときの `revision` |
  | `modules` | 付けているモジュールの名前 (合成の順。`scene_module` の `index` の順) |
  | `lighting`・`transform`・`background` | 見せ方。形はプロファイルのシーンと同じ (下の「プロファイルの形式」)。画像の背景を読めなければ `transparent` にして配る |
- `frame` はバイト列 (リトルエンディアン、`apps/studio/src-tauri/src/stream.rs` の `Frame::encode`)。

  | 位置 | 型 | 中身 |
  | --- | --- | --- |
  | 0 | u8 | 種類 (1) |
  | 1 | u8 | フラグ (1 = 適用する前に物理をリセットする。着せ替えなど、モデルを読み直さずに形が変わるとき。2 = リップシンクを当てる) |
  | 2 | u16 | 予約 (0) |
  | 4 | u32 | `revision` |
  | 8 | u64 | `seq` (シーンが変わっても続けて数える) |
  | 16 | f32 | `dt` (秒。0〜0.1 に収める) |
  | 20 | f32 | リップシンクの音量 (フラグ 2 が無ければ 0) |
  | 24 | f32 | リップシンクの強さ (フラグ 2 が無ければ 0) |
  | 28 | u32 | 値の数 `n` |
  | 32 | f32 × `n` | `values` (4 の倍数の位置なので、JS では写さずに `Float32Array` を重ねる) |
  | 32 + 4n | u32 | パーツの不透明度の数 `k` (カーブが無ければ 0。T0135) |
  | 36 + 4n | u32 × `k` | パーツの番号 (JS では `Uint32Array` を重ねる) |
  | 36 + 4n + 4k | f32 × 2`k` | 各パーツのカーブの値と重み (交互。`WebPuppet.follow` にそのまま渡す) |

  T0800 では物理のリセットを別のメッセージ `reset` (`seq` 付き) にしていたが、フレームの印にした (T0801)。フレームと別に届く順を気にせずに済み、
  どのフレームの前にリセットするかが 1 つのメッセージで決まるため。

- 受け手は `frame` を `seq` の順に 1 つずつ適用する (`Puppet::follow(values, lip_sync, part_opacities, dt)`。`values` を基準値として書き、
  物理・リップシンク・パーツの不透明度 (届いたモーションのカーブと受け手のポーズ) を `update` と同じ順に進める。前のフレームの出力と同じ値でも
  基準値になる。[motion.md#受け手として進める](spec/motion.md#受け手として進める)、T0133・T0134・T0135)。
  - 前のシーンのフレームは捨てる。まだモデルを読み終えていないシーンのフレームは、読み終えるまで待たせ、そのシーンの最初のフレームから適用する
    (新しいモデルの物理は新しく始まるので、どの受け手も同じ形になる)。
  - 同じシーンの中で `seq` が飛んだら (切断など)、物理をリセットして続きから適用する。
  - 受け手が `follow` を呼ぶ場所は 1 つにまとめてある (wasm は `packages/player/src/follower.ts` の `applyFrame`、ネイティブは
    `apps/studio/src-tauri/src/follower.rs` の `apply_frame`。仮想カメラの受け手もこれを使う)。`follow` の引数が変わったら、ここと `Frame` の形を合わせる。
- 出力ウィンドウへは Tauri の `Channel` で送る (順序を保つ)。ブラウザソースへは WebSocket で送る (`scene` はテキスト、`frame` はバイナリの
  メッセージ。同じ順で配る。[ブラウザソース](#ブラウザソース)、T0808)。
  仮想カメラへは同じプロセスのチャネルで `Frame` をそのまま渡す (バイト列にしない。[仮想カメラ](#仮想カメラ)、T0807)。
- 一致の検査 (ADR 0028 の 10.) は `apps/studio/src-tauri/tests/follow_match.rs`: 指揮役のフレームの列 (書き換え・揃っていない `dt`・
  リップシンク・パーツを切り替えるモーション・物理のリセット・モデルの読み直しを含む) をバイト列で記録し、ネイティブの受け手に適用して、
  物理を有効にした 1 つの `Puppet` とパラメータの値・パーツの不透明度の上書き・頂点・不透明度を比べる (許容誤差 1e-3)。まとめて適用してから比べても同じになることも確かめる。
  ブラウザソースのページの受け手は、出力ウィンドウと同じ部品 (`Output.svelte`) を WebSocket の口で動かす。配信のバイト列は `Channel` と同じで、
  `apps/studio/src-tauri/src/api/tests.rs` が WebSocket で届くシーンとフレームの順と中身を確かめる。画の一致は
  [ブラウザソースの画の確かめ](#画の確かめ-adr-0028-の-10) (ヘッドレスの Chrome。出力ウィンドウ・ブラウザソース・仮想カメラの画を同じフレームで比べる)。

## 操作ウィンドウ

左にシーンの一覧、中央に「いまの状態」、右にパネルを並べる。配信中に触るもの (シーン・表情・モーション) を大きく、
設定 (入力の機器・出力・API) は奥に置く。

```
┌ ツールバー: プロファイル ▾ | モデルを選ぶ… | 出力ウィンドウ [表示] | ソース ● | API ● | 負荷 12.3 ms / 60 fps | 設定 ⚙ ┐
├──────────────┬───────────────────────────────────┬──────────────────────────┤
│ シーン          │ いまの状態                            │ パネル (タブ)                │
│ ▶ 雑談 (F1)     │  モデル名・付けているモジュール            │ ・表情とモーション             │
│   ゲーム (F2)   │  トラッキング: 顔あり 30 fps            │ ・入力 (カメラ・マイク)         │
│   休憩 (F3)     │  口パク: ▁▃▅ (音量のメーター)           │ ・シーンの編集                 │
│ [+] [複製] [↑↓] │  主なパラメータの値 (角度・目・口)       │ ・ホットキー                   │
│               │  警告・エラー                           │ ・出力                        │
│               │                                     │ ・外部 API                     │
└──────────────┴───────────────────────────────────┴──────────────────────────┘
```

| パネル | 内容 | タスク |
| --- | --- | --- |
| シーン (左) | シーンの一覧・切り替え・追加・複製・並べ替え・削除。割り当てたホットキーを並べて示す | T0802 |
| いまの状態 (中央) | モデル・付けているモジュール・トラッキングと口パクの様子・主なパラメータの値・警告。モデルは描かない | T0801・T0803 |
| 表情とモーション | 表情の付け外し・モーションの再生 (優先度)・待機モーション・モーションを優先するパラメータ (T0721・T0722) | T0803 |
| 入力 | カメラの選択・トラッキングの開始と停止・キャリブレーション・平滑化。マイクの選択・感度・ノイズの閾値・音量のメーター | T0803 |
| シーンの編集 | 選んだシーンのモデル・着せ替え・ライティング・位置と大きさと回転・背景 (透過・単色・クロマキー・画像) | T0802 |
| ホットキー | 操作ごとのキーの割り当て (下の「ホットキー」)。ぶつかりの表示 | T0803 |
| 出力 | 出力ウィンドウの大きさ・最前面・刻みの速さ・負荷の表示。仮想カメラの開始と停止・解像度・フレームレート。ブラウザソース (OBS) の出す・やめる・URL のコピーと作り直し・OBS の手順 | T0804・T0807・T0808 |
| 外部 API | 有効にするスイッチ・接続先・ポート・トークンの写しと作り直し・承認したクライアントの一覧 (権限・切断・取り消し)・承認を待つアプリ | T0805 |

- 承認を待つクライアントがあるときは、どのパネルを開いていても上に知らせを出す (承認・拒否・後で)。
- プロファイルの設定 (シーンの編集・表情とモーション・入力・ホットキー・刻みの速さ・仮想カメラ) は、変えるたびにバックエンドへ送り、画面の値は `profile` の通知で変わる。
  送っている途中の値は通知を待たずに画面に出し、次の変更はその値を基にする (通知の前に続けて変えても、前の変更を消さない。T0824)。
  送るのは 1 つずつで、送っている間の変更は最後のものだけを次に送る。送り終えたら通知の値に戻す
  (シーンは `Control.svelte` の `editing`、ほかは `apps/studio/src/lib/pendingEdit.svelte.ts`)。
- 負荷の表示 (1 刻みの時間・受け手ごとの描画の時間と落としたフレーム) は操作ウィンドウだけに出す。出力ウィンドウには何も重ねない。
- 閉じる操作: 操作ウィンドウを閉じるとアプリを終える (待ち受けと仮想カメラも止める)。止める前に、配信中の出力があれば確かめる。
- ツールバーの右端の「設定」(歯車) のダイアログに、言語・テーマ・ライセンスをまとめる (ビューアと同じ形。T0907)。ツールバーは既定の 1280 幅で 1 行に収める。
  ライセンスは、設定の「ライセンスを表示…」で、スタジオのライセンス (GPL-3.0-only) と同梱する第三者のもの (MediaPipe の wasm とモデル・JS のライブラリ) の表記を出す
  (`apps/studio/public/third-party-notices.txt`。ビューアと同じ形。T0811。生成と検査は [release.md](release.md#同梱物のライセンスの表記))。
- 幅が 960px 以下では 3 つの列を縦に積み、列ごと送る (360px まで)。

## 出力ウィンドウ

| 設定 | 選択肢 | 既定 |
| --- | --- | --- |
| 大きさ | 1920×1080・1280×720・1080×1920 (縦)・1080×1080・自由 | 1920×1080 |
| 枠 | なし (左ボタンのドラッグで動かす。T0813) | なし |
| 背景 | シーンの背景に従う (透過・単色・クロマキー・画像) | 透過 |
| 最前面 | 入・切 | 切 |
| 刻みの速さ | 30・60・120 | 60 |

- モデルの位置と大きさと回転はシーンが持つ (出力の大きさに対する割合で持ち、大きさを変えても構図が保たれる)。
- バックグラウンドの抑制を切り、隠れても最小化されても止まらない ([隠れても止まらない](#隠れても止まらない)、T0804)。
- 出力ウィンドウは受け手なので、指揮役より速く描いても新しい形は出ない (刻みの速さが実質のフレームレート)。
- 大きさのプリセットは **物理ピクセル** (配信ソフトが取り込む大きさ)。画面の拡大率が 150% なら、画面の上では 1280×720 に見える。
  画面に収まらない大きさは OS が小さくすることがあり、そのときは操作ウィンドウに今の大きさと注意を出す。
- 出力ウィンドウを閉じる操作 (Alt+F4 など) では、閉じずに隠す (受け手を作り直さない)。操作ウィンドウの「出力ウィンドウを表示」で戻す。
- 出力ウィンドウが呼べるバックエンドのコマンドは、受け手に要るもの (配信の購読・今のシーンのファイル・描画の負荷と読めなかったことの報告) と
  ウィンドウのドラッグだけにする。プロファイル・外部 API のトークンや承認などは操作ウィンドウからしか呼べない。
  どちらのウィンドウも CSP で同梱したもの以外を読まない (多層の防御。T0820、`apps/studio/README.md`)。
- 背景の透過は、macOS では Tauri の `macOSPrivateApi` (`macos-private-api` feature) が要る。これを使うと Mac App Store では配布できない (T0801)。
  **使う** (2026-10-02、利用者の判断。Mac App Store では配布しない。Developer ID による直接配布には影響しない)。

## シーンとプロファイル

- **シーン:** 名前・モデル (ファイルのパス)・付けるモジュールの組・ライティング・位置と大きさと回転・背景。1 つのシーンにアバターは 1 体。
- **切り替え:** 指揮役が新しいシーンを読み、`scene` を配る。同じモデル (同じパス) のシーンどうしは、パラメータの値・トラッキング・再生中のモーションを
  引き継ぐ (着せ替えとライティングと配置だけが変わる)。別のモデルは読み直す (物理はリセット)。切り替えの瞬間は前の画を保ち、
  読み終えてから替える (途中の空の画を出さない)。ファイルを読めない・モジュールを付けられないときは、何も変えずに前のシーンを出し続ける
  (背景の画像だけは、読めなければ透過にして切り替える。配信中に切り替えを止めないため)。
- **プロファイル:** シーンの一覧・ホットキー・出力の設定・入力の機器を 1 つの JSON に持つ。版の番号 (`version`) 付き。
  最近のプロファイルを覚え、起動時は最後のものを開く。形式は下の「プロファイルの形式」。
- 外部 API のトークンと承認したクライアントの鍵は **プロファイルに入れない** (プロファイルを人に渡しても漏れない)。アプリのデータの場所に置く。

### 操作 (T0802)

- 左の一覧でシーンを押すと、そのシーンに切り替え、右の「シーンの編集」の対象にする。追加 (モデルの無いシーン)・複製 (すぐ後ろに置く)・
  上へ / 下へ・削除 (確かめのダイアログ) ができる。配信しているシーンに「配信中」の印を付ける。
- シーンの編集は、変えるたびにバックエンドへ送る。配信しているシーンなら、すぐ出し直す (出せなければ元の設定に戻してエラーを出す)。
  配信していないシーンは設定だけを変え、「このシーンに切り替える」で出す。
- ツールバーの「モデルを選ぶ」は、編集しているシーンのモデルを選び、そのシーンに切り替える (シーンが無ければ作る)。
  別のモデルを選ぶと、そのシーンのモジュールは外す (別のモデルのスロットには付かないことが多いため)。
- モデルが見つからない (別の計算機で作ったプロファイルなど) ときは、そのシーンを選び、「選び直す」のボタンを付けて知らせる。
- **保存:** プロファイルのメニューに 新しいプロファイル・開く・保存 (Ctrl/⌘+S)・名前を付けて保存・最近のプロファイル。
  保存先があるプロファイルは、変えてから 0.8 秒後に自動で保存する。保存先の無いプロファイルを変えたら、保存を促す知らせを出し、
  新しいプロファイルや別のプロファイルを開く前に、捨ててよいか確かめる。保存のダイアログで選んだ名前に `.json` が無ければ付ける
  (バックエンドの `save_file_dialog`。Linux のダイアログはフィルタの拡張子を付けずにパスを返すことがある。T0011)。
- **読み書きできるパス (T0838):** ファイルのダイアログはバックエンドが開き、画面のコマンドが読めるのは、ダイアログで選んだパス・
  今のプロファイルにあるパス・最近のプロファイルだけ、書けるのは保存のダイアログで選んだパス (1 回) と今の保存先だけ
  ([apps/studio/README.md](../apps/studio/README.md) の「ファイルの読み書きの許可」。ビューアと同じ考え)。
- **ファイルの読み方:** 画面や外部 API から受けたパスで読むファイル (モデル・モジュール・背景の画像・プロファイル) は、拡張子を確かめ、
  通常のファイル (リンクは辿る) のときだけ、大きさの上限 (モデルとモジュール 512 MiB・画像 64 MiB・プロファイル 16 MiB) までで読む
  (`ugoe_fs::read_regular_file`、T0011・T0025。エディタ・ビューアと同じ関数)。装置 (`/dev/zero`)・FIFO・ディレクトリは開かずに読めない
  (`unreadable`) とする (読み続けてメモリを使い果たす・開くだけで止まるため)。
- **起動:** 最後に開いた (保存した) プロファイルを開き、最後に使ったシーン (`activeScene`) に切り替える。見つからなければ新しいプロファイル
  (モデルの無いシーンが 1 つ) で始める。最近のプロファイルは、アプリの設定の場所 (Tauri の `app_config_dir`) の `recent-profiles.json` に
  新しい順に 10 個まで覚える。消えたファイルを開こうとしたら一覧から外す。
- 出力ウィンドウの大きさのプリセットはプロファイルに持つ (T0801 では localStorage)。プロファイルを開くと、出力ウィンドウをその大きさにする。
  刻みの速さと仮想カメラの設定もプロファイルに持ち (T0827)、開くとその速さで刻み、動いている仮想カメラにもその設定を効かせる
  (解像度かフレームレートが違えば始め直す。[仮想カメラ](#仮想カメラ))。
  画面の言語とテーマはアプリの設定 (localStorage) のまま。テーマは操作ウィンドウだけに効き、出力ウィンドウには効かせない (透過のまま)。

### プロファイルの形式

アプリの設定であって、モデルのファイル形式 ([spec/file-formats.md](spec/file-formats.md)) ではない。拡張子は `.json` (既定の名前は `profile.json`)。
UTF-8 の JSON の 1 ファイルで、書くときは一時ファイルに書いてから置き換える (途中で落ちても前のファイルを壊さない)。
読み書きは `apps/studio/src-tauri/src/profile.rs`。

```json
{
  "format": "ugoe-studio-profile",
  "version": 1,
  "scenes": [
    {
      "id": "scene-1",
      "name": "Chat",
      "model": "/home/me/avatars/avatar.ugoe",
      "modules": ["/home/me/avatars/cat-ears.ugoemod"],
      "lighting": null,
      "transform": { "x": 0, "y": 0.05, "scale": 1.2, "rotation": 0 },
      "background": { "kind": "transparent" }
    },
    {
      "id": "scene-2",
      "name": "Game",
      "model": "/home/me/avatars/avatar.ugoe",
      "background": { "kind": "chroma", "color": "#00ff00" }
    }
  ],
  "activeScene": "scene-1",
  "output": {
    "size": "1920x1080",
    "tickRate": 60,
    "virtualCamera": { "width": 1280, "height": 720, "fps": 30, "background": "#f0f0f0" }
  }
}
```

| 項目 | 型 | 中身 |
| --- | --- | --- |
| `format` | 文字列 | 常に `"ugoe-studio-profile"`。違えば「プロファイルではない」として開かない (JSON のモデルを開いたときなど) |
| `version` | 整数 | 形式の版 (今は 1)。下の「版」 |
| `scenes` | 配列 | シーンの一覧 (操作ウィンドウの並び)。省くと空 |
| `activeScene` | 文字列 / `null` | 最後に使ったシーンの `id`。開いたときにこのシーンにする。無いシーンを指していれば先頭 |
| `output.size` | 文字列 | 出力ウィンドウの大きさのプリセット (`1920x1080`・`1280x720`・`1080x1920`・`1080x1080`・`free`)。知らない値は `1920x1080` |
| `output.tickRate` | 整数 | 刻みの速さ (回/秒。`30`・`60`・`120`。[刻みの速さと正確さ](#刻みの速さと正確さ))。省くか選べない値なら `60` (T0827) |
| `output.virtualCamera` | オブジェクト | 仮想カメラの設定 ([仮想カメラ](#仮想カメラ))。`width`・`height`: 解像度 (1920×1080・1280×720。組が選べなければ 1280×720)。`fps`: フレームレート (30・60。選べなければ 30)。`background`: 透過のところを埋める色 (`#rrggbb`。形が違えば `#f0f0f0`)。省いた値は 1280×720・30・`#f0f0f0` (T0827) |

シーン:

| 項目 | 型 | 中身 |
| --- | --- | --- |
| `id` | 文字列 | プロファイルの中で一意 (ホットキーや外部 API がシーンを指す)。空や重複は読むときに `scene-<n>` に付け直す |
| `name` | 文字列 | 表示名 (100 文字まで)。空なら画面は「シーン 1」などと並びの番号で出す |
| `model` | 文字列 / `null` | モデル (`.ugoe` か JSON) の **絶対パス**。`null` はモデルの無いシーン (出力は何も描かない) |
| `modules` | 文字列の配列 | 付ける着せ替えのモジュール (`.ugoemod`) の絶対パス。**合成の順** (先のものから付ける)。省くと空 |
| `lighting` | オブジェクト / `null` | 光源の設定 (`@ugoe/player` の `LightingSettings`: `enabled`・`ambient`・`directional`・`point`。意味は [spec/rendering.md](spec/rendering.md#ライティング))。`null` は既定の光源 (「標準」)。足りない値・範囲の外の値は画面と受け手が既定値で埋めて収める |
| `transform` | オブジェクト | `x`・`y`: 出力に合わせて中央に置いた位置からのずれ (出力の幅・高さに対する割合。右・下が正。−2〜2)。`scale`: 出力に合わせた大きさに対する倍率 (0.05〜20)。`rotation`: 度 (時計回りが正。−360〜360)。省いた値は 0・0・1・0 |
| `background` | オブジェクト | `kind` で分ける。`transparent` (透過)・`color` (単色。`color` は `#rrggbb`)・`chroma` (クロマキー。見え方は単色と同じで、画面の色の選び方が緑・青になる)・`image` (`path` に PNG・JPEG・WebP の絶対パス。出力を覆うように拡大する)。省くと透過 |

- **版:** 読むときは、まず `format` と `version` だけを見る。`version` が読める版 (1) より新しければ、**中身を読まずに**
  「新しいスタジオで保存されています (版 N。読めるのは版 1 まで)」というエラーにする (黙って一部を読み落とさない)。0 や無い `version` は壊れたファイル。
  書くときは今の版で書く。
- **値の範囲:** 範囲の外の数は収め、数でない値は既定に戻す。色の形が違えば黒にする (`Profile::sanitize`)。
- **足すときの規則:** 省ける項目を足すだけなら版を上げない (古いスタジオは知らない項目を読み飛ばす。ただし保存し直すと消える)。
  意味を変える・項目を消すときは版を上げ、読む側に古い版からの読み替えを足す。ホットキー・入力・モーションの設定 (T0803) は省ける項目として足した
  (下の「入力とホットキーの項目」)。刻みの速さと仮想カメラの設定 (`output.tickRate`・`output.virtualCamera`。T0827) も、版 1 のまま省ける項目として足した。
  それより前のプロファイルは既定の値 (60・1280×720・30・`#f0f0f0`) で読み、それより前のスタジオは 2 つを読み飛ばす (保存し直すと消える)。
- **localStorage からの移し替え (T0827):** 刻みの速さと仮想カメラの設定は、以前は操作ウィンドウの localStorage
  (`ugoe-studio.tick-rate`・`ugoe-studio.virtual-camera`) に覚えていた。**引き継がずに捨てる** (起動したときに 2 つのキーを消す。
  `apps/studio/src/lib/settings.ts` の `forgetLegacySettings`)。プロファイルの値は、その計算機の設定でなくプロファイルを書いたときの値にしたい
  (人に渡したプロファイルが、受け取った計算機の localStorage で変わらないように)。項目の無いプロファイルに localStorage の値を当てると、
  開く計算機ごとに値が変わる。スタジオはまだ公開しておらず、失うのは開発中に選んだ値だけ。
- パスは絶対パスで持つ (ADR 0028 の 4.)。見つからなければ、そのシーンに切り替えるときに選び直させる。

#### 入力とホットキーの項目 (T0803)

どれも省ける (省くと既定値)。読み書きは `apps/studio/src-tauri/src/input.rs`・`hotkeys.rs`。

```json
{
  "hotkeys": [
    { "keys": "Ctrl+Shift+Digit1", "action": { "kind": "scene", "scene": "scene-1" } },
    { "keys": "Ctrl+Alt+KeyS", "action": { "kind": "expression", "expression": "smile", "mode": "toggle" } },
    { "keys": "F9", "action": { "kind": "dressUp", "slot": "Hair", "module": "/home/me/avatars/long-hair.ugoemod" } }
  ],
  "input": {
    "camera": { "id": "…", "label": "HD Webcam" },
    "smoothing": 0.5, "swapSides": false, "trackBody": true, "stopEyeBlink": true,
    "microphone": null, "sensitivity": 0.5, "noiseGate": 0.3
  },
  "motion": { "autoIdle": true, "idleMotion": null, "overTracking": true, "trackingKept": ["EyeLOpen", "EyeROpen"] }
}
```

| 項目 | 型 | 中身 |
| --- | --- | --- |
| `hotkeys[].keys` | 文字列 | キー。修飾キー (`Ctrl`・`Alt`・`Shift`・`Super`) と `KeyboardEvent.code` の名前 (`KeyA`・`Digit1`・`F1`・`Numpad1`・`ArrowUp` など。配列に依らない物理的なキー) を `+` でつなぐ (`tauri-plugin-global-shortcut` の書き方)。空はまだ決めていない |
| `hotkeys[].action` | オブジェクト | `kind` で分ける。下の「ホットキー」の表。知らない `kind` (新しい版) は読み飛ばして何もしない (保存し直すと `unknown` になる) |
| `input.camera`・`input.microphone` | オブジェクト / `null` | 選んだ機器 (`id` と `label`)。`id` が見つからなければ `label` で探し、無ければ既定の機器。`null` は既定の機器 |
| `input.smoothing` | 数 (0〜1) | トラッキングの平滑化の強さ |
| `input.swapSides`・`trackBody`・`stopEyeBlink` | 真偽 | 左右を入れ替える・体 (肩) もトラッキングする・トラッキング中は自動の目パチを止める (`@ugoe/face-tracking` の同じ名前の設定) |
| `input.sensitivity` | 数 (0〜1) | マイクの感度。0.5 で等倍、0 で 1/4、1 で 4 倍 |
| `input.noiseGate` | 数 (0〜1) | ノイズの閾値 (下の「マイクの口パク」の大きさの尺度)。これより小さな音では口を開かない |
| `motion.autoIdle` | 真偽 | 何も再生していないときに待機モーションを流す |
| `motion.idleMotion` | 文字列 / `null` | 待機モーション。`null` かモデルに無い名前なら名前で選ぶ (`idle`、無ければ `idle` で始まるもの。ループするものを先に) |
| `motion.overTracking` | 真偽 | トラッキング中も、再生中のモーション (待機を除く) が動かすパラメータではモーションを優先する |
| `motion.trackingKept` | 文字列の配列 | モーションを優先しても、トラッキングのままにするパラメータの ID |

### シーンの切り替えと受け手

受け手 (出力ウィンドウ) は、`scene` の通知を受けたら版の番号を比べて、することを選ぶ (`apps/studio/src/lib/outputLayout.ts` の `planScene`)。

| 変わったもの | 受け手がすること | フレーム |
| --- | --- | --- |
| `modelRevision` | モデルとモジュールを取って読み直す | そのシーンのフレームから最初から適用する (`followScene`。前のシーンのフレームは捨てる。物理は新しく始まる) |
| `modulesRevision` だけ | モジュールを取って付け直す | 前のシーンのフレームも続けて適用する (`continueScene`)。指揮役は、着せ替えたシーンの最初のフレームに物理のリセットの印を載せるので、どの受け手もそこで揃う |
| どちらも同じ | 見せ方 (ライティング・配置・背景) だけを変える | 前のシーンのフレームも続けて適用する (`continueScene`。受け手ごとに物理の刻みが抜けないように) |
| モデルが無い (`modelRevision` が 0) | 描かない (背景だけ出す) | 指揮役はフレームを作らない |

- **順序:** 受け手はシーンの通知を届いた順に 1 つずつ処理する。ファイルを取っている・読んでいる間に次のシーンが届いたら、前のシーンの続き
  (モデルの読み込み・モジュールの付け直し・見せ方・フレームの切り替え) は捨てる。続けて届いたシーンのうち、当たるのは最後のものだけ
  (途中のシーンのモデルは取らない)。背景の画像を替えたら、前の画像の blob URL を解放する。
- **配置:** 受け手はモデルを出力に合わせ (`fit`)、`scale` 倍にズームし、`x`・`y` の分だけパンする。回転は、描画の要素 (canvas を入れた舞台) を
  CSS で回す (ビューに回転が無いため)。回転するときだけ、舞台を出力の対角線の長さ (とずれの分) の正方形にして、回しても隅が欠けないようにする
  (描く画素はその分増える)。大きさの基準は出力に合わせた大きさにする (舞台が大きくなってもモデルの大きさは変わらない)。
  ブラウザソースのページも同じ部品なので同じ CSS で回す。仮想カメラは自分で描くので、回転をレンダラのビューで行う (`virtual_camera.rs` の
  `placement_view`)。CSS の回転は描いた画を回して標本を取り直すので、回したときだけ縁の画素が仮想カメラと少し違う。
- **背景:** 受け手のモデルの canvas は常に透過にし、背景は要素の CSS で描く (単色・クロマキーは色、画像は `cover`)。
- **ライティング:** シーンの光源を受け手の Player に当てる (受け手は光源も着せ替えの組も覚えない。`@ugoe/player` の受け手のモード)。

#### 受け手が読めなかったとき

受け手 (出力ウィンドウ・ブラウザソースのページ・仮想カメラ) が今のシーンのモデル・モジュール・背景の画像を取れない・読めないときは、
そのことをバックエンドへ返し、操作ウィンドウの上に受け手ごとの知らせとして出す (T0825。仮想カメラと背景の画像のデコードは T0836。1 つの受け手で読めなかったものをすべて出すのは T0840)。
**出力には何も重ねない。**

- **返すもの:** シーンの版 (`revision`)・何を (`asset`: `model`・`module`・`background`。モジュールなら `index` に `modules` の番号)・
  理由のコード (`code`)。文言は操作ウィンドウが `code` で選ぶ (ADR 0029 の 4.)。

  | `code` | いつ |
  | --- | --- |
  | `unavailable` | ファイルを受け取れなかった (`scene_model` などのコマンドや HTTP が失敗した) |
  | `unreadable` | 受け取ったが読めなかった (モデル・モジュールの形式が違う・壊れている・本体に付けられない。背景の画像をデコードできない) |
  | `noRenderer` | 受け手が描画を始められない (wasm・WebGPU・WebGL2 が使えない)。モデルは取らない |

- **口:** 出力ウィンドウは `report_load_failure(failure)`、ブラウザソースのページは同じ WebSocket で `{"kind":"loadFailure",…}` を送る
  (描画の負荷と同じ口)。仮想カメラはバックエンドの中のスレッドなので、そのスレッドの知らせ (`virtual_camera::Event::LoadFailures`) で渡す。
  出力ウィンドウとブラウザソースは読めなかったものを 1 つずつ返し (1 つのシーンでいくつもあれば、いくつも返す)、仮想カメラは
  1 つのシーンの分をまとめて返す。
- **知らせ:** 操作ウィンドウへは `subscribe_status` の `loadFailures` の通知で配る。

  ```json
  {"kind":"loadFailures","failures":[
    {"label":"output","revision":12,"asset":"module","index":0,"code":"unreadable"},
    {"label":"output","revision":12,"asset":"background","index":null,"code":"unavailable"},
    {"label":"virtualCamera","revision":12,"asset":"module","index":0,"code":"unreadable"}
  ]}
  ```

  `failures` は読めなかったものの平らな並び (受け手のラベルと上の項目。無ければ空)。**1 つの受け手で読めなかったものはすべて並ぶ** (T0840。
  以前は受け手ごとに 1 つだけ)。並びはラベルの順で、同じ受け手ではモデル・モジュール (番号の順)・背景の画像の順。ラベルは負荷の表示と同じ
  (`output`・`virtualCamera`・`browserSource`・`browserSource:2`…)。
  バックエンドは受け手ごとに、今のシーンで読めなかったものをすべて覚える。同じもの (モデル・同じ番号のモジュール・背景の画像) の報告は
  前のものを置き換え、変わらなければ配り直さない。受け手が去ったとき・仮想カメラが止まったとき (止めた・失敗した) は、その受け手の報告をすべて捨てる。
  操作ウィンドウは受け手ごとに 1 つの知らせにし、読めなかったものを 1 行ずつ並べる (`ReceiverFailuresNotices.svelte`)。閉じると、その受け手の
  知らせをすべて消す (次の通知で届けばまた出る)。
- **モデルを読めなかったとき:** モデルを読めなければ、そのシーンのモジュールと背景の画像は付けない・出さないので (下の取り直し)、
  知らせるのはモデルのことだけ。モデルを読めたら、受け取れない・読めないモジュールと背景の画像をすべて知らせる。
- **次のシーンに移ったための失敗は知らせない:** 受け手がファイルを取っている間に次のシーンになると、前のシーンのファイルは
  取れなくなる (今のシーンのファイルだけを出すため)。受け手は、失敗したときに最後に届いたシーンが変わっていれば返さない。
  バックエンドも、今のシーンの版でない報告は捨て、シーンが変わったら前のシーンの報告をすべて捨てる (受け手が去ったときも、その報告を捨てる)。
- **取り直し:** 読めなかったものは、次のシーンの通知 (見せ方だけの変更でも) で取り直す。モデルを読めなければ前のモデルを残し、
  このシーンのフレームを当てない (前のシーンの形のまま止まる)。モジュールを受け取れない・読めなければ、モデルと読めたモジュールで出す
  (出力ウィンドウも、以前は受け取れないモジュールがあるとモデルを読まずに止まっていた。T0840 で仮想カメラと揃えた)。
  背景の画像を受け取れない・デコードできなければ背景を出さない (仮想カメラは設定の色で埋める)。読めなかったものは見せ方だけの
  次のシーンでも取り直すので、まだ読めなければ新しいシーンの版でもう一度知らせる (前のシーンの報告はシーンが変わると捨てるため)。
- **背景の画像のデコード:** 出力ウィンドウとブラウザソースは背景を CSS で描くので、CSS は壊れた画像を黙って描かない。受け手は
  受け取った画像を、CSS に渡すのと同じ blob URL で画像の要素にデコードさせて (`HTMLImageElement.decode`。`apps/studio/src/lib/decodeImage.ts`)
  確かめ、できなければ `unreadable` を返して出さない。仮想カメラは自分でデコードする (`virtual_camera.rs` の `decode_background`)。
- **仮想カメラ:** 読めないことでは止まらない (以前は `model` で止まっていた)。モデルとモジュールの読み方は下の [描き方](#描き方)。

### シーンの切り替えと舞台のロック

舞台 (`apps/studio/src-tauri/src/stage.rs` の `Stage`。プロファイルと今のシーンのファイル) は 1 つのロックで守る。シーンの切り替え
(操作ウィンドウ・ホットキー・外部 API の `scene.activate`・`dressup.set`、出しているシーンの編集、プロファイルを開く) は、
大きなモデルを読む間もほかの操作 (パラメータ・表情・外部 API の読むだけの要求) を待たせないよう、3 つに分ける (T0834)。

1. **始める** (舞台を握る): シーンの設定と今のシーンで読んであるファイル (モデル・モジュール・背景の画像の `Arc`) を写し、始めた順の番号を振る。
   出しているシーンの編集は、ここで設定を置き換える。
2. **読む** (握らない): 読んでいないファイルを読んで解析する (`Pending::load`)。着せ替えは、モジュールを読んでスロットを知ってから付け外しを決める。
   モデルを読み直すときは、パペットの組み立て (モデルのコンパイルとモジュールの合成。`conductor.rs` の `assemble`) もここで行う (T0837)。
3. **差し込む** (舞台と指揮役を握る): 組み立てたパペットを指揮役に差し込み (`Conductor::present`。演技の読み込みだけを行う)、
   今のシーンのファイルを置き換え、通知を配る (`Stage::finish`)。同じモデルのままモジュールの組だけが変わるとき (着せ替え) は、
   今のパペットに付け直すので、モジュールの合成はここで行う (モジュールは本体より小さい)。

- **後から始めた切り替えが勝つ:** 差し込むときに、読んでいる間に後から始めた切り替え (別の切り替え・編集・着せ替え・プロファイルを開く・
  新しいプロファイル) があれば、読んだものを捨てる。読み終えた順によらず、出すのは最後に始めた切り替えだけ。捨てた要求はエラーにせず成功を返す
  (出してすぐ次のシーンに替えたのと同じ扱い)。組み立てたパペットも捨てる (指揮役には差し込まない)。
  読めなかった・組み立てられなかった (モジュールを付けられないなど) ときは、捨てられる要求でもエラーを返す (指揮役は前のシーンのまま)。
- 読んでいる間にそのシーンの設定が変わったら (操作ウィンドウで編集した・消した)、切り替えは今の設定で読み直す (消えていればエラー)。
  出しているシーンの編集と着せ替えは捨てる (編集した設定は残す。着せ替えは設定を書き換えない)。
- 出しているシーンの編集で出せなければ、設定がまだその編集のままなら元の設定に戻す。
- 読むファイルが無い (同じモデルの見せ方だけの編集・読んであるモジュールだけの着せ替えなど) ときは、握ったまま差し込む (通知が 1 回で済む)。
- 通知 (受け手への `scene`・操作ウィンドウのプロファイル・外部 API の `scene.changed` など) は、差し込むときに舞台を握ったまま送るので、
  差し込んだ順に届く。始めたときに設定を置き換えた編集は、その時点でもプロファイルの通知を送る。
- **操作ウィンドウの読み込み中 (T0837):** 操作ウィンドウが始めた切り替え (シーンを押す・出しているシーンの編集・モデルを選ぶ・
  プロファイルを開く) は、コマンドが返るまでを読み込み中とし、シーンの一覧で読み込んでいるシーンに「読み込み中」の印を付け、
  一覧の下の案内を「シーンを読み込んでいます…」に替える (`role="status"` で読み上げにも知らせる)。150 ms より早く返れば出さない
  (見せ方だけの編集でちらつかないように)。バックエンドと同じく後から始めた切り替えが勝ち、先の切り替えが後で返っても後の切り替えを出し続ける
  (`src/lib/sceneLoading.svelte.ts`)。ホットキーと外部 API の切り替えには出さない (操作ウィンドウは始まったことを知らない)。


## 入力

カメラのフェイストラッキングとマイクの口パクは操作ウィンドウの WebView で取り、値だけを指揮役に送る (ADR 0028 の 4.)。
映像と音はどこにも送らない。モーション・表情・待機モーション・トラッキング中のモーションの優先も指揮役で行い (`apps/studio/src-tauri/src/animation.rs`)、
受け手には値を配るだけにする (受け手はモーションも目パチも使わない)。

```
 操作ウィンドウ (WebView)                                   指揮役 (Puppet。物理は切る)
 カメラ → MediaPipe → キャリブレーション・平滑化 ── set_tracking ──► トラッキングの入力 (Rust の対応付けで変換)
 マイク → RMS → dB → 閾値・感度 → 開く速さ・閉じる速さ ── set_lip_sync_level ──► リップシンクの音量
 パネル・ホットキー ── play_motion・set_expression など ──► モーション・表情
```

- **入力の処理を描画に頼らない:** カメラとマイクの処理は、バックエンドの刻みのスレッドが刻みごとに送るメッセージ (`subscribe_pulse`) で回す
  (`apps/studio/src/lib/pulse.ts`、`@ugoe/face-tracking` の `FaceTracker` の `schedule`)。Channel のメッセージは隠れたページにも届くので、
  Linux で操作ウィンドウを最小化して `requestAnimationFrame` が止まっても、入力は止まらない (ヘッドレスの Chrome で `requestAnimationFrame` を
  止めても値が届き続けることを確かめた)。カメラは新しい映像のフレームがあるときだけ検出する。
  検出が刻みより重いときは刻みを間引く ([隠れても止まらない](#隠れても止まらない)、T0812)。
  ただし、最小化した WebView がカメラの映像やマイクの音を取り続けるか (WebKitGTK・WebView2・WKWebView) は実機で確かめていない。
- 値は IPC で送る。送っている途中に届いた値は最後のものだけを次に送る (`apps/studio/src/lib/latest.ts`。古い値を溜めない)。
- トラッキングを止める (`null` を送る)・一時停止すると、トラッキングが書き込んでいたパラメータを既定値に戻す (最後の値が基準値として残るため)。
  一時停止中に届いた値は捨てる。トラッキング中に自動の目パチを止める設定は、指揮役の目パチの段を切る。
- モデルを読み直しても (シーンの切り替え)、トラッキングの入力・口パクの音量・目パチの設定はそのまま新しいモデルに渡す。モーションと表情は初めからにし、待機モーションを流す。
- トラッキングの値が届いたら次の刻みを早める調整 (ADR 0028 の 3. の「遅れ」) はしていない。カメラからの遅れは、ビューアより
  「IPC の 1 往復 + 最大 1 刻み」多い (60 刻みで最大約 17 ms)。実機で遅れが気になれば後続のタスクで測って決める。
- 受け手 (`Puppet::follow`) はモーションのパーツの不透明度のカーブを使わない (T0133) ので、パーツの表示を切り替えるモーションの見た目は出力に出ない (後続の候補)。

### カメラのフェイストラッキング

`@ugoe/face-tracking` のパネル (入力の選択・映像とランドマーク・平滑化・キャリブレーション・記録) をそのまま使う。調整と使ったカメラはプロファイルの `input` に覚える。
ビューアと同じく、カメラを使えるのは操作ウィンドウだけ (バックエンドの `on_permission_request` が操作ウィンドウのカメラとマイクの要求だけを許す。
macOS は `Info.plist` の `NSCameraUsageDescription`・`NSMicrophoneUsageDescription` と `Entitlements.plist`)。
MediaPipe の wasm とモデルはアプリに同梱する (`pnpm mediapipe`。ビューアと同じ `ugoe-mediapipe-assets`)。

### マイクの口パク

`getUserMedia` (エコーキャンセル・ノイズ抑制・自動の音量調整は切る) の音を `AnalyserNode` で取り、刻みごとに口を開く量 (0〜1) を作る
(`apps/studio/src/lib/lipSync.ts`)。

1. 波形の RMS を dB にし、−60〜0 dB を 0〜1 に並べる (大きさ。音量のメーターもこの値)。
2. ノイズの閾値 (`noiseGate`) 以下なら 0。上なら閾値から 1 までを 0〜1 に広げ、感度の倍率 (`4^(2×sensitivity−1)`) を掛けて 0〜1 に収める。
3. 前の値から目標へ、開くときは時定数 0.03 秒、閉じるときは 0.12 秒で追う (口がぱたぱたしないように)。

指揮役のリップシンク (`Puppet::set_lip_sync_level`) はこの値をモデルの `lip_sync.parameters` に書く (`docs/spec/motion.md#リップシンク`)。
受け手にはフレームの `lip_sync` で届く (T0134)。マイクを止めると `null` を送り、口のパラメータに触らなくなる。

## ホットキー

グローバルなショートカット (アプリが前面に無くても効く。`tauri-plugin-global-shortcut`) で、次の操作を割り当てられる。

| 操作 | `kind` | 引数 |
| --- | --- | --- |
| シーンの切り替え | `scene` | `scene` (シーンの ID) |
| 表情 | `expression` | `expression` (名前)・`mode` (`set` = それだけにする / `toggle` = 重ねる・外す) |
| 表情をすべて外す | `clearExpressions` | — |
| モーションの再生 | `motion` | `motion` (名前)・`priority` (`idle` / `normal` / `force`) |
| モーションを止める (待機に戻る) | `stopMotions` | — |
| 着せ替え | `dressUp` | `slot`・`module` (`.ugoemod` の絶対パス。`null` はスロットを空ける) |
| トラッキングの一時停止・再開 (押すたびに切り替える) | `trackingPause` | — |
| トラッキングのキャリブレーション | `trackingCalibrate` | — |
| 口パクの一時停止・再開 | `lipSyncPause` | — |

- **割り当ての画面 (操作ウィンドウの「ホットキー」):** キーの欄を押してからキーを押すと割り当てる (Esc でやめる、Backspace で消す)。
  キーを待っている間はホットキーの登録を外す (`suspend_hotkeys`。押したキーが操作を行わないように)。操作の種類と引数を選ぶ。
  表情とモーションの選択肢は配信しているモデルのもの (別のモデルの名前の割り当ても残す)。着せ替えはモジュールのファイルを選ぶと、そのスロットを読む (`module_slot`)。
- **登録:** プロファイルの割り当てが変わるたびに、バックエンドがすべて登録し直す (`lib.rs` の `sync_hotkeys`)。同じキーは前の割り当てだけを登録し、
  後のものには「ぶつかり」を出す。キーを読めない・ほかのアプリや OS が使っていて登録できないものは、理由をパネルに出す (`hotkeys` の通知)。
  修飾キーの無いキーは登録できるが、スタジオを動かしている間ほかのアプリがそのキーを受け取れなくなるので注意を出す。
- **行う:** 押されたら、バックエンドで操作を行う (シーンの切り替えはファイルを読むので、イベントのスレッドを塞がないように別のスレッドで)。
  キャリブレーションは操作ウィンドウのトラッカーが行う (`hotkey` の通知で知らせる)。行えなかったら (モデルが無い・優先度が低くて始まらないなど) 操作ウィンドウに知らせる。
  着せ替えは、配信しているシーンの `modules` から同じスロットのモジュールを外して付け直し、シーンを出し直す (プロファイルの変更になる)。
- Wayland では、アプリが前面に無いとグローバルなショートカットを受けられない ([ADR 0028 の 9.](adr/0028-studio.md#9-グローバルなホットキー))。
  Wayland のセッション (`WAYLAND_DISPLAY`・`XDG_SESSION_TYPE`) ではパネルに知らせを出し、[外部 API](#外部-api) から同じ操作をすることを案内する。

## 外部 API

「スタジオの操作 API」(ugoe Studio API、T0805)。ループバックの WebSocket の上の JSON-RPC 2.0。安全性の規則は
[ADR 0028 の 6.](adr/0028-studio.md#6-外部-api-とブラウザソースの待ち受けの安全性)。メソッド・通知・誤り・閉じる符号の詳細は
英語のリファレンス [studio-api.md](studio-api.md)、メッセージの形は JSON Schema [studio-api.schema.json](studio-api.schema.json)。
実装は `apps/studio/src-tauri/src/api/`。

**接続の流れ:** `ws://127.0.0.1:<port>/api` に接続 → `session.hello` (クライアントの名前とトークン、承認済みなら鍵) →
初めてなら操作ウィンドウの上の知らせで利用者が承認する (権限を選ぶ。応答は承認まで返さない) → 応答に鍵を入れる →
以後は鍵で接続し、すぐに使える。拒否・違うトークン・知らない鍵は誤りを返して閉じる。

| メソッド | 権限 | 内容 |
| --- | --- | --- |
| `session.hello` | — | 名乗る。応答はスタジオの版・API の版・与えられた権限・送れる通知 (承認した直後だけ鍵) |
| `studio.state` | 読む | いまのシーン・モデル・付けているモジュール・表情・再生中のモーション・トラッキングと口パクの様子 |
| `scene.list` / `scene.activate` | 読む / 操作 | シーンの一覧 / 切り替え |
| `expression.list` / `expression.set` / `expression.add` / `expression.remove` / `expression.toggle` / `expression.clear` | 読む / 操作 | 表情 |
| `motion.list` / `motion.play` / `motion.stop` | 読む / 操作 | モーション (優先度付き) |
| `parameter.list` / `parameter.set` | 読む / 操作 | パラメータの定義と今の値 / 値の上書き (重みと期限付き) |
| `dressup.list` / `dressup.set` | 読む / 操作 | スロットと付けられるモジュール / 着せ替え |
| `tracking.pause` / `lipsync.pause` / `tracking.calibrate` | 操作 | ホットキーと同じ操作 (Wayland でホットキーの代わりに使える) |
| `events.subscribe` / `events.unsubscribe` | 読む | 通知を受け取る種類を選ぶ (接続したときは何も受け取らない) |

| 通知 | 内容 |
| --- | --- |
| `scene.changed` | 配信しているシーンが替わった |
| `scene.listChanged` | シーンの一覧 (並び・名前・モデル) が変わった |
| `expression.changed` | 使っている表情が変わった |
| `motion.started` / `motion.finished` | モーションの開始と終了 (待機モーションを含む) |
| `motion.event` | モーションのイベントに達した |
| `dressup.changed` | 配信しているシーンの着せ替えの組が変わった |
| `tracking.changed` | トラッキングの入力が届き始めた・止まった、トラッキングと口パクの一時停止 |

- **待ち受け:** 操作ウィンドウの「操作 API」のパネルで有効にする (既定は切。選んだことは覚える)。`127.0.0.1` と `::1` にだけ束ねる。
  既定のポートは **28451** (他製品の既定と重ならず、Linux と Windows の一時的なポートの範囲の外)。1024〜65535 で変えられる。
  待ち受けている間はツールバーに「API」の印を出す。HTTP と WebSocket を同じ口で扱う (`server.rs` の `route`)。ブラウザソースは
  経路 (`/source/<トークン>/…`) を足して同じ待ち受けとポートを使う。待ち受けは、操作 API とブラウザソースのどちらかが有効な間だけ動かし
  (`mod.rs` の `sync_listener`)、`/api` は操作 API を入れているときだけ答える (切っていれば `404`)。経路に依らず、`Host` がループバックの名前でない要求・転送ヘッダの付いた要求・
  スタジオ自身のページでない `Origin` の要求は `403` にする (`http.rs` の `check_request`)。
- **トークンと鍵:** アプリのデータの場所 (Tauri の `app_data_dir`) の `studio-api.json` に、有効かどうか・ポート・トークン・承認したクライアント
  (ID・名前・鍵・権限・承認した時刻・最後に接続した時刻)・ブラウザソースの設定 (`source`: 有効かどうかとトークン。T0808) を置く (Unix では 0600。プロファイルには入れない)。どれも OS の乱数の 256 ビットで、
  定数時間で比べる。パネルでトークンを写す・作り直す (承認済みの鍵はそのまま)、承認したクライアントを切断する (鍵は残す)・取り消す (鍵を消して切る)。
- **承認:** 承認を待つクライアントは、どのパネルを開いていても上に知らせを出す (`ApiApproval.svelte`。名前・権限の選択・承認・拒否・後で)。
  「後で」で隠したものは、パネルの「承認を待つアプリ」から出し直す。承認を待てるのは 4 つまで、接続は 32 まで。
- **パラメータの上書き:** 指揮役の `override_parameter` (`conductor.rs`)。刻みごとに、物理の段に入る直前の値 (受け手に配る値) を `value` へ
  `weight` の割合で寄せ、`dt` で期限 (既定 1 秒、最大 10 秒) を減らし、切れたらやめる。トラッキング・モーション・表情・目パチ・呼吸より後なので
  外部 API の値が勝つ。物理はその値から動き、マイクのリップシンクは受け手が後で重ねる。指揮役の `Puppet` には書かないので、期限が切れると
  トラッキングやモーションの値にすぐ戻る。モデルを読み直すと上書きは消える。
- **着せ替え:** `dressup.set` は、プロファイルのシーンが付けているモジュールと、ホットキーの着せ替えに割り当てたモジュールだけを付けられる
  (任意のパスを読ませない)。行うことはホットキーの着せ替えと同じ (配信しているシーンの `modules` を書き換えて出し直す)。
- **パスを受けない (T0838):** 操作 API のメソッドはファイルのパスを受けない。シーンは ID、モジュールは `dressup.list` の ID (今は
  ファイルのパスだが、中身を決めない文字列として扱わせる) で指し、ID は今のプロファイルにあるものだけを受ける。外のツールは、
  利用者が操作ウィンドウで選んでいない (プロファイルに無い) ファイルをスタジオに読ませられない。操作ウィンドウのコマンドと同じ規則
  ([apps/studio/README.md](../apps/studio/README.md) の「ファイルの読み書きの許可」)。モデルやモジュールを外から足すメソッドを作るなら、
  操作ウィンドウで利用者が確かめる手順を挟む。
- **通知の出どころ:** シーン・一覧・着せ替えは舞台を変える操作 (`with_stage`) の前後の差、表情・モーション・トラッキングは刻みのスレッドが
  演技の様子 (`AnimationView`) を配るときの前の様子との差、`motion.event` は刻みで発火したモーションのイベント。要求が起こした通知は、
  その要求の応答より先に届くことがある。同じモーションを始め直したときも `motion.finished` と `motion.started` を送り、`motion.event` は
  そのモーションの `motion.started` の後・`motion.finished` の前に送る (終わりで発火したイベントも、終わったモーションの名前で)。
  `motion.event` の `motion` は、イベントを発火したモーションの名前 (`Puppet::motion_event_sources`)。別のモーションに替えた後に
  フェードアウトしながら発火したイベントも、新しいモーションではなく替えられたモーションの名前で送る (T0821)。
  シーンを切り替えて付けているモジュールが変わったときは、`scene.changed` に続けて `dressup.changed` も送る。
- **WebSocket:** HTTP の要求の読み取り・検査・経路は自前で行い、`/api` の Upgrade のときだけ、握手の応答の鍵とフレームの読み書きを
  tungstenite (同期版。`derive_accept_key` と `WebSocket::from_raw_socket` の仲間) に任せる (利用者の決定、2026-10-02。`ws.rs`)。
  圧縮などの拡張は取り決めない。1 メッセージ 256 KiB・1 フレーム 64 KiB まで。tungstenite の `WebSocket` は読みと書きを分けられないので、
  接続ごとに 1 つのスレッドで、読むのを 20 ms で区切ってその合間に列のもの (応答・通知・閉じる) を送る (刻みのスレッドや承認の操作は接続を待たない)。
  20 秒何も届かなければ ping を送り (送るものがあっても。通知を受けるだけのクライアントを pong で確かめる)、60 秒何も届かなければ切る
  (`server.rs` の `Keepalive`。ブラウザソースのページも同じ)。
- **名乗らない接続と遅い要求 (T0822):** 操作 API の WebSocket は、つないでから 30 秒のうちに `session.hello` を受けなければ close の
  符号 `4008` で閉じる (承認待ちは除く。`server.rs` の `HelloDeadline`)。名乗らずに ping に答え続ける接続が、接続の上限 (32) を埋めないように。
  要求の頭 (要求の行とヘッダ) は、接続してから 10 秒のうちに読み終えなければ応答せずに閉じる (1 回の読み取りごとではなく全体の上限。
  1 バイトずつ送る相手も切る)。頭を読んでいる途中の接続は 64 までにし、超えた接続はスレッドを作らずに閉じる
  (経路が決まるまでは、経路ごとの接続の上限が効かないため)。

## ブラウザソース

OBS のブラウザソースに URL を入れるだけで、スタジオのアバターを背景の透過付きで取り込む (T0808)。ウィンドウの取り込みより設定が簡単で、
OBS の中で大きさや位置を変えやすい。安全性の規則は [ADR 0028 の 6.](adr/0028-studio.md#6-外部-api-とブラウザソースの待ち受けの安全性)。
実装は `apps/studio/src-tauri/src/api/source.rs` (経路と配信)、ページは `apps/studio/source.html`・`src/source.ts` (受け手は `Output.svelte`)。

- **出し方:** 操作ウィンドウの「ブラウザソース (OBS)」で入れる (既定は切。選んだことは覚える)。出している間はツールバーに「ソース」の印を出す。
  パネルは URL (トークンは伏せて出す)・「URL をコピー」・「URL を作り直す」・開いているページの数と、OBS での設定の手順を出す。
- **待ち受け:** 操作 API と同じ待ち受けとポート (既定 28451。ポートは「操作 API」のパネルで変える) を使い、**スイッチとトークンは別** に持つ
  (`studio-api.json` の `source`)。操作 API を切っていても、ブラウザソースを入れていれば待ち受ける。ループバックだけに束ねる。
- **URL:** `http://127.0.0.1:<port>/source/<トークン>/` (トークンは OS の乱数の 256 ビット。定数時間で比べる)。OBS はヘッダを付けられないので
  パスで渡す。末尾の `/` が無ければ付けた URL へ転送する (ページは相対のパスでファイルを読む)。作り直すと古い URL のページは閉じ、以後は `404`。
- **経路** (`/source/<トークン>/` の下。ブラウザソースを切っているとき・トークンが違うときは、どれも `404`):

  | 経路 | 中身 |
  | --- | --- |
  | (空) | ページ (`source.html`)。ビルドしたフロントエンド (Tauri に入れた `dist/`) から出す |
  | `assets/…` | ページのスクリプト・スタイル・wasm (英数字と `-`・`_`・`.` だけの名前。`..` などは `404`) |
  | `frames` | WebSocket。つないだら今の `scene` を最初に送り、以後は出力ウィンドウと同じ順で `scene` (テキスト) と `frame` (バイナリ) を送る |
  | `scene/<revision>/model`・`scene/<revision>/module/<index>`・`scene/<revision>/background` | 今のシーンのファイル (今のシーンでなければ `404`。任意のパスは読ませない) |

- **読むだけ:** ページはファイルとフレームを受け取るだけで、操作はできない。ページから送れるのは描画の負荷 (`{"kind":"renderStats",…}`。
  操作ウィンドウの「フレームレートと負荷」に「ブラウザソース」(2 つ目からは「ブラウザソース (2)」) として出る) と、
  今のシーンのファイルを読めなかったこと (`{"kind":"loadFailure",…}`。[受け手が読めなかったとき](#受け手が読めなかったとき)) だけで、バイナリを送ると閉じる。
- **ブラウザからの悪用を防ぐ:** 経路に依らない検査 (`Host`・転送ヘッダ・`Origin`) は操作 API と同じ。ページの WebSocket の `Origin` は
  スタジオ自身の `http://127.0.0.1:<port>` なので通り、ほかの Web ページからは接続できない。応答には `Referrer-Policy: no-referrer`
  (URL のトークンを外へ出さない)・`X-Content-Type-Options: nosniff`・外のものを読まない CSP (`default-src 'none'`、スクリプトと wasm と
  スタイルは自分のもの、画像は自分と blob、接続は自分の WebSocket だけ) を付ける。
- **ページ:** 出力ウィンドウと同じ受け手の部品 (`Output.svelte`。`@ugoe/player` の受け手のモード、wasm。WebGPU が無ければ WebGL2) を、
  WebSocket の口 (`src/lib/feed.ts` の `sourceFeed`) で動かす。シーンの見せ方 (ライティング・配置・回転・背景) と着せ替え・シーンの切り替えは
  出力ウィンドウと同じ規則で追う ([シーンの切り替えと受け手](#シーンの切り替えと受け手))。背景は透過 (シーンの背景が単色や画像ならそれも出る)。
  切れたら 1 秒後につなぎ直す (スタジオを起動し直しても OBS のページはそのまま戻る。同じシーンなら見せ方だけを当て直し、`seq` が飛んだので
  物理をリセットして続ける)。UI の要素は一切出さない。
- **溢れ:** 1 つのページに送らずに溜めておけるのは 256 メッセージ (60 刻みで約 4 秒) まで。超えたら (ページが止まっている) その接続を閉じ、
  ページはつなぎ直す。同時に開けるページは 8 まで。
- **開発モード:** `just studio` (`tauri dev`) では、ページのファイルを `apps/studio/dist/` から直に読む (Tauri の `AssetResolver`)。
  先に `pnpm --filter @ugoe/studio build` で作っておく (無ければ `404`)。

### OBS での設定

1. スタジオの「ブラウザソース (OBS)」を入れ、「URL をコピー」を押す。
2. OBS の「ソース」の「+」から「ブラウザ」を選び、新しいソースを作る。
3. 「URL」にコピーした URL を貼る。
4. 「幅」と「高さ」を出力ウィンドウと同じ大きさ (1920 と 1080 など。パネルに今のプリセットの値が出る) にする。モデルの位置と大きさは
   シーンの配置の割合のまま描くので、別の大きさにしても構図は保たれる。
5. 「カスタム CSS」は OBS の既定のままでよい (ページの背景は透過)。
6. 「ソースが表示されていないときにシャットダウン」と「シーンがアクティブになったときブラウザの表示を更新」は切ったままにする
   (切り替えのたびにページを読み直すと、揺れものの物理が始めからになる)。

- URL はトークンを含むので、人に見せたり配信の画面に映したりしない。漏れたら「URL を作り直す」。
- 実際の OBS (CEF) での確認は利用者が行う ([実機で確かめていないこと](#実機で確かめていないこと))。OBS の CEF で WebGL2 が使えないと描けない (ADR 0028 の見直すきっかけ)。

### 画の確かめ (ADR 0028 の 10.)

出力ウィンドウ・ブラウザソースのページ・仮想カメラの画を、同じフレームの列を適用して止めた状態で比べる (`apps/studio/README.md#ブラウザソースの画を確かめる`)。

- `apps/studio/src-tauri/src/api/source_check.rs` (手で実行する ignored のテスト。`--features gpu-tests`) が、見本のモデル
  (`avatar-lit.ugoe`。法線マップと動的物理) のシーンに光源・配置 (回転を含む)・背景の画像 (透過のところがある) を付けてブラウザソースを出す。
  ページが 2 つつないだら、頭を振るフレームを 150 個 (揃っていない `dt` を混ぜる) 配って止め、同じ列を仮想カメラの受け手 (`Feed`、RGBA) にも
  適用して読み戻した画を書く。
- ヘッドレスの Chrome (SwiftShader の WebGL2) で、ブラウザソースのページと、出力ウィンドウのページ (`output.html` を同じ Origin で開き、
  `StudioHost` を同じ WebSocket に差し替えたもの) を開き、止めた後の画を撮って比べる。
- 結果 (T0808、480×270): ページどうし (出力ウィンドウとブラウザソース) は **完全に一致**。仮想カメラ (ネイティブの wgpu) とは、回転なしで
  平均の差 0.45 (0〜255)・差が 16 を超える画素 0.3% (縁と、背景の画像の拡大の仕方の違い)、回転 8 度で平均 2.2・3.9% (CSS の回転による縁の標本の違い)。
  光源を入れても切っても差は変わらない (光源・法線マップは同じに当たっている)。

## 仮想カメラ

会議アプリや配信ソフトのカメラの入力として、スタジオの出力をそのまま選べるようにする (T0807。macOS は T0809 の Camera Extension)。
OS の部品の扱いと `unsafe` の例外は [ADR 0028 の 8.](adr/0028-studio.md#8-仮想カメラの-os-の部品と-unsafe-の例外)。

- 操作ウィンドウの「仮想カメラ」で開始と停止。解像度 (1920×1080・1280×720)・フレームレート (30・60)・透過を埋める色 (既定は `#f0f0f0`) を選ぶ。
  選んだ設定はプロファイルの `output.virtualCamera` に持つ (T0827。[プロファイルの形式](#プロファイルの形式))。開始は、そのときのプロファイルの設定で
  始める。動いている間に解像度かフレームレートが変わると (パネルで変えた・別のプロファイルを開いた) 始め直す (OS のカメラの形が変わるため)。
  色はその場で効く。比べて効かせるのはバックエンド (`lib.rs` の `sync_camera`)。止まった (失敗した) 仮想カメラは始め直さない。
- 背景は不透明にする。透過のシーンは設定した色で埋める (クロマキーの緑を既定にしない)。
- 止まった・遅れたことを操作ウィンドウに出す:

  | 知らせ | いつ |
  | --- | --- |
  | 使えません (注意) | 始める前から分かる理由: Windows 11 でない・ドライバが登録されていない・v4l2loopback が読み込まれていない・macOS 12.3 より前・macOS で拡張を入れていない束 |
  | 止まりました (エラー) | 始められなかった・途中で失敗した (機器が無い・機器を開く権限が無い・ほかのアプリが使っている・GPU が無い・描画中に GPU がエラーを返した (`gpuError`。デバイスの喪失・検証エラーなど)・GPU が応答しない (`gpuTimeout`。下の「GPU が止まったとき」)・OS のエラー・macOS で拡張の許可を待っている / 再起動が要る / 有効にできない) |
  | カメラを使っているアプリがありません (案内) | Windows と macOS で、カメラを開いているアプリが無い (Linux では分からないので出さない) |
  | 遅れています (注意) | 直近 1 秒に描けた回数が、フレームレートの 95% を下回った |

  理由に合わせて、v4l2loopback の入れ方 (Linux)・`video` のグループへの入り方 (Linux で機器を開く権限が無い)・OBS の仮想カメラを使う手順
  (Windows 10)・インストーラでの入れ直し (登録が無い) を案内する (`apps/studio/src/lib/virtualCamera.ts` の `guideFor`)。
  理由のコードは `ugoe_studio_vcam::Error::code` で、文言は `apps/studio/locales/*.json` の `virtualCamera.errors.*` (ADR 0029 の 4.)。
  負荷の表示 (「フレームレートと負荷」) にも「仮想カメラ」の行が出る (描いた回数・1 回の時間・描かなかった画の数。目標は仮想カメラのフレームレート)。

### 描き方

```
指揮役 ─ フレーム {seq, dt, values, lip_sync} ─▶ 仮想カメラのスレッド (同じプロセスのチャネル)
                                                 │ 受け手 (Follower): 届いたフレームをすべて順に follow で適用 (物理を回す)
                                                 │ 常駐の描画 (ugoe-headless の Resident): フレームレートごとに描き、
                                                 │   GPU で NV12 (Windows・macOS) / YUY2 (Linux) に変換してから読み戻す (待たない)
                                                 ▼
                                   ugoe-studio-vcam: Windows は共有メモリ → メディアソース、Linux は /dev/videoN に write、
                                                     macOS は Camera Extension の受ける側のストリームに積む
```

- 実装は `apps/studio/src-tauri/src/virtual_camera.rs` (受け手と描画の `Feed`、スレッドの `run`) と `apps/studio/vcam` (`ugoe-studio-vcam`。OS の境界)。
- 受け手は出力ウィンドウと同じ規則で、物理を含めて同じ形になる (ADR 0028 の 3.)。刻み (30 / 60 / 120) と仮想カメラのフレームレートは別で、
  フレームはすべて適用し、描くのはフレームレートの回数だけ。読み戻しは 3 枚のバッファを回して待たないので、画は 1〜2 フレーム遅れる。
  GPU が追いつかなければその回は描かない (「遅れています」)。
- シーンの通知は、出力ウィンドウの受け手と同じ規則で扱う ([シーンの切り替えと受け手](#シーンの切り替えと受け手)): モデルの版が変わったら読み直し、
  モジュールの版だけが変わったら付け直し (テクスチャの並びが変わるので描画は作り直す)、どちらも同じなら見せ方だけを変えて前のシーンのフレームも
  続けて適用する (`apps/studio/src-tauri/src/follower.rs` の `continue_scene`)。
- 見せ方: 位置と大きさと回転は出力ウィンドウと同じ置き方 (`virtual_camera.rs` の `placement_view`。出力に収め、倍率を掛け、ずらした位置を中心に回す)。
  背景は単色・クロマキーならその色、透過なら設定の色で埋める。画像の背景は、出力ウィンドウ (CSS の `cover`) と同じく出力を覆うように
  拡大・縮小して中央に置き (`ugoe_headless::image::cover`。バイリニア)、画像の透過のところは設定の色で埋めて、毎フレームその画を描画先に写して
  からモデルを描く (`Resident::set_backdrop`。GPU の中の写し)。画像は PNG (`png`)・JPEG (`zune-jpeg`)・WebP (`image-webp`) を読む (中身の先頭で見分ける。T0808。依存は利用者の判断 2026-10-02)。
  巨大な画像で固まらないよう、デコードの前に大きさを確かめ、一辺 8192 画素・3355 万画素 (32 Mi) を超えるものは読まずに設定の色で埋める
  (`virtual_camera.rs` の `decode_background`。ファイルの大きさの上限 64 MiB は舞台が読むときに見る)。
  光源はシーンの光源を出力ウィンドウと同じ規則でレンダラに渡す (`apps/studio/src-tauri/src/lighting.rs`。`@ugoe/player` の `sanitizeLighting`・
  `toLightingJson` と同じ。シーンに光源が無ければ既定の組)。モデルとモジュールの法線マップも渡す (T0808)。
- モデルとモジュールのテクスチャ・法線マップは PNG と、圧縮していない KTX2 (`R8G8B8(A8)` の `_UNORM`・`_SRGB`) を読む
  (`ugoe_headless::image::decode_image*`。T0836)。読めない形式の KTX2 (ブロック圧縮など) は、wasm の受け手と同じく
  テクスチャを不透明な白・法線マップを無しにして描く。壊れた画像を持つモデル・モジュールは読めないものとして知らせる
  ([受け手が読めなかったとき](#受け手が読めなかったとき))。モジュールは 1 つずつ読み、読めない・本体に付けられないものを飛ばして残りを付ける。
- 始めたときに今のシーンを送り、物理はその時点から始める (出力ウィンドウより後から始めた受け手なので、揺れの途中の形は合わない)。
  モデルが無いシーンでは背景の色だけの画を出す。
- 色の変換は BT.709 の限定範囲 (Y は 16〜235)。描画先の値をそのまま R'G'B' とみなし、色差は 2×2 (NV12)・横 2 画素 (YUY2) の平均から作る。
  計算シェーダの無い GPU では CPU で同じ式で変換する (`crates/ugoe-headless/src/yuv.rs`)。
- 止めている間は、スレッドも受け手も作らない (GPU を使わない)。GPU の機器は一度作ったら破棄しない (`crates/ugoe-headless/README.md#gpu`)。
- **GPU が止まったとき (T0832):** 毎フレームの描画と読み戻しは待たないのでスレッドは止まらないが、GPU が止まると読み戻しが来なくなり、
  画が止まる。そこで次のように扱う (`virtual_camera.rs` の `Stall`・`drain`・`GpuCell`)。
  - 動いている間: 読み戻しを待っているのに `STALL_LIMIT` (10 秒) 来なければ、GPU が止まったとみなして仮想カメラを止め、
    止まった理由 `gpuTimeout` (「GPU が応答しなくなった」) を操作ウィンドウに出す。**自動では作り直さない:** 本当に止まったドライバでは
    作り直しても同じことを繰り返すうえ、受け手の物理の状態を持ち越せないので、利用者が始め直す (止まった仮想カメラは始め直さないという上の規則と同じ)。
    それまでの間は「遅れています」が出る。10 秒は、追いつかないだけの GPU (1 枚に数十〜数百ミリ秒) と取り違えない長さ。
  - 止めるとき: 頼んだ読み戻しを `Wait::All` で待つ (上限は `ugoe_headless` の `Gpu::wait_timeout`、既定 30 秒)。上限を超えたら標準エラーに書く。
  - どちらの場合も、その GPU (と常駐の描画) を手放し (破棄はしない。MCP サーバと同じ)、次に始めるときに GPU を作り直す。
  - **描画中のほかの GPU のエラー (T0836):** 描画・読み戻し・描画の準備で GPU がエラーを返したら (デバイスの喪失・検証エラーなど)、
    止まった理由 `gpuError` (「描く間に GPU がエラーを返した」) で止める (以前は OS のエラーの `os` に混ざっていた)。`os` は OS の部品
    (`ugoe-studio-vcam`) のエラーだけにする。デバイスを失ったなら使い回せないので、この GPU も手放して次の開始で作り直す
    (止まったのではないので、常駐の描画はふつうに落とす)。
- 一致の検査 (ADR 0028 の 10.): `apps/studio/src-tauri/tests/virtual_camera_gpu.rs` (`just test-gpu`) が、指揮役のフレームの列を適用して
  読み戻した画を、物理を有効にした 1 つの `Puppet` を 1 枚の口で描いて同じ形に変換した画と比べる (許容誤差付き)。光源・法線マップ・背景の画像を
  付けたシーンも、同じ光源で描いたモデルを背景の上に重ねた画と比べる。出力ウィンドウ (WebView) の画との比べ合わせは [画の確かめ](#画の確かめ-adr-0028-の-10)。

### Windows (Media Foundation)

Windows 11 の Media Foundation の仮想カメラ (`MFCreateVirtualCamera`) で、「ugoe studio」という名前のカメラを出す。

- **しくみ:** スタジオがカメラを作ると (寿命は `Session`。スタジオが終わると消える。今の利用者だけ)、OS のサービス Frame Server が
  スタジオの DLL (`ugoe_studio_vcam.dll`。COM のメディアソース) を読み込む。メディアソースは共有メモリ (`Global\ugoe-studio-virtual-camera-1`)
  を作り、カメラを開いたアプリの求めに応じて最新の画を NV12 で渡す。スタジオは共有メモリを開いて画を書く
  (形は `apps/studio/vcam/src/shared.rs`。版の番号付きの seqlock)。
  - 共有メモリはメディアソース (サービス) が作る。別のセッションから見える名前の共有メモリは、ふつうの利用者の権限では作れないため。
    権限は SYSTEM・Local Service・管理者と、対話でログオンした利用者 (読み書き) に与える。**同じ計算機に対話でログオンした別の利用者も
    カメラの画を書ける** (読めるのは画だけで、ほかの情報は流れない)。
  - スタジオはカメラの機器に設定 (解像度とフレームレート) を付け、メディアソースはそれだけを出す。読めなければ選べる組をすべて出し、
    アプリが選んだ大きさと違えば最も近い画素で拡大縮小する。画がまだ無ければ黒を出す。出した組のほかの media type は受けない。
  - 共有メモリの形の版がメディアソースの DLL と合わなければ (入れ直しの途中など)、仮想カメラを止めて OS のエラーとして知らせる。
  - `MFCreateVirtualCamera` は Windows 11 にしか無いので、実行時に `mfsensorgroup.dll` から引く (Windows 10 でもスタジオは起動し、
    「Windows 11 が要ります」を出す)。
- **入れ方:** インストーラ (NSIS) は管理者の権限で動き (`installMode: perMachine`)、DLL を入れて `regsvr32` で登録する
  (`HKLM\SOFTWARE\Classes\CLSID\{128A1A50-B227-494B-952E-0C011BB01869}`)。アンインストールで登録を消す。スタジオの実行中は権限を求めない。
  - 設定は `apps/studio/src-tauri/tauri.windows.conf.json` と `apps/studio/src-tauri/windows/hooks.nsh`。DLL は `pnpm vcam`
    (`apps/studio/scripts/build-vcam.mjs`) が `target/vcam/x86_64-pc-windows-msvc/release/` に作る (CRT を静的にリンクする。Linux からは cargo-xwin でクロスビルド)。
  - COM の登録をインストーラで行うので、スタジオの Windows の配布物は NSIS だけにする (MSI は作らない)。
  - 入れ直しのときに前の DLL を Frame Server が使っていれば、名前を変えて退け、再起動のときに消す。
- **開発中 (`just studio`):** `pnpm vcam` で DLL を作ってから、管理者の PowerShell で一度だけ登録する:

  ```powershell
  regsvr32 "<リポジトリ>\target\vcam\x86_64-pc-windows-msvc\release\ugoe_studio_vcam.dll"
  ```

  DLL を作り直したら、Frame Server が古いものを読み込んだままのことがある。カメラを使うアプリをすべて閉じるか、
  管理者で `Restart-Service FrameServer` を実行する。
- **Windows 10 では (代わりの手順):** OBS Studio で出力ウィンドウを取り込み ([OBS でのウィンドウの取り込み](#obs-でのウィンドウの取り込み))、
  OBS の「コントロール」→「仮想カメラ開始」を押す。会議アプリではカメラに「OBS Virtual Camera」を選ぶ。背景はシーンの背景になる
  (透過は OBS の仮想カメラでも出せない)。

**未確認 (利用者の確認に残す。WSL の上では Windows の仮想カメラを動かせない):** コンパイル (`cargo xwin clippy --target x86_64-pc-windows-msvc`) と
DLL のリンク・書き出す関数 (`DllGetClassObject` など 4 つ) は確かめたが、実機では次を確かめていない。

1. インストーラで入れると UAC が出て、`regsvr32` が成功する (`HKLM\SOFTWARE\Classes\CLSID\{128A1A50-...}\InprocServer32` に DLL のパス)。
2. スタジオで仮想カメラを入れると、Windows の「設定」→「Bluetooth とデバイス」→「カメラ」と、カメラのアプリに「ugoe studio」が出る。
3. カメラのアプリ・Teams・Zoom・Chrome (Google Meet) で「ugoe studio」を選ぶと、モデルが動いて映る (色が正しい: 白い背景が白く、
   赤が赤く。色がずれるなら BT.709 / 限定範囲の扱いを確かめる)。1920×1080・1280×720、30・60 fps のそれぞれ。
4. カメラを開いているアプリが無いと「カメラを使っているアプリがありません」が出て、開くと消える。
5. スタジオを閉じるとカメラが一覧から消える。スタジオを強制終了しても、次に起動したときに使える。
6. Windows 10 で「Windows 11 が要ります」と OBS の手順が出て、スタジオ自体は動く。
7. アンインストールで登録が消える (再起動の後に DLL が残らない)。上書きの入れ直しが失敗しない。

### Linux (v4l2loopback)

v4l2loopback (仮想のビデオ機器を作るカーネルモジュール) の機器に YUYV の画を書く。**スタジオは v4l2loopback を入れない**
(入れるには管理者の権限が要る)。機器が見つからなければ、操作ウィンドウに次の入れ方を出す (自動で `sudo` しない)。

```sh
# 入れる (ディストリビューションごと)
sudo apt install v4l2loopback-dkms        # Debian / Ubuntu
sudo dnf install v4l2loopback             # Fedora (RPM Fusion)
sudo pacman -S v4l2loopback-dkms          # Arch Linux
# 読み込む (1 つの機器を /dev/video10 に作る。exclusive_caps=1 は Chrome などがカメラとして見つけるのに要る)
sudo modprobe v4l2loopback devices=1 video_nr=10 card_label="ugoe studio" exclusive_caps=1
# 起動のたびに読み込む
echo v4l2loopback | sudo tee /etc/modules-load.d/v4l2loopback.conf
echo 'options v4l2loopback devices=1 video_nr=10 card_label="ugoe studio" exclusive_caps=1' | sudo tee /etc/modprobe.d/v4l2loopback.conf
```

- スタジオは `/dev/video*` を番号順に調べ、ドライバが `v4l2 loopback` で書き込みを受ける最初の機器を使う。`VIDIOC_S_FMT` で YUYV と大きさ
  (BT.709・限定範囲) を決め、`VIDIOC_S_PARM` でフレームレートを伝え、1 枚ずつ `write` する (`apps/studio/vcam/src/v4l2.rs`)。
- loopback の機器があってもほかのアプリが書いている (`exclusive_caps=1` の機器は書き込みを 1 つしか受けない) なら「ほかのアプリが使っています」。
- 書ける loopback の機器が無く、権限が無くて開けない (`EACCES`・`EPERM`) 機器があり、v4l2loopback が読み込まれていれば、「機器を開く権限が
  ありません」(`noPermission`) と、`video` のグループに入る手順 (`sudo usermod -aG video "$USER"` の後でログインし直す) を案内する。
  開けない機器が loopback のものかは開かないと分からないので、モジュールが読み込まれていることで判断する (読み込まれていなければ
  入れ方を案内する)。`/dev/video*` は多くのディストリビューションで `root:video` の `0660` で、画面の前でログインした利用者には
  systemd-logind が ACL を足す (udev の `uaccess`)。ACL が付かない (リモートのセッション・logind を使わない環境など) ときに起こる。
- 「使えません」の判断は `/sys/module/v4l2loopback` があるか (モジュールが読み込まれているか) だけで行い、機器は開始したときに開く。
- Secure Boot を使っていると、DKMS で作ったモジュールに署名が要ることがある (ディストリビューションの手順に従う)。
- 受け取るアプリがあるかは分からない (v4l2loopback は知らせない) ので、「カメラを使っているアプリがありません」は出さない。

**未確認 (利用者の確認に残す。WSL のカーネルには v4l2loopback が無い):** ioctl の構造体の大きさと番号はテストで確かめたが、実機では次を確かめていない。

1. 上の手順で `/dev/video10` を作り、スタジオで仮想カメラを入れると「入: /dev/video10・…」になる。
2. `ffplay /dev/video10` (または `v4l2-ctl --device /dev/video10 --all`) で、YUYV・選んだ大きさで映る。
3. Chrome (Google Meet)・OBS (映像キャプチャデバイス (V4L2))・Zoom で「ugoe studio」を選ぶと映り、色が正しい。
4. v4l2loopback を読み込んでいないと「使えません」と入れ方が出る。ほかのアプリが同じ機器に書いていると「ほかのアプリが使っています」。
5. `video` のグループに入っていない利用者 (`sudo chmod 0660 /dev/video10` と `sudo setfacl -b /dev/video10` で ACL を外して試せる) で
   入れると、「機器を開く権限がありません」と `video` のグループの手順が出る。グループに入ってログインし直すと入る。

### macOS (Camera Extension)

macOS 12.3 以降の CoreMediaIO の Camera Extension (System Extension) で、「ugoe studio」という名前のカメラを出す (T0809)。
**配布物に入れるのは、利用者が Apple Developer Program のアカウントを用意してから** (ADR 0028 の 8.)。拡張を入れていない束
(今の配布物と、開発中の `just studio`) では、これまでどおり「この OS ではまだ仮想カメラを出せません」と、ウィンドウの取り込みか
ブラウザソースを案内する。

- **しくみ:**

  ```
  スタジオ (ugoe-studio-vcam の cmio.rs)                 Camera Extension (apps/studio/vcam/macos、Swift)
    NV12 ('420v') の CVPixelBuffer (IOSurface) ─┐         機器「ugoe studio」
    → CMSampleBuffer → CMSimpleQueue に積む ─────┴──────▶ 受ける側 (sink) のストリーム「ugoe studio input」
                                                           │ 出す側が動いている間、フレームレートごとに 1 枚取り出す
                                                           ▼
                                                         出す側 (source) のストリーム ──▶ 会議アプリ・配信ソフト
  ```

  - 拡張はアプリの束の `Contents/Library/SystemExtensions/app.ugoe.studio.camera.systemextension` に入れる。スタジオは、プロセスで
    最初に仮想カメラを入れるときに `OSSystemExtensionRequest` で拡張を有効にする (すでに有効ならすぐ終わり、版が違えば入れ替える)。
    初回は macOS が許可を求めるので、「システム設定」で許可してもらい (操作ウィンドウに「許可してください」を出す)、もう一度入れてもらう。
    求めが「再起動の後に終わる」(`OSSystemExtensionRequestResult.willCompleteAfterReboot`。前の版を外すのに再起動が要るとき) で終われば、
    「Mac を再起動してください」(`needsRestart`) を出す。再起動まではプロセスの中で求め直さない (結果は変わらないため)。
  - 有効になった拡張は OS (CoreMediaIO) が動かし、スタジオが動いていない間も機器は残る (画は黒)。拡張は別の利用者
    (`_cmiodalassistants`) のサンドボックスで動くので、Windows のような名前付きの共有メモリは使わず、CoreMediaIO の受ける側の
    ストリーム (Apple が推奨する、アプリから Camera Extension へ画を渡す方法) を使う。
  - 画は Windows と同じ NV12 (BT.709・限定範囲)。スタジオは CoreMediaIO の C の API で機器を UID
    (`07DA1CFA-007F-4E78-873E-5FFA646E00B4`) で、受ける側のストリームを名前で探し、`CMIODeviceStartStream` の後に `CMSimpleQueue` に積む。
    BT.709 の印 (`kCVImageBufferYCbCrMatrixKey` など) を画に付ける。
  - 拡張は 1280×720 と 1920×1080、30 と 60 fps の書式を出す。カメラを開いたアプリが選んだ大きさと届いた画の大きさが違えば
    VideoToolbox (`VTPixelTransferSession`) で拡大縮小する。画がまだ無い・スタジオが止めたときは黒を出す。
  - 拡張は、カメラを開いているアプリがある間だけ受ける側から取り出す。スタジオはキューが埋まっていれば積まず、埋まったままが
    2 秒続けば「カメラを使っているアプリがありません」を出す (Windows と同じ知らせと同じ長さ。アプリが選んだフレームレートが
    スタジオより低いと 1 枚ごとには埋まることがあるので、1 枚ごとには決めない)。
  - 始められない理由: macOS 12.3 より前 (`macosTooOld`)・許可を待っている (`needsApproval`)・アプリが「アプリケーション」フォルダに無い
    (`notInApplications`。System Extension は「アプリケーション」フォルダのアプリからしか有効にできない)・再起動の後に有効になる
    (`needsRestart`)・有効にできない / 機器が現れない
    (`extensionFailed`。署名の誤りなど。詳細を添える)。
- **コード:** Rust 側は `apps/studio/vcam/src/cmio.rs` (objc2 の束縛で SystemExtensions・CoreMediaIO・CoreMedia・CoreVideo を呼ぶ。
  `unsafe` は ADR 0028 の 8. の例外のクレートの中)。拡張は `apps/studio/vcam/macos/` (`Extension/Camera.swift`・`main.swift`・
  `Info.plist`・`Extension.entitlements`)。Camera Extension の API (CMIOExtension) は Swift と Objective-C 向けなので、拡張は Swift で書く。
- **ビルド:** `pnpm vcam:macos` (`apps/studio/scripts/build-vcam-macos.mjs`) が `xcrun swiftc` で arm64 と x86_64 を作って `lipo` で束ね、
  `target/vcam/macos/` に拡張の束を組み、拡張の entitlement で署名する。Xcode のプロジェクトは使わない (macOS と Xcode か
  コマンドラインツールが要る)。拡張を入れたスタジオは `just app::build TARGET=studio PLATFORM=macos VCAM=1` (`tauri.macos-vcam.conf.json` を重ねる) で作る
  (`bundle.macOS.files` が拡張とプロビジョニングプロファイルを束に入れ、`Entitlements.vcam.plist` で署名する)。署名・公証・
  entitlement・プロビジョニングプロファイルの用意は [release.md の macOS の仮想カメラ](release.md#macos-の仮想カメラ)。
- **開発中の確かめ方:** System Extension は「アプリケーション」フォルダのアプリから、正しく署名したものしか有効にできない。
  開発中は次のどちらかにする。どちらも Apple Developer Program のアカウント (System Extension の権限を付けたプロビジョニング
  プロファイル) が要る見込み (無料のアカウントの開発用の署名では System Extension の権限を付けられない。確かめていない)。
  1. **ふつうの手順:** Apple Development の証明書と開発用のプロファイルで上のビルドを行い、できた `ugoe-studio.app` を
     `/Applications` に写して開く。
  2. **束をどこに置いても有効にできるようにする:** 復旧モード (Apple シリコンは電源ボタンを長押し、Intel は Command + R で起動) の
     ターミナルで `csrutil disable` を実行して SIP を切り、再起動してから `systemextensionsctl developer on` を実行する。
     確かめ終わったら `systemextensionsctl developer off` と、復旧モードで `csrutil enable` を実行して戻す。
  - 入っている拡張は `systemextensionsctl list` で見る (`app.ugoe.studio.camera` が `[activated enabled]` になる)。
    外すには `systemextensionsctl uninstall <チーム ID> app.ugoe.studio.camera` (SIP を切っているときだけ) か、アプリを消して再起動する。
  - 拡張のログは `log stream --predicate 'subsystem == "com.apple.cmio" OR process == "app.ugoe.studio.camera"'` で見る。
  - 拡張を作り直したら版 (`CFBundleVersion`。ビルドの時刻) が変わるので、スタジオがもう一度有効にすると入れ替わる。カメラを使っている
    アプリは、入れ替わった後に開き直す。

**未確認 (利用者の確認に残す。WSL の上では macOS のビルドも実機の確認もできない):** Rust 側は `cargo clippy --target aarch64-apple-darwin`・
`x86_64-apple-darwin` (`ugoe-studio-vcam` だけ。`ugoe-studio` は依存の objc2-exception-helper が Objective-C を macOS の SDK で
コンパイルするので Linux では検査できない) を通したが、Swift の拡張はコンパイルもしていない。macOS で次を確かめる。

1. `pnpm vcam:macos` で拡張が作れる (Swift のコンパイルの誤りがあれば直す)。`codesign -dv --entitlements - <拡張>` で entitlement が付いている。
2. 拡張を入れたスタジオを `/Applications` から開き、仮想カメラを入れると、初回は「許可してください」が出て、macOS の通知か
   「システム設定」→「一般」→「ログイン項目と機能拡張」→「カメラ機能拡張」(macOS 14 までは「プライバシーとセキュリティ」) で許可できる。
   許可の後にもう一度入れると「入: ugoe studio・…」になる。`systemextensionsctl list` に出る。
3. FaceTime・Photo Booth・QuickTime Player (新規ムービー収録)・Zoom・Chrome (Google Meet)・OBS (映像キャプチャデバイス) で
   「ugoe studio」を選ぶと、モデルが動いて映る。色が正しい (白い背景が白く、赤が赤い)。1920×1080・1280×720、30・60 fps のそれぞれ。
   アプリが別の大きさを選んだときに拡大縮小される。
4. カメラを開いているアプリが無いと「カメラを使っているアプリがありません」が出て、開くと消える。スタジオを止める・閉じると黒になる。
5. スタジオがカメラ (CoreMediaIO の機器) を開くときに、カメラの使用の許可 (TCC) を求められるか。求められるなら
   `NSCameraUsageDescription` の文言 (いまはフェイストラッキングの説明) を仮想カメラにも合う文言にする。
6. 「アプリケーション」フォルダの外から開くと「アプリケーション フォルダに移して」が出る。macOS 12.3 より前では「macOS 12.3 以降が要ります」。
7. tauri の署名 (`bundle.macOS.signingIdentity`) が、中の拡張の署名を壊さない (`codesign --verify --deep --strict` が通る)。公証が通る。
8. スタジオを更新した (拡張の版が変わった) ときに、拡張が入れ替わる。入れ替えに再起動が要るときは「Mac を再起動してください」が出て、
   再起動の後にもう一度入れると入る。
9. スタジオは受ける側のストリームの書式 (既定は 0 番の 1280×720) を変えずに、設定の大きさ (1920×1080 も) の画を積む。
   1920×1080 を選んでも受ける側が画を受け取り、出す側に映る (受けなければ、スタジオが受ける側の書式を設定に合わせる)。

## 隠れても止まらない

WebView は、隠れたり最小化されたりしたページの `requestAnimationFrame` とタイマーを絞る (止める)。配信中は出力ウィンドウを
ほかのウィンドウの裏に置くことが多く、操作ウィンドウは最小化されがちなので、両方のウィンドウで次のようにする (T0804)。

| OS (WebView) | 手段 | 効くこと |
| --- | --- | --- |
| Windows (WebView2) | `tauri.conf.json` の `additionalBrowserArgs` に `--disable-background-timer-throttling`・`--disable-backgrounding-occluded-windows`・`--disable-renderer-backgrounding` と、`--disable-features` に `CalculateNativeWinOcclusion`・`IntensiveWakeUpThrottling` を足す (wry の既定の `msWebOOUI,msPdfOOUI,msSmartScreenProtection` も書き写す) | ほかのウィンドウの裏に隠れても「見えない」とみなさない。タイマーを絞らない |
| macOS (WKWebView) | `backgroundThrottling: "disabled"` (macOS 14 以降。`inactiveSchedulingPolicy` を `none` にする) | 隠れても最小化されても絞らない |
| Linux (WebKitGTK) | 切る口が無い | 最小化・隠すとページが「見えない」になり、`requestAnimationFrame` が止まる |

- WebView2 は、同じデータの場所を使う WebView の引数が食い違うと作れないので、2 つのウィンドウに同じ引数を書く (`lib.rs` のテストで確かめる)。
- **受け手の状態は描画に頼らない:** 出力ウィンドウは、届いたフレームを届いたときに `follow` まで適用し、`requestAnimationFrame` では描くだけにする
  (`@ugoe/player` の受け手のモード)。Tauri の `Channel` のメッセージは、ページが隠れていても届いて JS が動くので、どの OS でも物理は止まらない。
  描画が止まっている間 (Linux の最小化・Windows で `hide` した出力ウィンドウ) は画が古いままになるが、表示に戻ったときは最新の形から描く。
- 指揮役はバックエンドの刻みのスレッドで回るので、WebView の抑制を受けない ([ADR 0028 の 3.](adr/0028-studio.md#3-描画の場所と物理と時間の扱い))。
- 「出力ウィンドウを表示」を切った (隠した) 出力ウィンドウは描かない (Windows の WebView2 は `hide` で描画を止める)。配信ソフトは隠したウィンドウを
  取り込めないので、取り込むときは表示したまま、ほかのウィンドウの裏に置く。
- 入力 (カメラ・マイク、T0803) は操作ウィンドウの WebView で取る。Linux で操作ウィンドウを最小化すると `requestAnimationFrame` が止まるので、
  入力の処理はバックエンドの刻みのスレッドが送るメッセージで回す ([入力](#入力))。
- **刻みで回す処理は、重ければ間引く (T0812):** 刻みのメッセージは、JS の処理が追いつかなくても届き続けて WebView に溜まる
  (`requestAnimationFrame` は溜まらない)。MediaPipe の検出 1 回が刻みの間隔より重いと (WSL2 では顔と体で約 200ms)、溜まった刻みが
  ほかのメッセージや `set_tracking` の応答を十数秒待たせ、トラッキングが止まって見えた。そこで `apps/studio/src/lib/pulse.ts` の `Pulse.beat` は、
  前の処理が終わってから前の処理にかかった時間が経つまで届いた刻みを飛ばす (飛ばすのは安い)。1 つの処理が投げても、ほかの処理と次の刻みは止めない。
  平滑化の `dt` は刻みの間隔ではなく前の検出から測る (`@ugoe/face-tracking` の `FrameInterval`)。
- **Channel の受け取りは投げない:** `@tauri-apps/api` の `Channel` は、`onmessage` が一度でも投げると以後のメッセージを配らなくなる。
  スタジオの Channel (刻み・モニター・出力のフレーム) は `host.ts` の `subscribe` で `safeChannelHandler` (`lib/channel.ts`) に包み、
  投げた例外は console に出して次のメッセージを受け取る。
- **メインのスレッドを塞がない (T0819):** Tauri v2 の `async` でないコマンドはメインのスレッド (イベントループ) で動き、その間は両方の
  ウィンドウのイベントと `Channel` のメッセージが止まる。ファイルを読む (`activate_scene`・`update_scene`・`open_profile`・`restore_profile`・
  `module_slot`)・大きなバイト列を返す (`scene_model`・`scene_module`・`scene_background`)・スレッドの終わりを待つ
  (`start_virtual_camera`・`stop_virtual_camera`。仮想カメラを始め直すことのある `set_virtual_camera_settings`・`new_profile` も) コマンドは `async fn` にし、中身を `spawn_blocking` で行う (`lib.rs` の `blocking`)。
  ロックは `spawn_blocking` の中で取って放す (`.await` をまたいで握らない)。ホットキーの経路も同じく `spawn_blocking` で行う。
  シーンの切り替えは、ファイルを読んでパペットを組み立てるのを舞台のロックの外で行う
  ([シーンの切り替えと舞台のロック](#シーンの切り替えと舞台のロック)、T0834・T0837)。その間も刻み・パラメータ・表情・外部 API の読むだけの要求は待たない。
  操作ウィンドウは、自分が始めた切り替えが返るまで読み込み中を出す (応答を待つ間に何も出さないことが無いように)。
  外部 API の `dressup.list` は、付けていないモジュールを舞台のロックを放してから読む。
  読んだ概要 (ID・名前・スロット) はパス・更新時刻・大きさで覚え、変わっていなければ読み直さない (T0833。`methods.rs` の `ModuleSummaries`)。
  ファイルが消えたら一覧から外して忘れ、着せ替えに使えなくなったモジュールも忘れる。覚える数は 256 まで (超えた分は毎回読む)。

### 刻みの速さと正確さ

- 指揮役の刻みの速さ (出力のフレームレート) は 30・60・120 回/秒から選ぶ (既定は 60)。操作ウィンドウの「フレームレートと負荷」で変え、
  次の刻みから効く。選んだ値はプロファイルの `output.tickRate` に持ち (T0827)、プロファイルを開くとその速さにする
  (刻みのスレッドが読む値は、プロファイルを変える操作 (`lib.rs` の `with_stage`) のたびにプロファイルから写す)。
  ブラウザソースと仮想カメラの受け手も同じ刻みのフレームを受けるので、ブラウザソースの実質のフレームレートも変わる。
- 刻みの時刻は `apps/studio/src-tauri/src/pacing.rs`。遅れたときは取り戻そうとせず、次の刻みを今から数え直す (`dt` は実測なので時間は失わない)。
- **刻みの時刻がずれても、受け手どうしの形は揃う。** 指揮役は実測の `dt` を配り、受け手はその `dt` で物理を回すので、ずれが崩すのは動きの滑らかさだけ。
  そのため、待ち方に忙しい待ち (spin) は使わず、OS のスリープだけにする (CPU を使い続けない)。
- Windows の `Sleep` の粒度は既定で約 15.6 ms だが、Rust の `std::thread::sleep` は Windows 10 1803 以降では高精度の待機タイマー
  (`CREATE_WAITABLE_TIMER_HIGH_RESOLUTION`) を使うので、60・120 刻みでも 1 ms 程度の揺れに収まる見込み (Windows では未確認)。
  古い Windows で粒度が粗いときは、操作ウィンドウに「刻みの間隔が空いた」注意が出る。
- macOS の App Nap は、ウィンドウがすべて隠れたアプリのタイマーを遅らせる。`backgroundThrottling` は WebView の設定で、App Nap は止めない。
  App Nap を止めるには `NSProcessInfo` の `beginActivity` (Objective-C の呼び出し) が要る (未対応。macOS で揺れが出たら後続のタスクで扱う)。

### 負荷の表示

操作ウィンドウの「フレームレートと負荷」とツールバーに出す。**出力ウィンドウには何も重ねない。**

| 数値 | 出どころ | 注意を出すとき |
| --- | --- | --- |
| 1 刻みの時間 | 指揮役の `tick` (更新とフレームの送り出し) | 刻みの間隔の半分を超える |
| 実際の刻みの速さと最も長い間隔 | 刻みのスレッドが直近の約 1 秒を測る | 速さが設定の 95% を下回る・間隔が設定の 2 倍を超える |
| 出力ごとの描画の回数・1 回の時間 (平均と最大)・捨てたフレーム | 出力ウィンドウが約 1 秒ごとに `report_render_stats` で送る | 1 回の時間が刻みの間隔の半分を超える・回数が刻みの速さの 95% を下回る・捨てたフレームがある |
| 描いていない | 出力からの報告が 2 秒途絶えた (隠れている・最小化された) | いつも |

- 1 回の描画の時間は、受け手がフレームを適用して `render()` を呼ぶまでの CPU の時間 (GPU の実行の時間は含まない)。
- 判断は `apps/studio/src/lib/load.ts`、表示は `apps/studio/src/LoadPanel.svelte`。

## OBS でのウィンドウの取り込み

出力ウィンドウ (枠なし・背景の透過) を、OBS Studio のソースとして取り込む手順。OBS の画面の名前は日本語の表示 (OBS 30 系) で書く。
透過が使えない組み合わせでは、シーンの背景を単色にして OBS の「クロマキー」フィルタで抜くか、[ブラウザソース](#ブラウザソース) を使う。

共通:

1. スタジオでモデルを開き、「出力ウィンドウを表示」を入れる。大きさは配信の解像度 (1920×1080 など) にする。
2. 出力ウィンドウは **表示したまま** ほかのウィンドウの裏に置いてよい。最小化と「出力ウィンドウを表示」を切ることはしない (OS が描かなくなり、取り込めない)。
3. OBS のソースの「+」から下の OS ごとのソースを足し、ウィンドウの一覧から `ugoe studio output` を選ぶ。
4. ソースの大きさがキャンバスと違えば、ソースを右クリック →「変換」→「画面に合わせる」。

### Windows

1. ソースに「ウィンドウキャプチャ」を足し、「ウィンドウ」に `[ugoe-studio.exe]: ugoe studio output` を選ぶ。
2. 「キャプチャ方法」は「Windows 10 (1903 以降)」にする。「BitBlt」は WebView2 (GPU で描くウィンドウ) を黒く取り込み、裏に隠れたウィンドウも取り込めない。
3. 背景が黒く出るとき (透過が効かないとき) は、次のどちらかにする。
   - ソースを「ゲームキャプチャ」にし、「モード」を「特定のウィンドウをキャプチャ」、「透過を許可」を入れる。
   - シーンの背景を単色 (クロマキーの色) にし、ソースに「クロマキー」フィルタを掛ける。

**未確認 (利用者の確認に残す):** ウィンドウキャプチャ (Windows 10 (1903 以降)) で WebView2 の透過がアルファとして届くか、ゲームキャプチャの「透過を許可」で
取り込めるか、裏に隠れても取り込みが止まらないか。

### macOS

1. 初めてのときは「システム設定」→「プライバシーとセキュリティ」→「画面収録」で OBS を許可する (許可した後で OBS を開き直す)。
2. ソースに「macOS 画面キャプチャ」を足し、「方法」を「ウィンドウキャプチャ」にして、「ウィンドウ」に `ugoe studio output` を選ぶ。
3. 「ウィンドウの影を表示」を切る (出力ウィンドウは影を持たないが、余白ができないように)。
4. 出力ウィンドウの大きさは物理ピクセル。Retina (拡大率 200%) では、画面の上では半分の大きさに見えるが、取り込む大きさは選んだとおり。

**未確認 (利用者の確認に残す):** 透過がアルファとして届くか、ほかのウィンドウの裏に隠れても取り込みが止まらないか (`backgroundThrottling` と App Nap)。

### Linux

- **X11:** ソースに「ウィンドウキャプチャ (Xcomposite)」を足し、「ウィンドウ」に `ugoe studio output` を選ぶ。透過にはコンポジタ (GNOME・KDE は標準、
  i3 などでは picom など) が要る。コンポジタが無いと背景は黒くなる。
- **Wayland:** ソースに「画面キャプチャ (PipeWire)」を足し、「ウィンドウを選択」から出力ウィンドウを選ぶ (デスクトップのポータルが選ぶ画面を出す)。
  OBS を開き直すたびに選び直しを求められることがある。
- 最小化すると WebKitGTK はページを描かなくなる ([隠れても止まらない](#隠れても止まらない))。最小化せずに裏に置く。

**未確認 (利用者の確認に残す):** Xcomposite と PipeWire で透過がアルファとして届くか、裏に隠れても取り込みが止まらないか (WSL の上では確かめられない)。
