# スタジオの設計 (apps/studio)

配信者が配信中に使うデスクトップアプリ「スタジオ」の画面と操作の設計。範囲・構成・描画の場所・外部 API の安全性を決めた理由は
[ADR 0028](adr/0028-studio.md)。画面の部品と翻訳は ADR 0029 と docs/ui.md (T0900 で書く) に従う。

> この文書は T0800 で骨子を書いた。プロファイルの形式 (T0802)・ホットキーの保存 (T0803)・API のメッセージ (T0805) などは、
> 各タスクで詳しくする。

## 全体の構成

```
 操作ウィンドウ (WebView)                      バックエンド (Rust)                         受け手
 ┌──────────────────────┐   IPC     ┌──────────────────────────────┐  Channel   ┌────────────────────────┐
 │ シーン・入力・出力の設定 │ ───────► │ 指揮役 (conductor)             │ ─────────► │ 出力ウィンドウ (WebView)  │
 │ カメラ → トラッキング    │ トラッキング│  ugoe::Puppet (物理は切る)     │            │  wasm で物理を回して描く   │
 │ マイク → 音量          │ 音量      │  モーション・表情・トラッキング・ │  WebSocket ├────────────────────────┤
 │ (モデルは描かない)      │ 操作      │  目パチ・呼吸・リップシンク      │ ─────────► │ ブラウザソース (OBS)      │
 └──────────────────────┘           │  刻みごとに {seq, dt, values}   │            │  @ugoe/runtime (wasm)   │
          ▲                          │                              │  チャネル   ├────────────────────────┤
          │ 状態・負荷の通知           │ ホットキー (グローバル)          │ ─────────► │ 仮想カメラ               │
          └───────────────────────── │ 外部 API (WebSocket)           │            │  ugoe-render (常駐) →    │
                                     │ プロファイルの読み書き          │            │  NV12 などに変換して OS へ │
                                     └──────────────────────────────┘            └────────────────────────┘
```

- **指揮役** だけがパラメータの値を決める。受け手は届いたフレームを順に適用して物理を回し、描く ([ADR 0028 の 3.](adr/0028-studio.md#3-描画の場所と物理と時間の扱い))。
- 出力ウィンドウ・ブラウザソース・仮想カメラは独立で、どれを閉じても他は続く。

### フレームの配信 (内部の形)

外部 API とは別の、スタジオの中の形。版を上げて変えてよい (ブラウザソースのページもスタジオが配るので、いつも同じ版で揃う)。

| メッセージ | 中身 | いつ |
| --- | --- | --- |
| `scene` | `revision`・モデルの鍵 (受け手が読む場所)・付けるモジュールの組 (合成の順)・ライティング・位置と大きさと回転・背景・パラメータの ID の並び | 接続したとき、シーンが変わったとき |
| `frame` | `seq`・`revision`・`dt`・`values` (`scene` の ID の並びの順の `f32`) | 刻みごと (30 / 60 / 120 回/秒) |
| `reset` | `seq` (このフレームを適用する前に物理をリセットする) | 着せ替え・モデルの読み直しなど |

- 受け手は `frame` を `seq` の順に 1 つずつ適用する (`Puppet::follow(values, dt)`。`values` を基準値として書き、物理とポーズだけを進める。
  前のフレームの出力と同じ値でも基準値になる。[motion.md#受け手として進める](spec/motion.md#受け手として進める)、T0133)。`revision` が知らない版なら、`scene` を待つ。
- `seq` が飛んだら (切断など)、最新の `scene` から作り直し、物理をリセットして続きから適用する。
- 出力ウィンドウへは Tauri の `Channel` で、`values` はバイト列 (`Float32Array`) で送る。ブラウザソースへは WebSocket のバイナリのメッセージで送る。

## 操作ウィンドウ

左にシーンの一覧、中央に「いまの状態」、右にパネルを並べる。配信中に触るもの (シーン・表情・モーション) を大きく、
設定 (入力の機器・出力・API) は奥に置く。

```
┌ ツールバー: プロファイル ▾ | 出力ウィンドウ [表示] | 仮想カメラ ● | ブラウザソース ● | API ● | 言語 | 負荷 12.3 ms / 60 fps ┐
├──────────────┬───────────────────────────────────┬──────────────────────────┤
│ シーン          │ いまの状態                            │ パネル (タブ)                │
│ ▶ 雑談 (F1)     │  モデル名・付けているモジュール            │ ・表情とモーション             │
│   ゲーム (F2)   │  トラッキング: 顔あり 30 fps            │ ・入力 (カメラ・マイク)         │
│   休憩 (F3)     │  口パク: ▁▃▅ (音量のメーター)           │ ・シーンの編集                 │
│ [+] [複製] [↑↓] │  主なパラメータの値 (角度・目・口)       │ ・ホットキー                   │
│               │  警告・エラー                           │ ・出力                        │
│               │                                     │ ・外部 API                     │
└──────────────┴───────────────────────────────────┴──────────────────────────┘
```

| パネル | 内容 | タスク |
| --- | --- | --- |
| シーン (左) | シーンの一覧・切り替え・追加・複製・並べ替え・削除。割り当てたホットキーを並べて示す | T0802 |
| いまの状態 (中央) | モデル・付けているモジュール・トラッキングと口パクの様子・主なパラメータの値・警告。モデルは描かない | T0801・T0803 |
| 表情とモーション | 表情の付け外し・モーションの再生 (優先度)・待機モーション・モーションを優先するパラメータ (T0721・T0722) | T0803 |
| 入力 | カメラの選択・トラッキングの開始と停止・キャリブレーション・平滑化。マイクの選択・感度・ノイズの閾値・音量のメーター | T0803 |
| シーンの編集 | 選んだシーンのモデル・着せ替え・ライティング・位置と大きさと回転・背景 (透過・単色・クロマキー・画像) | T0802 |
| ホットキー | 操作ごとのキーの割り当て (下の「ホットキー」)。ぶつかりの表示 | T0803 |
| 出力 | 出力ウィンドウの大きさ・最前面・刻みの速さ・負荷の表示。仮想カメラの開始と停止・解像度・フレームレート。ブラウザソースの URL のコピーと OBS の手順 | T0804・T0807・T0808 |
| 外部 API | 有効にするスイッチ・ポート・トークンの作り直し・承認したクライアントの一覧 (権限・取り消し)・承認の待ち | T0805 |

- 承認を待つクライアントがあるときは、どのパネルを開いていても上に知らせを出す (承認・拒否・後で)。
- 負荷の表示 (1 刻みの時間・受け手ごとの描画の時間と落としたフレーム) は操作ウィンドウだけに出す。出力ウィンドウには何も重ねない。
- 閉じる操作: 操作ウィンドウを閉じるとアプリを終える (待ち受けと仮想カメラも止める)。止める前に、配信中の出力があれば確かめる。

## 出力ウィンドウ

| 設定 | 選択肢 | 既定 |
| --- | --- | --- |
| 大きさ | 1920×1080・1280×720・1080×1920 (縦)・1080×1080・自由 | 1920×1080 |
| 枠 | なし (動かすのは操作ウィンドウから、か Alt+ドラッグ) | なし |
| 背景 | シーンの背景に従う (透過・単色・クロマキー・画像) | 透過 |
| 最前面 | 入・切 | 切 |
| 刻みの速さ | 30・60・120 | 60 |

- モデルの位置と大きさと回転はシーンが持つ (出力の大きさに対する割合で持ち、大きさを変えても構図が保たれる)。
- バックグラウンドの抑制を切り、隠れても最小化されても描き続ける (T0804)。
- 出力ウィンドウは受け手なので、指揮役より速く描いても新しい形は出ない (刻みの速さが実質のフレームレート)。

## シーンとプロファイル

- **シーン:** 名前・モデル (ファイルのパス)・付けるモジュールの組・ライティング・位置と大きさと回転・背景。1 つのシーンにアバターは 1 体。
- **切り替え:** 指揮役が新しいシーンを読み、`scene` を配る。同じモデルのシーンどうしは、パラメータの値・トラッキング・再生中のモーションを
  引き継ぐ (着せ替えとライティングと配置だけが変わる)。別のモデルは読み直す (物理はリセット)。切り替えの瞬間は前の画を保ち、
  読み終えてから替える (途中の空の画を出さない)。
- **プロファイル:** シーンの一覧・ホットキー・出力の設定・入力の機器を 1 つの JSON に持つ。版の番号 (`version`) 付き。
  最近のプロファイルを覚え、起動時は最後のものを開く。形式の詳細は T0802 でここに書く。
- 外部 API のトークンと承認したクライアントの鍵は **プロファイルに入れない** (プロファイルを人に渡しても漏れない)。アプリのデータの場所に置く。

## ホットキー

グローバルなショートカット (アプリが前面に無くても効く) で、次の操作を割り当てられる。

| 操作 | 引数 |
| --- | --- |
| シーンの切り替え | シーン |
| 表情の切り替え・付け外し・すべて外す | 表情 |
| モーションの再生 | モーション・優先度 |
| 着せ替えの切り替え | スロット・モジュール (なし = 外す) |
| トラッキングの一時停止・再開・キャリブレーション | — |
| 口パクの一時停止 | — |

- 割り当てはプロファイルに保存する。ほかのアプリや OS とぶつかって登録できなかったキーは、パネルに理由を出す。
- Wayland では、アプリが前面に無いとグローバルなショートカットを受けられない ([ADR 0028 の 9.](adr/0028-studio.md#9-グローバルなホットキー))。
  外部 API から同じ操作をできるので、その使い方を案内する。

## 外部 API の骨子

「スタジオの操作 API」(ugoe Studio API)。ループバックの WebSocket の上の JSON-RPC 2.0。安全性の規則は
[ADR 0028 の 6.](adr/0028-studio.md#6-外部-api-とブラウザソースの待ち受けの安全性)。詳細と JSON Schema は T0805 で英語のリファレンスに書く。

**接続の流れ:** `ws://127.0.0.1:<port>/api` に接続 → `session.hello` (トークン・クライアントの名前、承認済みなら鍵) →
初めてなら操作ウィンドウで利用者が承認 (権限を選ぶ) → 鍵を返す → 以後は操作できる。

| メソッド | 権限 | 内容 |
| --- | --- | --- |
| `session.hello` | — | 名乗る。応答はスタジオの版・API の版・与えられた権限 |
| `studio.state` | 読む | いまのシーン・モデル・表情・再生中のモーション・トラッキングの有無 |
| `scene.list` / `scene.activate` | 読む / 操作 | シーンの一覧 / 切り替え |
| `expression.list` / `expression.set` / `expression.add` / `expression.remove` / `expression.clear` | 読む / 操作 | 表情 |
| `motion.list` / `motion.play` / `motion.stop` | 読む / 操作 | モーション (優先度付き) |
| `parameter.list` / `parameter.set` | 読む / 操作 | パラメータの定義と今の値 / 値の上書き (重みと期限付き。既定 1 秒で期限が切れる) |
| `dressup.list` / `dressup.set` | 読む / 操作 | スロットとモジュール / 着せ替え |
| `events.subscribe` / `events.unsubscribe` | 読む | 通知を受け取る種類を選ぶ |

| 通知 | 内容 |
| --- | --- |
| `scene.changed` | シーンが切り替わった |
| `expression.changed` | 使っている表情が変わった |
| `motion.started` / `motion.finished` | モーションの開始と終了 (モーションのイベントを含む) |
| `dressup.changed` | 着せ替えの組が変わった |
| `tracking.changed` | 顔を見つけた・見失った |

- ポートは設定で変えられる。既定のポートは T0805 で決める (他製品の既定と同じ番号にしない)。
- パラメータの上書きは、トラッキング・モーションの後に書く (外部 API の値が勝つ)。期限が切れたら上書きをやめ、元の値に戻る。

## ブラウザソース

- 操作ウィンドウの「出力」で有効にすると、`http://127.0.0.1:<port>/source/<トークン>/` を出す。コピーして OBS のブラウザソースに貼る。
  大きさは出力ウィンドウと同じ値を案内する。背景は透過 (OBS のブラウザソースは既定で透過を受ける)。
- ページは `@ugoe/runtime` (wasm) で描く受け手。モデルとモジュールのファイルは同じトークンの下から取る (今のプロファイルのシーンが使うものだけ)。
- トークンは読むだけ (操作はできない)。作り直すと古い URL は使えなくなる。

## 仮想カメラ

- 操作ウィンドウの「出力」で開始と停止。解像度 (1920×1080・1280×720) とフレームレート (30・60) を選ぶ。
- 背景は不透明にする。透過のシーンは単色 (既定は緑のクロマキー色ではなく、設定した色) で埋める。
- 止まった (受け取るアプリが無い・OS の部品が無い)・遅れた (刻みに描画が追いつかない) ことを操作ウィンドウに出す。
- OS ごと: Windows 11 は Media Foundation の仮想カメラ、Linux は v4l2loopback の機器、macOS は Camera Extension
  (T0807・T0809。OS の部品の扱いは [ADR 0028 の 8.](adr/0028-studio.md#8-仮想カメラの-os-の部品と-unsafe-の例外))。
- Windows 10 では Media Foundation の仮想カメラが使えないので、OBS で取り込んで OBS の仮想カメラを使う手順を案内する。
  Linux で v4l2loopback の機器が無いときは、入れ方を案内する (スタジオからは入れない)。macOS は配布物に入るまで、ウィンドウの取り込みかブラウザソースを案内する。
