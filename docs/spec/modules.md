# 着せ替えモジュール仕様

判断の経緯は [ADR 0014](../adr/0014-composable-modules.md)。

データ定義は `ugoe_model::module` (`Slot`、`Module`)、合成は `ugoe_runtime::compose` (T0111)、
ファイル形式 (`.ugoemod`) は `ugoe_format::module_file` ([file-formats.md#モジュール](file-formats.md#モジュール-ugoemod)、T0113)、
ランタイム SDK の付け外しは `ugoe::Puppet` ([Puppet での着せ替え](#puppet-での着せ替え)、T0121) にあります。

> エディタでの作成は [ADR 0024](../adr/0024-module-authoring.md) の方針で段階的に入れます。スロットの定義は T0647 ([editor.md#スロットの編集](../editor.md#スロットの編集))、
> モジュールのプロジェクトは T0648 ([editor.md#モジュールのプロジェクト](../editor.md#モジュールのプロジェクト))、プレビューでの付け外しは T0649 です。

## スロット

本体のモデルは `Model.slots` にスロットを公開します。

| フィールド | 内容 |
| --- | --- |
| `id` | スロットの名前 (例: `Hair`、`Outfit`、`HeadAccessory`)。モジュールはこの名前だけで取り付け先を指定する |
| `anchor` | 取り付け先。デフォーマの ID またはキャンバス (`None`) |
| `draw_order` | このスロットに入るメッシュの描画順の範囲 `{ "min", "max" }` (`min <= max`)。モジュールの描画順 (0〜1000) はこの範囲に写される |
| `replaces` | モジュールを取り付けたときに非表示にする本体のパーツの ID (例: 既定の髪)。省略可 |
| `parameters` | このスロットのモジュールが使ってよい本体のパラメータの ID。標準パラメータは常に使える。省略可 |
| `mask_sources` | このスロットのモジュールがマスクとして参照してよい本体のメッシュの ID。省略可 |
| `part` | モジュールの最上位のパーツの親にする本体のパーツ (例: 髪なら頭、衣装なら体)。省略するとモジュールの最上位のパーツは最上位のまま |
| `colliders` | このスロットのモジュールの物理のリグが衝突してよい本体の衝突体 (`PhysicsCollider::id`)。省略可 |
| `pose_parts` | このスロットのモジュールがパーツを追従させてよい本体のポーズの要素のパーツ ([ポーズ](#ポーズ))。省略可 |

```json
"slots": [
  { "id": "Hair", "anchor": "Head", "draw_order": { "min": 550, "max": 650 },
    "replaces": ["Hair"], "mask_sources": ["Face"], "part": "Head", "colliders": ["Neck"] }
]
```

1 つのスロットには、同時に 1 つのモジュールを取り付けます。
`Model.slots` は省略でき、空のときは書き出しません。これを含まない既存のデータもそのまま読めます (`SCHEMA_VERSION` は変えていません)。

## モジュール

モジュール (`Module`) は、次のものを持つ部分的なモデルです。

| フィールド | 内容 |
| --- | --- |
| `schema_version` | `Model` と同じスキーマバージョン |
| `name` | モジュールの名前。ID の付け替えに使う。空でなく、`/` を含まず、`#` で始まらないこと |
| `slot` | 取り付け先のスロットの名前 |
| `requires` | 対応する本体の条件 (下の表)。省略可 |
| `parts` / `deformers` / `meshes` / `glues` | `Model` と同じ型の要素。省略可 |
| `textures` | テクスチャの参照。メッシュの `texture` はこの列のインデックス。省略可 |
| `physics` | 物理の `rigs` と `colliders` (ADR 0011 の動的物理を含む)。重力・風・周波数は本体の設定を使う。省略可 |
| `pose` | ポーズの `groups` と `links` ([ポーズ](#ポーズ))。省略可 |

`requires` (`ModuleRequirements`):

| フィールド | 内容 |
| --- | --- |
| `avatar_level` | 本体のアバタープロファイル (`Model.avatar`) が宣言する `level` がこの値以上であること (準拠の検査の結果ではなく宣言の値)。アバタープロファイルのない本体は満たさない |
| `slots` | 本体にあるべきスロット (取り付け先は書かなくてよい) |
| `parameters` | 本体にあるべきパラメータ |

モジュールはパラメータを定義しません。キーフォームの軸・物理の入力と出力で、標準パラメータ (`standard::range` が値域を返すもの) と、
スロットの `parameters` が公開する本体のパラメータを ID で参照します。

モジュールの中の ID は、モジュールの中でだけ一意です。合成時に `<モジュールの名前>/<ID>` の形に付け替えます。
モジュールの最上位の要素 (親のないデフォーマとメッシュ、取り付け先のない衝突体) は、スロットの `anchor` の子として取り付けます。
そのため、**最上位の要素の座標は `anchor` の局所座標系で表します** (ワープなら UV 空間、回転なら原点からのピクセル。`anchor` がなければキャンバス)。
最上位のパーツはスロットの `part` の子になり (`part` がなければ最上位のまま)、本体のパーツの不透明度に追従します。
物理のリグの `frame` は、省略すればキャンバスの座標系のままです。

モジュールのマスクは、モジュールの中のメッシュと、本体がスロットで公開するメッシュ (`Slot::mask_sources`) だけを参照できます。
同じ ID があればモジュールの中のメッシュを指します。同じように、モジュールのリグは、モジュールの中の衝突体と、
本体がスロットで公開する衝突体 (`Slot::colliders`) を参照できます。同じ ID があればモジュールの中の衝突体を指します。

### ポーズ

モジュールのパーツは、2 通りの方法でポーズ ([model.md#ポーズ](model.md#ポーズ)) に入れられます (`Module::pose`、`ModulePose`)。

| フィールド | 内容 |
| --- | --- |
| `groups` | モジュールのパーツだけでできたグループ (`PoseGroup`)。本体のグループの後ろに加わる (例: 帽子の差分 A / B)。クロスフェードの時間は本体のもの |
| `links` | 本体のポーズの要素に追従させるモジュールのパーツ (`PoseEntry`)。`part` は本体のパーツでスロットの `pose_parts` にあるもの、`links` はモジュールのパーツ。本体の要素の `links` に加わる (例: 本体の腕の差分 A / B に合わせて、衣装の袖の差分 A / B を切り替える) |

```json
"pose": {
  "links": [ { "part": "ArmA", "links": ["SleeveA"] }, { "part": "ArmB", "links": ["SleeveB"] } ],
  "groups": [ { "entries": [ { "part": "HatA" }, { "part": "HatB" } ] } ]
}
```

スロットの `pose_parts` は、本体のポーズの要素のパーツ (リンクは含めない) でなければなりません (`validate` が検査する)。

### 検証

- `validate` は本体のスロットを検査します ([model.md#検証](model.md#検証))。スロットの `colliders` は `validate_physics` が検査します。
- `validate::validate_module` はモジュールを単体で検査します。モジュールの要素を 1 つのモデルとみなして `validate` と `validate_physics` を行い
  (参照するパラメータは存在するものとし、本体のメッシュへのマスク・本体の衝突体・本体のポーズの要素への参照は除く)、名前が上の規則を満たすかを調べます。
- 本体との整合 (スロット・条件・パラメータ・マスク・衝突体・ポーズの参照先) は合成が検査します。
- 未知の値の場所は `unknown::in_module` で調べられます (物理の場所は `physics.` で始まる)。

## 合成

```
compose(base: &Model, modules: &[&Module]) -> Result<Model, ComposeError>
compose_physics(base: &Model, physics: &PhysicsSettings, modules: &[&Module]) -> Result<PhysicsSettings, ComposeError>
```

取り付け先は各モジュールの `slot` で決まります。

1. モジュールごとに、名前の規則と重複、スロットが存在して空いていること、`requires`、参照するパラメータが本体にあって
   標準パラメータかスロットが公開するものであることを検査する。
2. モジュールの ID (パーツ・デフォーマ・メッシュ・グルー・テクスチャの名前・リグ・衝突体、ミラーとミラー元、マスク、物理の出力先) を付け替え
   (テクスチャの `normal_map` の名前は付け替えない)、
   最上位の要素をスロットの `anchor` の下に、最上位のパーツをスロットの `part` の下に取り付ける。パラメータの ID は付け替えない。
3. 要素を本体の要素の後ろに、モジュールの順に加える。本体の要素の並びは変わらないので、本体のパーツ・デフォーマ・メッシュのインデックスは合成の前後で同じ。
   メッシュの `texture` は、本体とそれより前のモジュールのテクスチャの数だけずらす。
4. 描画順をスロットの範囲に写す: `order' = min + (max − min) × order / 1000`。ブレンドシェイプ格子のセルにも同じ写像を適用する
   (写像は一次式なので、差分は `(max − min) / 1000` 倍になる)。
5. ポーズを加える。`pose.links` の `part` がスロットの `pose_parts` になければ `ComposeError::PoseNotExposed`。
   追従させるパーツを本体の要素の `links` に加え、`pose.groups` を本体のグループの後ろに加える。
6. スロットの `replaces` のパーツを隠す。パーツ自身の不透明度ではなく、不透明度 0 のパーツ `#replaced/<パーツの ID>` (名前は `#replaced/<パーツの名前>`、
   不透明度は一定の 0 (キーフォーム 1 つ・バインディングなし)、親は元のパーツの親) を親として挟む。
   ポーズやモーションがパーツ自身の不透明度を上書きしても隠れたままにするため。
   挟むパーツは、モジュールの順に、各モジュールの取り付け先のスロットの `replaces` の順で作り、パーツの列の末尾 (モジュールのパーツの後ろ) にその順で加える。
   同じパーツが複数回 (複数のスロット、または 1 つのスロットに 2 回) 挙がっていれば、最初に現れたところで 1 つだけ作る。
   この順は評価の結果を変えないが、合成したモデルを 1 つに決める。モジュールの順はホストが決める ([Puppet での着せ替え](#puppet-での着せ替え) の `attach_module` の規則)。
7. 合成したモデルを検証 (`validate`) し、エラーがあれば `ComposeError::Invalid` を返す。ランタイムはこれを通常どおりコンパイルする。

物理は `compose_physics` で、同じモジュールの組を本体の物理に加えます。リグと衝突体は本体のものの後ろに加わり、本体のリグが先に評価されます。
リグの衝突体の参照は、モジュールの衝突体なら付け替え、そうでなければスロットの `colliders` にあって本体の物理にある衝突体として
そのまま残します。どちらでもなければ `ComposeError::UnknownCollider` です。

組み替えは、合成とコンパイルをやり直して行います。パラメータの値は、合成の前後で同じ ID のものを引き継ぎます
(`ParameterValues::carry_over`。新しい値域にクランプする)。

### Puppet での着せ替え

ランタイム SDK の `ugoe::Puppet` は、モジュールの付け外しの API を持ちます (`crates/ugoe/src/dress_up.rs`)。

| 関数 | 内容 |
| --- | --- |
| `attach_module(Arc<Module>)` | モジュールを付ける。同じスロットか同じ名前のモジュールが付いていれば、合成の順の同じ位置で差し替える。なければ最後に加える |
| `detach_module(name)` | モジュールを外す。付いていなければ `DressUpError::NotAttached` |
| `set_modules(Vec<Arc<Module>>)` | 付けるモジュールの組をまとめて決める。空なら本体だけに戻す |
| `modules()` / `base_model()` | 付けているモジュール (合成の順) と本体のモデル |
| `texture_sources()` | 合成したモデルのテクスチャごとの出どころ (`TextureSource::Base(i)` か `TextureSource::Module { module, index }`) |

最初にモジュールを付けたときの Puppet のモデルと物理の設定を本体として覚え、付け外しのたびに本体とモジュールの組を合成・コンパイルし直します。
失敗したとき (`DressUpError`: 合成・コンパイル・合成した物理の検証) は何も変えません。本体に物理が無くてもモジュールにリグがあれば、
重力 `(0, 1)`・風なし・60 Hz の設定に加えます。モジュールを付けている間に `set_physics` で渡した設定は、次の組み替えで本体の設定から作り直されます。

組み替えでは、状態を次のように扱います。

- **パラメータ**: 値と基準値 (モーションの結果・ホストが書いた値) を同じ ID で引き継ぎます (`ParameterValues::carry_over`)。
  合成はパラメータを変えないので、モーション・表情・目パチ・呼吸・リップシンク・トラッキングはそのまま続きから動きます。
- **ポーズ**: 合成したモデルのポーズで作り直し、要素のパーツの並びが同じグループの状態 (表示中の要素と不透明度) を引き継ぎます
  (`PosePlayer::carry_over`)。本体のグループは、モジュールの `links` が加わっても表示中の要素を保ちます。新しいグループは先頭の要素の表示から始めます。
- **物理**: 合成した設定で作り直します。粒子は次の `update` で、その時の入力に対する静止姿勢から始めます (本体のリグの揺れも止まります)。
  付け外しは見た目の瞬間的な切り替えで、揺れの途中の髪が新しい衣装の衝突体にめり込んだ状態を引き継がないため、リセットを選びました。
- **評価**: 差し替えた直後に 1 回評価するので、`instance().drawables()` はすぐに新しいモデルのものになります。

付け外しの戻り値 `DressUpChange` は、描画のために利用者がすることを表します。

- `textures`: 出どころが変わったか新しく増えたテクスチャの番号 (昇順)。同じ名前の別のモジュール (`Arc` が違うもの。新しい版など) に差し替えたときも、そのテクスチャを含みます。テクスチャは本体、モジュールの順に並ぶので、前のモジュールを外すと後ろのモジュールのテクスチャの番号がずれます。
  レンダラの利用者は、この番号に `texture_sources()` の出どころの画像 (`ModuleFile::textures` / `normal_maps` の添字) を `Renderer::set_texture` / `set_normal_map` で設定し直します。
- `texture_count`: 合成したモデルのテクスチャの数。これ以上の番号は使われません。
- メッシュの並びなどは変わりますが、`ugoe_render::Renderer` は別のコンパイル済みモデルを渡されると描画用のバッファを作り直すので、利用者がすることはありません。

wasm (`ugoe-wasm` の `WebPuppet`) は、`.ugoemod` の読み込み (`load_module`) と付け外し (`attach_module` / `detach_module` /
`set_modules` / `unload_module`)、付けているモジュールと本体のスロットの一覧 (`attached_modules`・`modules_json`・`slots_json`) を持ちます
(`crates/ugoe-wasm/README.md#着せ替え-t0123`)。`DressUpChange` に従ってテクスチャと法線マップを登録し直し、使わなくなった番号の画像は
1x1 の白に置き換えて捨てます。モデルを読み直すと、付けていたモジュールを付け直します (付けられないものは外して警告します)。
失敗は `name` が `DressUpError` の `Error` で、`code` (`unknown_slot`・`missing_parameter` など) と `module`・`slot` などを持ちます。
ビューア (`apps/viewer`) はこれを使い、`.ugoemod` を開いてスロットごとに付ける・外す・差し替えることができます。
エラーの `code` は利用者に分かる文にして出します (`apps/viewer/README.md#着せ替え-t0706`、T0706)。

### 性能

組み替えのたびに合成とコンパイルが走ります。`cargo run --release -p ugoe-runtime --example compose_timing` で計測できます。
T0111 での計測 (本体: メッシュ 200 枚・頂点 12,800・ワープ 40 個、各格子 9 セル。モジュール 4 つで計メッシュ 64 枚・ワープ 16 個を加える):

| 処理 | 時間 (中央値) |
| --- | --- |
| 合成 (`compose`、検証を含む) | 約 0.3 ms |
| コンパイル (検証を含む) | 約 0.4 ms |
| 合成・コンパイル・最初の `update` | 約 0.9 ms |

ADR 0014 の目標 (中規模のモデルで数 ms 以内) を満たします。

## 旧ランタイムでの扱い

スロットとモジュールは任意機能 `modules` ([ADR 0013](../adr/0013-forward-compatibility.md)) です。知らないランタイムはスロットを無視し、本体だけを表示します。
