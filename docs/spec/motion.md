# モーション・表情・エフェクト仕様

対応するコードは、データが `ugoe_model::{motion, expression, effects, pose}`、再生が `crates/ugoe-motion`、フレーム内の順序の管理が `crates/ugoe` (`Puppet`)。

## モーション

### カーブ

カーブは対象 (`CurveTarget`) とセグメント列を持ちます。最初のセグメントは必ず `start` で、以降の各セグメントの始点は直前のセグメントの終点です。

| セグメント | 区間 `[p0.t, to.t]` での値 |
| --- | --- |
| `linear` | `lerp(p0.v, to.v, u)`、`u = (t - p0.t) / (to.t - p0.t)` |
| `bezier` | 3 次ベジェ `B(s) = (1-s)³p0 + 3(1-s)²s c1 + 3(1-s)s² c2 + s³ to`。時刻 `t` について `B_t(s) = t` を解いて `s` を求め、`B_v(s)` を値とする |
| `stepped` | 区間の終点より前は `p0.v`、終点では `to.v` |
| `inverse_stepped` | 区間の始点では `p0.v`、始点より後は `to.v` |

- ベジェの制御点の時刻は区間内 (`p0.t <= c.t <= to.t`) にあるものとします。これにより `B_t` は単調になり、`s` がただ 1 つに決まります。範囲外の値は評価時に区間内へクランプします (読み込み時にはデータを変えません)。
- `B_t(s) = t` は、単調性を前提に、ニュートン法を二分法で守って解きます (解を含む区間を保ち、ニュートン法の次の点が区間の外に出るときは二分する)。許容誤差は区間を `[0, 1]` に正規化した時刻で `1e-6` です。
- 最初の点より前の時刻では最初の点の値を、最後の点より後の時刻では最後の点の値を使います。

### 対象

| 対象 | 意味 |
| --- | --- |
| `parameter` | パラメータの値 |
| `part_opacity` | パーツの不透明度を上書きする |
| `effect_group` | エフェクトグループ (`EyeBlink`、`LipSync`。[エフェクトグループ](#エフェクトグループ)) の強さ。エフェクトの出力に掛ける |

### 再生とフェード

- モーションの重み `w = fade_in_weight * fade_out_weight`。フェードの曲線は `easing(x) = 0.5 - 0.5 cos(π x)` (0〜1) を使います。
- カーブ個別の `fade_in` / `fade_out` が指定されていれば、モーション全体の値の代わりにそれを使います。
- パラメータへの適用: `value = lerp(current, curve_value, w)` (`ParameterValues::blend`)。
- `looping = true` のモーションは `duration` で折り返します。ループの境目ではフェードをかけません。
- `events` は再生時刻がイベントの時刻を通過したフレームで発火します。ループをまたいだ場合も漏らさず発火します。

`MotionPlayer` (`crates/ugoe-motion/src/player.rs`) の細則:

- 時刻は 2 つ持ちます。経過時間 `elapsed` (再生開始から。フェードに使う) と、再生位置 `time` (モーション内の時刻。ループすると 0 に戻る)。
- フェードインの重みは `easing(elapsed / fade_in)` です (`fade_in <= 0` なら 1)。
- フェードアウトは終了時刻 `end` (経過時間で表す) に向けてかけます: `easing((end - elapsed) / fade_out)` (`fade_out <= 0` なら、終了時刻まで 1)。
  - ループしないモーションは `end = duration` です。つまり終わりの `fade_out` 秒前から自然にフェードアウトします。
  - ループするモーションは、止める (`stop()`) まで終わりません。`stop()` はその時点から `fade_out` 秒後を終了時刻にします (既に決まっている終了時刻のほうが早ければそちらを保つ)。モーションマネージャはこれで古いモーションをフェードアウトさせます。
  - 終了時刻を過ぎたプレイヤーは終わり (`is_finished()`) で、何も適用せず、イベントも発火しません。
- `update(parameters, dt, weight)` の `weight` はフェードとは別の外部の重みで、フェードの重みに掛けます。
- イベントは、1 回の `advance(dt)` で通過した再生位置の範囲 `(前の位置, 新しい位置]` にあるものを発火します。再生開始直後とループの折り返し直後は、範囲の始点ちょうど (時刻 0) のイベントも含めます。1 フレームで複数周回した場合は、周回ごとにすべて発火します。発火したイベントは次の `advance` まで `fired_events()` で読めます。
- 対象がパラメータのカーブは `apply` がパラメータへ適用します。パーツの不透明度とエフェクトグループの値は `curve_values()` (対象・値・フェードの重み) で取り出し、モーションマネージャと `Puppet` が扱います ([パーツの不透明度](#パーツの不透明度)、[エフェクトグループ](#エフェクトグループ))。
- 長さ 0 のループしないモーションは、開始した時点で終わり、何も適用しません。1 フレームだけ姿勢を与えたいときは、短い長さ (1 フレーム分など) のモーションにします。

### モーションマネージャ

`MotionManager` (`crates/ugoe-motion/src/manager.rs`)。

- 優先度 (`Priority`: `Idle` < `Normal` < `Force`) を持ちます。**現在のモーション** (最後に開始し、まだ止めていないもの) より低い優先度の要求は無視します (`start` が `false` を返す)。同じ優先度や高い優先度の要求は受け付けます。`Force` はしたがって常に受け付けます。
- 現在のモーションが終わるか、`stop_all()` で止めると、現在のモーションはなくなり、どの優先度でも開始できます。ループするモーションは止めるまで終わらないので、待機モーションをループさせているときは `Idle` で開始しておくと、`Normal` のモーションで上書きできます。
- 新しいモーションを開始すると、再生中のモーションはすべて `stop()` され、自身の `fade_out` の時間をかけてフェードアウトします。新しいモーションは `fade_in` の時間をかけてフェードインします。
- 毎フレーム、再生中のモーション (フェードアウト中のものを含む) を **開始した順** に進めてパラメータへ適用します。各モーションは `lerp(current, curve_value, w)` で重なるので、重なっている間は古いモーションから新しいモーションへのクロスフェードになります。終わったモーションは取り除きます。
- 発火したイベントは、開始した順のモーションごとに集めて `fired_events()` (`Puppet::motion_events()`) で読めます。
- キュー (「今のモーションが終わったら次を再生する」) は持ちません。ホストが `is_playing()` を見て次のモーションを開始します。

### パーツの不透明度

対象 `part_opacity` のカーブは、パーツ自身の不透明度 (キーフォームで補間した値 `o`) を上書きします。

- マネージャは、開始した順に各モーションのカーブを重ね、パーツごとに `(値 v, 重み W)` を作ります (`part_opacities()`)。重ねた結果は、各カーブで順に `o ← lerp(o, value, w)` とするのと同じです (`W = 1 - Π(1 - w)`)。
- `Puppet` は、パーツの不透明度を `lerp(o, v, W)` に上書きします (`ModelInstance::set_part_opacity_override`、[evaluation.md](evaluation.md#2-評価の順序))。上書きは毎フレーム作り直すので、カーブがなくなると元の不透明度に戻ります。
- ポーズのグループの要素のパーツへのカーブは、上書きではなくポーズへの **表示の要求** (値 `v * W`) になります ([ポーズ](#ポーズ))。

## 表情

表情は、モーションを適用した後のパラメータ値に重ねます。

| op | 式 |
| --- | --- |
| `add` | `v + value * w` |
| `multiply` | `v * lerp(1, value, w)` |
| `overwrite` | `lerp(v, value, w)` |

`w` は表情のフェードの重みです。複数の表情を同時に使う場合は、開始した順に適用します。

`ExpressionManager` (`crates/ugoe-motion/src/expression.rs`) の細則:

- フェードはモーションと同じ式です。`fade_in` で入り、止めてから `fade_out` 秒で抜けます。止めるまで終わりません (表情に長さはない)。
- `set(expression)` は使用中の表情をすべてフェードアウトさせてから `expression` を開始します (表情の切り替え)。`add(expression)` は使用中の表情の上に重ねます。`stop(name)` は名前が一致する表情を、`stop_all()` はすべての表情をフェードアウトさせます。
- 表情はフレームごとに基準値へ重ね直すので ([フレーム内の適用順](#フレーム内の適用順))、`add` の値が累積することはありません。
- `op` が未知の項目と、存在しないパラメータへの項目は無視します。

## エフェクト

設定のデータは `Model.effects` (`ugoe_model::effects::Effects`) と `Model.pose` (`ugoe_model::pose::Pose`) です ([model.md](model.md#エフェクト設定))。再生は T0303 で実装します。

| エフェクト | 挙動 |
| --- | --- |
| 目パチ | 対象パラメータ (`eye_blink.parameters`) を、ランダムな間隔 (平均 `interval`) で 1 → 0 → 1 と動かす。閉じるのに `closing`、閉じたまま `closed`、開くのに `opening` 秒かける |
| 呼吸 | `breath.parameters` の各要素について、対象パラメータに `weight * (offset + peak * sin(2π t / cycle))` を加算する |
| リップシンク | 外部から与えられた音量 (0〜1) を対象パラメータ (`lip_sync.parameters`) に書き込む |
| ポーズ | 排他的なパーツのグループで、表示中のパーツを 1 つに保つ。切り替えは `fade_duration` 秒でクロスフェードする。`links` のパーツはグループの要素と同じ不透明度にする |

再生のコードは `crates/ugoe-motion/src/effects.rs` (`EyeBlinkPlayer`・`BreathPlayer`・`LipSyncPlayer`) と `crates/ugoe-motion/src/pose.rs` (`PosePlayer`) です。`Puppet` はモデルの `effects` と `pose` から作り、`set_effects` / `set_pose` で差し替えられます。

### 目パチ

- 開き具合 `openness` を作ります。開いている間 (`Open`) は 1、閉じる間 (`Closing`) は `1 - t / closing` (線形)、閉じている間 (`Closed`) は 0、開く間 (`Opening`) は `t / opening` (線形) です。長さ 0 の段階は飛ばします。
- 対象パラメータには `v * lerp(1, openness, s)` を書き込みます (`s` はエフェクトグループ `EyeBlink` の強さ)。現在の値に **掛ける** ので、モーションや表情で半分閉じた目は、そこからさらに閉じます。値が 1 を超える「見開き」も比率を保ちます。
- 次のまばたきまでの間隔 (`Open` の長さ) は、`[0.5, 1.5) * interval` の一様分布です (平均 `interval`、最短でも `interval` の半分)。作成時に 1 つ引き、`Open` に戻るたびに引き直します。
- 乱数は SplitMix64 を `eye_blink.seed` で初期化したものです。`[0, 1)` の一様乱数は、出力の上位 24 ビットを `2^24` で割って作ります。同じシードと同じ `dt` の列からは、常に同じ目パチになります。時刻や OS の乱数は使いません。
- `interval <= 0` (不正な設定) なら、まばたきしません。

### 呼吸

- 要素ごとに周期内の時刻 `t ∈ [0, cycle)` を持ち、`dt` を足して `cycle` で折り返します (長時間動かしても `f32` の精度が落ちない)。`cycle <= 0` の要素は `sin` の項を 0 とします。
- 基準値に加算するので ([フレーム内の適用順](#フレーム内の適用順))、フレームをまたいで累積しません。

### リップシンク

- ホストが音量 (`Puppet::set_lip_sync_level`、0〜1 にクランプ) を与えます。音声の解析はしません。`None` (既定) の間は何も書き込みません。
- 対象パラメータに `lerp(v, level, s)` を書き込みます (`s` はエフェクトグループ `LipSync` の強さ)。音量は基準値に入らないので、`None` に戻すと口はモーションの値に戻ります。

### ポーズ

- 各グループは表示中の要素を 1 つ持ちます。最初は先頭の要素を表示します (先頭の不透明度 1、ほかは 0)。
- 表示する要素は、モーションのパーツの不透明度のカーブ ([パーツの不透明度](#パーツの不透明度)) の要求で決めます。グループの要素のうち、要求の値 (`v * W`) が 0 より大きく最大のもの (同じなら先の要素) を表示します。要求がなければ表示中の要素を保ちます。クロスフェード中は古いモーションの要求の重みが下がり、新しいモーションの要求の重みが上がるので、新しいモーションの重みが上回った時点で切り替わります。ホストは `PosePlayer::show(part)` でも切り替えられます。
- 毎フレーム、表示中の要素の不透明度を `dt / fade_duration` だけ上げ (1 で止める。`fade_duration <= 0` ならすぐ 1)、ほかの要素の不透明度を `1 - (表示中の要素の不透明度)` 以下に抑えます。したがって切り替えの間は、新旧の不透明度の和が 1 になります。
- 要素とその `links` のパーツの不透明度を、パーツ自身の不透明度の上書き (重み 1) として書き込みます。

### 既定値

`Effects::default()` は対象パラメータを持たず (何もしない)、時間などは下の値を持ちます。`Effects::standard()` は標準パラメータを対象にした推奨設定です。

| 項目 | `default()` | `standard()` |
| --- | --- | --- |
| 目パチの対象 | なし | `EyeLOpen`、`EyeROpen` |
| 目パチの時間 | `interval` 4.0、`closing` 0.1、`closed` 0.05、`opening` 0.15 秒、`seed` 0 | 同左 |
| リップシンクの対象 | なし | `MouthOpenY` |
| ポーズの `fade_duration` | 0.5 秒 | — |

`Breath::standard()` の呼吸 (周期は互いに割り切れない値にして、動きの繰り返しを目立たなくする):

| パラメータ | `offset` | `peak` | `cycle` (秒) | `weight` |
| --- | --- | --- | --- | --- |
| `AngleX` | 0 | 15 | 6.5345 | 0.5 |
| `AngleY` | 0 | 8 | 3.5345 | 0.5 |
| `AngleZ` | 0 | 10 | 5.5345 | 0.5 |
| `BodyAngleX` | 0 | 4 | 15.5345 | 0.5 |
| `Breath` | 0.5 | 0.5 | 3.2345 | 1 |

### エフェクトグループ

モーションのカーブの対象 `effect_group` (`CurveTarget::EffectGroup`) は、次の名前でエフェクトの出力の強さを指定します (`ugoe_model::effects` の定数)。

| 名前 | 定数 | 対象 |
| --- | --- | --- |
| `EyeBlink` | `EYE_BLINK_GROUP` | `eye_blink.parameters` |
| `LipSync` | `LIP_SYNC_GROUP` | `lip_sync.parameters` |

呼吸とポーズはエフェクトグループを持ちません。未知の名前のカーブは無視します。

強さ `s` は 1 から始め、開始した順に各モーションのカーブを `s ← lerp(s, value, w)` で重ねます (`w` はカーブのフェードの重み)。カーブがなければ 1 です。モーションがフェードアウトすると `s` は 1 に戻ります。

## フレーム内の適用順

`Puppet::update(dt)` (`crates/ugoe/src/lib.rs`) は次の順に適用します。

1. **基準値に戻す。** パラメータを「基準値」に戻す。ただし前フレームの `update` が書き込んだ値から変わっているパラメータは、ホストが `update` の合間に書き換えたものとみなし、その値を新しい基準値にする
2. モーション (モーションマネージャ)
3. トラッキング (`Puppet::set_tracking` で入力があるとき。`ugoe_motion::TrackingMap::apply`、[avatar-profile.md](avatar-profile.md#フェイストラッキングとの対応))
4. **基準値を保存する。** 現在の値を基準値にする
5. 表情
6. 目パチ
7. 呼吸
8. 物理 (`PhysicsSystem::update_instance`。動的物理を使う設定では、ここで評価の 1 段目を行う)
9. リップシンク
10. パーツの不透明度の上書き (モーションのパーツの不透明度のカーブとポーズ)
11. `ModelInstance::update()` (評価。動的物理を使う設定では 2 段目、[evaluation.md](evaluation.md#動的物理を使う場合-2-段階の評価))

決めたこと (T0303):

- **基準値に戻してからモーションを適用する。** 戻さないと、呼吸や表情の `add` のような「現在の値に重ねる」処理がフレームごとに累積してしまう。基準値はモーション (とトラッキング) を適用した直後の値なので、モーションが終わっても最後に適用した値はそのまま残り、表情・目パチ・呼吸・物理・リップシンクだけが毎フレーム重ね直される。この方式は、以前の未決に書いたとおり Cubism Framework のサンプル実装の考え方 (モーションの前に保存した値に戻す) と同じ。
- **ホストの書き換えを検出する。** ホスト (エディタのスライダーなど) は `update` の合間に `ModelInstance::parameters_mut()` で値を書き換える。前フレームの出力とビット列で比べて変わっている値を新しい基準値にするので、ホストは基準値を意識しなくてよい。`ParameterValues::reset()` も同じく基準値の書き換えになる。
- **トラッキングは基準値に含める。** トラッキング (T0306) は毎フレーム値を与えるので、基準値に含めても累積しない。含めておくと、表情・目パチ・呼吸がトラッキングの上に重なる。トラッキングは対応のあるパラメータをモーションの値ごと置き換える。入力を `None` に戻すと、最後に書き込んだ値が基準値として残る。目パチは `EyeLOpen` / `EyeROpen` に掛かるので、トラッキング中に目パチを止めるかはホストが決める (`set_effects`)。
- **物理は目パチ・呼吸の後。** 物理は顔の角度などの入力を読むので、入力を作る処理 (モーション・表情・呼吸) の後に置く。
- **動的物理の 1 段目は物理の段で行う (T0305)。** 1 段目は物理より前に書き込まれたパラメータで評価するので、衝突体や根元の位置はモーション・表情・呼吸の結果に従う。リップシンクなど、物理より後に書き換えたパラメータを束縛するデフォーマは 2 段目で評価し直すので、評価の結果は 1 回で評価した場合と変わらない。
- **物理の加算の出力は、物理の段の直前の値に足す (T0313)。** `blend = add` の出力 ([physics.md#合成の方法](physics.md#合成の方法)) は、モーション・トラッキング・表情・目パチ・呼吸を適用した値に揺れ (静止時の値からのずれ) を足す。基準値に戻してから毎フレーム足し直すので累積しない。トラッキングの `BodyAngleX` に体の遅れを重ねるなど、パラメータを複製せずに両立できる。
- **リップシンクとポーズの順は結果に影響しない。** ポーズはパラメータに触らず、パーツの不透明度だけを書くため、パラメータを扱う処理をすべて終えてから行う。

### 段の有効無効

`Puppet::set_toggles(Toggles { physics, eye_blink, breath, lip_sync, pose })` で、物理・目パチ・呼吸・リップシンク・ポーズの段を止められます (既定はすべて有効)。エディタのプレビューで、物理やエフェクトを切って確かめるためのものです。

- 止めた段はパラメータにもパーツの不透明度にも触りません。目パチ・呼吸は止めている間は時刻も進まず、再開すると続きから動きます。
- 物理を止めると、動的物理の加算量を 0 に戻します (揺れた形のまま残さない)。再開すると、粒子はその時の入力に対する静止姿勢から始めます (`PhysicsSystem::reset`)。
- ポーズを止めると、モーションのパーツの不透明度のカーブはポーズの要素のパーツにもそのまま上書きになり、ポーズは何も書きません。
- 物理の設定は `Puppet::set_physics(Option<PhysicsSettings>)` で差し替えられます。モデルと合わせて `validate_physics` で検査し、エラーがあれば何も変えません。差し替えると粒子は静止姿勢から始め、動的物理の加算量は 0 に戻します。

### 手で動かしたパラメータとの関係

エディタ・ビューアのスライダーのように、ホストが `update` の合間にパラメータを書き換えたときの扱いです (T0309)。上の「ホストの書き換えを検出する」から次が決まります。

| 書き換えたパラメータ | 見え方 |
| --- | --- |
| どの段も触らないもの | そのまま残る |
| モーションのカーブの対象 (再生中) | モーションの重みで上書きされる (重み 1 なら見えない)。モーションの後の値が基準値になるので、再生中に書き換えた値は失われ、終わった後はモーションの最後の値が残る |
| トラッキングの対象 (入力があるとき) | トラッキングで置き換わる |
| 表情・目パチ・呼吸の対象 | 書き換えた値が基準値になり、その上に重なる |
| 物理の入力 | 物理がその値を読む (スライダーで頭を振ると髪が揺れる) |
| 物理の出力 | 物理が出力の重みで上書きする。スライダーの値を見るには物理を止める |
| リップシンクの対象 (音量があるとき) | リップシンクが上書きする |

`update` を呼ばずに描画だけするホスト (エディタのビューポートの静止表示) では、書き換えた値がそのまま評価されます。

`WebPuppet` (`crates/ugoe-wasm`) は同じ `Puppet` を使うので、`set_parameter` の値も同じ規則に従います。JS からは `start_motion` / `start_motion_json`・`set_expression` / `set_expression_json`・`set_effects_json`・`set_lip_sync_level`・`set_enabled(stage, bool)`・`set_physics_json` で操作します (`crates/ugoe-wasm/README.md`)。
