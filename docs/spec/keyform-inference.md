# キーフォームの推定仕様

判断の経緯は [ADR 0010](../adr/0010-keyform-inference.md)。アルゴリズムはツール層のクレート `ugoe-rigging` (T0610) に置き、エディタのコマンド (T0611) から使う。

> 実装待ち: AI による深度推定は T0505 で実装します。加算合成は `ugoe_rigging::infer_additive` (T0610)、ミラーは `ugoe_rigging::mirror_keyforms`、深度からの回転は `ugoe_rigging::infer_depth_rotation` (T0612)、エディタのコマンドは `ugoe_editor_core` (T0611) にあります。データ (由来・推定の設定・ミラー・深度) は `ugoe-model` に定義済みです ([model.md#キーフォーム推定のデータ](model.md#キーフォーム推定のデータ))。

推定はツールで行い、結果はふつうのキーフォームとしてモデルに焼き込みます。**ランタイムの評価 ([evaluation.md](evaluation.md)) は推定を知りません。**

## セルの由来

キーフォーム格子の各セルは、次のどちらかの由来を持ちます (`KeyformGrid::origins`、型は `KeyformOrigin`)。
`origins` が空なら、すべてのセルが `authored` です。空でなければ `keyforms` と同じ長さ・同じ並びです。

| 由来 | 意味 |
| --- | --- |
| `authored` | 人が作った (または手で修正した) セル。推定はこのセルを上書きしない |
| `derived` | 推定で作ったセル。推定の元になったセルが変わると、エディタが作り直す |

`derived` のセルを手で編集すると、そのセルは `authored` になります。`authored` のセルを `derived` に戻す (推定をやり直す) コマンドも用意します。

`derived` のセルを作り直すときに使う方法は `KeyformGrid::inference` (型は `KeyformInference`) に持ちます。
`method` が `additive` なら加算合成、`depth_rotation` なら深度からの回転 (設定は [回転と投影](#回転と投影)) です。省略すると加算合成です。
ミラーで作ったセルの作り直しは、格子の設定ではなく要素の `mirror` と対称軸で決まります。

由来と推定の設定はオーサリング用のデータで、ランタイムは読み飛ばします ([ADR 0013](../adr/0013-forward-compatibility.md) の任意機能 `authoring.keyform_origins`)。

## 記法

- 格子は N 本の軸を持ち、軸 `k` のキー列を `K_k` とします。
- 軸 `k` の **中立のキー** `z_k` は、パラメータの `default` と等しい (差が 1e-5 以下の) キーです。中立のキーがない軸は、加算合成の対象にできません (エラー)。
- セル `c = (i_0, ..., i_{N-1})` について、中立でない軸の集合を `S(c) = { k | i_k ≠ z_k }` とします。
- `cell(S, c)` は「軸の集合 `S` だけを `c` の値にし、残りの軸を中立にしたセル」です。`B = cell(∅)` を **基準のセル** と呼びます。
  基準のセルは `authored` でなければなりません (`derived` ならエラー)。

## 加算合成

### 1 軸の変化

`|S(c)| = 1` のセル (1 つの軸だけが中立でないセル) を **1 軸セル** と呼びます。軸 `k` の 1 軸セルの変化を `Δ_k(c) = cell({k}, c) − B` とします。

1 軸セルが `derived` の場合、同じ軸上の `authored` のセルから次のように推定します。

- 両側に `authored` のセルがあれば、キーの値で線形に補間する。
- 片側にしかなければ、その側の最も近い 2 つの `authored` のセル (1 つなら基準のセル) から線形に外挿する。
  このとき基準のセルも `authored` のセルに数える。その側の `authored` のセルが基準のセルだけなら、基準のセルの値になる。

推定した 1 軸セルは (クランプしたうえで) 格子に書き込み、多軸セルの `Δ_k` にはその値を使います。

### 交互作用の項

2 軸以上のセルは、1 軸の変化の和に、`authored` の多軸セルが持つ **交互作用の項** を足して推定します。
軸の集合 `T` (`|T| ≥ 2`) の `authored` のセル `a` の交互作用の項を、次のように再帰的に定めます。

```
R(T, a) = cell(T, a) − B − Σ_{k∈T} Δ_k(a) − Σ_{U ⊊ T, |U| ≥ 2} R(U, a)
```

`authored` でない部分集合 `U` の項は 0 とします。

### 推定の式

```
derived(c) = B + Σ_{k∈S(c)} Δ_k(c) + Σ_{U ⊆ S(c), |U| ≥ 2} R(U, c)
```

- 多軸の修正を一度作れば、それを含むさらに多い軸の組み合わせにも自動で効きます。たとえば `AngleX × AngleY` の斜めを手で直すと、`AngleX × AngleY × 表情` のセルにもその修正が入ります。
- 足し合わせる値は、キーフォームの数値のフィールドすべてです (頂点位置、制御点、原点、角度、拡大率、描画順、色、不透明度、`mask_strength`、グルーの強さ)。
  `authored` のセルの頂点 (制御点) の数は、基準のセルと同じでなければなりません (エラー)。
- 推定後、不透明度・色・`mask_strength`・グルーの強さ (`intensity`) は 0〜1 に、拡大率は 0 以上にクランプします。真偽値のフィールド (`reflect_x` など) は基準のセルの値を使います。

## ミラー

左右の対になるものについて、片側のキーフォームを反転してもう片側を作ります。
元の要素 (`source`) と先の要素 (`target`) を指定して実行します (`ugoe_rigging::mirror_keyforms`)。対象はメッシュ・ワープデフォーマ・回転デフォーマです。

### 対応付け

| 対象 | 対応の決め方 |
| --- | --- |
| パラメータ | `Parameter::mirror` で対にしたもの (`EyeLOpen` ↔ `EyeROpen`) は、相手のパラメータの同じ値のキーに対応する。自分自身と対にしたパラメータ (`AngleX`) は、値の符号を反転したキーに対応する。符号を反転したキーが存在しない場合はエラー。`mirror` のないパラメータは自分自身の同じ値のキーに対応する |
| 格子の軸 | 先の格子の軸ごとに、上のパラメータの対応で元の格子の軸を 1 本ずつ選ぶ。1 対 1 に対応しない (相手の軸がない、余る、2 本が同じ軸に対応する) 場合はエラー。キーの並びや数は違ってよいが、先のキーに対応するキーが元になければエラー |
| メッシュ・デフォーマ | `Mesh::mirror` / `Deformer::mirror` で対にしたもの。対は双方向に張る (`validate` が検査する)。対にしていないもの (`mirror` が省略または自分自身) は自分自身と対応する (左右対称な 1 つのメッシュ)。先が元と対になっていなければエラー。デフォーマの種類 (ワープの行・列の数) が違えばエラー |
| 頂点 (メッシュ) | 元と先の基準のセルでの位置を使う。先の頂点ごとに、対称軸で反転した元の頂点のうち最も近いもの (同じ距離なら添字の小さいもの) を対応させる。許容距離を超える先の頂点があればエラーとし、対応しない頂点の一覧を返す |
| 制御点 (ワープ) | 位置は見ず、格子の並びで対応させる。行 `r`・列 `c` の制御点は、元の行 `r`・列 `cols − c` に対応する |

許容距離の既定はキャンバスの 1px です。元の親の座標系に換算して使います: 親がワープなら、その基準のセルの制御点の外接矩形の長いほうの辺 (ピクセル) で割り、回転デフォーマならその基準のセルの拡大率で割ります (祖先についても同様に掛け合わせる。回転デフォーマの子にワープの伸縮は伝わらないので、ワープの下の回転デフォーマでやめる)。

### 対称軸

対称軸は縦の直線 `x = a` で、要素の頂点・制御点・原点と同じ **親座標系** で表します。
要素ごとに `mirror_axis` (`a` の値) で指定し、省略すると親で決まる既定値になります。

| 親 | 座標系 | `mirror_axis` の既定値 |
| --- | --- | --- |
| なし | キャンバス座標 | キャンバスの原点の x (`meta.canvas.origin.x`) |
| ワープデフォーマ | 格子の UV 空間 | `0.5` |
| 回転デフォーマ | 原点を (0,0) とした局所座標 | `0` |

対にした 2 つの要素では、元の側 (`source`) の対称軸を使います。`MirrorKeyforms` の `axis` を指定すると、その実行に限り上書きします。

### 反転の式

元のセル `s` から、対応するセル `t` を次のように作ります。

- 頂点位置・制御点: `x' = 2a − x`、`y' = y`。頂点・制御点の並びは対応付けに従って並べ替える。ワープの制御点は列を左右反転する。
- 回転デフォーマ: 原点を反転し、角度の符号を反転する。拡大率と `reflect_x` / `reflect_y` はそのまま写す (`F·R(θ)·S·F = R(−θ)·S` なので、反転した子に対して正しい)。
- それ以外のフィールド (不透明度・描画順・色など) はそのまま写す。

作ったセルは `derived` になります。書き込みの規則は次のとおりです。

- 先の `authored` のセルは書きません。明示的な指定 (`MirrorOptions::overwrite_authored`) があれば上書きし、`derived` にします。
- 元のセルは、実行前の値を読みます (結果は書き込む順に依存しない)。
- 元と先が同じ要素 (左右対称な 1 つの要素) のときは、自分自身に写るセル (自分自身と対にした軸がすべて中立のセルなど) と、元のセルが `derived` のセルは書きません。推定したセルから推定しないので、何度実行しても同じ結果になります。
- 対になった別の要素では、元のセルが `derived` でも写します。
- 元と先が同じ要素で `overwrite_authored` を指定すると、左右の両方が `authored` のセルは互いの反転で置き換わります (左右が入れ替わる)。

## 深度からの回転

頂点ごとの **深度** (奥行き、キャンバスのピクセル単位、手前が正) を使い、疑似 3D として回転・投影して、顔や体の振り向きのキーフォームを作ります。

### 深度の入力

- 深度はオーサリング用のデータとして、メッシュの頂点ごと (`Mesh::depth`、長さは頂点数)、またはワープの制御点ごと (`WarpDeformer::depth`、長さは制御点数) に持ちます。ランタイムは読み飛ばします。
- 深度は基準のセルの形に対して与えます。
- 深度は、エディタで手で塗るか、原画から AI で推定した深度マップを標本化して作ります ([ai-integration.md](../ai-integration.md#深度推定による振り向きリグ))。

### 回転と投影

振り向きの対象 (推奨はワープデフォーマの制御点) の基準の位置を `p = (x, y, d)`、回転の中心を `o = (ox, oy, od)` とします (`ugoe_rigging::infer_depth_rotation`)。
対象はワープデフォーマとメッシュで、親の座標系がアフィン (親なし、または回転デフォーマ) でなければなりません。親がワープ (UV 空間) の場合は、ピクセル単位の深度と座標の単位が合わないのでエラーにします。
親が回転デフォーマのときは、深度 (と `pivot_depth`) を親の座標系の単位に直してから回します (祖先の回転デフォーマの基準のセルの拡大率で割る)。
設定は格子の `inference` に `{"method": "depth_rotation", ...}` として持ちます (型は `DepthRotation`)。

| フィールド | 意味 |
| --- | --- |
| `angle_scale` | 角度の係数 (既定 1) |
| `pivot` | 回転の中心 `(ox, oy)`。対象と同じ親座標系 |
| `pivot_depth` | 回転の中心の深度 `od` (既定 0) |
| `yaw` / `pitch` | 縦軸・横軸まわりの回転に使うパラメータ (通常 `AngleX` / `AngleY`)。格子の軸でなければならない。省略するとその向きには回さない (角度 0) |

```
yaw    = (`yaw` のパラメータ (AngleX) の値 − default) × angle_scale     // 縦軸まわり (度)
pitch  = (`pitch` のパラメータ (AngleY) の値 − default) × angle_scale   // 横軸まわり (度)
q      = R_y(yaw) · R_x(pitch) · (p − o) + o
結果   = (q.x, q.y)                                                  // 正射影

R_y(θ) = [[cos θ, 0, sin θ], [0, 1, 0], [−sin θ, 0, cos θ]]
R_x(φ) = [[1, 0, 0], [0, cos φ, −sin φ], [0, sin φ, cos φ]]
```

- 座標は x が右、y が下、深度 z が手前です。正の yaw で手前 (z > 0) の点が右 (+x) へ、正の pitch で手前の点が上 (−y) へ動きます。これはパラメータの向きの約束 ([model.md#標準パラメータ](model.md#標準パラメータ): `AngleX` 正で画面の右、`AngleY` 正で上を向く) に合わせたものです。
- 角度はパラメータの `default` からの差です (標準の `AngleX` / `AngleY` は `default` が 0 なので、値そのもの)。基準のセルは角度 0 になります。
- `angle_scale` の既定は 1 (パラメータの値を度として使う)。原画の振り向きを誇張・抑制したい場合に変えます。
- 深度が 0 の点だけなら、平らな板を回したのと同じです (yaw だけなら横に、pitch だけなら縦に、中心に向かって cos 倍縮む)。

- 回す順は **pitch が先、yaw が後** です。pitch は頭自身の横軸 (耳と耳を結ぶ軸) まわりのうなずき、yaw はそのあと縦軸 (首) まわりの振り向きで、頭の実際の動きに合わせています。
  この順では投影後の y が x によらない (`y' = y cos φ − z sin φ`) ので、斜めのセルでも目の線などの水平な線が傾きません (縦の線は傾きます)。
  逆の順 (`R_x(pitch) · R_y(yaw)`) では y が x に依存し、30°・30° で目の線が約 16° 傾いて、首をかしげた (AngleZ を回した) ように見えるため採りません (T0612 で描画して確認)。

#### 格子のセルの作り方

格子のすべてのセル (中間・斜めを含む) を作り、`derived` にします。手で直したセルは `authored` になり、上書きしません。

セル `c` の `yaw` / `pitch` の値で基準のセルを回した形を `Rot(c)` とし、次のように作ります。

```
E(a)       = cell(a) − Rot(a)                       // authored のセル a の、回転の式からのずれ
derived(c) = Rot(c) + 加算合成(E)(c)                  // E を加算合成の式で c に広げる (E(B) = 0)
```

- 手で直したセルがなければ `E = 0` なので、どのセルも回転の式どおりになります。
- `yaw` / `pitch` 以外の軸 (表情など) があれば、その軸の変化 `Δ_k = cell({k}) − B` は加算合成と同じように足し合わさります (その軸の 1 軸セルでは `Rot = B`)。
- 回す軸のセルを手で直すと、その修正が加算合成の規則で他のセルに広がります。たとえば `AngleX = 30` を直すと、斜めの `AngleX = 30, AngleY = 30` にも同じ修正が入ります。1 軸上の補間・外挿も加算合成と同じで、片側にしか修正がなければ基準のセルと結んで外挿します (`AngleX = 30` の修正 `+e` は `AngleX = −30` で `−e`)。
- 頂点・制御点の位置以外のフィールドは `Rot(c)` では基準のセルの値で、加算合成と同じく足し合わせてからクランプします。
- 手前のパーツが回り込んで奥のパーツを隠す、といった描画順の変化はこの方法では作りません。必要なら描画順のキーフォームを手で設定します。

## 推定の実行

推定は `ugoe_editor_core::Command` として実行します (Undo できる)。JSON の形とエラーは [editor.md#推定とミラー](../editor.md#推定とミラー) にあります。

| コマンド | 内容 |
| --- | --- |
| `InferKeyforms { target, method }` | 指定した格子の `derived` のセルを作り直す。`method` は `from_grid` (既定。格子の `inference` に従う) / `additive` / `depth_rotation` |
| `MirrorKeyforms { source, target, axis, tolerance, overwrite_authored }` | ミラーで対応するセルを作る (`MirrorOptions`) |
| `MarkKeyformAuthored { target, cells }` / `MarkKeyformDerived { target, cells }` | 由来を変える。`derived` にしたセルは格子の推定の設定で作り直す |

推定の元のセルを変えるコマンドを実行したとき、エディタはその格子の `derived` のセルを格子の `inference` の方法で自動で作り直します (同じ Undo 単位に含める)。
ミラーで作ったセルは、元の要素を変えても自動では作り直しません (`MirrorKeyforms` を再度実行する)。
