# キーフォームの推定仕様

判断の経緯は [ADR 0010](../adr/0010-keyform-inference.md)。アルゴリズムはツール層のクレート `ugoe-rigging` (T0610) に置き、エディタのコマンド (T0611) から使う。

> AI による深度推定と振り向きの提案は `ugoe_ai::turn` (T0505、[ai-integration.md](../ai-integration.md#深度推定による振り向きリグ)) にあります。加算合成は `ugoe_rigging::infer_additive` (T0610)、ミラーは `ugoe_rigging::mirror_keyforms`、深度からの回転は `ugoe_rigging::infer_depth_rotation` (T0612)、エディタのコマンドは `ugoe_editor_core` (T0611)、画面での操作は T0613 ([editor.md#推定の画面での操作](../editor.md#推定の画面での操作)) にあります。データ (由来・推定の設定・ミラー・深度) は `ugoe-model` に定義済みです ([model.md#キーフォーム推定のデータ](model.md#キーフォーム推定のデータ))。

推定はツールで行い、結果はふつうのキーフォームとしてモデルに焼き込みます。**ランタイムの評価 ([evaluation.md](evaluation.md)) は推定を知りません。**

推定の対象は要素の通常の格子だけです。ブレンドシェイプ格子 ([model.md#ブレンドシェイプ](model.md#ブレンドシェイプ)) は推定で書き換えず、ミラーもしません。

推定はセルの値だけを作り、格子の補間の種類 (`interpolation`、[evaluation.md#曲線補間](evaluation.md#曲線補間)) には触れません。曲線補間の格子でも作るセルは線形の格子と同じで、ミラーも先の格子の `interpolation` を変えません (左右で揃えるなら、それぞれの格子に設定する)。

## セルの由来

キーフォーム格子の各セルは由来を持ちます (`KeyformGrid::origins`、型は `KeyformOrigin`)。
`origins` が空なら、すべてのセルが `authored` です。空でなければ `keyforms` と同じ長さ・同じ並びです。
推定で作ったセルは、**どの方法で作ったか** を由来に記録します (T0614)。

| 由来 | 意味 |
| --- | --- |
| `authored` | 人が作った (または手で修正した) セル。推定はこのセルを上書きしない |
| `additive` | 加算合成で作ったセル |
| `depth_rotation` | 深度からの回転で作ったセル |
| `mirror` | ミラーで作ったセル。ミラー元は格子の `mirror_source` に記録する |
| `derived` | 推定で作ったセル (方法の記録なし)。格子の `inference` の方法で作ったものとして扱う |

`authored` 以外をまとめて **`derived` のセル** (推定で作ったセル) と呼びます。

- `derived` のセルを手で編集すると、そのセルは `authored` になります。`authored` のセルを推定に戻すコマンド (`MarkKeyformDerived`) は由来を `derived` (方法の記録なし) にし、格子の方法で作り直します。作り直したセルには方法が記録されます。
- 方法を記録していない `derived` のセルを作り直す方法は `KeyformGrid::inference` (型は `KeyformInference`) で決まります。
  `method` が `additive` なら加算合成、`depth_rotation` なら深度からの回転 (設定は [回転と投影](#回転と投影)) です。省略すると加算合成です。
  方法を記録しなかった版 (T0614 より前) のファイルはすべてのセルがこの扱いになり、以前と同じに作り直されます。
- `inference` が未知の方法 (新しい版のファイル) なら、方法を記録していない `derived` のセルは作り直しません。未知の由来のセルは `authored` として扱います (上書きせず、推定の元にする)。
- `depth_rotation` のセルの設定 (回転の中心など) は格子の `inference` にあります。`inference` が深度からの回転でない格子では、`depth_rotation` のセルは作り直しません (値をそのまま使う)。

### キーの追加とセルの由来

`AddKeyformKey` (エディタのコマンド `add_keyform_key`) で格子の軸にキーを加えると、新しいセルは既存の格子を補間した値で埋まり、見た目は変わりません ([editor.md#キーフォームの編集](../editor.md#キーフォームの編集))。新しいセルの由来は次のとおりです (T0617)。

1. **組み合わせのセル** (キーを加えた後の格子で、中立でない軸が 2 本以上あるセル。[記法](#記法)) は、格子の推定の方法が加算合成 (`inference` が省略または `additive`) なら、その場で (同じ Undo 単位で) 加算合成で推定します。
   推定は、新しい組み合わせのセルだけを書き換えるセルにし、他のセル (既存の `derived` のセルと、新しい 1 軸のセルを含む) をすべて書き換えずに元にして行います。
   推定した値が補間した値と一致する (数値のフィールドが値の大きさに対して 1e-4 以内で、真偽値などのフィールドが等しい) セルは、推定した値で `additive` になります。
2. 1 で `additive` にならなかった新しいセル (1 軸のセル・基準のセル・推定した値が補間と違う組み合わせのセル・深度からの回転の格子のセル) は、そのセルを埋めた元のセル (補間した 2 つのセル、キーの範囲の外なら端のセル) のどれかが推定で作ったセルなら `derived` (方法の記録なし)、なければ `authored` です。
3. キーを加えた後の格子に **中立のキーがない軸** があれば、1 と 2 は行わず、格子に推定で作ったセルがあれば新しいセルをすべて `derived`、なければ `authored` にします (T0608 の規則)。

- これで「端の形だけを作れば組み合わせは推定される」([ADR 0010](../adr/0010-keyform-inference.md)) が手順なしで成り立ちます。中立のキーを先に置いて端のキーを加えると、端 (1 軸) のセルは `authored`、斜めのセルは `additive` になり、端を編集するたびに斜めのセルが [自動の作り直し](#自動の作り直し) で作り直されます。
- 斜めのセルの推定した値が補間と一致するのは、補間の元のセルが加算合成と矛盾しない (交互作用の項を持つ `authored` の組み合わせのセルや、古い値の `derived` のセルを元にしない) ときです。たとえば中立のキーしかない軸に 2 つめのキーを加えると、新しいセルは中立の断面の写しなので必ず一致します。一致しないセルは見た目を保つために 2 の規則に従います。
- キーの追加・削除は **既存のセルを作り直しません** (T0608 の判断)。書き換えるのは新しい組み合わせのセルだけで、既存の `derived` のセルが古い値でもそのまま残り、推定の元として使われます。既存のセルは、その格子のセルを次に変えたとき (`set_keyform_cell` など) に作り直されます。
- 曲線補間 (`interpolation = smooth`) の格子では、新しいセルの形の値 (頂点・制御点・回転の原点・角度・拡大率) を、キーを加える前の格子のその値での **曲線の値** で埋めます (形以外は線形の補間)。キーを加えた位置の見た目は変わりませんが、接線が変わるので、キーの間の曲線は少し変わります。
- 深度からの回転の格子では組み合わせのセルもその場では推定しません (回転の式は補間と一致しないので、見た目が変わるため)。2 の規則で由来が決まり、推定のコマンドや次の編集で作り直されます。

### ミラー元の記録

ミラーでセルを作ると、先の格子の `mirror_source` に、元の要素の ID (`id`) と、実行時に明示した対称軸 (`axis`)・許容距離 (`tolerance`) を記録します (省略したものは記録しない)。
元の要素は格子を持つ要素と同じ種類です (メッシュならメッシュ、デフォーマならデフォーマ)。左右対称な 1 つの要素では自分自身の ID になります。
ミラーを実行しても 1 つもセルを書かなければ、記録は変えません。`validate` は `id` の要素が存在することを検査します。
`mirror` のセルがあっても `mirror_source` がなければ、そのセルは作り直しません。

### 方法ごとの書き換えの範囲

推定は、書き換えるセルの範囲 (`ugoe_rigging::InferScope`) を指定して実行します。

| 範囲 | 書き換えるセル |
| --- | --- |
| `own` | その方法の `derived` のセル (方法を記録していないセルは、格子の `inference` の方法ならその方法のセル) |
| `all_derived` | `authored` 以外のすべてのセル |

- どちらでも `authored` のセルは書き換えません (ミラーの `overwrite_authored` を除く)。書いたセルの由来はその方法になります。
- **書き換えないセルは、`authored` のセルと同じく推定の元にします。** たとえばミラーで作った `AngleX = -30` のセルは、加算合成で斜めのセルを作るときの 1 軸セルになります。基準のセルもミラーで作ったセルでかまいません。基準のセルが書き換えるセルならエラーです。
- エディタの自動の作り直しは `own` で行います。明示的なコマンドの範囲は [推定の実行](#推定の実行) にあります。

由来と推定の設定はオーサリング用のデータで、ランタイムは読み飛ばします ([ADR 0013](../adr/0013-forward-compatibility.md) の任意機能 `authoring.keyform_origins`)。

## 記法

- 格子は N 本の軸を持ち、軸 `k` のキー列を `K_k` とします。
- 推定は、格子が次を満たすことを自分で確かめます (`ugoe_model::validate` の前のモデル、たとえば読み込み途中や
  AI の提案の組み立て中でも、誤った値や NaN を作らずにエラーにする。エラーのときは格子を変えない)。
  - 軸は 64 本まで (`TooManyAxes`)。軸のパラメータはモデルにあり (`UnknownParameter`)、同じパラメータの軸は 1 本だけ (`DuplicateAxis`)。
  - 各軸のキーは有限で (`NonFiniteKey`)、狭義の昇順 (重複なし) に並ぶ (`KeysNotAscending`)。1 軸の補間はキーの添字の順を値の順とみなす。
  - セルの数 (軸のキー数の積) が `usize` に収まり (`GridTooLarge`)、`keyforms` の数と等しい (`GridSizeMismatch`)。
    `origins` は空か、同じ長さ (`OriginsLengthMismatch`)。
- 軸 `k` の **中立のキー** `z_k` は、パラメータの `default` と等しい (差が 1e-5 以下の) キーです。中立のキーがない軸は、加算合成の対象にできません (エラー)。
- セル `c = (i_0, ..., i_{N-1})` について、中立でない軸の集合を `S(c) = { k | i_k ≠ z_k }` とします。
- `cell(S, c)` は「軸の集合 `S` だけを `c` の値にし、残りの軸を中立にしたセル」です。`B = cell(∅)` を **基準のセル** と呼びます。
  基準のセルは `authored` でなければなりません (`derived` ならエラー)。

## 加算合成

### 1 軸の変化

`|S(c)| = 1` のセル (1 つの軸だけが中立でないセル) を **1 軸セル** と呼びます。軸 `k` の 1 軸セルの変化を `Δ_k(c) = cell({k}, c) − B` とします。

1 軸セルが `derived` の場合、同じ軸上の `authored` のセルから次のように推定します。

- 両側に `authored` のセルがあれば、キーの値で線形に補間する。
- 片側にしかなければ、その側の最も近い 2 つの `authored` のセル (1 つなら基準のセル) から線形に外挿する。
  このとき基準のセルも `authored` のセルに数える。その側の `authored` のセルが基準のセルだけなら、基準のセルの値になる。

推定した 1 軸セルは (クランプしたうえで) 格子に書き込み、多軸セルの `Δ_k` にはその値を使います。

### 交互作用の項

2 軸以上のセルは、1 軸の変化の和に、`authored` の多軸セルが持つ **交互作用の項** を足して推定します。
軸の集合 `T` (`|T| ≥ 2`) の `authored` のセル `a` の交互作用の項を、次のように再帰的に定めます。

```
R(T, a) = cell(T, a) − B − Σ_{k∈T} Δ_k(a) − Σ_{U ⊊ T, |U| ≥ 2} R(U, a)
```

`authored` でない部分集合 `U` の項は 0 とします。

### 推定の式

```
derived(c) = B + Σ_{k∈S(c)} Δ_k(c) + Σ_{U ⊆ S(c), |U| ≥ 2} R(U, c)
```

- 多軸の修正を一度作れば、それを含むさらに多い軸の組み合わせにも自動で効きます。たとえば `AngleX × AngleY` の斜めを手で直すと、`AngleX × AngleY × 表情` のセルにもその修正が入ります。
- 足し合わせる値は、キーフォームの数値のフィールドすべてです (頂点位置、制御点、原点、角度、拡大率、描画順、色、不透明度、`mask_strength`、グルーの強さ)。
  `authored` のセルの頂点 (制御点) の数は、基準のセルと同じでなければなりません (エラー)。
- 推定後、不透明度・色・`mask_strength`・グルーの強さ (`intensity`) は 0〜1 に、拡大率は 0 以上にクランプします。真偽値のフィールド (`reflect_x` など) は基準のセルの値を使います。

## ミラー

左右の対になるものについて、片側のキーフォームを反転してもう片側を作ります。
元の要素 (`source`) と先の要素 (`target`) を指定して実行します (`ugoe_rigging::mirror_keyforms`)。対象はメッシュ・ワープデフォーマ・回転デフォーマです。

### 対応付け

| 対象 | 対応の決め方 |
| --- | --- |
| パラメータ | `Parameter::mirror` で対にしたもの (`EyeLOpen` ↔ `EyeROpen`) は、相手のパラメータの同じ値のキーに対応する。自分自身と対にしたパラメータ (`AngleX`) は、値の符号を反転したキーに対応する。符号を反転したキーが存在しない場合はエラー。`mirror` のないパラメータは自分自身の同じ値のキーに対応する |
| 格子の軸 | 先の格子の軸ごとに、上のパラメータの対応で元の格子の軸を 1 本ずつ選ぶ。1 対 1 に対応しない (相手の軸がない、余る、2 本が同じ軸に対応する) 場合はエラー。キーの並びや数は違ってよいが、先のキーに対応するキーが元になければエラー |
| メッシュ・デフォーマ | `Mesh::mirror` / `Deformer::mirror` で対にしたもの。対は双方向に張る (`validate` が検査する)。対にしていないもの (`mirror` が省略または自分自身) は自分自身と対応する (左右対称な 1 つのメッシュ)。先が元と対になっていなければエラー。デフォーマの種類 (ワープの行・列の数) が違えばエラー |
| 頂点 (メッシュ) | 元と先の基準のセルでの位置を使う。先の頂点ごとに、対称軸で反転した元の頂点のうち最も近いもの (同じ距離なら添字の小さいもの) を対応させる。許容距離を超える先の頂点があればエラーとし、対応しない頂点の一覧を返す |
| 制御点 (ワープ) | 位置は見ず、格子の並びで対応させる。行 `r`・列 `c` の制御点は、元の行 `r`・列 `cols − c` に対応する |

許容距離の既定はキャンバスの 1px です。元の親の座標系に換算して使います: 親がワープなら、その基準のセルの制御点の外接矩形の長いほうの辺 (ピクセル) で割り、回転デフォーマならその基準のセルの拡大率で割ります (祖先についても同様に掛け合わせる。回転デフォーマの子にワープの伸縮は伝わらないので、ワープの下の回転デフォーマでやめる)。

元と先の親が異なる対では、頂点の対応付けもキャンバス座標で行います ([親が異なる対](#親が異なる対))。

### 対称軸

対称軸は縦の直線 `x = a` で、要素の頂点・制御点・原点と同じ **親座標系** で表します。
要素ごとに `mirror_axis` (`a` の値) で指定し、省略すると親で決まる既定値になります。

| 親 | 座標系 | `mirror_axis` の既定値 |
| --- | --- | --- |
| なし | キャンバス座標 | キャンバスの原点の x (`meta.canvas.origin.x`) |
| ワープデフォーマ | 格子の UV 空間 | `0.5` |
| 回転デフォーマ | 原点を (0,0) とした局所座標 | `0` |

対にした 2 つの要素では、元の側 (`source`) の対称軸を使います。`MirrorKeyforms` の `axis` を指定すると、その実行に限り上書きします。
上の表は元と先の親が同じ場合です。親が異なる対の対称軸はキャンバス座標で決めます ([親が異なる対](#親が異なる対))。

### 反転の式

元のセル `s` から、対応するセル `t` を次のように作ります。

- 頂点位置・制御点: `x' = 2a − x`、`y' = y`。頂点・制御点の並びは対応付けに従って並べ替える。ワープの制御点は列を左右反転する。
- 回転デフォーマ: 原点を反転し、角度の符号を反転する。拡大率と `reflect_x` / `reflect_y` はそのまま写す (`F·R(θ)·S·F = R(−θ)·S` なので、反転した子に対して正しい)。
- それ以外のフィールド (不透明度・描画順・色など) はそのまま写す。

作ったセルの由来は `mirror` になり、先の格子にミラー元を記録します ([ミラー元の記録](#ミラー元の記録))。書き込みの規則は次のとおりです。

- 先の `authored` のセルは書きません。明示的な指定 (`MirrorOptions::overwrite_authored`) があれば上書きし、`mirror` にします。
- 先の `derived` のセルは、範囲 (`MirrorOptions::scope`) が `all_derived` ならすべて、`own` なら `mirror` のセルだけを書きます。
- 元のセルは、実行前の値を読みます (結果は書き込む順に依存しない)。
- 元と先が同じ要素 (左右対称な 1 つの要素) のときは、自分自身に写るセル (自分自身と対にした軸がすべて中立のセルなど) と、元のセルが `derived` のセルは書きません。推定したセルから推定しないので、何度実行しても同じ結果になります。
- 対になった別の要素では、元のセルが `derived` でも写します。
- 元と先が同じ要素で `overwrite_authored` を指定すると、左右の両方が `authored` のセルは互いの反転で置き換わります (左右が入れ替わる)。

### 親が異なる対

元と先の親 (`parent`) が異なる対 (左右の髪が別々のデフォーマの下にある、片方だけ付け替えた、など) では、親の座標系どうしでは反転できないので、**キャンバス座標を経由して** 反転します。親が同じ対 (左右対称な 1 つの要素を含む) は、上の式のとおり親の座標系で反転します (結果は変わらない)。

- **姿勢:** 元のセル `s` を写すときの元の親の姿勢は、元の格子の軸のパラメータを `s` のキーにし、残りのパラメータを既定値にしたものです。先のセル `t` に戻すときの先の親の姿勢も同様に、先の格子の軸のパラメータを `t` のキーにしたものです。自分自身と対にしたパラメータ (`AngleX = 30` ↔ `-30`) では、元と先で違う値の姿勢になります。
- **写像:** 親の姿勢での親のワールド変換 ([evaluation.md#デフォーマのワールド変換を読む](evaluation.md#デフォーマのワールド変換を読む)) でキャンバス座標へ写し、先の親のワールド変換の逆で先の親の座標系へ戻します。逆はニュートン法で解きます (ワープの格子が折り返していれば、先のセルの今の値に近い解。解けなければ先の基準のセルから解き直し、それでも解けなければエラー)。実装は `ugoe_rigging::ParentWorld` で、エディタの座標変換 (`ugoe_editor_core::space`) と共通です。
- **対称軸:** キャンバス座標の縦の直線 `x = A` です。元の要素の `mirror_axis` か `MirrorKeyforms` の `axis` (値 `a`、元の親座標系) を指定していれば、既定値の姿勢で、元の基準のセルの点 (回転デフォーマは原点) の重心の高さ `ȳ` の点 `(a, ȳ)` をキャンバス座標へ写した x を `A` にします (親がワープ・回転デフォーマなら近似。付け替えで `mirror_axis` を写し直すのと同じ近似)。指定がなければ、キャンバスの原点の x (`meta.canvas.origin.x`) です。親の座標系の既定値 (ワープの `0.5` など) は使いません: 別々の親の中心は、ふつう左右の対称軸ではないためです。
- **頂点の対応付け:** 元と先の基準のセルの頂点を、既定値の姿勢でキャンバス座標へ写して行います。許容距離はキャンバスのピクセルで、既定は 1px、`tolerance` を指定すれば元の親座標系の値にその座標系の 1 単位のピクセル数 (上の換算の逆) を掛けます。ワープの制御点は親が同じ場合と同じく格子の並びで対応させます。
- **頂点位置・制御点:** 元の点 `p` を `q = F_t⁻¹(R(F_s(p)))` にします (`F_s` / `F_t` は元・先の親のそのセルの姿勢のワールド変換、`R` は `x = A` での反転)。
- **回転デフォーマ:** 原点は点と同じく写します。角度 `θ'` と拡大率 `s'` は、キャンバス座標のワールド変換 `W` を反転したもの `F·W·F` (`F` は x の反転) に先のワールド変換が一致するように決めます: 元の拡大率と反転を除いたワールド変換の線形部分を `L_s`、先の原点での先の親の向き (角度 0・拡大率 1 の子の線形部分) を `Q_t` として、`M = Q_t⁻¹·F·L_s·F` の 1 列目の向きを `θ'`、`s' = s·√|det M|` とします。`θ'` は、親が同じときの値 `−θ` との差が ±180° 以内になる値を選びます (補間が遠回りしないように)。`reflect_x` / `reflect_y` と、それ以外のフィールドはそのまま写します。
- **エラー:** 先の親が扱えない種類なら `UnsupportedParent`、写像が潰れていて戻せなければ `ParentTransform` です。

元と先のどちらかの親の祖先に、格子の軸にないパラメータで動くデフォーマがあると、そのパラメータが既定値以外の姿では左右対称になりません (そのパラメータは既定値の姿勢で写すため)。

## 深度からの回転

頂点ごとの **深度** (奥行き、キャンバスのピクセル単位、手前が正) を使い、疑似 3D として回転・投影して、顔や体の振り向きのキーフォームを作ります。

### 深度の入力

- 深度はオーサリング用のデータとして、メッシュの頂点ごと (`Mesh::depth`、長さは頂点数)、またはワープの制御点ごと (`WarpDeformer::depth`、長さは制御点数) に持ちます。ランタイムは読み飛ばします。
- 深度は基準のセルの形に対して与えます。
- 深度は、エディタで設定するか、原画から AI で推定した深度マップを標本化して作ります ([ai-integration.md](../ai-integration.md#深度推定による振り向きリグ))。
- エディタでは `SetDepth` (値をそのまま置き換える) と `ApplyDepthPreset` (一様・ドーム・選んだ点の値) で設定します。長さは点の数と同じで、値は有限でなければなりません。式と画面の操作は [editor.md#深度の編集](../editor.md#深度の編集) にあります。
- 深度を変えると、その格子の `derived` のセルを [自動の作り直し](#自動の作り直し) で作り直すので、深度からの回転のセルは新しい深度に追従します。深度からの回転のセルが残っている格子の深度は外せません (作り直しが失敗して拒否される)。

### 回転と投影

振り向きの対象 (推奨はワープデフォーマの制御点) の基準の位置を `p = (x, y, d)`、回転の中心を `o = (ox, oy, od)` とします (`ugoe_rigging::infer_depth_rotation`)。
対象はワープデフォーマとメッシュで、親の座標系がアフィン (親なし、または回転デフォーマ) でなければなりません。親がワープ (UV 空間) の場合は、ピクセル単位の深度と座標の単位が合わないのでエラーにします。
親が回転デフォーマのときは、深度 (と `pivot_depth`) を親の座標系の単位に直してから回します (祖先の回転デフォーマの基準のセルの拡大率で割る)。
設定は格子の `inference` に `{"method": "depth_rotation", ...}` として持ちます (型は `DepthRotation`)。

| フィールド | 意味 |
| --- | --- |
| `angle_scale` | 角度の係数 (既定 1) |
| `pivot` | 回転の中心 `(ox, oy)`。対象と同じ親座標系 |
| `pivot_depth` | 回転の中心の深度 `od` (既定 0) |
| `yaw` / `pitch` | 縦軸・横軸まわりの回転に使うパラメータ (通常 `AngleX` / `AngleY`)。格子の軸でなければならない。省略するとその向きには回さない (角度 0) |

```
yaw    = (`yaw` のパラメータ (AngleX) の値 − default) × angle_scale     // 縦軸まわり (度)
pitch  = (`pitch` のパラメータ (AngleY) の値 − default) × angle_scale   // 横軸まわり (度)
q      = R_y(yaw) · R_x(pitch) · (p − o) + o
結果   = (q.x, q.y)                                                  // 正射影

R_y(θ) = [[cos θ, 0, sin θ], [0, 1, 0], [−sin θ, 0, cos θ]]
R_x(φ) = [[1, 0, 0], [0, cos φ, −sin φ], [0, sin φ, cos φ]]
```

- 座標は x が右、y が下、深度 z が手前です。正の yaw で手前 (z > 0) の点が右 (+x) へ、正の pitch で手前の点が上 (−y) へ動きます。これはパラメータの向きの約束 ([model.md#標準パラメータ](model.md#標準パラメータ): `AngleX` 正で画面の右、`AngleY` 正で上を向く) に合わせたものです。
- 角度はパラメータの `default` からの差です (標準の `AngleX` / `AngleY` は `default` が 0 なので、値そのもの)。基準のセルは角度 0 になります。
- `angle_scale` の既定は 1 (パラメータの値を度として使う)。原画の振り向きを誇張・抑制したい場合に変えます。
- 深度が 0 の点だけなら、平らな板を回したのと同じです (yaw だけなら横に、pitch だけなら縦に、中心に向かって cos 倍縮む)。

- 回す順は **pitch が先、yaw が後** です。pitch は頭自身の横軸 (耳と耳を結ぶ軸) まわりのうなずき、yaw はそのあと縦軸 (首) まわりの振り向きで、頭の実際の動きに合わせています。
  この順では投影後の y が x によらない (`y' = y cos φ − z sin φ`) ので、斜めのセルでも目の線などの水平な線が傾きません (縦の線は傾きます)。
  逆の順 (`R_x(pitch) · R_y(yaw)`) では y が x に依存し、30°・30° で目の線が約 16° 傾いて、首をかしげた (AngleZ を回した) ように見えるため採りません (T0612 で描画して確認)。

#### 格子のセルの作り方

格子のすべてのセル (中間・斜めを含む) を作り、由来を `depth_rotation` にします。手で直したセルは `authored` になり、上書きしません。
下の式の「`authored` のセル」は、推定の元にするセル (書き換えないセル。[方法ごとの書き換えの範囲](#方法ごとの書き換えの範囲)) を指します。加算合成でも同じです。

セル `c` の `yaw` / `pitch` の値で基準のセルを回した形を `Rot(c)` とし、次のように作ります。

```
E(a)       = cell(a) − Rot(a)                       // authored のセル a の、回転の式からのずれ
derived(c) = Rot(c) + 加算合成(E)(c)                  // E を加算合成の式で c に広げる (E(B) = 0)
```

- 手で直したセルがなければ `E = 0` なので、どのセルも回転の式どおりになります。
- `yaw` / `pitch` 以外の軸 (表情など) があれば、その軸の変化 `Δ_k = cell({k}) − B` は加算合成と同じように足し合わさります (その軸の 1 軸セルでは `Rot = B`)。
- 回す軸のセルを手で直すと、その修正が加算合成の規則で他のセルに広がります。たとえば `AngleX = 30` を直すと、斜めの `AngleX = 30, AngleY = 30` にも同じ修正が入ります。1 軸上の補間・外挿も加算合成と同じで、片側にしか修正がなければ基準のセルと結んで外挿します (`AngleX = 30` の修正 `+e` は `AngleX = −30` で `−e`)。
- 頂点・制御点の位置以外のフィールドは `Rot(c)` では基準のセルの値で、加算合成と同じく足し合わせてからクランプします。
- 手前のパーツが回り込んで奥のパーツを隠す、といった描画順の変化はこの方法では作りません。必要なら描画順のキーフォームを手で設定します。

## 推定の実行

推定は `ugoe_editor_core::Command` として実行します (Undo できる)。JSON の形とエラーは [editor.md#推定とミラー](../editor.md#推定とミラー) にあります。

| コマンド | 内容 |
| --- | --- |
| `InferKeyforms { target, method, overwrite_derived }` | 指定した格子の `derived` のセルを作り直す。`method` は `from_grid` (既定。格子の `inference` に従う) / `additive` / `depth_rotation`。範囲は `own` で、`overwrite_derived` なら `all_derived` (別の方法で作ったセルも書き換える) |
| `MirrorKeyforms { source, target, axis, tolerance, overwrite_authored }` | ミラーで対応するセルを作る (`MirrorOptions`)。範囲は `all_derived` (先の `authored` 以外のセルをすべて書き換える)。`overwrite_authored` がなくても、先の [未編集のセル](#未編集のセル) は書き換える |
| `MarkKeyformAuthored { target, cells }` / `MarkKeyformDerived { target, cells }` | 由来を変える。`derived` にしたセルは格子の推定の設定で作り直す |
| `SetKeyformInference { target, inference }` | 格子の推定の設定を置き換え、方法を記録していない `derived` のセルを新しい設定で作り直す |
| `SetMirrorPair { target, mirror, axis }` | メッシュ・デフォーマの左右の対 (双方向) と対称軸を設定する |
| `SetDepth { target, depth }` / `ApplyDepthPreset { target, preset }` | メッシュ・ワープの深度を設定する ([深度の入力](#深度の入力))。深度からの回転のセルを作り直す |
| `AddKeyformKey { target, parameter, key }` | キーを加え、新しい組み合わせのセルをその場で推定する ([キーの追加とセルの由来](#キーの追加とセルの由来)) |

### 未編集のセル

キーを追加して埋めただけのセルは、中立のキーから推定の元を持たないので `authored` になります ([キーの追加とセルの由来](#キーの追加とセルの由来) の 2・3)。
たとえば目のワープに `EyeROpen` の 1 と 0 のキーを追加すると、0 のセルは 1 のセルの写しの `authored` です。このままでは、`overwrite_authored` なしのミラーが 1 つもセルを書かず、何もしなかったように見えます (T0624 で見つかった問題)。

そこでエディタの `MirrorKeyforms` は、先の格子の **未編集のセル** を `authored` でも書き換えます (T0627)。

- 未編集のセルは、由来が `authored` で、基準のセル (すべての軸が中立のキーのセル) ではなく、値が基準のセルと見た目で変わらない (キーの追加の推定と同じ比べ方: 数値のフィールドが値の大きさに対して 1e-4 以内、それ以外が等しい) セルです。中立のキーがない軸があれば、未編集のセルはありません。
- 未編集のセルは、ミラーの実行の間だけ書き換えるセルとして扱います。書いたセルは `mirror` になり、書かなかったセル (元と先が同じ要素で、元のセルも未編集のものなど) は `authored` に戻します。元と先が同じ要素では、未編集のセルは推定の元にもしません (`derived` のセルと同じ)。
- 基準のセルは書き換えません (`overwrite_authored` を除く)。形を 1 度でも変えたセルは、基準と同じ値に戻したものを除いて書き換えません。基準と同じ値の `authored` のセルは、形として「変えない」ことを表していても、ミラーで上書きされます (Undo で戻せる)。
- 自動の作り直し (ミラー元が変わったときのミラーし直し) は、これまでどおり `mirror` のセルだけを書きます。未編集のセルを書き換えるのは明示的な実行だけです。
- エディタは、書いたセル・書いたうちの未編集のセル・`overwrite_authored` なら書けたが残したセルの数を返します (`MirrorReport`、[editor.md#推定とミラー](../editor.md#推定とミラー))。
- 他の案として、キーの追加でできたセルに専用の由来を付ける方法もありますが、`ugoe-model` のファイル形式を変えることになるので採りませんでした。値を比べる方法なら、古いファイルのセルにも同じ規則が働きます。

### 自動の作り直し

セルを変えるコマンド (推定のコマンドを含む) を実行したとき、エディタは変わった格子の `derived` のセルを **セルに記録した方法で** 作り直します (範囲は `own`。同じ Undo 単位に含める)。

1. 変わった格子の `additive` と `depth_rotation` のセル (方法を記録していないセルは格子の方法のもの) を作り直す。深度からの回転を先に、加算合成を後に行う。
   `mirror` のセルは、ミラー元が自分自身 (左右対称な 1 つの要素) のときだけミラーし直す。ミラー元が別の要素なら、先の格子を編集しても `mirror` のセルは変えない。
2. 変わった格子を `mirror_source` にしている格子 (依存する格子) の `mirror` のセルを、記録した `axis` / `tolerance` でミラーし直し、続けてその格子の `additive` / `depth_rotation` のセルを作り直す。
3. 依存する格子の値が変われば、さらにその格子に依存する格子へ伝える。

- 循環 (A が B を、B が A をミラー元にする) では、値が変わらなくなるまで伝えます。値が往復し続ける場合に備えて、1 つの格子を作り直すのは 1 回のコマンドにつき 8 回までです。
- ミラーのやり直しに失敗したら (元の頂点を動かして対応しなくなった、対を外した、など)、その格子の `mirror` のセルは前の値のまま残します (コマンドは拒否しない)。
  代わりに警告 (`RederiveWarning`: 格子・ミラー元・理由) を返し、エディタは利用者に知らせます ([editor.md#推定とミラー](../editor.md#推定とミラー))。明示的に `MirrorKeyforms` を実行してもエラーが分かります。加算合成・深度からの回転に失敗したら、コマンドを拒否します。
- 親が異なる対も同じくミラーし直します ([親が異なる対](#親が異なる対))。片側だけを付け替えた対でも、ミラー元を編集すれば警告なしにミラーし直されます。
- 要素の親が変わった (`ReparentPreservingLook`、デフォーマを作って子を包んだ、など) コマンドでは、その要素と対の相手の間のミラー (どちらかの格子が相手をミラー元にし、`mirror` のセルを持つもの) を記録した `axis` / `tolerance` で試します。コマンドの前はミラーできたのに後はできなくなったら、同じ警告を返します (付け替えそのものは見た目を保って行い、拒否しない)。
  たとえば同じワープの下で `mirror_axis` を省略した (UV 空間の `0.5` で対称な) 対の片側を外へ出すと、対称軸がキャンバスの原点に変わるので、ワープの中心がキャンバスの原点になければ対応しなくなります。元の要素の `mirror_axis` を指定し直せば (`SetMirrorPair` の `axis`) 直ります。
- ミラー元の要素を削除すると、依存する格子の `mirror_source` を外し、その格子の `mirror` のセルを `authored` にします (値は変えない)。
