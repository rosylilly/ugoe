# 描画仕様

対応するコードは `crates/ugoe-render`。参照シェーダは `crates/ugoe-render/src/shaders/drawable.wgsl`。

ここに書く式は **すべてのレンダラの正** です。wgpu の参照レンダラも、ゲームエンジン向けの独自レンダラもこれに従います。

## 前提

- テクスチャは **乗算済みアルファ (premultiplied alpha)** の RGBA8 として扱います。PSD などの非乗算画像は、取り込み時またはアップロード時に変換します。
  8 ビットの画像は、色のチャンネルごとに `c' = (c × a + 127) / 255` (整数の割り算、切り捨て) で変換します (`ugoe_headless::image::premultiply`)。
- バンドルのテクスチャは PNG も KTX2 も **乗算していないアルファ** です ([file-formats.md](file-formats.md#バンドル-ugoe))。KTX2 では:
  - KTX2 のデータ形式の記述の `KHR_DF_FLAG_ALPHA_PREMULTIPLIED` は見ません (立っていても乗算していないとみなす。書き出しは立てない)。
  - 画素の値は、形式の `_SRGB` / `_UNORM` や転送関数によらず **保存された値のまま** 使います (sRGB からリニアへ変換しない。
    PNG と同じく、値をそのまま sRGB の値として合成する)。GPU で読むときも sRGB の形式で読まない (読むときに変換される) ようにします。
  - 圧縮した形式 (BCn・ETC2・ASTC・Basis Universal など) は、展開した画素を乗算済みに変換します (上の式)。
    乗算済みの値をバイリニアで読むため、圧縮したまま読んで後から乗算するのでは足りません (アルファの境目で色が変わる)。
  - ミップマップのあるファイルは最初の段 (いちばん大きいもの) だけを使います。
  - 参照の実装 (`ugoe render`・wasm。`ugoe_format::image::decode_ktx2`) がデコードするのは、今は圧縮していない 8 ビットの RGB / RGBA
    (超圧縮は無しか zstd) だけです。圧縮した形式は、`ugoe render` はエラー、wasm は白で代用して警告します (上の決まりを満たさない。
    [file-formats.md#読み込みの上限](file-formats.md#読み込みの上限))。Godot は圧縮した形式も展開して読みます。
- テクスチャは乗算済みの値を **バイリニア・端でクランプ・ミップマップなし** で読みます。
- 色空間: 現時点では sRGB の値をそのまま (リニア化せずに) 合成します。Cubism と同じ見た目にするためです。
  > 未決: リニア合成モードを選べるようにするか。
- 描画先は乗算済みアルファの RGBA として扱います。
  rgb がアルファを超える乗算済みの色も正しい結果です (参考): `additive` を透明な画素に描くとアルファ 0 のまま色が残り、
  1 を超える光 ([ライティング](#ライティング)) では rgb がアルファを超えます。描画先はこれをそのまま保ちます。
  描画先を乗算していない色に直すと (PNG に保存するときなど) この色は失われますが、ホストがどう直すかは仕様の外です。
- **画素を塗るかどうかは画素の中心で決めます。** 描画先の画素 `(x, y)` の中心 `(x + 0.5, y + 0.5)` が三角形の中にあれば、その三角形が画素を覆います。
  三角形の中で変わる値 (UV と、点光源が使う画素のキャンバス上の位置) も画素の中心での値を使います。
  2 つの三角形が共有する辺のちょうど上にある中心は、どちらか一方だけが覆うようにします (推奨。1 つのメッシュが同じ画素を 2 回描かないため)。
  GPU の API の top-left rule がこれに当たります。辺での扱いが違うレンダラ (アンチエイリアスなど) は、違う画素が少ない間だけ [互換の基準](#互換の基準) に収まります。

## 描画可能要素ごとのシェーディング

`c` をテクスチャから読んだ色 (乗算済み)、`M` を乗算色、`S` をスクリーン色、`α` を不透明度とします。

```
rgb = c.rgb * M
rgb = rgb + S * c.a - rgb * S           // スクリーン合成を乗算済みの空間で行う
out = vec4(rgb, c.a) * α
out = out * mask_coverage               // マスクがある場合
```

`α` (評価の `opacity`) はクランプせずに使います。

## 合成モード

`src` をシェーダの出力 (乗算済み)、`dst` を描画先とします。

| モード | RGB | A | wgpu の BlendState |
| --- | --- | --- | --- |
| `normal` | `src + dst * (1 - src.a)` | `src.a + dst.a * (1 - src.a)` | color: One / OneMinusSrcAlpha、alpha: One / OneMinusSrcAlpha |
| `additive` | `src + dst` | `dst.a` | color: One / One、alpha: Zero / One |
| `multiply` | `src * dst + dst * (1 - src.a)` | `dst.a` | color: Dst / OneMinusSrcAlpha、alpha: Zero / One |

## マスク

判断の経緯と、根拠にした調査は [ADR 0009](../adr/0009-clipping-mask-semantics.md) にあります。
基準は Cubism との一致ではなく、リガーにとって便利かどうかです。

### マスクの参照

メッシュは `masks` に、マスクとして使うメッシュへの参照 (`MaskRef { mesh, invert }`) を並べます。

- `invert = false` の参照を **通常マスク**、`invert = true` の参照を **反転マスク** と呼びます。1 つのメッシュで両方を同時に使えます。
- 通常マスクの結合方法は `mask_mode` で選びます。既定は `union` (和集合) で、`intersection` (共通部分) も選べます。反転マスクは常に和集合で結合します。

### マスクの効き具合

画面上の各点で、マスク用メッシュ `i` の **カバレッジ** `c_i` を次のように決めます。

```
c_i = α_i × k_i
  α_i : メッシュ i のテクスチャのアルファ (メッシュの外側では 0)
  k_i : メッシュ i 自身のマスク係数 (メッシュ i がマスクを持たなければ 1)
```

同じマスク用メッシュの三角形が重なる画素では、三角形ごとのカバレッジ `a` を `1 − Π(1 − a)` で重ねます (マスクパスの乗算合成の結果と同じ)。

**マスク用メッシュの不透明度・表示状態 (`visible`)・乗算色・スクリーン色・合成モード・裏面カリングは、カバレッジに影響しません。**
不透明度 0 のメッシュや、パーツごと見えなくなっているメッシュも、形どおりにマスクとして効きます。

`k_i` によって、マスクは **入れ子を継承** します。たとえば黒目を白目でクリップし、瞳孔を黒目でクリップすると、瞳孔は白目からはみ出しません。
マスクの参照が循環する場合 (自分自身を含む) は、モデルの検証でエラーにします。

マスクを持つメッシュのマスク係数 `k` は次のとおりです。`P` は通常マスク、`N` は反転マスクの集合です (集合なので、同じメッシュを同じ `invert` で 2 回参照しても 1 回と数える)。

```
pos = 1                      (P が空)
    = 1 − Π_{i∈P} (1 − c_i)  (mask_mode = union)
    = Π_{i∈P} c_i            (mask_mode = intersection)
neg = 1 − Π_{j∈N} (1 − c_j)  (N が空なら 0)
m   = pos × (1 − neg)
k   = 1 − s × (1 − m)        (s = mask_strength、キーフォームで補間した値。0〜1 にクランプ)
```

描画時の色は、[描画可能要素ごとのシェーディング](#描画可能要素ごとのシェーディング) の `mask_coverage` に `k` を使います。

- `mask_strength` を 1 未満にすると、マスクの外側 (反転マスクでは内側) も `1 − s` の割合で見えます。反転マスクで透かした部分の透け量の調整や、マスクのフェードに使います。
- 「すべてのマスクが見えなくなったらクリッピングを解除する」といった特別な挙動はありません。

### マスク専用メッシュ

`mask_only = true` のメッシュは、色としては描画せず、マスクとしてだけ働きます。
ランタイムの出力では常に `visible = false` になります。マスクに使うためのアートを、不透明度 0 などの回避策なしに用意するためのものです。
マスクとして誰からも参照されていないマスク専用メッシュは、何の効果も持ちません (エディタは警告を出す)。

### 精度

- マスクの数に上限はありません。
- 参照レンダラは既定で、各マスクをその **画面上の大きさ以上の解像度** で描きます。これにより縁がぼやけません。
- 性能のために解像度を下げる設定は、レンダラのオプションとして持ちます (モデルのデータには含めない)。

### 実装方式 (参照レンダラ)

1. ロード時に、各メッシュが読むマスクの **内容** (アトラスの 1 チャンネルに描く値) を決める。同じ値になるメッシュどうしは内容を共有する。
2. フレームごとに、内容を読む要素の画面上の外接矩形を求め、入れ子のマスクへ伝播する。
3. 各内容に、外接矩形の画素数以上の大きさのセル (アトラスの矩形とチャンネル) を割り当てる。入れ子のレベルごとに別のアトラスを使う。
4. マスクパスで、アトラスを 1 でクリアし、各内容を担当チャンネルに **乗算合成** (dst × src) で描く。レベルの小さいアトラスから描く。
5. 本描画パスでは、アトラスの矩形・チャンネル・読み方と `mask_strength` を要素ごとの値 (下の「描画の最適化」) で渡し、係数 `k` を求めて色に掛ける。

WebGL2 でも動くように、ストレージバッファ・コンピュートシェーダ・浮動小数点の描画先は使いません。使うのは RGBA8 の描画先、
乗算合成とチャンネルごとの書き込みマスク、シザー矩形だけです。

詳細 (参照レンダラの決めごと。独自レンダラは同じ結果になれば別の方式でもよい):

- **内容**: `P`・`N` は、参照を通常・反転に分けて重複を除いた集合です (`masks` の並びと重複は区別しない)。内容は次の 2 種類です。
  - `Product(S)` = `Π_{i∈S} (1 − c_i)`。
    - `N` が空で、`mask_mode = union` または `P` が 1 つ: `Product(P)` を **1 から引いて** 読む (`pos = 1 − Π(1 − c)`)。
    - `P` が空: `Product(N)` を **そのまま** 読む (`1 − neg`)。
    - このため、ある集合を通常マスクの和集合として使う要素と、同じ集合を反転マスクとして使う要素は、同じセルを共有します。
  - `Clip(P, mode, N)` = `m` そのもの (そのまま読む)。通常と反転の併用と、2 つ以上の通常マスクの共通部分に使います。
    `mode` は `P` が 2 つ以上のときだけ区別します。
- **マスクパスの手順**: アトラスは RGB の 3 チャンネルに内容を描き、A を作業領域に使います。チャンネルはクリア時に 1 です。
  マスク用メッシュ `i` を描くと、書き込み先に `1 − c_i` を掛けます (乗算合成、他のチャンネルには 1 を出す)。
  メッシュの外では何も掛けない (`c = 0` と同じ) ので、`Π(1 − c)` はメッシュを描くだけで作れます。
  - `Product(S)`: `S` の各メッシュをチャンネルに描く。
  - `Clip`、和集合: 作業領域を 1 で埋め、`P` の各メッシュを作業領域に描き (`Π(1 − c)`)、チャンネルに `1 − 作業領域` を掛ける (全面描画、
    合成 `dst × (1 − dst.a)`、書き込みマスクでそのチャンネルだけ)。これで `pos` が掛かる。
  - `Clip`、共通部分: `P` の各メッシュについて、作業領域を 1 で埋め、メッシュを作業領域に描き (`1 − c`)、チャンネルに `1 − 作業領域` (= `c`) を掛ける。
    メッシュの外ではチャンネルに 0 が掛かるので `Π c` になる。
  - `Clip` の反転マスク: `N` の各メッシュをチャンネルに直接描く (`1 − neg` が掛かる)。
  - 全面描画はシザー矩形 (セル) の範囲だけに効きます。作業領域は内容ごとに埋め直すので、同じセルの他のチャンネルの内容と干渉しません。
- **カバレッジ**: マスクパスでは `c_i = テクスチャのアルファ × k_i` を出します。`k_i` はメッシュ `i` 自身のマスク係数で、
  本描画と同じ式 (自身の内容・読み方・`mask_strength`) で求めます。マスク用メッシュの不透明度・色・合成モード・カリングは使いません。
- **入れ子のレベル**: 内容のレベルは、そのマスク用メッシュのマスクの依存の深さ (`CompiledModel::mask_depth`) の最大値です。
  マスク用メッシュ自身の内容のレベルは必ずそれより小さいので、レベルごとに別のアトラスに描き、レベルの小さいアトラスから描けば、
  描いている最中のアトラスを読むことはありません。
- **外接矩形**: 内容を読む要素 (表示されていて三角形を持つもの) の頂点を画面 UV (0..1、左上原点) に写した外接矩形です。
  入れ子では、内容の外接矩形とマスク用メッシュ `i` の外接矩形の共通部分を、`i` 自身の内容の外接矩形に加えます (レベルの大きい順に伝播する)。
  最後に画面で切り詰め、画素の境界まで外側に広げます。面積が 0 になる (画面外など) 内容は描かず、それを読む要素も描きません。
  自身の内容が描かれないマスク用メッシュは、内容のセルの範囲に画素を持たないので描きません (カバレッジ 0 と同じ)。
- **精度とセル**: セルの内側は、外接矩形の画素数 (描画先のテクスチャの大きさで数える) を `downscale` で割って切り上げた texel 数です。
  外接矩形を画素の境界に広げているので、既定 (`downscale = 1`) では texel と画素が一致し、マスクは画面と同じ解像度で描かれます。
  セルは内側の周りに 1 texel の縁を持ちます。縁にもマスクは描かれるので、外接矩形の端でもバイリニア補間は正しい値を読みます。
- **アトラスの割り当て**: セルをチャンネルごとに棚詰め (高いセルから) で詰めます。アトラスの一辺は 2 の冪で、
  最大のセルが収まる大きさ (256 以上) から始め、レベルの数より多くのアトラスが要るなら上限まで倍にします。
  上限でも収まらなければアトラスを増やします。
- **アトラスの縮小と解放**: アトラスはフレームをまたいで使い回し、足りなくなったらそのフレームで大きくします (一辺を変えたら作り直す)。
  小さくするのは、条件が `MaskAtlasOptions::shrink_after_frames` (既定 120) フレーム **続いてから** です (ヒステリシス)。
  - 一辺: そのフレームだけで要る一辺 (前のフレームを考えずに上の手順で決めた大きさ。マスクを使わなければ 0) が
    今の一辺の半分以下のフレームが続いたら、その間に要った一辺の最大値で作り直します。0 ならすべて解放します。
  - 枚数: 今持っている枚数より少ない枚数で済むフレームが続いたら、その間に要った枚数の最大値まで解放します (溢れたアトラスやレベルの分)。
  - 半分を超える大きさが 1 フレームでも要ると数え直すので、大きさが半分と今の間で揺れても作り直しません。
    拡大と縮小を繰り返しても、持つ量は拡大時の大きさを超えません。`shrink_after_frames = 0` なら縮小しません。
  - 持っているアトラスの合計のバイト数 (RGBA8、縮小を待っている分を含む) は `FrameStats::mask_atlas_bytes` で分かります。
  一辺の上限は `MaskAtlasOptions::max_size` (既定 4096) とデバイスの `max_texture_dimension_2d` の小さい方で、
  これより大きいセルは縮小して描きます。
- **外接矩形 → セル**: 外接矩形をセルの内側に (縦横別々の倍率で) 写す `atlas_uv = offset + screen_uv * scale` を、
  マスクパスでは書き込み先 (`target_rect`)、読む側では `mask_rect` (`xy = offset`, `zw = scale`) で渡します。
  マスクパスではシザー矩形をセル全体にして、隣のセルに書き込まないようにします。
- **読み方**: `m = mask_params.x + dot(texel, mask_channel)` (`mask_channel` は符号付きの one-hot。1 から引いて読むなら
  `x = 1`、チャンネル `−1`)。`k = 1 − mask_params.y × (1 − m)` で、`mask_params.y` は `mask_strength` です。
  マスクを持たない要素は `mask_params.y = 0` (係数 1) とし、中身を読まない 1x1 のダミーを束縛します。
- 解像度を下げる設定は `RendererOptions::mask_atlas` (`MaskAtlasOptions { max_size, downscale, shrink_after_frames }`) です。
  `downscale = 2` なら縦横 1/2 の解像度で描き、アトラスが小さくなる代わりに縁がぼやけます。

## 裏面カリング

`culling = true` の要素は、キャンバス座標 (Y 下向き) で **反時計回り** に並んだ三角形を表とします。
ここでの「反時計回り」は、キャンバスを Y 下向きのまま表示したときに画面上で反時計回りに見えることを指します。
式で書くと、三角形 `(p0, p1, p2)` がキャンバス座標で

```
(p1.x - p0.x) * (p2.y - p0.y) - (p2.x - p0.x) * (p1.y - p0.y) < 0
```

を満たすとき表です (Y 下向きの座標系なので、画面上の反時計回りは符号付き面積が負になります)。

ビュー変換で Y 軸が反転するときは、レンダラが表裏の判定を補正します。参照レンダラは
`view_proj` の左上 2x2 (線形部分) の行列式で判定します。

- 行列式 < 0 (通常のビュー。キャンバスの Y 下向きをクリップ座標の Y 上向きへ反転する): クリップ座標で反時計回りを表とする (`FrontFace::Ccw`)
- 行列式 ≥ 0 (Y 軸を反転しないビュー): クリップ座標で時計回りを表とする (`FrontFace::Cw`)

どちらの場合も、表裏はキャンバス座標での向きだけで決まり、ビューには左右されません。

## ライティング

判断の経緯は [ADR 0015](../adr/0015-lighting.md)。

データ定義は [model.md#ライティング](model.md#ライティング)。法線マップの生成 (アルファの形・深度推定から) は [ai-integration.md#法線マップの生成](../ai-integration.md#法線マップの生成)。

- テクスチャに **法線マップ** を添えられます (`TextureRef::normal_map`)。法線マップはテクスチャと同じ UV 空間の接空間法線で、RGB = (x, y, z) を `n = 2c − 1` で表します
  (sRGB の変換はしない。アルファは使わない)。**x は画像の右 (+u)、y は画像の上 (−v)、z は手前向き** です
  (G が上向きの、いわゆる OpenGL 形式。G が下向きの DirectX 形式の画像は G を反転してから使う)。大きさはテクスチャと違ってもかまいません。
  読んだ値は正規化して使います (長さ 0 なら `(0, 0, 1)`)。
- 光源はホストがフレームごとに渡します (`Lighting { ambient, lights }`)。光源は平行光源 (`directional { direction, color }`) と点光源 (`point { position, color, range }`) で、
  位置と向きは **キャンバス座標 (ピクセル単位・Y 下向き) + 奥行き (z、キャンバスから手前向き・ピクセル単位)** で表します。ビュー変換 (ズーム・パン・反転) は陰影に影響しません。
  - 色 (`ambient` も) は 1 を超えてもかまいません (強さを兼ねる)。
  - `direction` は **光が進む向き** です (長さは問わない)。光源へ向かう単位ベクトル `l = −normalize(direction)`、`attenuation = 1`。例: 左上の手前から照らすなら `(1, 1, −1)`。
  - 点光源は、描く点 `p = (x, y, 0)` (`(x, y)` は画素の中心をビュー変換で戻したキャンバス上の位置) から `l = normalize(position − p)`、`attenuation = clamp(1 − |position − p| / range, 0, 1)²` です。`range = ∞` なら減衰しません。
  - 向きが 0 か有限でない平行光源、`range` が正でない (NaN を含む) か位置が有限でない点光源は使いません。使える光源が 8 個を超えるとき、レンダラはそのうち 8 個だけを使ってもかまいません (どれを使うかは決めない)。
    [互換の基準](#互換の基準) は使える光源が 8 個以下のフレームだけが対象です。参照レンダラは、使える光源のうち先頭の 8 個 (`ugoe_render::MAX_LIGHTS`) だけを使います。
  - ホストが光源を渡さないときは、環境光が白 (1, 1, 1) で光源なしとします。ライティングを受ける要素も、受けない場合と同じ色になります。
- **変形に合わせて法線を回します。** 三角形ごとに、UV 空間からキャンバス座標への写像のヤコビ行列 `J = [t b]` (`t = ∂P/∂u`、`b = ∂P/∂v`) を求め、
  法線の xy 成分を `J` の回転成分で回します。テクスチャの軸に沿った拡大縮小 (軸ごとに倍率が違ってもよい) は法線の向きを変えず、回転と反転は変えます。
  せん断は、極分解の回転の分だけ法線を回します。
  - 法線マップの y は画像の上向きなので、まず UV 空間の向き `(x, −y, z)` に直します (`J` が恒等ならキャンバス座標でも同じ向き)。
  - `det J < 0` (反転している) なら、`t` を `−t` に (u 軸を反転した写像に) 置き換え、法線の x の符号を反転します。
  - 回転成分は極分解の回転で、`(cos θ, sin θ) = normalize(t.x + b.y, t.y − b.x)` です。写像が潰れていて求まらなければ回しません。
  - z 成分は変えません。回した法線を正規化して使います。
  - 例: 左右反転 (`J = diag(−1, 1)`) では法線の x だけ、上下反転 (`J = diag(1, −1)`) では y だけが反転します。
    せん断の例: `t = (12, 0)`、`b = (4, 16)` なら `(t.x + b.y, t.y − b.x) = (28, −4)` で、法線は `atan2(−4, 28) ≈ −8.13°` 回ります。
- 陰影の式 (乗算済みアルファのまま適用する):

  ```
  light = ambient + Σ_i color_i × max(0, dot(n, l_i)) × attenuation_i
  rgb   = rgb × light
  ```

  乗算色・スクリーン色の後、不透明度とマスクの前に適用します。`light` が 1 を超えると rgb がアルファを超えることがあります (描画先に書くときに `[0, 1]` に丸める)。
- ライティングの有無は、モデル全体 (`Model::lighting`) とメッシュごと (`Mesh::lit`) に選べ、両方が `true` のメッシュだけがライティングを受けます。
  法線マップのないテクスチャ (参照レンダラでは、法線マップが登録されていないテクスチャ) を使うメッシュは、法線を `(0, 0, 1)` として扱います。
  ライティングを受けないメッシュの出力は、ライティングを実装する前と画素単位で同じです。
- 任意機能 `lighting.normal_map` ([ADR 0013](../adr/0013-forward-compatibility.md)) です。知らないランタイムはライティングなしで描きます。

### 参照レンダラでのライティング

- ホストは `Renderer::set_lighting(&Lighting)` で光源を、`Renderer::set_normal_map(device, queue, texture, width, height, rgba)` で
  テクスチャの番号ごとに法線マップ (RGBA8) を渡します (`remove_normal_map` で外す)。バンドルの法線マップは `ugoe_format::Bundle::normal_map(texture)` で引けます。
- ヤコビ行列はフラグメントシェーダで、キャンバス座標と UV の画面での微分 (`dpdx` / `dpdy`) から求めます。
  頂点の属性は三角形の中で線形なので、微分は三角形の中で一定で、三角形ごとに求めるのと同じです。WebGL2 (GLSL ES 3.0) でも使えます。
- 法線マップはテクスチャと同じバインドグループ (テクスチャ・サンプラ・法線マップ) に束縛します。法線マップはテクスチャと同じ描画の状態に含まれ、
  状態の数は増えません。法線マップのないテクスチャには 1x1 のダミーを束縛します。
- ライティングの種類 (受けない・法線 `(0, 0, 1)`・法線マップを読む) は要素ごとの値 (マスクの読み方の texel の空き) で渡すので、
  ライティングを受ける要素と受けない要素もまとめて描けます。受けない要素ではシェーダは陰影を掛けません。
- 光源は 1 つのユニフォームバッファ (最大 8 個分) に置き、ライティングを受ける要素を描くフレームで、前に転送した内容と違うときだけ転送します。

### ホストでのライティング

参照レンダラを使うホストは、バンドルを読んだら法線マップを登録し、光源はホストの状態として渡します。

- `ugoe` (SDK) の `ugoe::lighting` に、テクスチャの番号ごとの法線マップ (`bundle_normal_maps`) と、ライティングを受けるメッシュがあるか
  (`uses_lighting`・`Puppet::uses_lighting`。光源の操作を出すかの判断に使う) があります。`Puppet` はレンダラを持たないので、登録はホストが行います。
- 法線マップの PNG は **アルファを掛けずに** デコードします (テクスチャと違って乗算済みにしない。アルファは使わない)。
  KTX2 の法線マップも、値を保存されたまま使います (sRGB からリニアへ変換しない。[前提](#前提))。
  KTX2 をデコードできないホストは、警告を出してその法線マップを使いません (法線 `(0, 0, 1)`)。
- `ugoe render` (`ugoe-headless`): `--ambient <COLOR>` と `--light directional:DX,DY,DZ[:COLOR]` / `--light point:X,Y,Z[:COLOR[:RANGE]]`
  で光源を渡します。どちらも無ければ光源を渡さないので、出力は法線マップが無いのと 1 画素も変わりません
  (書式は [crates/ugoe-cli/README.md](../../crates/ugoe-cli/README.md#ugoe-render))。MCP サーバの `render_png` は光源を渡しません。
- `ugoe-wasm` (`WebPuppet`): `load_bundle` が法線マップを登録し (前のモデルの法線マップは外す)、`set_lighting_json` で光源を渡します
  (JSON の形は [crates/ugoe-wasm/README.md](../../crates/ugoe-wasm/README.md))。光源はモデルを読み直しても保ちます。
- ビューア (`apps/viewer`): `uses_lighting` が真のモデルのときだけ光源のパネルを出し、環境光・平行光源・点光源を操作できます
  (点光源の位置と範囲はキャンバスの大きさに対する割合で持つ。[apps/viewer/README.md](../../apps/viewer/README.md#ライティング-t0705))。
  光源の印をビューポートに重ね、平行光源の向きと点光源の位置をドラッグで変えられる (印の位置はビュー変換 `view_transform` で合わせる)。

## 互換の基準

公開仕様 ([spec/rendering.md#conformance](../../spec/rendering.md#conformance)) と同じです。同じ評価結果・テクスチャ・ビュー・光源・描画先の大きさで、
描画先 (乗算済み、1 チャンネル 8 ビット、透明な黒でクリア) の **99% 以上の画素** で、すべてのチャンネルの差が **3/255 以下** なら互換です。
残りの画素は、三角形の縁のラスタライズとテクスチャのフィルタの違いの分です。解像度を下げたマスク (`downscale`) の結果は対象外です。

- 基準の出力は実数で計算し、`[0, 1]` に丸めるのは描画先に書くとき (描画ごと) だけです。許容誤差には、8 ビットのテクスチャ・途中の結果・描画先の丸めが含まれます。
- 使える光源が 8 個以下のフレームが対象です ([ライティング](#ライティング))。
- 公開仕様の [描画の例](../../spec/examples/README.md#rendering-examples) は、三角形の辺から離れた (ラスタライズの細部によらない) 画素を選んで期待値を持ちます。
  調べる画素はすべて許容誤差に収まる必要があります。参照レンダラは `crates/ugoe-render/tests/spec_render.rs` (`just test-gpu`) で、
  8 ビット unorm の描画先に描いてこれを確かめます (unorm は描画ごとの `[0, 1]` の丸めに当たり、アルファ 0 の色やアルファを超える色も保つ)。

## 描画の最適化

判断の経緯は [ADR 0016](../adr/0016-draw-batching.md)。

テクスチャのアトラス化 (描画順で隣り合う要素が同じテクスチャを使うようにする) はビルド時に行います ([file-formats.md#テクスチャのアトラス化](file-formats.md#テクスチャのアトラス化))。
マスクアトラスの使い回しと転送の省略は下の「転送の省略」を参照。

- **描画順は決して入れ替えません。** 最適化は見た目を変えない範囲で行います。
- 描画順で隣り合う要素のうち、次の **描画の状態** が同じものを 1 回の描画にまとめます。
  - テクスチャ (と法線マップ)
  - 合成モード
  - カリング (の有無と、表とする向き)
  - 読むマスクアトラス (1 枚のテクスチャ)。アトラスの中のセル・チャンネル・読み方は要素ごとの値なので、違ってもまとめられます。
    マスクを読まない要素は、どのアトラスを読む要素ともまとめられます (`mask_strength` が 0 と同じで、アトラスの値が結果に効かないため)。
- 要素ごとの値 (不透明度・乗算色・スクリーン色・マスクの読み方と `mask_strength`・ライティングの種類) は頂点属性またはインスタンスのデータで渡し、状態の違いにしません。
- 1 回の描画の中の三角形は、インデックスの順に合成されます (GPU は同じ描画の中でもプリミティブの順に合成する)。
  まとめた描画のインデックスを描画順に並べれば、要素ごとに描いた場合と同じ順に合成されます。
- 独自レンダラも同じ条件でまとめてかまいません。この条件の範囲なら、結果は要素ごとに描いた場合と一致します。
- `FrameStats` に次を出します。

  | フィールド | 意味 |
  | --- | --- |
  | `draw_calls` | 本描画の描画コマンドの数 (まとめた後) |
  | `state_changes` | 本描画で描画の状態を前の描画から切り替えた回数。最初の描画は数えない |
  | `position_bytes` / `uniform_bytes` / `index_bytes` | 転送した頂点位置・ユニフォーム (要素ごとの値・ビュー・光源を含む)・本描画のインデックスのバイト数 |
  | `uploaded_bytes` | 転送したバイト数の合計 |

- 比較や調査のために、`RendererOptions::batch_draws = false` でまとめずに要素ごとに描けます (既定は `true`)。
  `state_changes` はまとめるかどうかに関係なく同じ値になります。

### 参照レンダラでのまとめ方

WebGL2 は `base_vertex` とストレージバッファを使えないので、次のようにします。

- 頂点ごとに要素の番号 (`u32`) を持つ静的な頂点バッファを作ります。全要素の位置・UV もそれぞれ 1 本のバッファで、描画のたびに束縛し直しません。
- 要素ごとの値は `Rgba32Float` のテクスチャ (要素 1 つ = 横に 5 texel、1 行に最大 64 要素) に置き、頂点シェーダが要素の番号で `textureLoad` して
  flat な補間で渡します。値は「転送の省略」と同じく、控えと比べて違う要素だけ転送します。
- 本描画のインデックスバッファ (`u32`、全体の頂点番号) には、描く要素のインデックスを描画順に並べます。並びが変わるのは描画順か表示が変わったときだけなので、
  控えと比べて違う範囲だけ転送します。まとめた描画は、このバッファの連続した範囲を 1 回の `draw_indexed` で描きます。
- 状態が変わらないものは束縛し直しません (パイプライン・テクスチャ・マスクアトラスをそれぞれ比べる)。

## ビュー変換

`ugoe_render::View::view_proj` はキャンバス座標からクリップ座標への 3x3 行列 (列優先) です。どこを表示するか (フィット・ズーム・パン) はホストが決めます。

ビュー変換はアフィン変換で、ホストが決めます。逆変換の無いビュー変換 (線形部分の行列式が 0) は、どの三角形も線か点に写すので、
画素の中心を覆う三角形が無く、何も描きません。そのため点光源に使う「画素の中心をビュー変換で戻した位置」は要りません
([spec/rendering.md#inputs](../../spec/rendering.md#inputs)。T0414 で決めた)。参照レンダラも同じで (面積 0 の三角形はラスタライズされない)、
`ugoe render --view` はそのようなビューも受け付けて、背景だけの画像を書きます。

## GPU リソースの方針

- 頂点バッファには要素ごとの `positions` を、変わったときだけ書き込みます (下の「転送の省略」)。UV・要素の番号・宣言順のインデックスは静的なので、ロード時に一度だけ書き込みます。
  - 全要素の位置・UV・要素の番号・インデックスは、それぞれ 1 本のバッファにまとめます。インデックスは `u32` で全体の頂点番号を指すので、
    `base_vertex` (WebGL2 では使えない) もバッファのスライスも要りません。本描画は描画順に並べ直したインデックスを使います (上の「参照レンダラでのまとめ方」)。
- 本描画の要素ごとの値は、ユニフォームではなく要素ごとの値のテクスチャで渡します (上の「参照レンダラでのまとめ方」)。
- マスクパスでマスク用メッシュを描く分の値は、動的オフセット付きの 1 つのユニフォームバッファにまとめます (内容ごとに並べる)。間隔は `min_uniform_buffer_offset_alignment` に揃えます。
- 本描画のパイプラインは `合成モード × カリングの有無` の組み合わせで作り、キャッシュします。カリングありのパイプラインは、表とする向き (上の「裏面カリング」) ごとに別に作ります。
  マスクの有無と読み方は要素ごとの値で切り替えるので、パイプラインは分けません (組み合わせを増やさず、描画順どおりに切り替えるため)。
  マスクパス用のパイプラインは固定の 5 つです (マスク用メッシュの乗算合成・作業領域を埋める全面描画・作業領域をチャンネル R/G/B に掛ける全面描画。どれもカリングなし)。
- テクスチャは `Rgba8Unorm` (sRGB 形式ではない) で作ります。値をリニア化せずに合成するためです。サンプラはバイリニア・端でクランプです。
- テクスチャと法線マップの登録 (`set_texture` / `set_normal_map`) は、受け付けない入力をエラー (`RenderError`) で返し、何も変えません。
  幅か高さがデバイスの `max_texture_dimension_2d` を超える (`TextureTooLarge` / `NormalMapTooLarge`。wgpu の検証エラーは既定でパニックするので、
  wgpu に渡す前に確かめる)、番号が `MAX_TEXTURES` (65536) 以上 (`TextureIndexOutOfRange`。番号で表を伸ばすので、極端な番号でメモリを使い切らないため)、
  データの長さが `幅 × 高さ × 4` でない (`InvalidTextureData`) の 3 つです。いくつものテクスチャを何も変えずに先に確かめたいホストは、
  `check_texture` / `check_normal_map` で同じ検査 (データの長さを除く) を行えます。
- 描画先はクリアせずに上に重ねます (`LoadOp::Load`)。クリアや背景の描画はホストが行います。
- 1 つの `Renderer` の `encode` は、1 回の `Queue::submit` につき 1 回だけ呼びます (バッファを `Queue::write_buffer` で書き換えるため)。
- 非表示 (`visible = false`) の要素は描きません。描く要素 (と、そのマスク用メッシュ) のテクスチャが登録されていなければエラーを返し、コマンドを積みません。

### 転送の省略

変わっていないデータは GPU に転送しません。ランタイムの変更フラグ ([evaluation.md#変更フラグ](evaluation.md#変更フラグ)) は
「そのインスタンスの直前の `update()` から」の変化なので、そのままでは使えません。1 つの `Renderer` が同じモデルの
複数のインスタンスを交互に描くことも、`encode` の間に `update()` が何度も呼ばれることもあるからです。そこで参照レンダラは次のようにします。

- バッファに転送済みの内容 (頂点位置・要素ごとの値・マスクパスのユニフォーム・ビュー・本描画のインデックス) を CPU 側に控えておきます。控えはバッファと常に同じ内容です。
- 頂点位置は、控えを最後に書いたときのインスタンスの `(ModelInstance::id(), update_count())` を覚えておき、要素ごとに転送するかを次のように決めます。
  隣り合う要素の転送は 1 回の書き込みにまとめます。

  | 描くインスタンス | 決め方 |
  | --- | --- |
  | 初めて (バッファを作った直後) | すべて転送する |
  | 同じインスタンスで `update_count` も同じ | 出力は `update()` でしか変わらないので、何も転送しない |
  | 同じインスタンスで `update_count` がちょうど 1 つ後 | 変更フラグの `POSITIONS` を信じる |
  | それ以外 (別のインスタンス、または `update()` を 2 回以上挟んだ) | 控えとビット列で比べ、違う要素だけ転送する |

  別のモデルのインスタンスを描くとバッファを作り直すので、控えも捨ててすべて転送します。`mark_all_changed()` の後の `update()` はすべてが変更ありと報告するので、すべて転送します。
- 要素ごとの値とユニフォームはマスクの割り当てやビューにも依存するので、変更フラグは使わず、毎フレーム作った値を控えとスロット (要素 1 つ分) ごとに比べ、違うスロットだけ転送します。ビューのユニフォームも同様です。
- **マスクアトラスの使い回し:** 次がすべて前回描いたときと同じなら、マスクパスを省いてアトラスの内容をそのまま使います。
  - アトラス (作り直していない)、一辺、内容ごとの割り当て (アトラス・チャンネル・セル・画面からの変換)
  - ビュー、登録したテクスチャ (`set_texture` を呼んだら描き直す)
  - このフレームでマスクパスのユニフォームを転送していない (マスク用メッシュの係数・`mask_strength`・入れ子のマスクの読み方を含む)
  - このフレームで、使う内容のマスク用メッシュの頂点位置を転送していない

  マスクを読む要素の外接矩形の変化は、割り当ての変換の違いとして現れます。
- `FrameStats` の `position_bytes` / `uniform_bytes` / `index_bytes` (合計は `uploaded_bytes`) に転送したバイト数を、`masks_reused` にマスクパスを省いたかを出します。
