# 評価仕様 (キーフォーム補間とデフォーマ変形)

対応するコードは `crates/ugoe-runtime`。この文書は、パラメータ値から描画可能要素の状態を計算する方法を定義します。

## 用語と前提

- 計算はすべて `f32` で行います。
- 評価は **決定的** です。同じモデルと同じパラメータ値からは、同じプラットフォーム上で常にビット単位で同じ結果が出ます。そのため加算の順序も仕様の一部です。
- `lerp(a, b, t) = a + (b - a) * t`

## 1. キーフォームの重み

`KeyformGrid` は N 本の軸 (`bindings`) を持ちます。軸 `k` はパラメータ `p_k` と、昇順のキー列 `K_k = [k_0, ..., k_{n_k - 1}]` を持ちます。

### 1 軸の位置

パラメータ値 `v` について:

1. `v <= k_0` なら `(seg, t) = (0, 0)`
2. `v >= k_{n-1}` なら `(seg, t) = (n-1, 0)`
3. それ以外は `k_seg <= v < k_{seg+1}` を満たす `seg` を選び、`t = (v - k_seg) / (k_{seg+1} - k_seg)`

キーが 1 つだけの軸は常に `(0, 0)` です。**キーの範囲の外側へは外挿しません** (値を端のキーにクランプします)。

### 多重線形の重み

格子座標 `(i_0, ..., i_{N-1})` の線形インデックスは `i_0 + n_0 * (i_1 + n_1 * (i_2 + ...))` です。軸 0 が最も速く変化します。

重みは次の手順で作ります (`keyform::weights` の実装と同じ順序)。

```
W = [(index 0, weight 1)]
stride = 1
for 軸 k in 0..N:
    (seg, t) = 軸 k の位置
    W の各要素 (i, w) を (i + seg*stride, w*(1-t)) に置き換える
    t > 0 なら、元の各要素について (i + (seg+1)*stride, w*t) を W の末尾に追加する
    stride *= n_k
重みが 0 の要素を W から取り除く
```

補間後の値 = `Σ w_i * keyform[i]`。和は W の順序で取ります。頂点位置・不透明度・描画順・色など、キーフォームのすべての数値フィールドを同じ重みで補間します。真偽値のフィールド (`reflect_x` など) は、重みが最大の要素の値を使います (重みが同じなら小さいインデックスを優先します)。

## 2. 評価の順序

1. すべてのパーツ・デフォーマ・メッシュについて、キーフォームの重みを計算し、局所的な値を補間する。
2. パーツの不透明度を根から葉へ伝播する: `part_opacity = own * parent_part_opacity`
   - `own` は、ホストが上書き `(value, weight)` を与えていれば (`ModelInstance::set_part_opacity_override`)、補間した値 `o` の代わりに `lerp(o, value, weight)` を使う。既定は重み 0 (上書きしない)。モーションのパーツの不透明度のカーブとポーズが使う ([motion.md](motion.md#パーツの不透明度))
3. デフォーマを **トポロジカル順 (親が先)** に評価し (親が先という条件のほかは `deformers` の配列順。結果はこの順序に依存しません)、それぞれの **ワールド変換** (局所座標 → キャンバス座標の写像) を作る。
4. メッシュの局所頂点を、親デフォーマのワールド変換でキャンバス座標に写す。
5. グルーを適用する。
6. 最終的な不透明度・可視性・描画順を決める。

### 動的物理を使う場合 (2 段階の評価)

判断の経緯は [ADR 0011](../adr/0011-dynamic-physics.md)。

動的物理 ([physics.md#動的物理](physics.md#動的物理-揺れ用パラメータのいらない物理)) を使う設定では、1 フレームを次の順に評価します。

1. **1 段目** (`ModelInstance::update_first_stage`): その時点のパラメータ値でデフォーマを手順 3 のとおりに評価し、ワールド変換を作る。動的物理の加算量は加えない。パラメータ値を控えておく。出力 (`drawables` など) と `update_count` は変えない。
2. **物理** (`PhysicsSystem::update_instance`): 1 段目のワールド変換 (`deformer_world` など) から、根元の位置・衝突体・重力の基準・角度の基準を求めて物理を進める。パラメータへの出力をパラメータに書き込み、それ以外の出力を加算量 (`ModelInstance::dynamic_offsets_mut`) に書き込む。
3. (ホストが、ポーズ・リップシンクなどでさらにパラメータを書き換えてもよい。)
4. **2 段目** (1 段目の後の `ModelInstance::update`): 次のデフォーマだけを、トポロジカル順に評価し直す。
   - 加算量を受けるデフォーマ (加算量を一度でも書き込んだもの)
   - 束縛するパラメータの値が 1 段目の控えとビット列で異なるデフォーマ
   - 評価し直したデフォーマの子孫

   その後、手順 1 (パーツ)・4〜6 と変更フラグの計算を行う。`update_count` は 1 増える (2 段で 1 回と数える)。

加算量は次のように加えます (値の求め方は physics.md)。

| 加算量 | 加え方 |
| --- | --- |
| 回転デフォーマの角度 | キーフォームで補間した角度 (局所座標系) に足してから、ワールド変換を作る |
| 回転デフォーマの原点 | 作ったワールド変換の平行移動 (原点のキャンバス座標) に足す |
| ワープの制御点 | 親のワールド変換で写した制御点 (キャンバス座標) に足す |
| メッシュの頂点 | 親のワールド変換で写した頂点 (キャンバス座標) に、グルーの前に足す |

- 2 段目で評価し直さなかったデフォーマは、1 段目の結果をそのまま使う。入力 (パラメータ値と加算量) が同じなので、すべてを評価し直した場合とビット単位で同じ結果になる。
- 1 段目を呼ばずに `update` を呼ぶと、すべてを評価し、加算量があれば加える (加算量は `DynamicOffsets::clear` するまで残る)。
- パラメータへの物理の出力は、1 段目の **後** に書き込みます (物理を進めるのに 1 段目の結果が要るため)。そのパラメータを束縛するデフォーマは 2 段目で評価し直すので、結果は 1 段目の前に書き込んだ場合と同じです。メッシュ・パーツ・グルーはもともと 2 段目で評価します。
- **動的物理を使わない設定のコストは変わりません。** `update_instance` は 1 段目を行わず、`ModelInstance` は加算量や 2 段階の評価の状態を持ちません (`dynamic_offsets()` が `None`)。評価の経路で増えるのは、要素ごとの `Option` の確認だけです。T0305 で、`rotation_chain`・`rotation_under_warp`・`warp_grid`・`glued_quads` の `update()` の時間を変更の前後で測り、差が測定の揺れ (±10%) の範囲に収まることを確かめました。
- 動的物理を使う場合の追加の費用は、1 段目のデフォーマの評価と、2 段目で評価し直すデフォーマの分です (`dynamic_hair` で 1 フレーム 210 ns → 270 ns 程度)。

## 3. デフォーマのワールド変換

デフォーマ `D` のワールド変換を `F_D: 局所座標 → キャンバス座標` と書きます。親を持たない要素の親変換は恒等写像 `F_root(p) = p` とします。

### ワープデフォーマ

- 補間後の制御点 `P_local[x, y]` (0 <= x <= cols, 0 <= y <= rows、行優先で x が速い) は親の局所座標で表されています。
- ワールド空間の制御点は `P[x, y] = F_parent(P_local[x, y])` です。
- `rows >= 1` かつ `cols >= 1` であること (0 のワープはコンパイル時に `CompileError::Unsupported` で拒否します)。
- 局所座標 `(u, v)` が [0,1]² の内側にあるときの写像 (セル単位の双線形):

```
gx = u * cols,  gy = v * rows
i = clamp(floor(gx), 0, cols - 1),  j = clamp(floor(gy), 0, rows - 1)
fx = gx - i,  fy = gy - j
B(u, v) = lerp( lerp(P[i, j],   P[i+1, j],   fx),
                lerp(P[i, j+1], P[i+1, j+1], fx), fy )
```

#### 範囲外の外挿

`(u, v)` が [0,1]² の外にあるときは、**境界へクランプした点の双線形の値に、格子の四隅から作ったアフィン近似の軸で、はみ出した分を足します**。

```
C00 = P[0, 0], C10 = P[cols, 0], C01 = P[0, rows], C11 = P[cols, rows]
A_u = ((C10 - C00) + (C11 - C01)) * 0.5      // u 方向の軸 (四隅の平均)
A_v = ((C01 - C00) + (C11 - C10)) * 0.5      // v 方向の軸
c   = (clamp(u, 0, 1), clamp(v, 0, 1))
d   = (u, v) - c
F(u, v) = B(c) + A_u * d.x + A_v * d.y      // 内側では d = 0 なので F = B
```

T0104 で、端のセルの双線形式をそのまま延長する方式 (線形外挿) と比べて決めました (`crates/ugoe-runtime/src/deform.rs` のテスト)。

| 観点 | 端のセルの延長 | 採用した方式 |
| --- | --- | --- |
| 格子がアフィン (回転・せん断・拡縮だけ) | 正確なアフィン写像 | 同じ (正確なアフィン写像) |
| 境界での連続性 | 連続 | 連続 (境界では `d = 0`) |
| 台形の格子 | `fx * fy` の項で 2 次的に歪み、先細りの側では幅が負になって像が裏返る | はみ出し量に比例して動くだけで、裏返らない |
| 端のセルだけが局所的に潰れている | その潰れを格子の外で増幅する (格子 1 枚分外へ出ても数 px しか進まない) | 格子全体の大きさで進む |

格子の外に出た頂点 (髪の先や、変形で格子からはみ出したパーツ) が崩れないこと、つまり Cubism と同じように「格子全体の動きにおおむね追従する」見た目を優先しました。
採用した方式は境界で折れ曲がる (微分が不連続になる) ことがありますが、表示上は目立ちません。

### 回転デフォーマ

補間後のキーフォームは `origin`, `angle` (度、時計回りが正), `scale`, `reflect_x`, `reflect_y` です。
局所変換は次のとおりです。

```
L(p) = origin + R(angle) * S * p
R(θ) = [[cos θ, -sin θ], [sin θ, cos θ]]      // Y 下向きの座標系では時計回り
S    = diag(scale * (reflect_x ? -1 : 1), scale * (reflect_y ? -1 : 1))
```

ワールド変換は親の種類で決まります。

- **親なし**: `F = L`
- **親が回転デフォーマ**: `F = F_parent ∘ L` (アフィン変換の合成)。祖先にワープがあっても、ワープの直下の回転デフォーマで一度アフィンになるので、その子孫はすべてアフィンです。
- **親がワープデフォーマ**: 子の座標はワープを通さず、**原点と向きだけ** をワープで変換します。
  ```
  o      = F_parent(origin)                       // origin は親の UV 空間での位置
  up     = F_parent(origin + (0, -ε)) - o          // ε = 0.01
  δ      = atan2(up.x, -up.y) (度に直す)            // R(δ) * (0, -1) が up の向き。時計回りが正
  F(p)   = o + R(angle + δ) * S * p
  ```
  `up` が長さ 0 (格子が潰れている) のときは `atan2(0, 0) = 0` なので δ = 0 です。ε は親の UV 空間での幅で、`origin` が格子の上端付近にあるときは範囲外の外挿を使います。
  回転デフォーマの子はピクセル単位で表されているため、ワープの伸縮は子に伝わりません。これは Cubism と同じ振る舞いです。

### デフォーマの不透明度

`deformer_opacity = own * parent_deformer_opacity` (親がなければ 1)。

## 4. メッシュ

```
world_position[i] = F_parent(local_position[i])
opacity           = mesh_opacity * part_opacity(mesh.part) * deformer_opacity(mesh.parent)
visible           = !mask_only && opacity > 0
mask_strength     = clamp(補間した mask_strength, 0, 1)
```

乗算色とスクリーン色は補間した値をそのまま使います。パーツやデフォーマの色は継承しません。

> 未決: Cubism 5 にはパーツ単位の乗算色・スクリーン色の上書きがある。これをランタイム API (`ModelInstance` の上書き値) として提供するか、データとして持つか。

## 5. グルー

メッシュ A の頂点 `a` と、メッシュ B の頂点 `b` のペアごとに、ワールド座標で次の計算をします。

```
target = lerp(pa, pb, weight)
pa'    = lerp(pa, target, intensity)
pb'    = lerp(pb, target, intensity)
```

グルーは `glues` 配列の順に適用し、1 つのグルーの中では `pairs` の順に適用します。1 つの頂点に複数のグルー (またはペア) がかかる場合、後から適用したものが前の結果を入力にします。`intensity` はグルーのキーフォームを補間した値です。

## 6. ブレンドシェイプ

要素の格子の `blend_shapes` にある格子 (軸は `kind = blend_shape` のパラメータ) を、ブレンドシェイプ格子と呼びます ([model.md#ブレンドシェイプ](model.md#ブレンドシェイプ))。

```
delta  = interp(bs_grid, 現在値) - interp(bs_grid, 各パラメータの default)
result = interp(通常の格子) + Σ_{ブレンドシェイプ格子} delta
```

- `interp` は 1. の重みによる補間です。既定値での重みはロード時に求めておきます。
- 加算は格子の宣言順に 1 つずつ行います: `((interp(通常の格子) + delta_0) + delta_1) + ...`。フィールドごとに独立に加えます。
- 現在の重みが既定値での重みと (添字と値のビット列が) 同じ格子は、差分が 0 なので加算しません。したがって、ブレンドシェイプのパラメータがすべて既定値なら、結果はブレンドシェイプ格子がないときとビット単位で同じです。
- 頂点位置と制御点は頂点ごとに `delta` を求めて加えます (重みの順序で和を取る)。
- 加算は親座標系 (局所座標) で行い、その後に親デフォーマのワールド変換で写します (2. の手順 1 の一部)。
- 加えるフィールド: メッシュの頂点位置・不透明度・描画順・乗算色・スクリーン色・`mask_strength` (クランプは加算の後)、ワープの制御点・不透明度、回転の原点・角度・拡大率・不透明度。真偽値 (`reflect_x` / `reflect_y`) は通常の格子の値を使います。

## 7. 描画順

- `render_order` は、描画可能要素を `draw_order` の昇順 (奥から手前) に並べたインデックス列です。
- `draw_order` が同じ場合は `meshes` 配列での順序を保ちます (安定ソート)。`draw_order` は `f32::total_cmp` で比べます。
- 描画順は可視性と関係なく、すべての要素について計算します。

## 8. 出力

`ModelInstance` の出力 (`DrawableState`) は次のとおりです。

| フィールド | 説明 |
| --- | --- |
| `positions` | キャンバス座標の頂点位置 |
| `opacity` | 最終的な不透明度 |
| `draw_order` | 補間後の描画順 |
| `multiply_color` / `screen_color` | 補間後の色 |
| `blend` | 合成モード (静的) |
| `mask_strength` | マスクの効き具合 (0〜1、[rendering.md#マスク](rendering.md#マスク)) |
| `visible` | 色として描画するかどうか (マスクとしての効き具合には影響しない) |

UV とインデックスは静的なデータなので `CompiledModel` から取得します。
マスクの参照も静的なデータで、`CompiledModel` がインデックスに解決して提供します。

- `mask_refs(i)`: メッシュ `i` のマスクの参照 (マスク用メッシュのインデックスと反転の有無)。並びは `masks` と同じ
- `mask_mode(i)`: メッシュ `i` の通常マスクの結合方法
- `mask_depth(i)`: マスクの依存の深さ。マスクを持たなければ 0、持てば 1 + (マスク用メッシュの深さの最大値)
- `mask_order()`: マスクとして参照されるメッシュを、深さの昇順 (同じ深さは宣言順) に並べたもの。各メッシュのマスクはそのメッシュより前に現れるので、この順に評価すれば入れ子のマスクを継承できる

### 変更フラグ

エンジン統合での転送量を減らすため、`update()` は前回の `update()` からどの出力が変わったかをフラグで報告します。

- `changes()`: 描画可能要素ごとの `DrawableChanges` (`drawables()` と同じ並び)。次のビットの集合です。

  | ビット | 対象 |
  | --- | --- |
  | `POSITIONS` | `positions` (どれか 1 頂点でも変われば立つ) |
  | `OPACITY` | `opacity` |
  | `DRAW_ORDER` | その要素自身の `draw_order` |
  | `VISIBILITY` | `visible` |
  | `MULTIPLY_COLOR` / `SCREEN_COLOR` | `multiply_color` / `screen_color` |
  | `MASK_STRENGTH` | `mask_strength` (クランプ後の値) |

  `blend` は静的なのでフラグを持ちません。
- `render_order_changed()`: `render_order` の並びが変わったか (モデル全体で 1 つ)。`DRAW_ORDER` が立っても並びが変わらないことはあります。

規則:

- 比較は **値のビット列の一致** で行います (許容誤差なし)。決定的で、補間やクランプの結果が前回と同じなら変更なしです。`-0.0` と `0.0` は異なる値として扱います (変更ありの側に倒れるだけで、転送の省略として安全)。NaN は同じビット列が続けば変更なしです。
- 比較の相手は直前の `update()` の出力です。`update()` を呼ばずにパラメータを書き換えてもフラグは変わりません。
- **最初の報告ではすべてが変更あり** です。`ModelInstance::new` の直後と、その後にホストが最初に呼ぶ `update()` の両方で、すべての要素が `ALL`、`render_order_changed()` が `true` になります (new の直後に `update()` してから読むホストでも最初の転送を取りこぼさないため)。
- `mark_all_changed()` を呼ぶと、次の `update()` で比較をせずにすべてを変更ありとして報告します (描画側の資源を作り直したときに使う)。
- 描画側が「どのインスタンスのどの `update()` の出力を転送済みか」を覚えられるように、`ModelInstance::id()` (プロセス内で一意な番号) と `update_count()` (`update()` を呼んだ回数。`new` の中の 1 回を含む) を提供します。出力は `update()` でしか変わらないので、`update_count()` が同じなら出力も同じです。フラグは、描画側が前回見た `update_count()` のちょうど 1 つ後のときだけ、そのとき見た出力からの変化を表します ([rendering.md#転送の省略](rendering.md#転送の省略))。
- 実装は前回の出力を控えておき、`update()` の最後に比べます。控えのバッファは `new` で確保し、頂点位置は変わったときだけコピーするので、毎フレームのヒープ確保はなく、止まっているメッシュの費用は頂点数に比例する比較 1 回です。

### デフォーマのワールド変換を読む

エディタのギズモや座標変換のために、`ModelInstance` は直前の `update()` で評価したデフォーマのワールド変換 (3.) を公開します。
どれも評価済みの状態を借りて読むだけで、`update()` の費用やメモリ確保は増えません。添字は `Model::deformers` / `Model::meshes` のもので、ID からは `CompiledModel::deformer_index(id)` / `mesh_index(id)` で引きます。

| API | 内容 |
| --- | --- |
| `deformer_world(d)` | デフォーマ `d` のワールド変換 `F_d` (子の座標系 → キャンバス座標)。未知の種類は恒等変換なので親の `F` と同じ |
| `deformer_parent_world(d)` / `mesh_parent_world(m)` | 要素の親の座標系 (キーフォームの原点・制御点・頂点の座標系) → キャンバス座標。親がなければ恒等写像 |
| `deformer_world_point(d, p)` / `deformer_world_jacobian(d, p)` | `deformer_world(d)` の `point(p)` / `jacobian(p)` の略記 |
| `warp_world_points(d)` | ワープのキャンバス座標の制御点 `P[x, y]` (行優先、x が速い)。ワープでなければ `None` |
| `rotation_world_frame(d)` | 回転デフォーマのワールド変換 (アフィン)。`translation` が原点、`matrix2` の列が局所座標の x 軸・y 軸の単位ベクトルの像。回転デフォーマでなければ `None` |
| `mesh_local_positions(m)` | メッシュのキーフォームを今のパラメータ値で補間した頂点位置 (ブレンドシェイプの差分を含む。親のワールド変換とグルーの前)。問い合わせ用で、呼ぶたびに `Vec` を確保する |
| `rotation_local_keyform(d)` | 回転デフォーマのキーフォームを今のパラメータ値で補間した値 (原点・角度など。ブレンドシェイプの差分を含み、動的物理の加算量は含まない)。回転デフォーマでなければ `None`。問い合わせ用で、呼ぶたびに補間し直す |

写像 (`WorldTransform`) は次を持ちます。

- `point(p)`: `update()` がメッシュの頂点に使うのと同じ式・同じ演算順で写す。したがって、グルーで動かされないメッシュでは `mesh_parent_world(m).point(mesh_local_positions(m)[i])` が `drawables()[m].positions[i]` とビット単位で一致する。
- `jacobian(p)`: 点 `p` でのヤコビ行列 (列は局所座標の x・y 方向の微分) を解析的に求める。祖先の変換はワールド座標の制御点・アフィン変換に畳み込み済みなので、連鎖も含む。
  - 恒等写像は単位行列、回転デフォーマは線形部分 `R * S` (親がワープのときは向きを補正した後のもの)。
  - ワープは、内側ではセルの双線形式の微分 `∂B/∂u = cols * lerp(P[i+1, j] - P[i, j], P[i+1, j+1] - P[i, j+1], fy)`、`∂B/∂v = rows * lerp(P[i, j+1] - P[i, j], P[i+1, j+1] - P[i+1, j], fx)`。セルの境目では写像と同じく `floor` で選んだセル (右端・下端では端のセル) の片側の微分になる。
  - ワープの範囲外では、はみ出した方向の列が `A_u` / `A_v`、はみ出していない方向の列はクランプした点での双線形式の微分になる (外挿の規則の微分)。
- `is_identity()`: 恒等写像か。
- `rotation_child(keyform)`: この写像を親に持つ回転デフォーマのワールド変換 (補間後のキーフォームから。親がワープなら原点と向きだけを写す)。

まだモデルにないデフォーマの写像 (エディタがデフォーマを作る前に子の座標を写し直すときなど) は、`WorldTransform::IDENTITY`、`from_affine(affine)`、`from_warp_points(points, cols, rows)` (キャンバス座標の制御点から) で作れます。作った写像も `update()` と同じ式で写します。

逆写像 (キャンバス座標 → 局所座標。ワープの UV を求めるニュートン法など) はランタイムには置かず、エディタ (`ugoe-editor-core` の `space`) がこの `point` と `jacobian` を使って解きます。

## 9. 当たり判定

`Model::hit_areas` の各当たり判定は、参照するメッシュの **変形後の形** (直前の `update()` の `positions`) で判定します。タップ・クリックなどの判定用で、座標はキャンバス座標です。

- 点がメッシュのいずれかの三角形 (`indices`) の内側にあれば当たりです。辺と頂点の上も含み、三角形の向き (時計回りか) は問いません。範囲外の頂点を指す三角形は無視します。
- テクスチャの透明部分は考えません (外接矩形ではなく三角形で判定する)。
- **可視性と不透明度は見ません。** 不透明度 0 のメッシュ、`visible` が `false` のメッシュ (マスク専用やパーツごと非表示) でも当たります。判定専用の透明なメッシュを置けるようにするためです。非表示のものを除きたいホストは、`drawables()[mesh].visible` を自分で確かめます。
- 点を含む当たり判定を列挙するときは **手前から奥へ** 並べます。順序はメッシュの描画順 (`render_order` の逆) で、同じメッシュを参照する当たり判定どうしは `hit_areas` の宣言順です。
- `update()` を呼ばずにパラメータを変えても、判定は前回の `update()` の形のままです。判定は評価済みの状態を読むだけで、再評価しません。

| API | 内容 |
| --- | --- |
| `CompiledModel::hit_area_index(id)` / `hit_area_mesh(h)` | 当たり判定の添字 (`Model::hit_areas` のインデックス) / 判定に使うメッシュの添字 |
| `ModelInstance::mesh_contains(m, p)` | メッシュ `m` の変形後の三角形が点 `p` を含むか (上の規則。エディタの要素選択も、これに可視性の条件を足して使う) |
| `ModelInstance::hit_area_contains(h, p)` | 当たり判定 `h` が点 `p` を含むか |
| `ModelInstance::hit_areas_at(p)` | 点 `p` を含む当たり判定の添字 (手前から) |
| `Puppet::hit_areas_at(p)` / `Puppet::hit_test(id, p)` | 上の 2 つの ID 版。未知の ID は当たらない |
| `WebPuppet.hit_area_ids()` / `hit_areas_at(x, y)` / `hit_area_test(id, x, y)` | wasm 版。問い合わせの前に、未反映のパラメータ変更を評価する |
