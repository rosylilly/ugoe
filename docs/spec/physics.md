# 物理演算仕様

対応するコードは、データが `ugoe_model::physics`、アルゴリズムが `crates/ugoe-physics`。

## 概要

物理リグ (`PhysicsRig`) は **入力 → 振り子チェーン → 出力** の 3 段で動きます。

1. **入力**: 顔の角度などのパラメータから、チェーンの根元の平行移動と回転を作ります。
2. **振り子チェーン**: 粒子を距離拘束でつないだ鎖を、重力・風・根元の動きに従ってシミュレーションします。
3. **出力**: 粒子の位置や、隣り合う粒子の成す角を、髪揺れなどのパラメータに書き込みます。

## 座標と単位

- 物理空間は **y 軸下向き** (キャンバスと同じ向き) の 2 次元空間で、長さの単位は任意です (正規化の範囲 `normalization.position` と粒子の `radius` で決まる)。重力の既定は `(0, 1)` (真下) です。動的物理のリグでは、物理空間はキャンバス座標 (ピクセル) です ([物理空間と根元の取り付け先](#物理空間と根元の取り付け先))。
- 角度は **度** で、時計回りが正です ([evaluation.md](evaluation.md) の回転デフォーマと同じ)。
- 係数の時間の基準は **基準フレーム (1/30 秒)** です。`mobility` と `delay` は「基準フレームあたり」の値なので、ステップの周波数 (`fps`) を変えても揺れの速さと減衰はほぼ変わりません。

## 時間の進め方

- 固定ステップで積分します。ステップ幅は `1 / settings.fps` です。`fps` が正の有限値でなければ 60 を使います。
- `update(dt)` は `dt` を累積し、ステップ幅を超えた分だけステップを実行します。`dt` が負・非有限なら 0 とみなします。
- 1 回の `update` で実行するステップ数には上限 (既定 8、`MAX_STEPS_PER_UPDATE`) を設けます。上限を超えた分の時間は捨てます (スパイク対策)。
- 入力 (根元の姿勢) は、前回ステップを実行した時点の姿勢から今回の `update` の姿勢へ、ステップごとに線形補間して与えます。1 フレームで何ステップも進むときに、入力の変化が最初のステップに集中しないようにするためです。
- 出力は、直前 2 ステップの出力値を、余りの時間 (`accumulator / step`) で線形補間して書き込みます。表示のフレームレートと物理のステップが揃わなくても揺れが滑らかになります。代わりに、出力は最大 1 ステップ遅れます。
- 最初の `update` (と `reset` の後の最初の `update`) では、ステップを進める前に、その時点の入力に対する **静止姿勢** (各区間が力 `gravity * acceleration + wind` の向きに垂れた姿勢) に粒子を置きます。頭を傾けたまま読み込んでも、髪が揺れ始めません。

## 入力

各入力 (`PhysicsInput`) は、パラメータの値を正規化してから重み付きで加算します。

```
n = normalize(value, param.min, param.default, param.max, range)   // range は normalization.position または angle
if reflect: n = -n
translation.x += n * weight/100      (source = x)
translation.y += n * weight/100      (source = y)
angle         += n * weight/100      (source = angle、度)
```

`normalize` は、パラメータの default から min 側・max 側で別々に線形写像します。
`value` が default より大きければ `[default, max] → [range.default, range.max]`、小さければ `[min, default] → [range.min, range.default]` に写します。
default と等しい (または写す側の幅が 0) なら `range.default` です。

存在しないパラメータを参照する入力と、`source` が未知の入力は無視します。

## 振り子チェーン

粒子 0 は根元で、`translation + particles[0].position` に固定されます。粒子 i (i >= 1) ごとに、根元に近い順に、各ステップで次の計算をします。
`parent` はこのステップで更新済みの粒子 i-1 の位置です。

```
h        = (step / (1/30)) * delay                        // 基準フレーム単位のステップ幅
gravity' = rotate(settings.gravity, angle)                // 根元の回転だけ重力を回す
last     = position
position = parent + rotate(position - parent, Δangle * 0.2)   // 根元の回転に引きずられる
force    = gravity' * acceleration + settings.wind
position = position + velocity * h + force * h²
position = parent + normalize(position - parent) * radius     // 距離拘束
velocity = (position - last) / h * mobility^(step / (1/30))   // h = 0 なら 0
```

`Δangle` はこのステップでの根元の角度の変化量です。距離拘束で向きが決まらない (親と同じ位置) ときは、初期位置での親からの向きを使います。

### 係数の意味

| 係数 | 意味 | Cubism エディタでの名前 |
| --- | --- | --- |
| `radius` | 親の粒子からの距離 (振り子の長さ) | 振り子の長さ |
| `mobility` | 基準フレームあたりに残す速度の割合 (0〜1)。1 で減衰なし、小さいほど揺れがすぐ止まる | 揺れやすさ |
| `delay` | 時間の進み方の倍率。1 で等速、大きいほど入力に機敏に反応して速く揺れ、小さいほどゆっくり揺れる | 反応速度 |
| `acceleration` | 重力の倍率。大きいほど元の向きに戻ろうとする力が強く、揺れが速く収まる。風には掛からない | 収束の速さ |

- 根元の回転は 2 通りに効きます。**重力を根元の角度だけ回す** ので、頭を傾けると静止姿勢も同じ角度だけ傾きます (出力 `angle` の静止値 = 入力の角度)。また、角度が変わった瞬間に、各粒子を親のまわりに変化量の 0.2 倍 (`ROOT_ROTATION_FOLLOW`) だけ回して、鎖を回転に引きずらせます。
- `mobility` が 1 を超えると揺れが増幅して発散します。エディタでは 0〜1 に制限することを推奨します。

### 決め方の根拠 (T0301)

Cubism を並べて動かすことはできないため、公開されているマニュアルの説明 (各係数を 1 より大きく/小さくしたときに何が起きるか) と物理的な解釈から、上の式と係数の意味を決めました。互換の基準は「見た目の挙動が近いこと」で、数値が一致する必要はありません。

- 「反応速度」は 1 で等倍、1 より大きいと機敏になる、「収束の速さ」は 1 で等倍、1 より大きいと揺れが速く収まる、と説明されています。前者を時間の倍率 (`delay`)、後者を重力の倍率 (`acceleration`) として表しました ([How to Set Up Physics](https://docs.live2d.com/en/cubism-editor-manual/physical-operation-setting/)、[About Physics](https://docs.live2d.com/en/cubism-editor-manual/physics-operation/))。
- 基準フレームを 1/30 秒とし、`fps = 30` のとき `mobility` がそのまま 1 ステップあたりの速度の残存率になるようにしました。`fps` を上げると `mobility` を累乗して、単位時間あたりの減衰を揃えます。
- フィクスチャ (`ugoe_model::fixtures::physics_hair_settings`) で頭を 0.3 秒かけて動かすと、揺れの周期はおよそ 0.3〜0.7 秒、2 秒ほどで収まり、髪揺れとして自然な範囲に入ることを確かめました。
- Cubism の出力の角度はラジアンに scale を掛けたものです ([SDK Manual: Physics](https://docs.live2d.com/en/cubism-sdk-manual/physics/))。ugoe は度で扱うので、Cubism の設定を移すときは `scale` に `π / 180` を掛けます。

## 出力

```
source = x     → 粒子 i の位置 (1 つ前の粒子からの相対) の x 成分
source = y     → 同じく y 成分
source = angle → 粒子 i-2 → i-1 のベクトル (i = 1 なら settings.gravity。根元の角度で回さない) から
                 粒子 i-1 → i のベクトルへの符号付きの角度 (度、時計回りが正)
value = source * scale
if reflect: value = -value
value をパラメータに合成する (方法は blend で選ぶ。下の「合成の方法」)
  overwrite (既定): value を値域にクランプし、現在値に weight/100 の割合でブレンドする
                    (param = param + (clamp(value) - param) * weight/100)
  add:              param = clamp(param + (value - rest) * weight/100)
```

`particle` が 0 または粒子数以上の出力、存在しないパラメータへの出力、`source` が未知の出力は無視します。
同じパラメータへの出力が複数あるときは、リグ・出力の順に続けてブレンドします。

### 合成の方法

判断の経緯と実装は T0313。

パラメータへの出力 (`target.type = parameter`) は、`blend` で現在の値との合成の方法を選びます。

| `blend` | 合成 | 用途 |
| --- | --- | --- |
| `overwrite` (既定) | `param + (clamp(value) - param) * weight/100`。重み 100 なら物理の値で置き換える | 揺れ用のパラメータ (髪揺れなど、物理だけが動かすもの) |
| `add` | `clamp(param + (value - rest) * weight/100)`。物理の値の **静止時の値からのずれ** を足す | トラッキング・モーション・手で動かす値に、物理の揺れを重ねる |

Live2D の実践では、トラッキングの値と物理の揺れを両立させるために、体の角度などのパラメータを「トラッキング用」と「物理用」に複製し、
両方にキーを付けます ([乾物ひもの「物理演算を用いた動き表現」](https://note.com/himono_vtuber/n/n9015f0030d53))。
物理の出力が値を置き換えるためです。`add` を使うと、パラメータを複製せずに、
トラッキングが書いた `BodyAngleX` (頭の回転 × 0.3) に、頭の動きに遅れて付いてくる揺れ (遅れと行き過ぎ) を足せます。

- **静止時の値 (`rest`)** は、そのステップの入力 (根元の姿勢・重力・風) での **静止姿勢** (各区間が力 `gravity * acceleration + wind` の向きに垂れた姿勢、
  [時間の進め方](#時間の進め方)) から、同じ `source`・`scale`・`reflect` で求めた出力の値です。衝突体は考えません。
  鎖が静止していれば `value = rest` なので足す量は 0 で、パラメータは物理を進める前の値のままです。
  たとえば `source = angle` の粒子 1 は、根元が回っていれば (入力の角度)、静止していても 0 でない角度を出しますが、
  `add` ではその分を引くので、頭を傾けたまま止まっていれば何も足しません。
- **足す先の値 (`param`)** は、物理を書き込む直前の値です。`Puppet` では、フレームの始めに戻した基準値に、モーション・トラッキング・表情・目パチ・呼吸を
  適用した値です ([motion.md#フレーム内の適用順](motion.md#フレーム内の適用順))。フレームごとに基準値へ戻すので、足した量は **フレームをまたいで累積しません**。
  `PhysicsSystem::update` を直接使うホストが `add` の出力を使うときは、毎フレーム出力先の値を書き直してから呼びます (書き直さないと、前のフレームの値に足し続ける)。
- 補間: 直前 2 ステップの `value - rest` を補間してから足します ([時間の進め方](#時間の進め方))。
- クランプ: 足した結果をパラメータの値域にクランプします。`overwrite` と違い、`value` 自体はクランプしません。
- 中継 ([リグの順序と中継](#リグの順序と中継)): パラメータの写しにも同じ規則で書くので、後ろのリグの中継の入力は **足した後の値** (物理を進める前の値 + ずれ) を読みます。
  写しの出力先はステップの始めにフレームの始めの値に戻すので、ステップの間でも累積しません。
  基準値が 0 のままなら、静止時の値が 0 の出力 (`source = x` で重力が真下など) では `add` と `overwrite` は同じ結果になります。
- パラメータ以外の出力先 (動的物理) は、もともと加算量として足すので `blend` を使いません。
- 省略時 (`blend` のない古いデータ) は `overwrite` です。未知の値は `overwrite` として扱います
  ([file-formats.md#未知の値の読み込み](file-formats.md#未知の値の読み込み))。
- 任意機能 `physics.additive_output` です。知らないランタイムは `blend` を読み飛ばし、`overwrite` として扱います。
  1.0 の基準の機能なので宣言しません ([file-formats.md#10-の基準の機能](file-formats.md#10-の基準の機能))。

## リグの順序と中継

判断の経緯と実装は T0312。

リグは `PhysicsSettings::rigs` の順に処理します。あるリグがパラメータに書く出力を、後ろのリグが入力に読むと、
2 つのリグは **同じステップの中で** 連鎖します。
「体が遅れて付いてくる → 弾む → 角度に戻る」のように、1 つのリグでは作れない動きを、中継用のパラメータ (中継パラメータ) を挟んで組み立てるためです
(Cubism の物理でも、グループは上から順に処理され、上のグループの出力を下のグループの入力にする使い方をします。
参考: [乾物ひもの「物理演算を用いた動き表現」](https://note.com/himono_vtuber/n/n9015f0030d53))。

- リグ k の入力のうち、**k より前のリグ** のどれかがパラメータの出力先 (`target.type = parameter`) にしているパラメータを読むものを **中継の入力** と呼びます。
  どのリグが中継の入力を持つかは、設定から (実行前に) 決まります。
- 各ステップでは、リグを並びの順に 1 つずつ進めます。リグを進めた直後に、そのステップの出力 (**補間しない** 値) を、
  パラメータへの書き込みと同じ規則 (値域へのクランプと重みでのブレンド、[出力](#出力)) で、ステップの間だけ使うパラメータの写しに書き込みます。
  写しの出力先のパラメータは、各ステップの始めにフレームの始めの値に戻します (ブレンドは毎ステップ同じ値から始める)。
- 中継の入力はこの写しから読みます。それ以外の入力 (外からのパラメータ、自分自身や後ろのリグの出力) は、従来どおりフレームの始めの値を読み、フレームの間で線形補間します。
  中継の入力による根元の平行移動と角度は、補間した姿勢に足します (補間しない。前のリグの出力はステップごとの値なので)。
  根元の回転に鎖を引きずらせる量 (`Δangle`) は、中継の分を含めた角度の変化から求めます。
- 最初の `update` (と `reset` の後) の静止姿勢も、並びの順に求めます。後ろのリグは、前のリグの静止姿勢の出力を読んで静止します。
- パラメータに書き込む値 (外から見える値) は、従来どおり直前 2 ステップの出力の補間です ([時間の進め方](#時間の進め方))。
  つまり中継パラメータには補間した値が見えますが、後ろのリグはステップごとの補間しない値を読むので、連鎖しても遅れは増えません。
- 前のリグの出力を読まない入力 (自分自身や後ろのリグの出力を読む入力) は、フレームの始めの値、すなわち前のフレームに書いた補間した値を読みます。
  1 フレーム 1 ステップなら、連鎖の段ごとに 2 フレーム (次のフレームで読む分と、出力の補間の 1 ステップの分) 遅れます。
  順序を入れ替えると結果が変わるので、エディタでは並べ替えられるようにしています ([editor.md#物理の編集](../editor.md#物理の編集))。
- 中継の入力を持つリグがない設定では、処理の順序はリグの結果に影響しません (従来と同じ結果で、写しも作りません)。
- 動的物理のリグも同じ順序で進めます。中継パラメータを入力にして、デフォーマや頂点に出力するリグを後ろに置けます。
  ただし、動的物理の 1 段目の評価 (根元・衝突体・重力の基準) は、フレームの始めのパラメータで行います。

中継にだけ使うパラメータには `Parameter::internal` を付けます ([model.md#パラメータ](model.md#パラメータ))。
トラッキングはこのパラメータに書き込まず、ビューアなどのアプリの一覧では既定で隠します。

## 決定性

物理演算も決定的です。同じ入力列 (パラメータ値の列と `dt` の列) からは、常に同じ出力が得られます。乱数は使いません。

## 動的物理 (揺れ用パラメータのいらない物理)

判断の経緯は [ADR 0011](../adr/0011-dynamic-physics.md)。

データ定義は `ugoe_model::physics` (T0304)、シミュレーションは `ugoe_physics::PhysicsSystem::update_instance` (T0305) です。

パラメータ以外の出力先・衝突体・重力の基準 (`frame`) のどれかを使うリグを **動的物理のリグ** と呼び、1 つでもあれば設定全体が動的物理を使います (`PhysicsSystem::is_dynamic`)。
動的物理を使わない設定では、`update_instance` は従来の `update` (パラメータだけを書き換える) と同じで、評価も 1 回のままです。

### 物理空間と根元の取り付け先

動的物理のリグは、物理空間を **キャンバス座標 (ピクセル、y 軸下向き)** とみなします。粒子の初期位置・`radius`・`collision_radius`・入力の平行移動 (正規化の範囲 `normalization.position`) はピクセル単位です。

粒子 0 (根元) は、リグの **取り付け先のデフォーマ** A のワールド変換 `F_A` (1 段目の評価のもの) で動きます。

```
root = F_A(particles[0].position) + 入力の平行移動
```

A は次の順に決めます。

1. 出力の並びで最初の `deformer_angle` / `deformer_offset` の出力先 (回転デフォーマ)。`particles[0].position` をそのデフォーマの局所座標 (ふつうは `(0,0)` で、デフォーマの原点) として写すので、髪の房の根元のデフォーマに出力すれば、根元は頭と一緒に動きます。
2. なければ `frame` のデフォーマ (スカートなど、頂点だけに出力するリグは `frame` に体のデフォーマを指定する)。
3. どちらもなければキャンバス (従来どおり `root = particles[0].position + 平行移動`)。

根元を取り付けるデフォーマを別のフィールドとして持たず、出力先と `frame` から決めたのは、データ形式を増やさずに「揺れものの根元はその揺れもののデフォーマの原点」という普通の使い方を自動で満たすためです (T0305 で決定)。
根元の位置は、ステップの間で前回のステップの位置から線形補間します (入力の平行移動と同じ)。

### 出力先

`PhysicsOutput::target` (`PhysicsTarget`) で出力先を選びます。パラメータ以外の出力先が動的物理です。

| 出力先 (`type`) | フィールド | 内容 |
| --- | --- | --- |
| `parameter` | `id` (パラメータ) | 従来どおりパラメータに書き込む |
| `deformer_angle` | `deformer` (回転デフォーマ) | 回転デフォーマの角度に、粒子の区間の角度 (の `scale` 倍) を足す。粒子の区間とデフォーマを 1 対 1 に対応させると、デフォーマの鎖が揺れもののボーンのように動く |
| `deformer_offset` | `deformer` (回転デフォーマ) | 回転デフォーマの原点を、粒子の変位 (の `scale` 倍) だけずらす |
| `vertices` | `owner`、`weights` | ワープデフォーマの制御点 (`owner: {"warp": ID}`)、またはメッシュの頂点 (`owner: {"mesh": ID}`) を、重み付きで粒子の変位に追従させる。`weights` は頂点 (制御点) ごとの重み (0〜1) で、並びと長さは `Mesh::uvs` または `WarpKeyform::points` と同じ |

```json
{ "target": { "type": "deformer_angle", "deformer": "HairFront1" },
  "particle": 1, "source": "angle", "scale": 1.0, "weight": 100.0 }
{ "target": { "type": "vertices", "owner": { "mesh": "Skirt" }, "weights": [0.0, 0.5, 1.0] },
  "particle": 2, "source": "x", "scale": 1.0, "weight": 100.0 }
```

- `particle`・`scale`・`weight`・`reflect` の意味はパラメータへの出力と同じです。値は直前 2 ステップの値を補間したものです (パラメータへの出力と同じ)。
- 出力先が見つからない、または種類が合わない (`deformer_angle` の出力先がワープなど) 出力は無視します。
- 同じ出力先への出力が複数あれば、足し合わせます。加算量は毎フレーム 0 から作り直します。

#### 角度 (`deformer_angle`)

`source` と値の求め方はパラメータへの出力と同じで、値 (度) の `weight/100` 倍を、回転デフォーマのキーフォームで補間した角度 (局所座標系) に足します。
ただし `source = angle` で `particle = 1` のときの基準の向きは、`settings.gravity` をそのまま使うのではなく、**出力先の親の座標系での重力の向き** (1 段目の評価での、親のワールド変換のヤコビ行列 `J` を出力先の原点で求め、`J * gravity` としたもの) にします。
親の座標系が裏返っている (`det J < 0`、親の `reflect_x` など) ときは、値の符号を反転してから足します。

- 基準のデフォーマがなければ、重力はキャンバスの下向きです。頭を 30 度傾けると、頭の子の髪のデフォーマには -30 度が足され、髪は真下に垂れたままになります。
- `frame` に頭を指定すると、重力も頭と一緒に 30 度回るので、足す角度は 0 で、髪は頭と一緒に傾きます。
- 粒子 i (i >= 2) の角度は、1 つ前の区間からの相対の角度です。粒子の区間とデフォーマを 1 対 1 に対応させ、デフォーマを鎖の順に親子にすると (`Hair1` → `Hair2` → `Hair3`)、各デフォーマが粒子の区間に沿います。

#### 変位 (`deformer_offset`・`vertices`)

粒子 i の **変位** を、根元からの相対位置と、静止姿勢 (衝突体を考えない) での根元からの相対位置の差とします。

```
rest_i = Σ_{k=1..i} normalize(gravity' * acceleration_k + wind') * radius_k   // 静止姿勢での相対位置
d_i    = (p_i - p_0) - rest_i
source = x → (d_i.x, 0)、y → (0, d_i.y)、angle → 使えない (出力を無視する)
value  = source * scale (reflect なら符号を反転)
```

`gravity'`・`wind'` はそのステップで使った重力・風です。根元が動いても鎖全体が一緒に動くだけなら変位は 0 で、遅れて揺れた分だけが出ます。

- `deformer_offset`: 回転デフォーマの原点のワールド位置を `value * weight/100` だけずらします。
- `vertices`: ワープの制御点 (ワールド座標) またはメッシュの頂点 (ワールド座標、グルーの前) を、頂点ごとに `value * weight/100 * weights[v]` だけずらします。`weights` が頂点数より短ければ、足りない頂点は動かしません。

変位は **ワールド変換を適用した後のキャンバス座標で** 足します (局所座標系には直しません)。物理空間がキャンバス座標なので、親のワープで写し直すと伸縮や非線形性で粒子の動きからずれるためです。
x と y を両方動かすには、`source` が `x` と `y` の出力を 1 つずつ置きます。
- 旧形式 (`target` の代わりに `"parameter": "HairFront"` を持つ出力) も読めます。`parameter` 出力先として読み、書き出しは常に `target` を使います。両方あれば `target` を使います。

### 衝突体

`PhysicsSettings::colliders` (`PhysicsCollider { id, name, attach, shape }`) に、円 (`{"type": "circle", "center", "radius"}`) とカプセル (`{"type": "capsule", "a", "b", "radius"}`。線分 a–b から `radius` 以内の領域) の衝突体を置けます。

- 衝突体はデフォーマに取り付け (`attach`)、そのデフォーマのワールド変換 (1 段目の評価のもの) で動きます。形状の位置 (`center`・`a`・`b`) は取り付け先の局所座標系で、半径はキャンバスのピクセル単位で表します。`attach` を省略するとキャンバスに固定します。取り付け先が見つからない衝突体は無視します。
- 半径は取り付け先の拡大率やワープの伸縮を **受けません** (位置だけを写す)。ワープに取り付けると位置は UV で表しますが、半径はピクセルのままです。
- 各ステップの距離拘束の後、粒子 i (i >= 1) ごとに、リグの衝突体を `PhysicsRig::colliders` の順に調べ、内側に入っていれば表面の最も近い点まで押し出します。押し出す向きは、形状の芯 (円の中心・カプセルの線分) の最も近い点から粒子への向きです。粒子が芯の上にあって向きが決まらなければ、円は上 (`-y`)、カプセルは線分の向きを反時計回りに 90 度回した向きに押し出します。
- 押し出した位置から速度を求めるので、衝突体に当たった粒子は勢いを失います。押し出した後は距離拘束を満たさないことがあります (次のステップで戻る)。
- 押し出しは最も近い表面へ向けて行うので、静止姿勢の鎖が衝突体を貫いていると、粒子は衝突体の反対側 (たとえば肩の下側) に押し出され、
  区間が伸びたままになります。角度の出力先 (`deformer_angle`) は区間の向きしか伝えないので、描かれる房は衝突体に食い込みます
  (T0310 で確認。`fixtures::dynamic_hair_settings` の肩はこの状態。T0311 で直す)。衝突体は静止姿勢の髪の外に置いてください。
  外から当たる場合、描かれる関節は出力の補間 (最大 1 ステップの遅れ) の分だけ衝突半径に食い込むことがあります (T0310 で確かめた場面では、衝突体の形そのものには入らなかった)。
- 1 フレームの中の複数のステップでは、衝突体の位置はそのフレームの 1 段目の評価の位置で固定します。
- 最初の `update` (と `reset` の後) で静止姿勢に置くときも、根元に近い粒子から順に押し出します (押し出した粒子を次の粒子の親にする)。
- 粒子には衝突用の半径 (`PhysicsParticle::collision_radius`、既定 0) を持たせ、押し出しはこの半径を含めて行います。既存の `radius` は粒子の間の距離 (区間の長さ) なので、衝突には使いません。
- 物理リグごとに、どの衝突体と衝突するかを衝突体の ID の列で選びます (`PhysicsRig::colliders`、既定は空)。

### 重力と風の基準

`PhysicsRig::frame` に基準のデフォーマを指定すると、重力と風のベクトルをそのデフォーマの座標系で解釈します。
たとえば頭の回転デフォーマを指定すると、頭を傾けたときに髪の垂れる向きも傾きます。既定 (省略、`None`) はキャンバスの座標系です。

- 基準のデフォーマの回転 `θ_f` は、1 段目の評価でのワールド変換のヤコビ行列 `J_f` が重力の向き `ĝ` をどれだけ回すか (`signed_angle(ĝ, J_f * ĝ)`) で求めます。`J_f` は、回転デフォーマではどこでも同じ、ワープでは格子の中心 `(0.5, 0.5)` で求めます。拡大・せん断は向きにだけ効き、重力の大きさは変えません。
- 重力は `θ_f + 入力の角度` だけ回し、風は `θ_f` だけ回します (入力の角度で風を回さないのは従来どおり)。
- `θ_f` の変化は入力の角度の変化と同じく、根元の回転として鎖を引きずります (`ROOT_ROTATION_FOLLOW`)。`θ_f` は前のステップの値から近い側に回ったとみなし (±180 度をまたいでも跳ばない)、ステップの間で線形補間します。

### 評価との関係

動的物理はデフォーマのワールド座標を必要とするため、評価を 2 段階にします ([evaluation.md#2-評価の順序](evaluation.md#2-評価の順序))。
`PhysicsSystem::update_instance` が 1 段目 (`ModelInstance::update_first_stage`) を行い、その結果から根元・衝突体・重力の基準・角度の基準を求めてステップを進め、パラメータと加算量 (`ModelInstance::dynamic_offsets_mut`) を書き換えます。続く `ModelInstance::update()` が 2 段目です。
`Puppet::update` はこれを物理の段で行います。

パラメータだけを受け取る `PhysicsSystem::update` は、動的物理の設定でも動的物理の機能を使いません (根元はキャンバスに固定、衝突体と `frame` は無視、パラメータ以外への出力は捨てる)。

### 旧ランタイムでの扱い

任意機能 `physics.dynamic` ([ADR 0013](../adr/0013-forward-compatibility.md)) です。知らないランタイムは、パラメータ以外への出力と衝突体を無視します (揺れない)。
1.0 の基準の機能なので、1.0 以降のファイルでは宣言しません ([file-formats.md#10-の基準の機能](file-formats.md#10-の基準の機能))。

1.0 より後に出力先や衝突体の形状が増えたときは、知らない `type` を `Unknown` として読み、その出力・衝突体を無視します ([file-formats.md#未知の値の読み込み](file-formats.md#未知の値の読み込み))。

### 検証

参照先と値の検査は `validate_physics` で行います ([model.md#物理の検証](model.md#物理の検証))。
`.ugoe` の読み込み (`ugoe_format::read_bundle`) は、`PHYS` があればモデルと合わせてこれを通し、エラーがあれば `FormatError::InvalidPhysics` で読み込みを失敗させます。
実行中に設定を差し替える `Puppet::set_physics` も同じ検査を行います。検査を通さない `Puppet::with_physics` で渡した設定では、参照先が見つからない出力・衝突体を実行時に無視します。
