# UI の監査 (`just ui-audit`)

エディタ・ビューア・スタジオの画面を、同じ物差しで繰り返し確かめる道具です (T0915)。基準は [docs/ui.md の「UI の品質の基準」](../../docs/ui.md#ui-の品質の基準)。
ビルドした画面をヘッドレスの Chrome で開き、テーマ・言語・幅・devicePixelRatio を変えて撮り、機械で見つけられる崩れを数えます。
見た目の良し悪し (配置・余白・階層) は機械では決まらないので、撮った画像を人が見ます。

## 実行

```sh
just ui-audit                          # 3 つのアプリをビルドしてすべての場面を撮る (10 分ほど)
just ui-audit --only editor,viewer     # アプリを選ぶ
just ui-audit --quick                  # ライトの英語の広い幅と狭い幅だけ (反復中に)
just ui-audit --variants forced,zoom200   # 組の名前の一部で絞る (反復中に)
just ui-audit --no-build               # 前にビルドした dist と見本を使う (アプリのコードを変えていないとき)
just ui-audit --out target/ui-audit-before   # 結果の置き場 (既定 target/ui-audit)
just ui-audit --compare target/ui-audit-before  # 前の summary.json と比べて、増えた・消えた・数が変わった種類を出す
just ui-audit --strict                 # 見つけたものがあれば終了コード 1 (既定は、場面が開けなかったときだけ 1)
just ui-audit --jobs 1                 # 組を 1 つずつ流す (既定は 3 つの組を並行に。下)
```

**時間と並行の数 (T0054):** 組 (下の「場面」) ごとに別のブラウザのコンテキストとページ (と偽のホスト) を開くので、組どうしは
互いに影響しません。既定では 3 つの組を並行に流します (`--jobs N` で変える)。結果 (報告・`summary.json`・`tab.txt`) は並行の数に
よらず組の順に並びます。エディタの 13 の組 (604 の場面) は、3 つの並行で 6 分半ほど、1 つずつでは 16 分ほどかかります
(ほかの作業でロードアベレージが 5〜10 の 24 コアの機械。ビルドを除く)。エージェントが前面で流す Bash の上限 (600 秒) に収まります。
機械が混んでいて場面の待ち (`waitForTimeout`) が足りなくなるときは、並行の数を減らします。

直す前に `--out target/ui-audit-before` で撮っておき、直した後に `--compare target/ui-audit-before` で比べると、
M10 のタスクの「見直しの前と後」の比較になります。

要るもの: Google Chrome か Chromium (環境変数 `CHROME` で場所を指定できる)、`just wasm` に要るもの (wasm-bindgen-cli)、
cargo (エディタの見本を `ugoe sample dress-up` で作る)。Linux と WSL で確かめています。`just ci` には含めません (アプリのビルドと
200 ほどの場面の撮影で重いため)。道具の単体テストは `just ui-audit-check` (`just ci` に含む)。

## 流れ

1. **ビルド:** アプリごとに `just wasm <出力先>` と `vite build` (出力は `<out>/dist/<アプリ>`)。エディタには `ugoe sample dress-up --project` で
   見本のプロジェクトと、同じモデルの `.ugoe` を作る (`<out>/sample/`)。
2. **配る:** dist を小さな静的サーバ (`lib/serve.mjs`。空いているポート) で配る。並行に流してもぶつからない。
   組 (下の「場面」) は既定で 3 つずつ並行に、それぞれ別のページで開く (`--jobs`。上の「時間と並行の数」)。
3. **偽のホスト:** Tauri の代わりを置く。画面を見るための偽物で、編集や保存はしない。
   - エディタ (`lib/editor-host.mjs`): `window.__TAURI_INTERNALS__.invoke` を Node の側の読むだけの偽物に中継する。開く前は空のプロジェクト、
     「開く…」で見本のプロジェクト (model.json・physics.json・motions・expressions と `.ugoe`) を開いたことにする。編集のコマンドは
     `ui_audit.read_only` のエラー、知らないコマンドは `null` を返して報告に名前を出す (バックエンドのコマンドが増えたら足す)。
     ファイルのダイアログは `window.__UGOE_FILE_DIALOGS__` で差し替える。
     見本のモデルにはグルーを 1 つ足す (袖と手を `ArmWave` の 3 つのキーでつなぐ `SleeveHandGlue`。グルーのパネルの編集の欄を撮るため。
     `ugoe_model::fixtures` と `ugoe sample` は変えない。T0044)。マスク専用かつ非表示のメッシュも 1 つ足す (非表示のパーツ「Wave」の手を写した
     `HandWaveMask`。ツリーにマスクと非表示の札を持つ行を出すため。T1670)。バックエンドが送るイベント (`listen` で待つもの) は、ページの
     `window.__uiAuditEmit(event, payload)` で送る (エージェントが提案を置いた `mcp-bridge` の `proposals` など)。
     GPU を失った状態は、ページの `window.__uiAuditLoseGpu()` (描いている canvas の WebGL2 のコンテキストを `WEBGL_lose_context` で
     失わせる) と `window.__uiAuditRestoreGpu()` (戻す) で作る (apps/editor/browser-test と同じやり方。T0060)。
     見本に無い状態 (T0676) は `host.set({ ai, restoring, dressUp, module, manyParameters, externalChange, baseChange })` で切り替える (中身は `lib/editor-fixtures.mjs`。
     作りものだが、提案のコマンドの種類 (`op`) と分類のラベルは本物にあるものだけを使う。`hosts.test.mjs` が
     `crates/ugoe-editor-core/src/command.rs` と `crates/ugoe-ai/src/classify.rs` に照らして確かめる。T0047):
     `ai` は提案と分類があり外部に送れる設定 (分類は同意が無ければ確認を求め、同意の後は `cancel_ai_requests` まで答えない。
     リグの提案は `ai.time_limit` で失敗する)、`restoring` は分類のキャッシュを戻している最中、`dressUp` はプレビューの着せ替えに
     見本の `.ugoemod` と読めないファイル、`module` はモジュールのプロジェクト (本体は見本、モジュールは Sailor。今の編集は
     `.ugoemod` の `MODU` の名前を `Sailor (editing)` に書き換えて作る) と、今の編集とファイルの違いの長い一覧、`manyParameters` は
     パラメータを 100 個・グループを 10 個に増やしたモデル (`get_model_json` だけを変え、描くのは見本の `.ugoe` のまま。T1630)、
     `externalChange` は外での書き換え (`check_external_change` が 5 つのファイルの変化を答える)、`baseChange` はモジュールのプロジェクトの
     本体の変化 (`check_base_change`。T0044)。
   - スタジオ (`lib/studio-host.mjs`): `window.__UGOE_STUDIO_HOST__` に、`StudioHost` (apps/studio/src/lib/host.ts) のすべてのメソッドを置く。
     見本のプロファイル (apps/studio/scripts/sample-profile.mjs) に画面の既定値 (src/lib/inputs.ts・virtualCamera.ts) を足して送る。
     プロファイルの場所はコミットした見本のプロファイル (`assets/samples/ugoe-sample-profile.json`。英語の画面は `ugoe-sample-profile.en.json`。
     拡張子は保存のダイアログが付けるもの。`src-tauri/src/lib.rs` の `PROFILE_EXTENSION`)。プロファイルの中のパスは絶対パスに解いて送る (本物のスタジオと同じ)。
     配信中のシーン「雑談」のモデル (`avatar.ugoe`) のパラメータ (27。名前は ID)・モーション・表情・ポーズのグループ (`earwear` / `no_earwear`) は、
     見本を作るソース (`crates/ugoe-cli/src/sample.rs`・`sample/animations/`、`ugoe-model` の `standard.rs`) から読み、本物の指揮役と同じく
     ポーズは各グループの先頭を表示し、待機のモーション `idle` を流している様子で送る (T0047)。
     ページの `window.__uiAuditStudio` の `emit` (指揮役の通知を送る)・`setStatus` (負荷の数値を変える)・`setOutput` (出力ウィンドウの様子を変えて送る) で、
     読み込んだ後に状態を変えて撮る (初めて起動した画面・承認を待つアプリ・登録できないホットキー・負荷の注意・透過が効かない出力。
     通知の組は `firstRunMessages`・`attentionMessages`。T0818・T0849)。出力ウィンドウの透過は、ふだんは `supported` (効く) にしておく。
     `failSave` は今の保存先への保存 (`saveProfile()`) を失敗させる (`autosaveFailure` が作る、`profile.io` のエラーと、書けない場所なら
     書き換えないプロファイルにする印。本物と同じく、書き換えないプロファイルの通知を送ってから失敗を返す。T0874)。
     操作 API の承認・拒否・取り消しは、様子を変えて送り直す (承認の後の「取り消す」の知らせを撮るため)。
   - ビューア: Tauri の外の口 (ブラウザの口) のまま。ツールバーの「サンプル」で見本を開く。
4. **撮って検査する:** 下の「場面」ごとに PNG を撮り、下の「検査」を流す。
5. **まとめる:** `<out>/<アプリ>/report.md` (見つけたものと Tab の順)・`<アプリ>/tab.txt`・`<アプリ>/*.aria.yml`
   (アクセシビリティの木。スクリーンリーダーが読むものの近似)・`<アプリ>/*.outline.txt` (骨組み: ランドマーク・見出し・live region を
   文書の順に並べ、ランドマークの入れ子を字下げで示したもの。docs/ui.md#骨組み-ランドマークと見出し の表と比べる)、`<out>/summary.md` と `summary.json` (数の表と、比べるためのデータ)。

広い幅のライトの英語と `en-dark-forced-wide` では、Tab を最大 120 回押してフォーカスをたどる (`-tab`。強制色では影 (`box-shadow`) で
描いたフォーカスの印が消えるので、印の無い止まりが見つかる)。印の有無は下の「フォーカスの印の判定」で決める。

場面を足すときは `lib/apps.mjs` の `extras` (読み込んだ後) か `load` (読み込みの途中) で、操作してから `ctx.scene("名前")` を呼ぶ。
送る枠の中の要素まで送るときは `scrollToElement`・`scrollToSection` を使う (送る枠だけを送り、枠の頭に固定された (sticky) タブや見出しの下に隠れないよう、その高さを引く。T0048)。
失敗の出し方を撮る場面は `ctx.scene("名前", { errors: true })` にすると、画面に出たエラーの文を数えない (スクリプトのエラーは数える)。
場面が意図して起こした失敗のコンソールのエラー (GPU を失わせたときの `ugoe: WebGL context lost` など) は、`ctx.ignoreErrors(正規表現)` が返す関数を呼ぶまで数えない (T0060)。
ダイアログ・メニュー・Popover を開いて撮る場面は `ctx.scene("名前", { overlay: true })` にし、撮った後は `closeOverlay` で閉じる
(閉じるまで Esc を押して待ち、戻ったフォーカスとポインタの Tooltip が残らないよう外す。閉じられなければ場面の失敗)。
ほかの場面で開いている重ねものは、前の場面の閉じ忘れ (`left open by an earlier scene`) として `error` に数える (T0053)。
ボタンは役割と名前 (アプリのカタログ `apps/<アプリ>/locales/<言語>.json` から `text()` で引く) で探す。使ったキーが英語と日本語の
カタログにあるかは `just ui-audit-check` が確かめる。

## 検査

| 名前 (報告の見出し) | 見つけるもの | 作り |
| --- | --- | --- |
| `contrast` (文字のコントラスト) | 4.5:1 (大きい文字は 3:1) に届かない文字 | 自前 (`lib/page-checks.js`)。文字の色と、祖先をたどって重ねた地の色を WCAG 2.x の式で比べる。無効の部品とモーダルのダイアログの後ろの文字は数えない。地を CSS から決められない文字 (下) は画素で測る |
| `overflow` (横のはみ出し) | 文書の横の送り・窓の右端を越える要素・送る (切り取る) 枠の外を位置の基準にして枠の外へ出ている `position: absolute` の要素 (`… escapes …`。T0954) | 自前。送る祖先の中は除く。枠に重ねて置いた絵 (枠の内側にあるもの) は数えない |

| `scrollbar` (重ねて描くスクロールバーの下の文字・部品) | 今縦に送れる枠の中で、右端が枠の見える右端から `--ugoe-scrollbar-gap` (16px) の中に入る文字と押せる部品 (`… is under the overlay scrollbar of …`。T0055) | 自前。下の「重ねて描くスクロールバー」 |
| `target-size` (24px 未満の押せるもの) | 24×24 CSS px 未満のボタン・リンク・入力・タブなど | 自前。数値の欄は枠の全体、チェックボックスとスイッチは見えるラベルまで、標準のチェックボックス・ラジオは包む `<label>` までを押せる範囲とする。スライダーのつまみは除く |

**フォーカスの印の判定 (T0045):** Tab の止まりごとに、止まりの矩形を 6 CSS px 広げた範囲 (窓で切る) を、フォーカスのある今 (後) と、
`blur()` で外した後 (前) に撮って比べ、撮った後はフォーカスを戻します。印の形 (outline・影・地の色・枠の色・下線・3 つ以上上の祖先の
`:focus-within`) を問わず、見えた変化で決めるためです。

- **変わった画素:** RGB のどれかの差が 16 (/255) 以上の画素。描き方の揺れ・縁のなめらかさの数画素を数えないため。
- **はっきり変わった画素:** そのうち、前と後の色のコントラスト比が 3:1 以上の画素 (WCAG 2.4.13 のフォーカスの印の「前と後の比」と、
  1.4.11 の 3:1)。
- **要る量:** 止まりの (窓の中に見える) 幅と高さの和の面積 (CSS px²)。1 CSS px の線で周りの半分をなぞる量で、2px の輪なら周りの
  4 分の 1 で足ります (2.4.13 の「2 CSS px の太さで周り全体」の 4 分の 1)。欄のカーソル (1 本で十数画素) は届きません。
  今の 3 つのアプリで印ありの止まりは、はっきり変わった画素がこの 1.5 倍以上あります (いちばん少ないのはビューアの光の向きのつまみ)。
- **判定:** はっきり変わった画素が要る量に届けば印あり、変わった画素だけが届けば `faint focus ring` (印は見えるが、前と後の比が 3:1 に
  届かない。報告に比の最大を出す)、どちらも届かなければ `no focus ring`。画面の外の止まりは撮れないので、CSS の判定 (自分と 2 つ上の
  祖先の `outline`・`box-shadow`) を使います。
- **撮る間に隠すもの:** 欄のカーソル (点滅する)・文字の選択の地 (Tab で入った欄の文字は選ばれる)・ツールチップ (フォーカスで開くが印
  ではない)。
- `tab.txt` では、CSS の判定と食い違う止まりに `(css: ring)`・`(css: none)` を付けます。印ありでない止まりと食い違う止まりは、
  前と後の画像を `<組>-focus-<止まりの番号>-before.png`・`-after.png` に書きます。フォーカスを戻せなかった止まりには `FOCUS-LOST` を付けます
  (その後の Tab の順は信じられない)。
- 撮った PNG は Node の側で読みます (`lib/png.mjs`。zlib で展開してフィルタを戻す小さな読み手。Chrome の撮る 8 ビットの PNG だけを読む。T0054)。
  ページの中で読む (`createImageBitmap`) と、止まりごとに base64 で送り返す分も含めて 40ms ほどかかったためです。
- 1 回のたどりは 120 の止まりで 15〜20 秒ほどかかります (画像を撮る前は 5 秒ほど。ほとんどは止まりごとに 2 回撮る時間で、1 回 40〜50ms。
  ロードアベレージ 10 ほどの機械)。
- 見ないこと: 範囲の外 (止まりから 6px より離れた所) に出る印 (祖先の大きな枠の遠い辺など。範囲の中の辺で足りることが多い)。
  フォーカスで開くもの (メニュー・Popover) は範囲に入れば変化に数えます。

**押せる部品の重なり (T0049):** `target-size` と同じ押せる部品 (数値の欄は枠の全体) の、見える矩形 (送る枠と窓で切った部分) どうしが
幅と高さともに 2 CSS px を超えて重なり、重なりの中ほどの点 (`elementFromPoint`) で一方がもう一方の上に描かれていれば、下の部品を
`… is covered by …` として数えます。T0044 で、エディタのグルーの軸を足す行 (`*-zoom200-glue-edit`) の選択欄の右端 (矢印) が右の数値の欄の
下に隠れていたのを、文字の重なりの検査が出さなかったために足しました (T1650 で直す前のコードで、この 2 つの場面に出ることを確かめた)。

- **数えないもの:** 入れ子の部品 (行の中のボタン)、枠の線を重ねて並べた部品 (2px 以下の重なり)、上に描かれた点がどちらの部品でもない
  (ダイアログの幕などが両方を覆う) もの、**意図して重ねたもの**。意図して重ねたものは、上に描かれた側から共通の祖先の手前までに、
  `position` が absolute・fixed・sticky の要素 (バッジ・ビューポートやタイムラインの上の道具・メニュー・送っても残る頭)、最上層の要素
  (モーダルのダイアログ・Popover)、`data-ui-audit-overlay` の印のどれかがあるものです。流れの中に置いた部品どうしが重なるのは、
  縮めすぎ・負の余白などの崩れで、意図して重ねることはほぼ無いためです。流れの中で意図して重ねるときは、上の側に `data-ui-audit-overlay` を付けます (同じ印で、下の「重ねて描くスクロールバー」の検査からも外れます)。
- **誤検出の多さ:** 意図して重ねたものを数えないと、英語のライトの広い幅と狭い幅だけでも、3 つのアプリで 28 種類 (エディタ 15・ビューア 6・
  スタジオ 7。開いたメニューの項目・設定のダイアログ・送っても残る頭・タイムラインのキーの印が下の部品を覆う) が出ます。数えると、すべての
  場面で 0 です (T0049 の時点)。
- 見ないこと: 部品の外の文字・絵 (札・アイコン) に部品が隠れるもの (文字の重なりの検査か画像で見る)、部品が窓や送る枠の端で切れるもの
  (`overflow`)、上の側を流れから外したために隠れた崩れ (意図した重なりと見分けられない)。

**重ねて描くスクロールバー (T0055):** WebKitGTK (Linux)・macOS のスクロールバーは幅を取らずに中身の上に重ねて描き、指を乗せると
右端から 14px まで太ります (T0970)。ヘッドレスの Chrome はスクロールバーに幅を取るので、中身が隠れる形は画像には出ません。そこで、
送る枠の見える右端 (スクロールバーと枠の線を除いた `clientWidth` の右) から中身の右端までの空きを測ります。この空きは、重ねて描く形で
中身がスクロールバーから離れている幅と同じです。決め (docs/ui.md#レイアウト の「送り」) は、縦に送る枠の行末を `--ugoe-scrollbar-gap`
空けることです。

- **枠:** `overflow-y` が `auto`・`scroll` で、今縦に送れる (中身が枠より 1px を超えて高い) もの。画面の全体の送り (ビューア・スタジオの
  狭い幅) も含める。送らない枠 (`hidden`・中身が収まっている) はスクロールバーが出ないので見ない。**横にも今送れる枠** (表・タイムライン)
  も見ない: 中身は右の端の先へ続き、行末を空ける形にならないため。
- **見るもの:** 文字 (文字を直に持つ要素の行の矩形) と、`target-size` と同じ押せる部品 (数値の欄は枠の全体)。どちらも、はみ出しを切り取る
  祖先と窓で切った見える部分の右端を測る。部品でない地・枠の線・区切り線・絵 (意図して枠の端まで描くもの) は数えない
  (重なっても読めなくならず、押せなくもならない)。押せる行 (ツリーの行など) は部品なので、行の矩形の右端を測る。枠との間に `position: fixed` の要素があるもの (枠の外に描く Popover など) は枠の上に無い。
- **閾値:** 空きが `--ugoe-scrollbar-gap` (画面の CSS の値。読めなければ 16px) より 0.5px を超えて小さければ数える (小数の幅の丸めで
  16px が 15.9px に測られても数えない)。部品ごとに、いちばん内側の枠で 1 つだけ数える。
- **効き目:** T0970 と T1662 で空ける前の CSS を作業ツリーに戻すと、`--quick` でビューア 3 種類・スタジオ 9 種類・エディタ 23 種類を
  出す (ビューアのパラメータの一覧のグループの数・スタジオの右の列のボタン・エディタのパネルの部品など)。直した後は 0 (下の意図した残りを除く)。
- **意図したもの (`data-ui-audit-overlay`。T0064):** 部品から枠の手前までに `data-ui-audit-overlay` の印があるものは数えない。
  押せる範囲を見た目より広げて、範囲の端だけが行末の空きに出る部品に付ける。今は、エディタの帯の端の値・時刻にあるキーの印
  (ParametersPanel.svelte の `button.marker` のパラメータの最大の値のキー、MotionEditor.svelte の `button.diamond` のモーションの
  終わりのキー)。印の押せる範囲 (24px) を見た目の印 (◆) より広げて中心に置くので、範囲の端が帯の端の先に出る (空き 12px・8.7px)。
  見た目の印は空きの中 (約 20px・13.7px) にあり、指を乗せたスクロールバーが押せる範囲の端の数 px を取るだけなので、帯を縮めない。
  T0055 から毎回出ていて新しい指摘を埋もれさせるので外した。
  - 印は重なりの検査 (上の「押せる部品の重なり」) と同じものを使う: 「意図して重ねた (ほかの部品・スクロールバーと)」という意味が同じで、
    印の種類を増やさないため。この 2 つの印は `position: absolute` なので、重なりの検査からはもとから外れていて、印を付けても重なりの
    検査の結果は変わらない (`--variants zoom200,narrow` で、付ける前と後の重なりはどちらも 0)。印を付けるのは、空きに出るのが押せる範囲の
    端だけで見た目の部品が空きの中にあるものに限る。文字や見た目の部品そのものが空きに入るなら、印を付けずに行末を空ける。
- **残る指摘 (意図したもの):** ありません (上の印で外した)。
- **残る指摘 (直していないもの):** ありません。エディタの 200% の拡大 (`*-zoom200-settings-ai`) で全体が送る大きいダイアログの
  閉じるボタン (`.ugoe-dialog__close`。右から `space-4` = 12px で、指を乗せたスクロールバーが 2px 掛かっていた) は、T0979 で右を
  `--ugoe-scrollbar-gap` 空けた (本物の WebKitGTK でも、指を乗せて太ったスクロールバーの左の端とボタンの右の端が 2px 重なっていたのが 2px 離れた)。
- 見ないこと: 左に置くスクロールバー (右から左の言語)・横のスクロールバー (下の端)・フォーカスの印 (`outline`) の空き。

**canvas・画像の上の文字 (T0952):** 不透明な地の祖先の中に文字に重なる canvas・video・img がある文字 (ビューポートの上の知らせ・道具の札など)、
祖先に画像の地・グラデーション・hover の重ね (`background-image`) がある文字は、CSS の色だけでは地が決まりません。これらは、
画面のすべての文字を透明にして撮った PNG を地とし、文字の行の矩形の中の画素ごとに、文字の色を重ねた色との比を求めます。下から 1 割の比
(9 割の地の画素で届く比) を文字の比とします (縁や模様の数画素で落とさないため)。報告の `on pixels such as rgb(…)` は最も比の低かった地の画素です。
場面ごとのログの `by pixels` が画素で測った文字の数、`unmeasured` が矩形が無く測れなかった数です。
ビューポートの背景色を白・黒に変えた場面は撮りません (T0044): 今の画面で画素で測る文字は hover の重ねの上の文字と、エディタの空のプロジェクトの
案内 (地はテーマの `sunken`。エディタの背景色はテーマで決まり、変えられない) だけです。背景色を変えられるビューアのビューポートの上の知らせは
自分の地の札 (`surface`) を持ち、背景色に依りません。地の札なしで描画の上に文字を置くときは、背景色を変えた場面を足します。

同じ部品の行 (メッシュの一覧の 14 個のボタンなど) は 1 つの「種類」にまとめて数えます。種類は、クラスの付いた要素なら `tag.class`、
クラスが無ければ 3 つ上までの祖先のクラス (`tag@.class`)、どちらも無ければ名前まで含めた要素です。報告の数は「種類 (延べ)」で、
延べは場面ごとに数えた数です。

### 依存

- **playwright-core** (Apache-2.0): 入っている Chrome を動かす (ブラウザはダウンロードしない)。役割と名前で要素を探し、操作を待つため。
- **axe-core** (MPL-2.0): 読み上げの名前と ARIA の規則。名前の計算 (accname) を自前で正しく書くのは難しく、規則も多いため。
  道具の中でだけ使い、手を加えず、アプリには入りません (ルートの devDependencies)。

### 確かめないこと

- 実物の WebView (WebView2・WKWebView・WebKitGTK) での表示。WebKitGTK は `just e2e` (T0006) の側で撮る (T0919)。
- 実際のスクリーンリーダーの読み上げ (`.aria.yml` と `.outline.txt` は近似。docs/ui.md#確かめ方。実物は docs/manual-check.md の U03)。
  強制色の実物 (Windows のコントラスト テーマ。U04) と、強制色の場面の canvas の上の文字のコントラスト (文字を透明にして撮れないので、
  画素では測らずに `unmeasured` に数える)。
- ビューポート (モデルの描画) の中身・ギズモの見分けやすさ (上に重ねた文字のコントラストは測る)。偽のホストが返さない状態 (エラーの知らせの帯・
  接続中のクライアントなど。AI の提案・モジュールのプロジェクト・着せ替えは T0676 で足した) の画面。要るなら場面と偽のホストの答えを足す。
- 配置・余白・階層などの見た目の良し悪し (撮った画像を人が見る。docs/ui.md#ui-の品質の基準)。
